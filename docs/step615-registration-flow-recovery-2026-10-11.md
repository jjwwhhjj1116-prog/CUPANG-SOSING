# Step615 — 수정한 초안 재개와 공식 견적서·전송 연결

구현 우선순위는 카테고리 선택 → 1688 URL → 1–7단계 초안 → 사용자가 확인·수정 → Supplier Hub 등록전송 → 해당 견적서 접수·SKU 확인이다. Codex 소싱 플러그인은 이 등록 흐름의 대조·검수를 마친 뒤 진행한다. 이번 변경은 다음 오류들의 수정이며 전체 쿠플러스 동등성이나 신규 운영 상품의 접수 완료로 계산하지 않는다.

## 수동 옵션 수정 후 수집 작업 재개

이미 한국어 이름이 저장된 옵션의 공급자 원문 이름을 직접 정정하면, 저장된 최초 번역 결과의 이전 원문과 다르다는 이유로 남은 이미지 수집 후 최종 완료 판정이 실패했다. 수집 대기열은 계속 오류 상태에 남았다.

최초 수집의 완료 번역 결과를 다시 계획할 때만, 직접 수정된 원문이며 한국어 이름 또는 명시적인 수동 공란이 이미 있는 옵션의 오래된 이름 결과를 제외한다. 저장한 번역 요청·원문·결과·색상·사이즈 연결은 변경하지 않는다. 아직 번역 대상인 새 원문과 출처가 증명되지 않은 원문 변경은 계속 거부하고, 일반 번역 적용의 원문 일치 검사는 유지한다.

양회사 합성 실제 API·수집 대기열 검사에서 이미지 18/19 상태의 실패 후 옵션 원문·원가·수량·한국어 공란·색상·사이즈·포함 여부·옵션 삭제·견적서 수동 가격·표시사항 사진을 수정하고 작업을 재개한다. 남은 이미지 한 장만 수집하여 19/19와 초안 저장 완료에 도달한다. 추가 번역 서비스 호출은 없고 수동 값·사진 bytes·출처·수집 회사·설정·번역 요청·가격 정책·견적서 입력을 유지한다. 누락 이미지 추가에 따른 콘텐츠 버전 갱신만 정상 동작으로 허용한다.

## 공식 원본의 이전 상품 행 검사

공식 XLSX에 이전 상품의 입력행이 남아 있으면 출력한 행 수 보고서는 현재 선택한 옵션만 세면서 실제 파일에는 이전 상품도 유지되는 문제가 있었다. 공식 원본의 상품명 열을 실제 원본 헤더에서 확인하고, 선택한 출력 범위 앞뒤의 상품명 또는 상품명 수식이 있으면 파일 생성을 거부한다. 사용자 매핑 변경으로 원본 상품명 열 검사를 우회하지 않는다.

일반 미리보기의 1,000행 제한으로 먼 잔여행을 놓치지 않도록 원본 XML의 해당 셀을 별도의 검사 복사본에 모으고 기존 OOXML 문자열 디코더로 검사한다. 공유 문자열·여러 조각의 문자열·Excel 문자 이스케이프와 마지막 Excel 행까지 확인한다. 상품명 수식은 캐시가 비어 있어도 결과를 보장할 수 없어 거부하며 수식을 실행하지 않는다.

원본 파일·저장한 프로필·상품 입력을 삭제하거나 수정하지 않는다. 안내·예시·빈 기본값·상품명 외의 수식과 파일의 다른 구성요소를 보존한다. 일반 XLSX의 인접 행 보존과 기존 수식 덮어쓰기 거부도 유지한다. 사용자에게 상품 입력이 없는 원본 양식으로 다시 준비하도록 오류를 반환한다.

## 현재 동의 문구 확인과 확장 0.2.59

Supplier Hub 가격 정보·라벨 연락처 항목은 이미 선택되어 있어도 현재 화면의 문구가 검토한 항목과 정확히 일치해야 한다. 체크 전 전체 항목을 검사하고, 업로드 대기·회사 메뉴 확인 후 검증 버튼을 누르기 직전에도 다시 확인한다. 문구가 달라지거나 사라지면 검증 요청 표시와 버튼 클릭을 하지 않는다. 정확한 기존 수동 선택은 다시 누르지 않는다.

확장은 `exactAgreementLabels` 기능을 PING에 응답한다. 새 첨부 준비·전송과 기존 첨부 검증 재개는 해당 기능을 먼저 확인한다. 직접 전송 함수도 패키지 bytes를 읽기 전에 확인하여 호출자의 사전 검사를 누락해도 이전 확장으로 전송하지 않는다. 법적 서류 선택·회사·파일·현재 입력·중복 전송 보호와 최종 접수 판단을 유지한다.

이전 확장의 보관된 전송 결과와 카테고리 조회는 유지한다. 앱 다운로드 링크와 설치 검사에는 0.2.59를 연결하며 다운로드 버전을 실제 설치 버전으로 표시하지 않는다. 기존 0.2.57·0.2.58 ZIP, 권한·허용 호스트·DB 마이그레이션을 보존한다. 새 Chrome 프로필·창을 생성하거나 기존 작업 상품의 수집·번역·저장·전송·삭제를 하지 않았다.

## 원래 첨부의 검증 재개와 내부 기록 분리

전체 상품 전송 이력 검사에서 재개하려는 원래 첨부 시도까지 새 전송으로 판단하여 정상 검증 재개를 막는 문제가 있었다. 첫 확인은 앱 원본·회사·탭·보관 결과를 읽고, 원래 Hub 첨부 목록과 표시를 확인한 뒤에만 재개 전용 이력 검사를 한다. 최신 저장 기록·탭 연결·회사·원본 파일 표시가 그대로인 자기 전송 시도 한 건만 이 검사의 계획에서 제외한다. 파일 업로드나 원본 기록 삭제는 없다.

다른 시도·접수·불확실한 이력과 서버 기록의 차단은 유지한다. 검증 요청 표시 직전에 같은 확인을 다시 수행하고, 이전 검증 응답이 불확실하면 기존 내부 요청 기록으로 중복 실행을 막는다. 회사·창·원본·파일 표시·저장 기록이 중간에 달라져도 재개하지 않는다.

IndexedDB의 내부 `:validation` 요청 기록도 전체 상품 전송 목록에 섞여 일반 전송 기록 검사를 실패시키는 문제가 있었다. 원래 전송 기록이 실제로 있고 동일한 식별값·허용 회사·옵션 수·파일·검증 재개 상태·요청 시각이 확인되는 내부 기록만 읽기 목록에서 분리한다. 내부 기록 자체는 그대로 보관하고 재개 시 계속 조회한다. 부모 없는 기록·잘못된 요청·알 수 없는 접미사는 숨기지 않고 거부한다. 상품 전송 기록 200건, 내부 기록을 포함한 조회 크기 512KiB를 유지한다.

실제 저장 이력을 반환하는 합성 재개 테스트와 실제 IndexedDB 커서 모양의 검사에서 수정 전 실패를 확인했다. 회사별 다른 시도·서버 이력·원본 변경·응답 유실, 정상 내부 기록 분리와 원본 보존을 검증한다. 과거 테스트의 빈 이력 가정으로 재개 성공을 만들지 않는다.

## 검수 범위

실제 API·SQLite/R2·React 콜백과 XLSX bytes 및 직렬화한 확장 DOM 함수를 사용한 합성 회귀를 수행한다. 이 결과를 신규 1688 실수집이나 원격 Supplier Hub 견적서 접수 성공으로 설명하지 않는다. 기존 지정 Chrome의 앱 화면에서는 회사별 기본설정과 등록표를 읽기만 하고 배포 전후 값 보존을 확인한다.

전체 카테고리의 실제 쿠플러스 기본값 대조, 신규 실제 상품의 초안·이미지 검토와 Supplier Hub 접수·SKU 확인은 아직 별도의 최종 검수가 필요하다.

최종 회귀는 수집·초안 82개, 공식 견적서·카테고리 135개, 잔여 상품의 실제 API·화면 경계 4개, 전송·동의·재개·이력 284개로 **505/505** 통과했다. 실패·취소·건너뜀은 0이다. TypeScript 오류 0, ESLint 오류 0과 기존 경고 8, 운영 빌드 통과를 확인했다. 독립 코드 검토에서 추가 확정 결함은 발견하지 못했다.

별도로 같은 Chrome의 검수 탭에서 실제 IndexedDB를 사용하는 합성 전송 기록 10개를 검사했다. 양회사의 정상 내부 검증 기록 분리, 부모 없는 기록·잘못된 상태·알 수 없는 접미사·변경된 부모 기록 거부와 원래 기록 보존을 확인했다. 해당 로컬 서버는 종료하고 탭을 운영 앱으로 복원했다. 실제 판매자 사이트 요청이나 운영 상품 저장은 없다.

운영 Worker 버전은 `49417e8d-e490-4d7e-89c1-a27e9b30c829`다. 최신 등록 화면 자산을 확인했고, 검수 앱의 비밀번호 제외 입력 29개·등록표 1행 및 유앤채 기본설정 입력 35개가 배포 전후 같았다. 확장 0.2.59는 원본 39개 파일과 바이트 대조한 ZIP으로 제공하며, 이전 ZIP 2개·마이그레이션 17개·폰트의 SHA를 유지한다. 설치된 확장을 이번 검사에서 직접 갱신한 것으로 보고하지 않는다. 기록과 운영 화면 스크린샷은 Git 제외 `outputs/step615-*`에 보관한다.
