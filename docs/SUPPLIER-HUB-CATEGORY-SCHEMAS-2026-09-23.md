## 구현

- 관찰 JSON → `scripts/generate-hub-product-schemas.mjs` → `app/hub-product-schemas.ts`로 재생성한다. 전체 경로와 공식 코드가 불일치하면 생성하지 않는다.
- 카테고리 선택 시 해당 옵션·속성·고시 항목을 견적 편집기에 구성한다. SEO·가격·기본설정·이미지의 기존 자동 연결을 유지한다. 새 고유 속성의 실제 값을 확보하지 못하면 공란으로 둔다.
- 80719 기존 필드 ID와 수동 수정값을 보존한다. 추가 21개 카테고리의 속성 398개에는 카테고리별 ID를 부여하여 같은 이름의 다른 선택 목록으로 값이 섞이지 않게 한다. 단 수 노출 속성도 추가했다.
- Excel 열 연결 후보는 해당 카테고리의 관찰 필드로 제한한다. 다른 카테고리 전용 필드는 서버 검증에서 거절한다. 실제 공식 Excel 서식과의 일치는 아직 미검증이다.
- 최종 공통·옵션별 수정값을 기준으로 공급가/판매가 관계를 검사한다. 수동 가격을 몰래 변경하지 않으며, 편집 중 공급가를 수정해 오류를 해소하면 판매가 오류도 갱신한다.

## 추정

쿠플러스는 카테고리 코드로 서로 다른 상품 속성 구성을 선택하고 공통 설정·수집 데이터·옵션 값을 견적에 합치는 것으로 보인다. 화면의 대응 관계는 확인했으나 쿠플러스 내부 서버 처리·전체 API 계약은 관찰하지 않았다. 상품정보의 다음 버튼 뒤 마지막 저장 시각이 표시되어 조사 초안이 자동 저장되었을 가능성이 있으나 저장 위치와 지속성은 확인하지 못했다.

## 미확인 및 제한

전체 분류는 여전히 미완료다. 주방수납/정리 밖의 모든 말단과 양식을 22개 자료로 대신하지 않는다. Product Page 다음은 필수 옵션 입력을 요구했으므로 조사용 허위 가격·옵션을 넣어 진행하지 않았다. 공식 이미지·인증·물류 폼과 원본 Excel 전체 구조, 실제 파일 업로드·등록 전송·접수번호 회수는 미확인이다.

조사용 제목은 `양식 구조 확인용 — 운영 등록 아님`이다. 실제 상품 자료·가격·옵션을 입력하지 않았으며 저장하기·약관 동의·최종 등록을 실행하지 않았다. 쿠키·숨은 앱 상태·비공개 API 재실행을 사용하지 않았다.

## 검증

전체 자동 테스트 248/248, TypeScript, ESLint, 일반 production build 통과. 22개 원문 자료와 속성 순서·필수값·선택값·고시 이름을 대조하고 카테고리간 값 격리, 옵션별 가격 수정 및 Excel 열 연결을 검증했다. Chrome 로컬 UI에서 Hub 코드 확인 22개, 80714 검색·선택, 56개 견적 항목 준비와 URL 입력 진입 가능 표시를 확인했다. 상품·수집·견적 저장 없이 닫았다. 실제 상품 수집/유료 AI/운영 접수/Cloudflare 배포 성공 검증은 아니다.

공식 원본 Excel 파일 경로 확보 후 셀·목록·시트 규격 대조, 나머지 카테고리 관찰 확대, 공식 이미지·인증·물류 요구 확인, 권한 있는 실상품 수집 연결, Supplier Hub 전송 adapter와 접수번호 검증을 이어간다. 운영 제출과 유료 작업은 구체적인 자료 확인 및 승인 후 진행한다.
