# Step641 — 최초 카테고리 원본 연결과 옵션 작업창 복귀

처음 카테고리를 선택할 때 공식 원본 Excel은 정상인데 별도 Excel 상세 조회가 실패하면 URL 입력까지 막히는 경로를 수정했다. 옵션 단계 작업창을 닫으면 기존 옵션목록으로 돌아가는 쿠플러스 동작도 연결했다. 기존 상품이나 과거 견적서를 새 검수용으로 수정하지 않는다.

## 최초 카테고리 선택

Step603에서 기록한 실제 69900 Single/원본 Kan2624 계약은 원본 파일 연결이 정상인데 별도 Excel 상세 조회는 HTTP500으로 실패한 사례다. 기존 상품추가에는 상세 조회가 성공해야만 선택할 수 있었고, 설정 편집기에 있는 명시적인 공식 파일 기준 연결 경로가 없었다.

원본의 회사·코드·전체 경로·식별값·해시 검사를 통과한 후 별도 상세 조회의 운송 요청만 실패했을 때 구분된 오류를 전달한다. 이 경우에만 사용자가 직접 선택할 수 있는 공식 파일 기준 경로를 표시한다. 잘못된 원본, 잘못 반환된 상세 양식, 다른 회사·경로·해시 오류에는 이 선택지를 표시하지 않는다. 실패의 원래 설명과 코드는 보존한다.

명시 선택 시 회사·Single 정의·원본 파일을 다시 확인하고 기존 공식 원본 연결 계약으로 프로필을 준비한다. 처음 확인한 회사나 정의가 달라졌거나 선택·계정·컴포넌트 수명이 바뀌면 이전 콜백을 실행하지 않는다. 기존 작업 프로필과 revision을 자동 교체하지 않는다. `excelSchemaVerified: false`를 유지하며 별도 상세 조회 성공이나 모든 카테고리의 기본값 검증으로 표시하지 않는다.

원본의 선택지·필수 열 검사와 최종 견적서 검수는 계속 적용한다. 제조사·포장 무게·치수·첨부 등 확인되지 않은 사실을 파일 연결 때문에 채우거나 통과시키지 않는다. URL 초안 작성은 사용자가 해당 카테고리를 확정한 후 실행한다.

## 옵션 단계 작업과 복귀

같은 사용자 Chrome의 새 읽기 탭에서 쿠플러스 등록표 SEO 셀 → 옵션목록 → 옵션 SEO 작업창을 열었다. 작업창만 닫았을 때 옵션목록이 그대로 남는 것을 확인했다. 1~7단계의 표시와 버튼을 읽기 기록으로 보관했으며 저장·AI 실행·업로드·전송은 하지 않았다. 다른 작업의 탭은 제어하지 않았다.

등록표 셀이 옵션목록을 먼저 여는 패턴은 유지한다. YOOFAM의 옵션 단계 진입 때 원래 표를 숨김·inert 상태로 유지하고 정확한 상품·계정·진입 세대를 복귀 문맥으로 보관한다. 작업창을 정상적으로 닫으면 검색·선택과 표의 인스턴스를 유지한 채 최신 저장값을 다시 읽는다. 원래 단계 버튼이 여전히 있으면 포커스를 복원한다. 숨긴 표는 보이거나 조작되지 않으며 이전 콜백은 다른 작업을 열 수 없다.

처리 중에는 닫기와 이동을 차단하고 미저장 입력은 기존 확인을 거친다. 다른 상품·회원·카테고리 관리·전송으로 이동하면 이전 복귀 문맥을 폐기한다. 전송 준비의 미저장·진행 중 검사와 회사 보호는 유지한다. 공통 Modal의 전역 동작이나 확장 권한을 변경하지 않는다.
