# 수집 상품의 작업 개시와 견적 초안 연결

## 범위와 관찰

- Couplus의 기록된 `startProcessing()`은 전체 작업을 선택하면 상품의 미완료 작업을 진행한다. YOOFAM PLUS의 기존 일괄 작업은 가격 단계만 실행해, SEO·가격 모드로 수집한 원본 이미지가 자료함에 있어도 3~5단계 초안에 연결되지 않았다.
- 기본 URL 수집은 관찰된 SEO·가격 동작을 유지한다. 사용자가 명시적으로 작업을 개시할 때 저장된 원본을 이미지 초안으로 준비하도록 보완했다.
- 2026-10-05 사용자가 지정한 별도 Chrome에서 와이홉 Supplier Hub 로그인과 새 개별 상품 등록 화면을 확인했다. 실제 검색 결과에서 `69900`, `패션의류잡화>유니섹스/남녀공용 패션>공용 잡화>선글라스>남녀공용패션선글라스`를 선택해 상품 정보 화면까지 확인했다. 기존 등록 상품은 불러오거나 수정하지 않았다.
- 같은 화면의 ‘와이홉’ 회사 메뉴를 열어 `Company Code: A01464742`를 직접 확인했다. 회사명만으로 코드를 추정하지 않았으며 기록 후 메뉴를 닫았다. 좁힌 DOM 및 화면 근거는 `outputs/step571-yhope-company.txt/png`에 보관했다.
- 새 확인용 상품명은 화면상 ‘와이홉 선글라스 양식’이다. ‘다음’ 이동 시 Hub가 이 새 초안을 자동 저장했고 화면에 2026-10-05 16:09 저장 시각이 표시됐다. ‘저장’ 버튼을 직접 누르지 않았더라도 외부 저장이 전혀 없었다고 보고하지 않는다. 실제 등록전송이나 견적 ID·SKU 완료 확인은 하지 않았다.
- 실제 상품 정보 화면의 필수 옵션은 색상·패션의류/잡화 사이즈다. 검색 부가 정보 선택형 10개(렌즈 종류, 자외선 차단 가능 여부, 선글라스 스타일, 프레임 재질, 사용 대상, 패션의류/잡화 색상 계열, 제조년도, 출시 계절, 상품 재질, 렌즈 색상)는 모두 ‘해당사항없음’이 선택돼 있고 DOM 전송값은 빈 문자열이다. 선택지 수는 각각 6·2·6·35·20·18·8·5·124·19다.
- 이 10개 선택의 기본값·표시 문구·CSV/XLSX value/label 처리 규칙은 현재 compiler와 일치한다. 이 DOM 관찰은 필수 nullable 스키마나 69900 전체 원본 양식·법적/물류 단계 검증 근거가 아니다. 회사코드·회원 배정이나 미확인 상업 카테고리 schema를 임의로 생성하지 않았다. 원문 DOM과 화면은 Git 제외 `outputs/step571-hub-69900-product-dom.json`, `outputs/step571-yhope-69900.png`에 보관했다.

## 구현

### 명시적 이미지 초안 준비

- 상품의 최신 버전을 조회하고 `/api/products/[id]/work-draft`를 호출한다. 서버는 같은 소유자의 정확한 상품·수집 작업 연결을 사용하며 URL로 다른 작업을 찾지 않는다.
- 수집 목표와 당시 카테고리·기본설정·수집 원문을 그대로 둔다. 상품 버전, 콘텐츠·옵션 revision, 원문·설정, 이미지 목록을 확인한 뒤 하나의 트랜잭션으로 저장한다.
- 저장된 이미지 중 수정하지 않은 대표·추가·상세 영역과 대응 SKU 이미지만 연결한다. 수동 공란, 직접 선택한 이미지와 순서, 제외 옵션, 포장 정보, 견적 수정값은 유지한다.
- 갱신된 상품 버전으로 가격 작업을 이어간다. 응답이 유실되어 재실행해도 같은 원문을 재수집하거나 이미 연결한 초안을 덮어쓰지 않는다.
- 연결 원문이나 남은 원본 이미지가 없으면 그 이유를 표시하고 저장된 가격 입력을 확인한다. 원본 초안을 번역 완료나 등록 완료로 표시하지 않는다.
- 작업 결과에서 이미지와 견적 초안 검토 화면으로 이동할 수 있다. 일괄 초안 생성 후 목록의 이전 버전으로 편집 화면을 열던 오류도 실제 Dashboard→API/SQLite→이미지 준비 흐름에서 수정 전 재현했다. 검토 버튼은 정확한 상품을 다시 조회하고 해당 목록 행과 선택 단계를 갱신한다. 조회 오류 후 재시도, 닫기·다른 상품 이동·unmount 후 늦은 응답 차단을 검증했다.

### 원문 속성의 의미 보존

- 기록된 원문 `镜片材质`, `镜框材质`, `镜架材质`는 각각 부품 재질이고 `货号`는 판매자 품번이다. AI 번역 제목이 단순히 ‘재질’ 또는 ‘모델명’이 되어도 이를 상품 전체 고시값으로 자동 승격하지 않는다.
- 원문·번역 속성 자체를 삭제하지 않으며 사용자의 명시적 연결과 수정은 허용한다. 일반 재질·모델명 원문은 기존 자동 연결을 유지한다.
- 이는 허용 가능한 AI 응답을 제어한 회귀에서 재현한 결함이다. 실제 운영 AI가 해당 오류를 낸 관찰 증거로 표현하지 않는다.

### 허용된 빈 선택값

- 카테고리 양식의 ‘해당사항없음’ 선택이 빈 전송값으로 정의된 경우, 실제로 공급된 선택값이면 필수 미입력으로 잘못 차단하지 않는다.
- 견적 resolver, 편집 화면, 전송 준비 검사에서 같은 출처 판정을 사용한다. 실제 미입력, 필수 텍스트·이미지 공란, 다른 선택값과는 구분한다.
- 원본 양식과 선택값의 전송 형태, 필드 ID, CSV/XLSX 출력값은 바꾸지 않는다. 재현에 사용한 nullable 필수 선택 스키마는 계약 테스트 자료이며, 실제 영업 카테고리에서 관측한 스키마라고 주장하지 않는다.

## 검증과 남은 확인

- 양사 API·임시 SQLite에서 기록된 1688 상품 813724060928의 6개 옵션과 이미지 연결, 견적 출력, 수동 수정 보존을 확인했다. 실시간 운영 AI 응답이나 Hub 최종 접수 증거와는 구분한다.
- 전체 회귀 2051/2051(175.945초) 통과 후 독립 검토에서 발견한 Dashboard 버전 연결 오류를 수정했다. 이후 신규 3개를 포함한 Dashboard·초안·이미지 집중 29/29(10.409초), TypeScript 및 해당 파일 lint를 통과했다. 전체 검사와 집중 검사 수를 합산하지 않는다. 버전 연결 수정 전 실패도 확인했다.
- 초안 준비 API/SQLite 19개·실제 UI 2개, 부품 속성 범위 39개, 빈 선택값 관련 검사를 실행했다. 세 경로를 상호 독립 검토했으며 최종 검토의 추가 확정 결함은 없다.
- 최종 TypeScript와 변경 18개 코드/시험 파일 ESLint 오류·경고 0, 운영 빌드, 기존 11개 migration 산출물, 확장 소스·번들·ZIP 일치 검사를 통과했다. 확장 0.2.46/37개 파일/449839바이트/SHA256 `c92dbc07363c5bfa47621f65fe9f69382fdbfc079cb3f19059e3a0c4dc9b7e31`은 유지한다.
- 기존 운영 Worker `0a7d86c8-795d-4dc5-920b-bc306bc940b7`로 배포했다. 익명 `/login`과 `/api/supplier-hub/catalog-context`가 Access302로 보호되는 것만 확인했다. 이는 인증된 앱 UI나 최종 Hub 접수의 성공 증거가 아니다. 이번 앱 변경은 새로고침으로 적용한다. 운영 상품/회원/설정/DB migration/비밀/권한·호스트/새 유료 자원은 바꾸지 않았다.
- 모든 실제 카테고리의 기본값, 운영 AI·이미지 번역, 양사 최종 Supplier Hub 견적 ID와 SKU는 별도 실제 검증이 필요하다. 전체 기능의 완전 일치 또는 100% 완료를 뜻하지 않는다.
