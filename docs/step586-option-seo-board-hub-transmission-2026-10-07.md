# Step 586 — 옵션 SEO·목록·Supplier Hub 전송 연결

기준은 step585 운영 배포와 `30e316c9544dd1b527609b9bf9873cd0a09cf040`이다. 기존 쿠플러스·Supplier Hub 작업 상품은 수정하거나 전송하지 않았다.

## 구현

- 옵션 목록에서 SEO를 누르면 선택한 SKU의 상품명·검색태그를 편집한다. 공통 SEO·설명은 별도의 펼침 영역에서 수정한다. 정확한 `startPage.productName`과 `productPage.searchTags` 연결 및 같은 옵션의 기존 요약 항목을 한 번의 명시적 저장으로 반영하며, 다른 옵션·공통 자료·직접 비운 값은 유지한다.
- 옵션·공통 편집기는 단계 이동 중에도 유지한다. 저장하지 않은 SEO, 진행 중인 요청, 저장본·옵션·회사·카테고리 변경은 기존 작업 공간 검사와 버전 비교를 거친다. 필수 이름을 비운 초안은 저장할 수 있지만 최종 견적 검사에서는 필요한 입력으로 표시한다.
- 견적 수정 API는 정상 저장 때 상품 버전도 올린다. 조회는 현재 상품 버전을 확인하고, 자신의 저장 응답은 정확히 다음 견적 revision·같은 수정 시각과 상품 버전·증가한 시각·같은 원천 자료·같은 항목 연결·요청한 값을 확인한다. 정상 저장을 실패로 취급해 다음 저장이 충돌하던 새 편집기 오류를 실제 API 검사에서 발견해 수정했다. 변조되거나 다른 저장이 섞인 응답은 입력을 지우지 않는다.
- 옵션 목록은 현재 견적서의 최종 상품명과 대표·추가·상세·표시사항 이미지 참조를 표시한다. 정확한 기본 Hub 경로가 있으면 해당 값을 읽으며, 직접 비운 값을 이전 공통 이미지로 대체하지 않는다. 소유 이미지 목록과 현재 버전을 확인한다. 사이즈표는 기존 상품 공통 자료를 유지한다.
- 정상 이미지 검토 안내와 실제 연결·검증 오류를 구분한다. 일반 검토 안내가 있다고 유효한 이미지를 ‘연결 확인 필요’로 표시하지 않는다. 수집 원본 미리보기는 계속 대표 이미지 설정으로 계산하지 않는다.
- Supplier Hub의 `/qvt/wims` 조회 화면만 열려 있어도, 같은 Chrome 창의 회사코드를 확인한 뒤 새 `/qvt/registration` 탭을 준비할 수 있다. 기존 등록 탭 → 대시보드 → 조회 화면의 우선순위를 지키며 기존 조회·작업 탭을 이동하거나 첨부 자료를 덮어쓰지 않는다. 후보가 여러 개이거나 회사·창·경로·최신 저장본·접수 기록이 다르면 첨부하지 않는다.
- 확장 0.2.53과 앱의 다운로드 링크를 준비했다. 기존 권한·허용 호스트·공개 메시지는 추가하지 않았다. 기존 Chrome에 로드된 확장이 새 코드로 동작하는지는 별도 확인이 필요하다.

## 검증 범위

테스트는 실제 React 콜백과 API 처리 코드, 임시 SQLite, 기록된 1688 원문과 합성 공식 양식 계약을 이용한다. 회사 두 곳의 옵션 수정값과 표시사항 계획·견적 XLSX 행이 연결되는지 확인하며, 실제 Supplier Hub에 파일을 보내거나 접수를 만들지 않는다. 확장 전송 검사는 실제 전송 함수를 Chrome 어댑터와 직렬화한 화면 계약으로 실행한다.

기존 Chrome 4의 쿠플러스 URL과 탭은 목록에 보였지만, 탭 읽기는 `Debugger unattached`, 같은 프로필의 새 검수 탭은 `Emulation.setFocusEmulationEnabled` 응답 시간 초과로 실패했다. 로그인 실패·사이트 차단·승인 부족을 확인한 결과가 아니다. 기존 탭을 새로고침하거나 다른 프로필을 열지 않았고 기존 상품에 저장·삭제·전송을 실행하지 않았다.

전체 카테고리 기본값 대조와 운영 웹의 실상품 입력 → 이미지 저장 → 공식 Excel → 실제 접수·SKU 완료 검수는 아직 남아 있다.
