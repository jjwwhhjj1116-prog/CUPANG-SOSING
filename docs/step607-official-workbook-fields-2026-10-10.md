# 공식 원본 견적서 추가 항목과 수동 편집 연결

공식 파일에 있지만 저장된 Single 상세 양식에는 없는 항목도 7단계에서 직접 확인·수정하고 같은 Excel 열로 출력할 수 있게 연결했다. 기존 Single API 경로를 추측하거나 원본의 예시 값을 상품 기본값으로 적용하지 않는다.

## 변경 내용

- 원본 XLSX의 머리글, 필수 구분, 작성 안내, 정적 드롭다운에서 미연결 항목을 도출한다. 빈 구조 열, 중복 머리글, 지원하지 않거나 모호한 입력 규칙은 그대로 미연결 상태로 둔다.
- 항목 ID는 카테고리 코드·전체 원본 SHA-256·열 위치에 묶인다. 저장과 출력 시 실제 원본을 다시 읽어 안내·선택값까지 재도출하여 비교한다. 사용자 입력 JSON만으로 원본 근거를 확정하지 않는다.
- 공통 수정 → 옵션별 수정, 직접 저장한 공란, 수정 해제를 기존 견적 편집 규칙과 동일하게 적용한다. 원본 파일이 바뀌면 이전 항목의 수정값은 보존하되 새 항목에 자동 이식하지 않는다.
- 확인된 원본의 조건부 필수는 조건부로 표시한다. 조건의 적용 여부나 설치방식을 추측하지 않는다.
- 이전 프로필은 명시적인 ‘미연결 열 자동 연결’과 저장으로 추가 항목을 연결한다. 자동 데이터 변경이나 기존 상품 재수집은 하지 않는다.
- 일반 견적 항목의 검증은 XLSX 파서를 불러오지 않는 별도 순수 모듈로 유지한다.
- 카테고리 선택기의 저장 양식 미리보기도 동일한 저장 schema/template을 사용한다. 실제 선택한 코드·전체 경로와 snapshot을 대조하며, 잘못된 회사·경로·코드·원본 근거는 경고와 기존 기본 미리보기로 처리한다. 확인·저장·Hub 조회 로직은 바꾸지 않는다.

## 실제 확인한 64455 양식

검수용으로 새로 만든 유앤채 A01526306 / 생활용품 > 청소용품 > 청소솔/스틱 설정만 버전 2에서 3으로 저장했다. 기존 작업 상품, 선글라스 양식, 와이홉 양식은 수정하지 않았다.

원본 `SupplierHub-A01526306-Kan1836.xlsx`의 58열 중 이름 있는 57열을 연결했다. 머리글은 5행, 상품 입력 시작은 9행이다. 구조용 빈 1열은 미연결로 보존했다.

| 열 | 원본 항목 | 처리 |
| --- | --- | --- |
| AR / 44 | 설치지원방식 | 조건부 필수. 원본 목록 순서인 ‘고객직접설치’, ‘방문설치(출장장착)’ 제공. 기본값은 공란. |
| BE / 57 | 소싱 채널 | 선택 입력, 공란 기본값. |
| BF / 58 | 소싱 채널 ID | 기존 판매 채널에 등록된 상품의 벤더아이템 ID를 직접 입력. 1688 offer ID를 자동 입력하지 않음. |

원본 및 Single 지문, 회사, 코드·전체 경로, 칸 카테고리, 고시번호, 버전 검사는 유지한다. `excelSchemaVerified:false`도 유지하며 별도 Excel JSON 상세 양식을 확인한 것으로 바꾸지 않는다.

## 검증

두 회사의 격리된 기록 fixture로 실제 API 저장·수집 초안·견적 수정·XLSX 출력과 자료 ZIP 보존을 검사했다. 공통값, 옵션값, 직접 공란, 수정 해제, 원본 안내·예시·검증식·수식 보존, 위조 descriptor, 다른 회사·소유자, 원본 SHA 변경, 오래된 저장·다운로드 지문 거절을 검증했다.

운영 Chrome에서는 해당 새 설정의 저장과 재조회, 74개 견적 항목 미리보기, 기존 입력·상품 보존을 확인했다. 기존 작업 중 상품의 생성·번역·전송 버튼은 실행하지 않았다.

최종 관련 검사 263건 통과, 건너뛴 검사 0건. 타입 오류 0건, 린트 오류 0건이며 기존 경고 8건은 유지된다. 운영 빌드와 기존 확장 패키지·17개 마이그레이션의 보존 검사도 통과했다. 기존 Worker 배포 버전은 `4bc95df5-8a35-4aad-88ce-3bb11fc1baed`이다.

## 남은 실제 검증

새 1688 실상품의 신규 수집부터 이미지 번역·편집, 모든 카테고리의 쿠플러스 초안 대조, Supplier Hub 최종 접수번호 확인은 이 작업의 fixture 또는 양식 저장 검사로 대체하지 않았다. 실제 신규 견적 접수 완료나 모든 카테고리의 일치를 주장하지 않는다.

원본 파일, 회사별 원본 payload, 화면 기록은 Git에 포함하지 않고 로컬 검수 출력에만 보관한다.
