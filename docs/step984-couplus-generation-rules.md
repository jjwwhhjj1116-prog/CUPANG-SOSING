# COUPLUS 작성 규칙 분석

> 2026-11-07 한국 시각 기준 분석 자료입니다. R9 소스 반영·배포, 라벨 8옵션 연결, 상세 편집 문서의 저장·재열기와 최종 상세 게시를 확인했습니다. 신규 양말의 견적 revision 17은 공통·8개 옵션의 합성 이미지와 기존 32개 생성값을 유지했고, 저장본 검사 79개 필드·8옵션의 오류가 0건입니다. Supplier Hub 실제 접수, 나머지 신규 카테고리 생성 검증과 첫 진입 속도 개선은 진행 중입니다. 이 문서는 접수 완료 보고서가 아닙니다.

2026-11-06 관찰 기준. 최근 한 달의 서로 다른 10개 카테고리, 36개 옵션과 실제 견적 화면을 대조했다. 현재 배포된 COUPLUS 클라이언트의 입력·정규화·검사 규칙을 독립 구현하는 작업이다. 비공개 서버의 RAG와 모델 내부 지침까지 확인했다는 의미는 아니다. 구현은 실제 새 수집본과 모델 결과로 계속 검증 중이며, Supplier Hub 실제 접수는 아직 확인되지 않았다.

## 단계와 반응 속도

기본 단계는 SEO, 가격, 대표이미지, 추가이미지, 상세이미지, 한글표시사항, 견적서다. 공식 카테고리가 사이즈표를 요구하면 상세이미지 다음에 사이즈표를 넣어 8단계로 표시한다. COUPLUS의 방문한 단계 이동은 메모리에 있는 데이터를 표시하며, 14회 관찰에서 추가 fetch/XHR이 없었다. 첫 DOM 변경은 약 6~59ms였다. 이는 사용 중인 탭의 관찰이며 초기 로딩이나 화면 그리기 완료 시간은 아니다.

YOOFAM의 수정 전 새 상품에서 8단계를 방문한 뒤 상품명 하나를 저장한 측정은 클릭 후 12초 동안 API 요청 48건이었다. 전체 상품·설정·작업 목록·카테고리 양식과 견적서의 중복 조회가 포함됐다. 저장한 상품만 갱신하고, 방문한 편집기를 보존하며, 다른 단계의 읽기를 줄이는 것이 개선 기준이다. 저장 응답이 불명확한 경우에는 원래 결과를 읽어 확인하고 쓰기를 반복하지 않는다.

실제 배포 후 같은 저장 동작의 12초 관찰은 요청 18건, 응답 본문 합계 10,215,568→848,787바이트였다. 이는 압축 전 응답 크기이며 실제 전송량과 구별한다. 저장 확인 시간은 845.5→885.3ms로 줄지 않았다. 후속 R4의 방문한 8단계 이동에서는 해당 상품 API가 0건이고 DOM 준비는 44.7~111.5ms였다. 별도 수집함 배경 조회는 이 수치에서 분리했다. 초기 방문, 이미지 해독·화면 그리기 완료, 빠른 연속 클릭까지 검증한 결과는 아니다.

COUPLUS 배포 코드에서는 편집 진입 시 필요한 전체 상품을 한 번 가져오고, 진행 중인 같은 조회를 공유해 store에 보관한다. 이후 단계들은 같은 저장 데이터를 표시한다. YOOFAM R9는 방문한 화면은 유지하지만 각 화면의 최초 조회는 별도로 시작한다. 후속 후보에서는 가격·대표 구간의 동일 content/options/quote 조회를 3/3/2→2/2/1로 줄였고, 조회 중인 표시사항을 저장 중으로 잘못 표시하던 경로도 분리했다. 두 변경은 독립 검토를 통과했으나 실제 첫 진입 속도 개선과 전체 1~8단계 동등성이 완료됐다는 의미는 아니다.

## 접수 준비의 응답 유실

신규 양말의 원요청 `569152de-5d6c-423e-90a7-12e80d5d7ef6`은 문서 `2365826`을 만들고 단계 2·3·4·5 검증을 마쳤다. 정상 준비 완료 응답은 2026-11-06 17:04:42.265 UTC에 왔지만, 앱의 준비 응답 대기 120초가 이미 끝난 뒤였다. 같은 문서를 조회한 정상 복구도 17:11:20.336→17:16:33.719 UTC, 313.383초가 걸려 앱의 180초 대기를 넘겼다. 17:23 UTC의 Hub 조회는 HTTP 200, `UNFINISHED`였다. 최종 제출·접수는 아직 완료되지 않았다.

응답을 늦게 받은 경우에도 원요청의 nonce·상품·회사·본문·문서·단계 증거를 검사하고, 현재 저장본을 새로 확인한 뒤 정상 조회 결과를 반영하도록 수정 중이다. 준비 완료 응답 자체를 최종 접수 증거로 사용하지 않는다. 자동 조회가 같은 장시간 복구를 재귀적으로 반복하지 않도록 구분한다. 조회 자체의 313초 지연과 화면의 응답 유실은 별도 문제이며, 이 수치를 이미 개선했다고 보고하지 않는다.

## 공통 고시 작성 기준

후속 조사에서 COUPLUS의 정상 경로는 법정고시 전체를 공통으로 분류하고, 한 세트를 한 번 생성한 뒤 모든 옵션에 적용하는 것으로 확인됐다. 상품 노출·비노출 속성과 물류는 옵션별 차등 대상이다. 공통 고시에는 여러 색상·규격을 이어 붙이지 않고 선택한 원문 옵션에서 근거가 있는 대표값 하나를 사용한다.

신규 양말의 실제 전송 전 본문에서는 8개 옵션의 색상, `패션의류/잡화 사이즈`, 고시의 `치수`, `취급시 주의사항`에 해당하는 생성값 32개를 공식 필드명으로 각각 대조했다. 전부 저장한 생성값과 같았다. 수집 근거가 없는 사이즈·치수를 `해당사항없음`으로 두었으며, 별도의 포장 추정치 `100*150*20`을 상품 실측 치수로 옮기지 않았다. 상품명·판매가·공급가, 최종 상세 PNG와 옵션별 라벨의 전송 슬롯도 대조했다. 이는 제출 전 본문 검사이며 최종 Hub 접수 증거는 아니다.

## 이미지 편집과 원문 제거

대표·상세 편집은 텍스트, 글꼴·크기·정렬·굵기·기울임·행간, 단색·그라데이션, 테두리·그림자·각도, 지우개·브러시·자르기, 확대·이동, 실행 취소·다시 실행과 PNG 저장을 제공한다. 저장 대상은 현재 상품·옵션·이미지에 묶고 원본은 보존한다. 실제 신규 양말의 상세 번역·교정본은 저장 후 공통 행과 8개 옵션의 견적 이미지 키에 연결됐다. 이 확인은 모든 폰트·효과의 픽셀 일치나 전체 자동 번역 품질을 보장하지 않는다.

실제 소재표 이미지에서는 인식 문구의 영역 밖 원문 획이 합성본에 남았다. 후속 보완은 새 인식 실행의 단색 문구 패널에서 연결된 글자 획만 제한된 주변 영역으로 추적하며, 사진·상품표시·다른 문구를 침범하면 보정하지 않는다. 기존 저장본·캐시·재조회는 바꾸지 않는다. 같은 원본의 로컬 회귀에서는 검사 대상 잔획 542개를 포함했고 사진과 새 제거 영역 밖 픽셀은 그대로였다. 실제 상품에서의 기본 자동 결과와 로컬 원본 재생 검증을 구별한다.

신규 양말의 실제 자동 표시사항은 단품 내용량을 `1개`, 출처를 `label-default`로 저장했다. R9 실제 검증에서는 옵션별 인쇄 내용으로 PNG를 연결했으며, 공통 내용량 기본값과 옵션별 공란을 유지했다. 포장 `100*150*20mm`는 `ai-estimate`, `measured:false`인 견적 초안으로만 저장했으며, 원본 옵션의 치수 공란과 중량 50g은 바꾸지 않았다. 이 상태를 공급사 실측이나 최종 Hub 접수로 보고하지 않는다.

상세 소재표의 새 저장본은 원본 이미지와 편집 문서, 6개 편집 영역을 함께 보존했다. 정상 UI로 저장한 뒤 원본과 글자 레이어를 다시 열었고, 8개 옵션의 견적 이미지 연결도 자동 갱신됐다. 최종 게시에서는 순서가 있는 7장 입력을 800×4795 PNG로 합성해 공통·8개 옵션에 연결했다. 업로드 HTTP 201, 상세 저장 HTTP 200과 별도 GET의 일치를 확인했다. 이 저장 검증과 Hub 제출·접수 확인은 별도 단계다.

## 기본값이 남는 저장 경로

현재 보존된 COUPLUS 클라이언트에는 고시 생성값을 메모리의 `noticeItemValue`와 견적 메타데이터에 넣은 뒤, 부분 저장 패치에서는 `noticeContent`를 쓰는 필드명 불일치가 있다. 참조 36옵션의 고시 214개는 모두 `noticeItemName`·`noticeItemValue`를 사용하며 `noticeContent`는 없다. 이 경로에서는 생성값과 화면의 완료 상태가 있어도 실제 저장 고시에 초기 `해당사항없음`이 남을 수 있다.

이는 현재 클라이언트의 정적 호출·저장 순서에서 확인한 경로다. 과거 197개 차이 각각의 실행 이력, 실제 axios wire 변환과 비공개 서버의 보정 여부까지 확인한 결과는 아니다. 실제 미해당, 번역 대체 문구, 초기값과 저장 누락을 구분해야 한다. YOOFAM은 현재 공식 양식의 실제 필드에 생성값을 연결하고 저장·조회·내보내기·전송 본문을 함께 검사한다.

## 견적서 작성 지침

1. 현재 공식 카테고리 양식의 그룹, 항목명, 자료형, 단위, 필수 조건, 허용값을 먼저 읽는다. 표시 여부와 필수 여부는 별개다. 숨김 항목 자동 작성이 꺼져 있어도 공식 필수 항목의 생성·검사를 생략하지 않는다.
2. 사용자 직접 입력, 현재 저장된 상품 사실, 자동 초안, 항목별 기본 표기의 출처를 구분한다. 사용자 입력·공란·삭제를 자동 생성으로 덮어쓰지 않는다. 자동 초안은 관련 원문이나 옵션이 바뀌면 다시 검토한다.
3. `해당사항없음`과 `상세정보참조`는 모든 칸의 공통 대체값이 아니다. 법정 고시의 미해당 여부, 설명 참조가 가능한 항목, 숫자와 필수 선택 항목을 구분한다. 사용자 요청으로 미해당이 확인된 인증서·시험성적서 처리는 실제 인증 보유라는 주장으로 바꾸지 않는다.
