# 카테고리 항목과 7단계 가격 연결

7단계에서 공급가·판매가·권장소비자가격을 직접 수정할 때 내부 계산 필드와 Supplier Hub의 실제 가격 필드가 분리되어 Excel 연결 검사가 실패할 수 있던 문제를 수정했다. 명시적으로 입력·비우기·복원한 가격만 정확한 연결 필드에 함께 반영한다. 기존에 서로 다르게 저장된 값은 조회만으로 바꾸지 않으며, 별도 공식 판매처 가격(OSRP)도 유지한다. 서로 다른 연결 가격을 동시에 입력하거나 판매가를 공급가보다 낮게 입력하면 해당 가격 변경을 저장하지 않는다.

실제 69900 선글라스의 배포 전 화면에서 공급가·판매가·권장소비자가격 입력이 각각 중복되어 총 7개 가격 입력이 표시되는 것을 확인했다. 실제 Supplier Hub 가격 입력을 표시하고 내부 연결 필드는 별도로 노출하지 않도록 정리했다. 배포 후 같은 상품에서 가격 입력 4개와 기존 금액이 유지되는 것을 확인했다. 별도 OSRP 입력은 유지한다. 공통값·개별 옵션값·다른 옵션 적용·공란·복원과 가격 오류 위치 이동은 같은 연결 규칙을 사용한다. 예전 내부 가격에만 직접 수정값이 저장되어 있어도 표시된 가격 입력에서 수정 해제가 가능하다.

카테고리 속성·인증·상품고시의 이름/값 구조가 JSON 속성 순서에 의존하던 문제도 수정했다. `name`과 `value`의 순서가 바뀌어도 같은 항목·기본값·원본 상품 연결을 유지한다. 비표준 키가 두 개 모두 이름 후보로 해석되는 모호한 구조는 계속 미확인 처리한다.

## 검증 범위

두 승인 회사의 카테고리 양식, 공통·옵션별 가격 수정, 전체 옵션 적용, 공란·복원, 기존 불일치 보존, 별도 OSRP, 실제 SQLite/API 저장과 생성 XLSX의 가격 연결을 검사했다. 카테고리 구조 12건·기본값 연결 33건·7단계 가격 15건·기존 가격 기능 50건·견적 파일 준비 42건, 총 152건이 통과했다. 타입 검사에 오류가 없었고 정적 검사는 오류 0건과 기존 경고 8건이었다. 배포 파일의 기존 마이그레이션 17개와 확장 0.2.57 패키지도 그대로 유지되었다.

배포 후 와이홉 계정의 기존 상품을 읽기 전용으로 확인했다. 표시되는 72개 입력값은 배포 전의 대응 값과 같았으며, 중복 내부 가격 입력 3개만 화면에서 제거되었다. 저장 버튼은 수정 없는 상태로 비활성화되어 있었다. 타입·정적 검사·배포 파일·실제 화면과 스크린샷 기록은 비공개 `outputs/step597-*`에 보관했다.

같은 와이홉 Chrome에서 쿠플러스에 등록 완료된 편지지/세트(79776)의 견적서 항목을 읽기 전용으로 확인했다. 저장된 상품명·가격·물류 값은 해당 상품의 편집 결과이며 다른 상품의 기본값이나 사실로 복사하지 않았다. 기존 쿠플러스와 YOOFAM PLUS 상품에 저장·삭제·OCR·외부 번역·등록 전송은 실행하지 않았다. 모든 카테고리의 실제 기본값 동등성과 신규 Supplier Hub 최종 접수 완료는 이 검사만으로 입증하지 않는다.
