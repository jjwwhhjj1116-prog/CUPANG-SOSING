# 카테고리 상세 견적 양식의 문자열·숫자 조건

선택한 회사와 최종 카테고리에서 보관한 Supplier Hub 상세 양식의 입력 조건을 견적 편집, 저장 API, 전송 전 검토 및 견적 출력에 연결했다. 기존에는 `minLength` 2 이상과 숫자 배수·배타적 경계를 미지원으로 분류했고, 숫자 선택 항목은 숫자 검사와 출력 변환에서 빠졌다.

## 이번 연결

| 양식 조건 | 앱 처리 |
| --- | --- |
| `minLength`, `maxLength` | 0을 포함한 유효한 정수 조건을 반영한다. 최대 길이 0은 비어 있는 문자열만 허용한다. |
| `minimum`, `maximum` | 기존 포함 경계 검사를 유지한다. |
| 숫자형 `exclusiveMinimum`, `exclusiveMaximum` | 경계와 같은 값도 오류로 표시한다. |
| `multipleOf` | 양수인 배수 조건을 검사한다. 소수를 정수 계수와 소수 자릿수로 비교해 `0.3 / 0.1`의 부동소수점 오차를 피한다. |
| 숫자 `enum` | 화면에서는 선택 목록을 사용하고, 검사와 견적 출력에서는 숫자로 처리한다. |

길이의 문자 기준, 배수와 경계의 의미는 [JSON Schema Validation 2020-12의 문자열·숫자 규칙](https://json-schema.org/draft/2020-12/draft-bhutton-json-schema-validation-01#section-6.2)을 따른다. 상세 양식의 문자열은 Unicode 코드 포인트로 길이를 계산하며 화면의 글자 수 표시와 서버 저장 검사에 같은 함수를 사용한다. 기존에 기록한 Couplus 고정 양식의 글자 수 계산은 유지한다.

숫자 파싱과 배수 검사는 견적 출력에 실제로 직렬화할 JavaScript 숫자를 기준으로 한다. 상세 양식이 숫자 필드인 경우 음수와 지수 표기를 지원하고, 유한하지 않은 값 및 0으로 소실되는 비영 숫자는 거절한다. 정수 필드의 안전한 정수 범위 검사와 기존 고정 양식의 숫자 입력 형식은 유지한다. 숫자 표기를 바꾸거나 공급가·판매가 계산식을 수정하는 기능은 아니다.

## 수동 작업 보존

- 사용자가 비운 값은 작성 중인 초안으로 저장할 수 있다. 필수 공란 또는 최소 글자 수에 맞지 않는 문자열은 현재 견적의 검토 오류로 표시한다. 명시적인 해당사항없음 선택은 기존 선택값 처리로 구분한다.
- 조건 위반을 고치려고 수동값, 원가, 마진율, 공급가 또는 판매가를 자동 반올림·치환하지 않는다.
- 저장 API는 비어 있지 않은 조건 위반 값을 거절하며 revision을 변경하지 않는다. 수동값은 문자 그대로 보관하고 숫자로 된 최종 출력 값만 같은 파서로 변환한다.
- 기존 상품에 고정한 카테고리 양식과 수동 수정값을 유지한다. 이후 카테고리 프로필의 배수 조건을 바꿔도 이미 작성 중인 상품의 조건은 바뀌지 않는다.
- 재사용 속성 연결 규칙에는 전체 필드 서명이 포함된다. 길이·경계·배수 조건이 달라진 양식에는 이전 규칙을 그대로 적용하지 않는다.

잘못된 조건 타입, 음수 글자 수, 0 이하 배수, 모순되는 경계, 표현하지 못하는 문자열·숫자 혼합 타입은 미확인 양식으로 남는다. Draft 4의 Boolean 배타적 경계, 정규식, 조건부 양식, 참조 및 고정값 지원을 추가한 것은 아니다. 입력 처리 한도를 넘어서는 양식도 확인 없이 전송하지 않는다.

## 확인한 범위

신규 테스트 9개는 실제 프로젝트 함수, 임시 SQLite와 API, 기록된 1688 원문 fixture를 사용한다. 두 회사 A01464742(와이홉), A01526306(유앤채)에 대해 합성 상세 분류 991234 선택 → URL 초안/6옵션 → 수동 편집 → 조건 위반 저장 거절 → 정상 저장 → 숫자 형식 견적 출력 → 프로필 갱신 후 기존 상품 보존을 검사했다. 숫자 선택의 배수 우회, 음수·지수 값, 극단적 유한 숫자, 길이 0, 공란·Unicode 길이 및 연결 규칙 서명 변경도 확인했다.

전체 회귀 검사 1,815/1,815(141.903초) 통과 후 공란 처리 보완에 관련된 집중 검사 318/318(23.731초)를 다시 통과했다. 최종 TypeScript 및 변경 파일 lint 오류·경고 0, 운영 빌드와 기존 확장 원본/배포 ZIP 일치 검사를 수행했다. 확장은 0.2.39 그대로이며 이번 앱 기능은 페이지 새로고침으로 적용한다.

합성 분류·시험 데이터는 실제 Supplier Hub 전체 카테고리의 확인 자료나 견적 접수 결과가 아니다. 전 카테고리 Couplus 기본값/필수서류 대조, 운영 AI·이미지 번역 및 두 회사 실제 최종 접수번호·SKU 확인은 남아 있다. 이번 변경으로 기존 Couplus 작업 상품이나 Supplier Hub 견적을 수정·접수하지 않았다.
