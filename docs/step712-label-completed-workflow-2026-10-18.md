# Step712 — 표시사항 처리·완료·재작성 화면

기준 커밋 `613f568f0993680f61d40892e31a9c4e7191da41`. 보관 원본의 REA 근거는 `docs/step711-label-rewrite-parity-audit.md`의 전체 render/getter/resetLabels 구문과 고정 digest를 재사용한다. 새 원본 실행·브라우저 접근·기존 작업 상품 변경은 없다.

원본은 처리 중, 생성 이미지 완료, 편집 폼을 상호배타적으로 표시한다. 완료 카드의 동작은 이미지 다운로드와 재작성 두 가지다. 자체에서도 처리 중에는 주 편집 폼을 숨기고, 현재 저장·연결된 생성 PNG가 확인되면 결과 이미지와 두 동작을 표시한다. 재작성은 기존 명시 POST와 확인창을 사용하며 문구·항목 구조·공통/옵션 직접값·견적 참조·파일을 보존한다. 이전 생성 세대의 이미지가 남아 있어도 편집 화면으로 돌아온다.

자체에는 원본의 root/옵션 생성 status 필드가 없다. 따라서 파일 존재만으로 원본의 truthy 상태를 흉내 내지 않고, 인증된 저장 증빙을 읽는 자체의 완료 조건을 사용한다. 원본의 private backend나 내부 저장 필드까지 동일하다는 주장이 아니다.

## 완료 확인

`readCurrentProductLabelResult()`는 현재 상품·프로필의 표시사항/견적 쌍과 선택 옵션의 최종 라벨 참조를 읽는다. 정확히 한 장이 현재 이미지 풀에 있고, 인증된 파일 조회 응답의 실제 키가 그 참조와 일치해야 한다. 파일명은 조회 위치를 찾는 단서일 뿐 완료 증거가 아니다. 서버가 반환한 생성 recipe·상품·프로필·카테고리 해시·출력 계획 해시·재작성 세대가 현재 값과 일치해야 한다. 기존 빈 행을 포함한 출력 계획도 같은 세대일 때만 호환한다.

공통 PNG는 선택 옵션이 관련 견적 필드를 직접 수정하지 않았고 공통과 현재 해석값이 정확히 같은 실제 상속일 때만 완료로 사용할 수 있다. 다른 옵션에서 생성한 동일 문구의 파일을 임의로 완료 승격하지 않는다. 여러 라벨, 수동 파일, 미증명·없는 파일, 오래된 세대/내용은 기존 편집·참조 검토 화면을 유지한다. 수동 파일을 삭제하거나 무효화하지 않는다.

파일 증빙을 읽은 뒤 표시사항과 견적을 다시 읽어 전체 snapshot이 같은지 확인한다. 조회 장애나 손상된 응답은 완료로 처리하지 않는다. 이 읽기 과정에는 업로드·재생성·상품/견적 저장·전송이 없다.

## 편집 보존

주 편집기는 완료 결과를 정확한 source/옵션/프로필/저장 view와 조회 token에 결속한다. 입력, 참조 선택, 저장 중, 재작성 결과 불확실, 단계 또는 source 변경은 이전 token을 무효화한다. 늦은 조회가 새 입력을 숨기거나 다른 범위의 완료 화면을 열 수 없다. 읽기 확인은 주 편집을 잠그지 않는다.

최종 라벨 연결 편집기는 처리·완료 전환에도 mounted 상태를 유지한다. 완료 화면에서는 접힌 연결 편집 영역에서 참조 교체·제외·번역·명시 저장을 계속 사용할 수 있다. 자식 자신의 dirty/busy를 다시 자식 disabled로 되먹이지 않아 저장·취소가 자기 잠금되지 않게 한다. 처리 중에는 영역을 숨기되 진행 중 요청과 cleanup을 보존한다.

## 검수와 한계

순수 조회 계약, 실제 자체 React callback의 완료/편집 전환, 양사 격리 SQLite/D1/R2/API의 PNG 생성·첨부·재작성·새 생성물 연결을 구분해 검사한다. 최종 소스 고정 TAP, 타입·린트·스키마·빌드·배포 결과는 `outputs/step712-final-validation.json`을 기준으로 기록한다. focused 반복 검사를 최종 개수에 더하지 않는다.

생성 완료는 표시사항 PNG가 현재 저장값과 연결됐다는 의미다. Supplier Hub 접수 완료나 PNG 픽셀/글꼴·원본 UI 전체 동일성의 증명이 아니다. 실제 신규1688 수집, 모든 카테고리 공식 양식/default, Hub 접수번호/SKU의 최종 검증은 별도 잔여다. 기존 `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 gate를 유지하며 새 자원·migration·유료 공급자·확장 버전 변경은 없다.
