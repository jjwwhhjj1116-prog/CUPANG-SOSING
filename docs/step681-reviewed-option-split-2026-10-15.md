# Step681 · 검토한 옵션 그룹으로 상품 분할 저장

기준 커밋 `c121f5bda9d1f1d1a65e1c72e552216b611c88f0`. 작성일 2026-10-15.

7단계 견적 편집기에 옵션별 상품 나누기를 연결했다. 그룹별 SEO 제목·원본 상품명·옵션 수·회사를 미리 확인하고 명시적으로 저장한다. 첫 그룹은 현재 상품 ID와 등록번호를 유지하며 나머지는 새 상품·옵션 ID와 새 등록번호를 받는다. 기존 같은 URL 상품이나 독립 원문 초안을 분할 가족으로 추정하지 않는다.

## 원본 근거와 구현 범위

[Step680 정적 조사](step680-split-audit.md)의 보관된 Couplus JavaScript를 재사용했다. `splitProductByAdditionalAttributes`는 첫 그룹으로 원본을 갱신하고 나머지 그룹을 새로 만들며, 빈 속성/모두 같은 속성의 fallback은 옵션별 개별 그룹이다. 관찰된 `issueSplitRegistrationId` 서버 내부 번호 정책은 여전히 불명이다. 이번에는 외부 원본 브라우저나 새 1688 URL에 접근하지 않았다.

이번 구현은 **명시적으로 검토한 분할 계획의 생성·저장·복구**다. 원본의 AI 그룹 분류, raw 노출속성 전체 JSON detector, suffix 기반 가족 탐지와 동일하다고 주장하지 않는다. 2~20개 그룹, 전체 원본 옵션 2~200개를 지원한다. 20개 이하에서는 옵션마다 한 그룹을 제안하고, 20개 초과는 모든 옵션을 직접 배정해야 한다. 120자를 넘는 옵션명을 그룹 이름으로 조용히 자르지 않는다.

제외 옵션도 정확히 한 그룹에 속해야 하며 누락·중복·빈 그룹·기존 ID 재사용은 거절한다. 그룹 이름의 앞뒤 공백은 보존한다. 직접 쓴 공통·옵션별 견적 제목과 수동 공란은 유지한다. 이는 원본의 제목 덧붙이기를 모든 수동 항목에 강제하는 처리와 구분되는 보존 정책이며 미리보기에서 안내한다.

## 저장과 복구

- `product-option-split-plan.ts`는 원본을 변경하지 않는 순수 계획 함수다. 모든 카테고리의 견적 수정값·표시사항·포장 확인 기준의 내부 옵션 ID까지 부분집합으로 다시 연결한다. 옵션의 원문·출처·각 필드 시각·기존 포장 측정 수량을 그대로 유지한다. 새 상품에 과거 상세 저장 영수증/백업이나 오래된 자동 처리 증명을 복제하지 않는다.
- `POST /api/products/:id/option-splits?profileId=...`의 `preview`는 새 상품을 만들지 않는다. 상품/옵션/콘텐츠/견적/표시사항, 회원 회사, 설정/카테고리, 수집 job/context/result/supplement/image 연결의 정확한 원문과 현재 활동·삭제 상태를 묶은 지문을 만든다. 이미지 소유권과 저장소 실재도 확인한다.
- `commit`은 검토 지문을 다시 확인한다. 원본 첫 그룹 갱신, 새 상품과 모든 동반 저장 자료, 새로운 수집 연결, 등록번호·옵션 번호, 명시적 가족 관계와 불변 기록을 하나의 D1 batch에 넣는다. 최종 SQL assertion은 동반 저장이 무시된 경우에도 전체 batch를 롤백시킨다. 기존 수집 URL claim은 이동·추가하지 않는다.
- 자식 수집 연결에는 당시의 회사·카테고리·양식·설정·수집 시각과 원문을 그대로 보관한다. 현재 설정으로 과거 수집 사실을 새로 만들지 않는다. 같은 소유자의 불변 이미지 참조를 공유하며 기존 이미지 파일을 다시 쓰지 않는다.
- 결과를 잃으면 같은 POST를 자동 반복하지 않는다. 입력·할당 ID·미리보기를 세션에 보관하고 `GET ...&requestId=...`로만 확인한다. 새로고침 뒤에도 같은 요청으로 복구한다. 이후 값이 바뀐 과거 성공은 `current:false`로 구분하여 최신 입력을 덮어쓰지 않는다. 불명확한 DB 통신 결과는 실패/미저장으로 단정하지 않고 503으로 결과 확인을 요구한다.
- 미저장 견적, 다른 실행 중 작업, 전송 기록이 있는 상품에서는 시작을 막는다. 분할 창을 연 동안 다른 견적 편집·전송과 작업 창 종료를 잠그고 준비 중 Escape 취소·키보드 초점 순환·닫은 뒤 초점 복원을 제공한다. 손상된 로컬 확인 자료에는 상품 목록을 명시적으로 확인한 뒤 로컬 확인 자료만 정리하는 경로가 있다.

법적 첨부 원본과 번들 원본/삭제 이력이 있는 상품은 현재 분할을 지원하지 않는다. 이를 버리거나 새 상품에 잘못된 증거로 연결하지 않고 구체적 사유로 거절한다. 그룹별 새 상품에 대한 상세 이미지 일괄 적용과 AI 그룹 제안은 후속 작업이다.

## 배포와 남은 검증

기존 무료 Worker **`fb92af14-ac7f-4534-a9e8-b15a1bf85daf`** 배포 완료. 기존 무료 D1에서 0025 분할 기록 테이블을 적용했다. 실제 Wrangler migration ledger에는 0022~0024도 미적용으로 나와, 멱등 CREATE TABLE/INDEX인 해당 마이그레이션과 0025를 함께 적용하고 모두 완료 표시를 확인했다. 기존 상품 데이터 UPDATE/백필/삭제는 없다. 과거 인수인계의 0024 적용 상태 단정과 실제 ledger의 차이는 이 기록으로 정정한다. 새 리소스·유료 플랜·OAuth·R2 권한·확장 업데이트는 없다.
