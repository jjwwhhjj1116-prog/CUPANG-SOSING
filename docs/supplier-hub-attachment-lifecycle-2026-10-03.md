# Supplier Hub 첨부·검증 재개 최종 검수 — 2026-10-03

카테고리 → 지정 1688 URL → 수정 가능한 1~7단계 → 견적서 전송 → 접수·SKU 조회의 마지막 구간을 이어서 검수했다. 앞선 [회사 메뉴 검수](supplier-hub-company-menu-2026-10-03.md)의 후속이다.

## 재현한 오류와 수정

업로드 뒤 파일명이 표시될 때 회사 메뉴가 닫히면, 업로드 대기 함수가 같은 회사의 정상 첨부도 회사 변경으로 판단했다. `waitForSupplierHubAttachments`가 기존 80회×250ms 범위에서 회사 메뉴를 다시 열고 실제 코드·원래 첨부 기록·파일명 순서를 확인한다. 회사코드가 숨겨진 동안에는 첨부 완료로 반환하지 않는다. 잘못된 코드·중복 코드·바뀐 기록·페이지·시간 초과는 검증 요청으로 이어지지 않는다.

앱에서 기존 첨부의 검증을 재개할 때도 회사 메뉴를 열기 전에 첨부 검사부터 실행해 실패했다. 재개 함수가 원래 창·탭의 정확한 회사코드를 먼저 확인하고 첨부를 검사한다. 최신 저장본·접수 기록 확인 후 검증 요청을 점유하기 직전에도 회사코드를 다시 확인한다. 검증 응답이 유실된 경우 원래 화면의 요청 표시를 대조하며 클릭을 반복하지 않는다. 재개에는 새 ZIP·파일 재첨부·탭 생성이 없다.

견적서·상품 이미지·표시사항·필수 서류의 첫 업로드 이벤트가 다음 구역에 수동 파일을 넣거나 회사·화면·기록을 바꾸면, 기존 함수는 나머지 구역을 계속 덮어썼다. 각 구역 전달 전과 마지막 이벤트 뒤에 현재 파일·표시된 파일명·회사·주소·기록·남은 입력 구역을 확인한다. 이미 전달한 구역의 입력이 비워지거나 빈 입력으로 다시 그려지는 것은 허용한다. 다음 구역의 파일이나 입력이 교체되면 보존하고 `partial`로 중단한다. 메뉴 대기 중에도 같은 검사를 수행하며 단조 증가하는 구역 위치로 이미 실행한 이벤트를 반복하지 않는다.

저장한 서류 선택이 `required`이고 파일 참조가 없을 때 XLSX 미리보기에는 `LEGAL_DOCUMENT_MISSING`이 있었지만 등록 전 검사에는 없었다. 두 검사에 기존 오류 규칙을 공유했다. 원본 첨부·삭제·해당없음 전환 이후에는 같은 저장 상태에 따라 오류와 검토 지문이 갱신된다. 카테고리 기본값과 서류 해당 여부는 변경하지 않았다.

## 배포 호환 범위

확장 `0.2.41`이 `attachmentLifecycleRecovery` 기능을 알린다. 앱의 새 첨부 파일 준비·직접 등록전송·검증 재개에는 이 기능이 필요하다. `0.2.40`은 회사 메뉴 기능을 제공해도 위 생명주기를 처리하지 못하므로 새 파일 전달에는 사용하지 않는다. 이전 전송의 저장 결과 읽기·새로고침·SKU 조회는 기존 기능 검사 범위를 유지한다.

매니페스트·콘텐츠 브리지·세 다운로드 링크·ZIP 버전을 맞췄다. 적용에는 기존에 로드한 확장 폴더와 앱 페이지 새로고침이 필요하다. 새 Chrome 프로필·권한·허용 호스트·DB 마이그레이션은 추가하지 않았다.

## 근거와 검수 범위

- 실제 직렬화 함수와 합성 DOM에서 업로드 중 메뉴 닫힘, 닫힌 메뉴의 검증 재개, 응답 유실 재개 3개 회귀가 수정 전에 실패했다. 관련 전송·재개·조회 검사 75개가 통과했다.
- 그룹 첨부에서 수동 파일·표시 파일명·회사·기록·주소 변경과 마지막 이벤트의 변경을 재현했다. 수정 전 신규 6개 실패를 확인했으며 보완 후 실제 함수의 집중 검사 33개가 통과했다. 아직 전달하지 않은 입력 교체는 부분 전달로 중단한다.
- 두 회사의 실제 앱 API와 임시 SQLite에서 필수 서류 없음의 검사 불일치를 수정 전 재현했다. 서류 전환·수동 값 보존·카테고리 연결 포함 73개 집중 검사가 통과했다. 검사로 원본 바이트와 상품 편집 데이터를 변경하지 않았다.
- 새 확장 기능이 없거나 `false`·문자열인 경우 파일 준비·전송·검증 메시지와 바이트를 보내지 않고 PING만 수행한다. 새 기능이 있으면 한 번 전달하며, 구형 확장의 접수 결과·갱신·SKU 조회가 계속 동작하는지도 검사했다. 브리지·최신 저장본 연결 37개 검사가 통과했다. 집중 검사 간 중복이 있어 합산하지 않는다.

등록 전 검사는 저장한 서류 참조를 확인하며 패키지 미리보기·생성에서 실제 원본 바이트를 검사한다. 임시 저장소의 원본만 삭제하면 등록 전 참조 검사는 그대로이고 패키지 미리보기는 HTTP 409로 차단했다. 참조 개수 확인을 원본 바이트 검증이라고 표시하지 않는다.

이번 기존 Chrome 두 연결의 쿠플러스·Supplier Hub·운영 앱 호스트 한정 조회에는 대상 탭이 반환되지 않았다. 이를 사이트 차단·로그아웃·권한 거절로 해석하지 않는다. 기존 쿠플러스 작업 상품을 수정하지 않았고 새 Chrome 창·프로필도 열지 않았다.

앞선 읽기 전용 운영 회원 집계에서 관리자 회사정보는 빈 값이었고 연결할 회사 선택 질문은 답변 대기 중이다. 임의로 소속을 지정하지 않았다. 모든 실제 카테고리 기본값·공식 양식, 운영 AI·이미지 번역, 두 회사 최종 견적서 ID·SKU 검증은 남아 있다. 이번 합성 DOM·임시 DB 검사를 실제 Hub 등록 완료 또는 전체 완성률로 바꾸어 보고하지 않는다.
