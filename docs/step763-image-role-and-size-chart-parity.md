## 저장·편집 상태 보호

이미지 업로드는 파일 POST 후 `image-upload-link` POST로 보관함·콘텐츠 역할·현재 카테고리 견적을 같은 D1 batch에 저장한다. owner/승인 회원·회사, 상품 사실, 원문·설정·프로필, 옵션·콘텐츠·견적의 버전과 정확한 저장 payload를 전후 확인한다. 일부 동반 저장만 적용되거나 중간에 원문이 바뀌면 NOT NULL/CHECK 무결성 검사로 batch 전체를 되돌린다. 소유 파일 키·크기·지원 이미지 헤더를 검사하지만 이를 일반 이미지의 전체 PNG 해독·전체 파일 SHA 증명으로 확대하지 않는다.

사이즈표는 현재 입력으로 만든 PNG와 chart/plan/source 해시를 보관한 시도로 묶는다. 불변 private PNG를 업로드·읽기 검증한 뒤 콘텐츠·역할·보관함·상품 clock을 D1에서 함께 저장한다. **R2 객체와 SQL은 하나의 트랜잭션이 아니다.** SQL 실패 후 남은 PNG는 보관하며 자동으로 다시 생성·업로드하지 않는다. 사이즈표 저장은 상품 치수·무게나 법적 고시 값을 임의로 바꾸지 않는다.

응답이 불명확하면 입력·정확한 시도·업로드 키를 보존하고 GET으로 결과를 확인한다. 자동 재POST·재업로드는 하지 않는다. 정확히 미반영된 상태를 확인한 뒤에만 명시 재시도를 허용한다. 사이즈표 복구·재시도는 원래 상품·프로필에서만 가능하며, 다른 프로필의 화면에서 이전 결과를 채택하지 않는다.

작업 공간의 source-write 검사는 **현재 작업이 소비하는 자기 초안만 제외**하고 다른 단계의 미저장 입력·진행 작업을 검사한다. 숨겨진 편집기에도 적용한다. 업로드·편집·사이즈표의 동기 ref와 mutex를 함께 사용해 이전 callback, scope/버전 변경, 작업 중 새 편집 진입을 차단한다.
