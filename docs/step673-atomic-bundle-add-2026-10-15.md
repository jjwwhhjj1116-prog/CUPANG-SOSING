# Step673 — 번들 추가와 견적서의 동시 저장

기준 commit `6ab27f19030347bcec33b4285bdf37d462e53591`의 번들 적용/선택 삭제를 유지하고 편집 가능한 2단계 가격표에 번들 추가를 연결한다. 이전 단계 구현을 다시 진행한 것이 아니다.

## 대조 근거

REA의 보관된 UI Evidence `ev_c99b4dd7210509e941b9723030fabc9c3f03d1c54d7f52bcc381d5df0e843340`, 저장/문서 Evidence `ev_cd5b12712ef6b71c2acfc13858957b76b067e15d1319aac6ac68b3c3a642258a`를 재사용했다. 소스 SHA256와 범위는 `outputs/step672-price-bundle-audit/source-manifest.json`에 보관했다. 새 사이트 접근이나 기존 쿠플러스 상품 변경을 수행하지 않았다.

원본은 선택한 행을 깊이 복제해 목록 끝에 붙인다. 수량 기본 2, parseInt, 최소 2다. 번호는 현재 원본번호 뒤에 `B수량`을 붙인다. 기존 번들에 추가하면 `ROOTB3B2`처럼 현재 번들에 연결하며 수량은 6으로 곱하지 않고 2로 바꾼다. 이름의 끝 `(N개묶음)`을 새 수량으로 교체하고 재고는 floor(원본 재고/수량)이다. 새 행의 한글 라벨 값은 초기화한다. 옵션 문서의 일반 이미지와 나머지 정보는 복사하고 최종 문서 가격을 재계산한다.

`quotation.options`는 번호·이름 외 수동 가격을 유지하는 별도 경로가 있고, `jsonDocument`의 최종 가격은 새 값으로 바뀐다. 문서를 찾지 못하면 첫 문서로 대체하는 원본 코드도 있다. 이 정적 관찰은 서버 중복 처리/중첩 수용/실제 저장 성공을 확인한 결과가 아니다.

## 구현

- 새 옵션에 UUID를 발급하고 기존 행 뒤에 붙인다. 저장된 원본 행은 누락된 옛 선택 필드·포장 기준·provenance·행 시각까지 그대로 보존한다. 새 행은 이름·수량·계산된 재고를 변경하고 원가·색상·사이즈·일반 이미지·실측값을 복사한다.
- `ProductOptions.bundleSources`에 자식 UUID의 직접 원본 UUID와 생성 수량을 보관한다. 이후 구성 수량 편집/원본 또는 자식 삭제에도 연결은 유지한다. 일반 편집 요청으로 연결값을 변경하지 않는다. 예전 payload에는 속성을 만들지 않아 기존 형태를 유지한다.
- 기존의 소유자별 옵션번호 lifetime 매핑에서 직접 원본과 역사적 연결을 찾아 응답 표시번호를 재귀적으로 구성한다. 번호는 경로/견적 키/작업 식별자로 사용하지 않는다. 번호 조회는 신규 할당을 하지 않으며 기존 숫자 매핑은 그대로 유지한다. 숫자 매핑이 없는 legacy 상품은 UUID 표시를 유지한다.
- 현재 카테고리 범위의 **저장된 원본 옵션별 수동 수정값**을 복사한다. 공통값은 기존 상속을 유지하고, readOnly/알 수 없는 키/가격/한글 라벨 키는 복사하지 않는다. 새 번들의 라벨에 명시 공란을 저장해 공통 라벨도 자동 상속하지 않게 한다. 포함한 새 행의 공급가·판매가·MSRP는 2단계 직접 최소금액 계산으로 canonical/확인된 Hub 가격 연결에 함께 저장한다.
- 포장 실측과 이미 기록된 옵션별 포장 확인 기준은 원본의 과거 구성에 맞춰 보존한다. 1개입 기준 250g을 5개입 번들에 복사해도 5개입 확인 기록을 만들지 않으며 재확인 메시지가 유지된다. 다른 견적 범위와 포장 sidecar는 보존한다.
- 전용 POST `/api/products/:id/option-bundles`는 상품/옵션/견적서/설정/내용/카테고리의 버전과 원본 payload를 검사한다. 옵션·상품 시각·번호 할당·현재 견적서 변경을 한 D1 batch로 저장한다. 어느 companion SQL이 실패해도 전체가 rollback되며 기존 상품을 자동 수정하지 않는다.
- UI는 저장되지 않은 옵션/가격이 있으면 먼저 저장하도록 안내한다. 입력·자식 UUID를 고정한 뒤 한 번만 요청하며, 응답을 확인하지 못하면 수정/다른 쓰기를 잠그고 GET으로 결과를 확인한다. 실제 저장이 확인되면 재전송하지 않는다. 원래 옵션과 견적서가 정확히 그대로인 경우에만 같은 UUID로 재시도할 수 있다. 회사/프로필 전환과 늦은 응답으로 다른 상품에 적용하지 않는다.

명시적인 자체 선택: DOM 확인창, API 수량 상한 1,000,000/옵션 200/연결 999/중첩 32 제한, 같은 원본·생성 수량의 lifetime 중복 거절, 고유 SKU 제약 때문에 새 행의 SKU를 비우고 UUID 원본 연결을 따로 보관, 미확인 재고 null 유지(원본 JavaScript는 null을 0으로 강제 변환), 저장본을 기준으로 복제, 모르는 첫 문서 대체 금지. 옛 일반 옵션 편집의 복수 구성 복제는 별도 기존 기능이며 편집 가능한 가격 화면에서는 해당 항목을 숨겨 전용 동시 저장 경로를 사용한다. 모든 버그·서버 내부 동작과 픽셀까지 동일하다는 주장은 하지 않는다.
