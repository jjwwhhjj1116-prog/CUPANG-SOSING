# 쿠플러스 카테고리 DOM 관찰 기록

관찰일: 2026-09-22. 출처: 로그인된 Chrome의 [쿠플러스 로켓배송 AI 상품등록](https://www.couplus.co.kr/AIRocketReg) → 상품 추가 → 빈 상품 대기열 → 상품 추가 → 카테고리 선택.

기존 사용자 상품 편집 탭은 유지하고 새 조사 탭에서 관찰했다. 결과 데이터는 [couplus-category-dom-2026-09-22.json](./couplus-category-dom-2026-09-22.json)에 있다. 이 파일은 **일부 트리의 관찰 기록이며 전체 카테고리 사전이나 Supplier Hub 공식 분류표가 아니다.**

## 확인

- 1단계 대분류는 16개다: 패션의류잡화, 뷰티, 출산/유아동, 식품, 주방용품, 생활용품, 가구/홈데코, 가전/디지털, 스포츠/레져, 자동차용품, 도서, 문구/오피스, 음반/DVD, 완구/취미, 반려/애완용품, 기프트카드.
- 15개 대분류의 화면에 표시된 2단계 항목 173개를 읽었다. 동일한 이름이라도 상위 경로가 다르면 별도 항목으로 기록했다.
- `주방용품 > 주방수납/정리`는 마지막 단계까지 따라가 최종 분류 22개의 이름과 경로를 관찰했다. 가장 깊은 경로는 5단계다. 각 항목의 `isLeaf`는 화면의 `최종` 배지를 근거로 한다.
- 분류 모달에는 이름 검색, 단계별 목록, 취소, 선택 완료가 보인다. 관찰한 모달에는 전체 카테고리 다운로드·내보내기 버튼이나 링크가 없었다.
- `주방용품` 검색 결과는 없었다. `주방수납바구니` 검색은 `주방수납바구니/바스켓` 최종 분류와 전체 경로를 반환했다. 이름 검색이 모든 하위 경로를 한꺼번에 반환한다고 볼 수 없다.
- 목록 항목과 검색 결과의 렌더링된 DOM에는 분류 코드가 표시되지 않았다. 분류 선택 후에도 경로만 보였으므로 이 조사에서 새로 확보한 코드 수는 0개다.
- 기프트카드를 선택하면 선택 표시와 경로는 기프트카드로 바뀌었지만, 2단계에는 이전 반려/애완용품 목록이 그대로 남았다. 갱신을 기다린 후에도 같은 상태여서 그 목록을 기프트카드의 하위 분류로 기록하지 않았다.

## 추정

- 이름과 경로를 추가로 수집하려면 각 단계의 실제 표시 목록을 순서대로 순회할 수 있다. 다만 부모를 누른 직후 이전 자식 목록이 잠시 남을 수 있어, 이전 항목이 사라지고 새 목록이 표시된 것을 확인한 후 저장해야 한다.
- 분류 코드와 견적서 필드 정의를 모두 확보하려면 코드가 표시되는 별도 공식 자료나 사용자에게 제공되는 내보내기 기능이 필요할 가능성이 있다. 현재 관찰한 트리만으로 전체 코드·필드 정의를 복원할 수 있다는 근거는 없다.

## 미확인과 다음 시작점

- 전체 최종 분류 개수, 아직 펼치지 않은 가지, 기프트카드의 실제 하위 목록, 각 분류의 코드, 카테고리별 입력 필드 전체는 미확인이다.
- 이 쿠플러스 트리 조사만으로는 코드 일치를 확인하지 않았다. **이후 같은 날 Supplier Hub 개별 등록에서80719의 전체 경로와 코드 일치를 확인했고**, 추가19개 코드도 대조했다. [공식 코드 기록](supplier-hub-category-ids-2026-09-22.json)과 [비교 분석](COUPLUS-SUPPLIER-HUB-COMPARISON.md)을 최신 근거로 사용한다. 아직 미확인인 나머지 코드와 양식을 전체 확인으로 일반화하지 않는다.
- 앱의 분류 선택 UI에는 실제 확인된 경로와 코드만 추가하고, 이름만 확보한 항목에 임의 코드를 붙이지 않는다. 이 데이터의 모든 분류에 `80719`의 속성이나 상품고시 필드를 재사용하면 안 된다.
- 후속 트리 관찰은 JSON의 `nodes`에서 `isLeaf:false`이며 같은 경로의 자식 기록이 없는 항목부터 이어갈 수 있다. 현재 완료한 하위 트리는 `completeObservedSubtrees`에 표시했다.

## 작업 경계

브라우저의 실제 DOM과 UI 조작만 사용했다. 숨겨진 앱 상태, 쿠키·세션, 네트워크 요청 재실행, 비공개 API 호출, CDP는 사용하지 않았다.

`선택 완료`를 눌렀을 때 URL 없는 임시 대기열 행이 하나 생겨 즉시 제거했고, 종료 전 `대기열이 비어있습니다`와 `전체 시작 (0건)`을 확인했다. URL 입력, 전체 시작, AI 실행, 상품 생성·등록, Supplier Hub 전송은 실행하지 않았다.
