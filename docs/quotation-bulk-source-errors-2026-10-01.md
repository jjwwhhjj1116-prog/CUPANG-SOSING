# 견적서 전체 적용에서 원본 연결 오류를 보존

## 재현

7단계의 다른 옵션에 적용 미리보기는 원본이 미입력인 경우만 복사에서 제외했다. 일부 상품 치수만 입력한 옵션은 `source: option`인 공란과 연결 오류를 반환하므로 이 제외 조건을 통과했다. 유효 참조와 삭제된 참조가 섞인 대표 이미지, 구성 수량을 바꾼 뒤 이전 개입 기준인 포장 정보도 같은 문제를 보였다.

이 값을 다른 옵션의 수동 수정값으로 만들면 원본 연결 오류가 없어지고, 대상 SKU의 유효한 크기·대표 이미지·포장 정보가 잘못 대체됐다. 수정 전 새 회귀 두 건에서 제외 항목 수가 각각 `0 !== 3`, `0 !== 2`로 실패했다.

## 변경

전체 적용은 원본 셀의 연결·계산 오류를 확인하고, 오류가 있으면 해당 항목을 복사하지 않는다. 기존 미리보기의 제외 목록에 항목명과 원래 오류를 표시한다. 유효한 다른 항목은 같은 미리보기에서 적용할 수 있다.

일반적인 값 검증과 연결 오류를 구분한다. 사용자가 명시적으로 지운 필수 항목, `해당사항없음` 선택, 공란 적용과 자동값 복원은 기존 동작을 유지한다. 일반 입력 오류는 기존 화면·저장 검증을 사용한다. 원본을 확인하고 직접 수정한 값은 자동 연결 오류를 해소하며 다른 옵션에 적용할 수 있다. 새 기본값이나 카테고리 선택지를 추가하지 않았다.

## 검증

편집기 검사 78건을 통과했다. 새 순수 회귀 두 건은 실제 견적서 resolver로 일부 치수·혼합 이미지 참조·변경한 포장 수량을 만들고 전체 적용과 복원 결과를 확인한다. 대상의 수동 구매 크기·고시 크기와 개별 대표 이미지·포장값, 원본의 오류와 입력 불변성을 검사한다. 직접 확인한 치수·이미지·포장 수정값은 복사할 수 있는 것도 확인했다.

새 통합 검사 두 건은 와이홉 `A01464742`, 유앤채 `A01526306`에서 실제 앱 API·임시 SQLite·견적 편집 함수·Excel 생성·전송 준비 컴포넌트를 연결한다.

1. 기록된 URL 원문으로 6개 옵션 초안을 만들고 한 옵션을 제외한다.
2. 첫 SKU에 일부 상품 치수와 1개입 포장 정보를 저장한 후 판매 수량을 2개입으로 변경한다. 두 번째 SKU에는 고유한 구매 크기·고시 크기와 500g 포장값을 유지한다.
3. 전체 적용에서 상품 고시 크기와 포장 무게·치수 세 항목을 제외한다. 선택한 유효 브랜드만 다른 포함 SKU에 반영하고 제외 옵션은 그대로 둔다.
4. 해당 SKU의 오류 세 개가 남고 등록전송 버튼이 비활성임을 확인한다. 사용자가 7단계에서 실제 확인한 값으로 수정하면 오류가 해소된다.
5. 수집 재시도는 외부 원문 재조회·AI 재실행 없이 수정값·입력 fingerprint·견적 revision을 보존한다.
6. Excel 5행의 SKU별 크기·고시·포장값·수량·회사·카테고리를 확인한다. 첫 SKU의 3.6 CNY × 2개입과 저장 정책으로 공급가 5,520원, 판매가 9,200원, 권장가 초안 11,960원이 유지된다.
7. 실제 전송 준비 컴포넌트에서 동의 후 로컬로 포착한 전송 데이터의 회사와 포함 옵션 수를 확인한다. 실계정 Hub에는 쓰지 않았고 상품 상태는 `미전송`이다.

기록 원문 `813724060928`은 선글라스이고 `80719`는 관찰 폼 시험 계약이지 이 상품의 실제 판매 분류가 아니다. 인증·AI·이미지 바이트·공식 Excel 대신의 합성 시험 양식·최종 전송은 격리된 시험 자료다. 공개 원가와 과거 쿠플러스 관찰 원가의 차이를 임의 할인율로 보정하지 않는다. 초기 통합 시험은 구매 사이즈 원문을 물리 치수로 예상한 시험값과 잘못된 시험 DB 테이블 조회를 실제 API 조회로 보정해 통과했다.

## 빌드·배포

추가 회귀 4개 포함 전체 **1,509/1,509**, TypeScript, 변경 파일 lint 오류/경고 **0**, Cloudflare 운영 빌드·산출물·diff 검사를 통과했다. 전체 저장소 lint 또는 전체 카테고리 대조 완료로 보고하지 않는다.

운영 앱 `https://sourceflow.jjwwhhjj1116.workers.dev`에 버전 `6fe857f6-b4ed-43be-8fa6-a5e4cd74c0be`를 배포했다. 앱 새로고침으로 적용한다. 확장 0.2.29는 변경하지 않았고 빌드 시 30개 파일/366,181바이트/SHA-256 `80a1d38d37bcd65b6b6d8e83e7c268d289b95320f00c91d0ae80147b21684444`를 확인했다. DB·비밀 설정·공개 이미지 Worker·유료 자원 변경은 없다.

앱·확장 ZIP·원문 수집 API의 익명 요청 세 건은 기존 Cloudflare Access 호스트로 HTTP 302를 반환했다. 인증한 운영 화면·다운로드 바이트·실제 Hub 접수 성공 검사가 아니다. 기존 Chrome 바인딩의 탭 목록은 빈 목록이었다. 새 창·프로필을 열거나 기존 작업 상품을 수정하지 않았고, 사이트 차단·로그아웃으로 해석하거나 추가 승인·로그인을 요청하지 않았다.

## 남은 실검증

전체 카테고리의 쿠플러스 기본값·공식 Excel 대조, 지정 Chrome의 URL→1~7단계 초안·운영 이미지 번역·법적 서류 첨부와 두 회사의 실제 최종 견적 접수·SKU 확인은 남아 있다. 이 변경만으로 전체 시스템 완성을 판정하지 않는다.
