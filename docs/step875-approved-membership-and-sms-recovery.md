# 승인제 회원가입과 SOLAPI 휴대폰 인증

아이디·비밀번호·이름·휴대폰 번호로 가입 신청한다. 서버는 일반 회원·승인 대기로만 저장하며 가입 요청에 관리자 권한이나 회사 정보를 넣을 수 없다. 관리자는 로그인 후 알림과 팝업에서 아이디·이름·전화번호·요청 시각을 보고 승인·거부한다. 비밀번호나 해시는 목록에 표시하지 않는다. 승인 전 로그인은 차단한다.

기존 두 계정의 ID, 비밀번호 해시, 회사 정보와 사업 자료 소유자는 바꾸지 않는다. 새 회원은 별도 소유자 UUID를 사용하며 기존 회사·상품을 상속하지 않는다. 신규 회원의 회사 연결은 미설정 상태로 명확히 표시한다. 기본 설정과 개인 프로필은 본인 계정 범위만 읽고 저장한다.

비밀번호 변경은 현재 비밀번호 확인과 저장된 해시의 조건부 갱신을 사용한다. 변경 후 기존 로그인 세션을 모두 폐기한다. 가입 승인·거부·정지·재개와 비밀번호·휴대폰 변경은 credential_version으로 이전 인증 요청을 무효화한다.

가입 신청에 적은 전화번호는 소유 확인 전까지 계정 복구에 쓰지 않는다. 승인된 회원이 본인 계정 화면에서 현재 비밀번호와 문자 인증번호를 확인해야 복구 번호로 등록된다. 인증번호는 5분, 최대 5회 시도, 1회 사용이며 발송은 번호별 최소 1분 간격과 계정·IP·번호 제한을 둔다. 인증번호는 목적·요청번호와 함께 HMAC으로 저장한다. 아이디 찾기는 인증 후 아이디를 보여주고, 비밀번호 찾기는 기존 비밀번호 공개 대신 단기 일회용 재설정 토큰을 발급한다. 재설정은 기존 세션과 다른 복구 요청을 모두 무효화한다.

SOLAPI는 서버에서 HMAC-SHA256으로 서명해 인증문자 한 건을 요청하며 자동 재발송하지 않는다. API 접수 응답과 휴대폰 도착을 구분한다. 관리자 계정 화면에서 API Key·API Secret·등록된 발신번호를 설정한다. 별도 서버 암호화 키를 이용해 AES-GCM으로 보관하고, 화면에는 키 끝 4자리만 표시한다. 암호화 키나 문자 서비스 설정이 없으면 발송 성공으로 표시하지 않는다.

공식 연결 규격: [SOLAPI API Key 인증](https://solapi.com/developers/api/authentication-api-key), [메시지 발송](https://solapi.com/developers/api/messages). 계정 복구 기준: [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).

## 배포 전 확인

기존 Worker에 회원 인증·비밀번호 pepper·자격정보 암호화 키 설정은 존재하며 SOLAPI 설정은 아직 없다. 값은 읽거나 출력하지 않았다. 익명 요청의 `/login`·`/recover`가 Cloudflare Access로 302 이동하는 것을 확인했다. 따라서 외부 가입자가 이용하려면 새 네이티브 승인제 인증을 검증한 뒤 기존 외부 Access 관문을 전환해야 한다. 해당 보호 변경은 별도의 실행 시점 승인 전에는 수행하지 않는다.

0036은 회원 표에 메타데이터 열만 추가한다. 0037은 전화 인증 요청·발송 간격·암호화 문자 설정 표와 인증된 전화번호의 고유 인덱스를 추가한다. 사업 상품·견적서·Supplier Hub 문서 수정은 이 작업에 없다. 실제 승인 계정이나 문자 발송은 합성 자료·모의 제공자 검사와 구분한다.

## 검증·배포 결과

- 고유 17개 검사 파일의 185개 중 182개 통과, 기존 Access fixture의 누락 의존성 때문에 3개 실패했다. fixture를 실제 receipt/removal 의존성과 소유자·무인증 저장소 검증에 맞추고 해당 7개를 다시 실행해 전부 통과했다. TypeScript·ESLint·55개 표/21개 인덱스 스키마 비교·운영 빌드 통과. 36개 릴리스 파일의 소스 SHA가 일치한다.
- 0036·0037을 운영 D1에 적용하고 읽기로 확인했다. 0036 적용 뒤 CLI 진행 문구 때문에 JSON 파싱만 실패했으며, 재적용하지 않고 PRAGMA로 6개 열이 모두 설치된 것을 확인했다. 기존 회원 2명·상품 8건 유지. 원래 886 상품·회원 공개 메타데이터·설정 35개 표 47행의 SHA `39f1f5b9ff48173e6d68b0e8d9689aac8eb587f2fb469a0ed6b2984913a3455d`는 Step874와 같다.
- 운영 Worker `8c1e125c-d4aa-4708-9ba7-feac7a43f929` 배포. 실제 `/login`의 회원가입 전환에서 네 입력란과 승인 요청 버튼을 확인했다. `/account`에서 기존 관리자 신원·회원 2명·개인 프로필·전화 인증·암호화 SOLAPI 설정 화면과 승인 알림 0건 팝업을 확인했다. 신규 운영 가입자 생성·승인, 실제 계정 비밀번호 변경, 실제 문자 발송은 하지 않았다.
- 기존 Cloudflare 호스트 앱 SourceFlow의 `SourceFlow owner only` 정책이 가입자 접근을 막는다. 기존 정책을 남기고 동일 호스트 한 곳에 `YOOFAM native approved membership`/Bypass/Everyone 정책을 추가하는 초안만 화면에 준비했다. 저장 버튼은 누르지 않았다. 외부 관문 전환은 실행 시점 승인 대기다.
- SOLAPI 키·등록 발신번호 미설정으로 실제 문자 도착은 미검증이다. 관리자가 계정 화면에서 연결한 후 본인 휴대폰 인증으로 검수한다. 실번호·인증번호·API 키를 채팅이나 저장소에 남기지 않는다.
- 실화면에서 `/recover?purpose=reset-password`가 아이디 찾기로 열리는 추가 결함을 확인해 초기 URL 모드를 반영했다. 해당 UI 13개(기존 11개에 2개 추가)와 TypeScript·lint·최종 운영 빌드를 다시 확인했다. 최종 Worker는 `49f243f9-465f-4ce5-8f6c-d53852d73bbc`다. 실제 재로드 뒤 재설정 탭 선택과 아이디·이름·인증 휴대전화 세 필드를 확인했다. `outputs/step875-recovery-live-fixed.png`.
- 접근 정책 초안은 SourceFlow 앱(같은 단일 호스트)의 새 정책 생성 팝업에만 있으며 아직 저장하지 않았다. `outputs/step875-access-transition-review.png`에 저장 직전 범위를 남겼다. 외부 관문 전환 승인과 SOLAPI 실제 키 입력은 대기 상태다.
