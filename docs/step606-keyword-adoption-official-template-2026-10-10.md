# 초안 검색태그의 견적서 연결과 공식 파일 검증 — 606

## 번역 재시도 뒤 검색태그가 남던 문제

상품 추가에서 입력한 타겟 키워드는 초기 검색태그로 저장된다. 실제 수동 수정과 구분하려고 원문·저장 시각을 함께 기록한다. 최초 무료 Google 요청이 HTTP 429로 실패한 뒤 1단계의 새 초안을 작성하면, 참고 입력용 제목이 원래 검색어 원문에 섞여 초기값 대조가 실패했다. 상품명과 옵션은 번역 결과를 반영해도 검색태그는 직접 수정한 값으로 잘못 판단해 초기 타겟 키워드에 머물렀다.

초안 요청은 원래 검색어 원문을 정확히 유지한다. 새로 입력한 키워드 메모는 별도 특징 참고 구역에 표시해 원문 검색어 목록을 대신하지 않는다. 검색태그의 기존 수동 수정 보호 규칙은 변경하지 않았다. 과거 번역 요청이나 기존 운영 상품도 다시 작성하지 않는다.

격리 API 검사에서 같은 회사·카테고리로 새 상품을 수집하고 최초 Google 429 실패를 기록했다. 그다음 초안 작성·반영 미리보기·명시적 저장·실제 견적 항목 조회까지 연결했다. 수정하지 않은 초기 태그는 생성 결과를 반영하고, 같은 값을 직접 저장하거나 공란을 직접 저장한 태그는 그대로 유지된다. 포함 옵션 6개 모두 7단계 검색태그와 일치한다. 직접 수정한 라벨·첫 옵션명, 원가·포장 수치·사진·원문과 실패 이력도 보존된다. 외부 번역 응답과 공급처 응답은 fixture이며 운영 서비스의 새 수집·번역·접수를 실행한 검사가 아니다.

## 공식 파일 저장 검증의 중복 처리

공식 파일 기준 연결을 저장할 때 같은 XLSX를 일반 머리글 검사와 공식 근거 검사에서 각각 압축 해제·해석했다. 원본 바이트·머리글·입력 행·Single 지문·회사·카테고리·Kan·scope·고시·버전 확인을 공통 함수로 모아 공식 근거가 있는 저장은 한 번의 전체 원본 검사로 처리한다. 저장소 소유권·정확한 파일 키·메타데이터 검사와 일반 XLSX·CSV·TSV의 머리글 검사는 유지한다. 클라이언트의 근거를 그대로 신뢰하거나 검사를 생략하는 캐시는 추가하지 않는다.

합성 압축 OOXML 검사로 요청마다 전체 원본 검사가 한 번씩 실행되는지 확인한다. 변경된 머리글·행·근거·원본 바이트·회사·카테고리·Single·Kan과 잘못된 공식 작성 구조는 계속 거절한다. 서버 자원 절감은 확인한 중복 처리 수정이며, 아래 운영 HTTP 503의 원인을 단정한 것은 아니다.

## 실제 청소솔 카테고리 대조

같은 Chrome의 쿠플러스에서 완료된 청소솔 상품의 견적서를 읽기만 했다. 현재 Supplier Hub 유앤채와 앱 관리자 계정이 일치하는 상태에서 생활용품 → 청소용품 → 청소솔/스틱의 최종 코드 `64455`를 확인했다. 앱에 회사별 Single 양식과 입력 항목 71개를 연결했다. 이때 보이는 기본값 54개는 양식의 초기값이며 실제 상품 정보 확인을 의미하지 않는다. 기존 상품의 무게·치수 같은 개별 입력값을 다른 상품의 기본값으로 복사하지 않았다.

새 빈 검수 행만 추가했다가 정리했고 기존 URL·특징·키워드·선택 상태는 모두 유지됐다. 기존 쿠플러스·앱 상품의 저장·번역·재수집·삭제·전송과 회사 배정 변경은 실행하지 않았다.

별도 Excel 상세 양식 조회는 HTTP 500으로 실패했다. 원본 파일 기준 연결은 초기 시도에서 앱 저장 단계의 HTTP 503 HTML 응답을 받았으며, 범위를 제한한 서버 조회로 새 설정이 revision 1·양식 미연결 상태인 것도 확인했다. 이 오류 응답을 공식 연결이나 제출 완료로 계산하지 않는다. 최종 검사·배포 및 같은 설정의 재확인 결과는 릴리스 기록에 추가한다.

중복 검사를 제거한 운영 배포 뒤 같은 회사·설정의 원본 파일 연결을 다시 실행했다. 앱의 정상 저장 응답과 설정 재조회, 범위를 제한한 서버 조회에서 revision 2와 공식 원본 연결을 확인했다. 별도 Excel 상세 양식 조회는 성공한 것으로 바꾸지 않았으며 `excelSchemaVerified: false`를 유지한다. 한 번의 저장 성공만으로 초기 HTTP 503의 원인을 단정하지 않는다.
