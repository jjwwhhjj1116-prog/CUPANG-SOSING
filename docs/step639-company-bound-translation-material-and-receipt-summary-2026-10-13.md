# Step639 — 회사별 번역, 6단계 소재, 최신 견적 접수 상태

수집 당시 회사와 현재 로그인 회사가 달라진 뒤에도 번역 서비스가 호출되는 경우, 6단계 재질이 공식 견적의 상품 재질 열에 빠지는 경우, 과거 반려 견적을 다시 조회하면 최신 접수 상태가 가려지는 경우를 수정했다. 기존 실상품과 작업 중인 Couplus 자료는 수정하지 않았다.

## 수정 동작

- 번역 POST의 준비·승인·실행·재시도 전에 소유 상품의 정확한 수집 연결과 수집 당시 회사를 확인한다. 회사가 다르거나 조회 중 연결이 달라지면 기존 409 응답을 반환한다. 번역 작업 생성·변경과 Google/AI 호출 전에 차단한다. 읽기 전용 GET 이력 및 수집 연결이 없는 기존 수동 상품의 동작은 유지한다.
- 기록된 공식 필드 중 숨김 `상품 재질`의 정확한 이름·select 규격·선택지·원래 wire 경로가 일치할 때만 6단계 재질을 연결한다. 원문을 보고 확인한 입력이 7단계 상품 재질과 고시 소재 및 원본 Excel 두 열에 반영된다. 프레임·렌즈 소재를 추정하지 않으며, 기존 직접 입력·직접 공란·옵션별 수동값과 공식 enum 검증은 유지한다.
- 등록목록의 접수 요약은 서버에 나중에 처음 저장된 전송 기록을 사용한다. 같은 기록의 일반 UPSERT와 과거 조회 UPDATE는 최초 rowid를 유지하므로, 예전 반려 견적의 관찰시각이 갱신되어도 나중에 저장된 접수·SKU 상태를 가리지 않는다. 개별 견적 이력의 관찰시각 정렬·소유자 범위·삭제 보호·저장 비교는 바뀌지 않는다. 테이블 변경이나 마이그레이션 추가는 없다.

같은 Chrome의 실제 `ProductContentEditor` 6단계 화면에 플라스틱을 직접 입력하고 명시 저장 1회 후 검수했다. 기록된 유앤채 Single69900v188 계약과 원본2624.xlsx를 로컬 메모리에서 연결했고, 7단계와 원본 dataStartRow 9의 6개 옵션 행에서 0-based 열18(상품 재질)·50(고시 소재)가 모두 일치했다. 실제 콘텐츠·견적 API, SQLite, 원본 XLSX 작성기를 사용했다. 원문·수집 문맥·카테고리·옵션·가격·설정·이미지·원본 R2 바이트는 보존됐다. 와이홉 시험은 이 공개 양식 계약을 독립 계정 fixture에 재사용했으며 새 와이홉 공식 양식 캡처를 뜻하지 않는다.

같은 Chrome의 실제 `RegistrationBoard`에서 양사 각각 합성 과거 A 파일 반려 → SEO 수정 후 B 견적 접수 → A 과거 조회 갱신을 실행했다. 실제 접수 API와 상품목록 API, SQLite를 사용했고, A 관찰값만 갱신되며 B 접수 ID·요약·삭제 잠금은 유지되는 것을 확인했다. 등록 상태 필터 `견적서 접수`에서도 B가 남는다. 원문·콘텐츠·가격·옵션·설정·R2 및 다른 소유자의 격리를 검사했다. 합성 접수 ID는 실제 Supplier Hub 접수 증명이 아니다.

## 실제 화면 대조와 남은 범위

진행 중인 Couplus 상품을 건드리지 않고, 같은 Chrome의 별도 임시 참고 탭에서 기본설정과 상품추가 화면을 읽었다. 빈 대기열의 주방용품 → 주방수납/정리 → 주방수납바구니/바스켓 선택, URL·특징·키워드 입력, SEO+가격 기본 작업 형태를 확인했다. URL을 입력하거나 작업을 개시하지 않았고, 이 탭에서 만든 URL 없는 임시 행만 제거하여 다시 0건으로 확인하고 탭을 닫았다. UI에서 카테고리 코드는 읽지 않았으므로 새 코드 매핑 증거로 계산하지 않는다.

기본설정의 공급마진50·쿠팡마진40·환율350·10원 단위·MSRP1.3·최소마진3000과 통합통관의 현재290 표시를 읽었다. 현재 앱의 통합통관 환율은 사람이 확인한 설정값을 쓰므로 이 화면만으로 Couplus의 자동 환율 조회까지 동일하다고 판정하지 않는다. 기존 회원 기본설정은 저장·교체하지 않았다. CLI 안내의 명령이나 업데이트는 실행하지 않았다.

기존 운영 상품·복구된 상품추가 입력·회원 기본설정은 배포 전후 읽기 값으로 보존을 검수한다. 아직 모든 카테고리의 Couplus 동작 일치, 새 실상품 1688 수집, 사람 검토 후 실제 Supplier Hub 접수·SKU 완료까지는 완료로 표시하지 않는다. 로컬 합성 시험과 확장 버전 확인은 해당 실상품 등록의 완료 증명이 아니다.
