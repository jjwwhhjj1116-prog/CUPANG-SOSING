# Step697 — 판매가 수정과 자동 권장소비자가 저장 연결

2026-10-18 KST. 기준 `878313905810615887ad8b1f5e6442606674a108`. 보관된 REA 원본과 자체 격리 UI/API를 대조했다. [원본 조사](step697-fixed-target-parity-audit.md)의 고정 목표가는 후속 CLI 대기열 기능이며 일반 카테고리→URL 초안에 도입하지 않았다.

## 확인한 동작과 수정

쿠플러스 가격표는 개별 공급가·판매가 입력 때 해당 금액과 마진 표시만 바꾸지만, 가격 저장 때에는 현재 판매가에 배수·단위 반올림을 적용해 MSRP/OSRP를 쓴다. 자체는 판매가만 바꾸면 저장이 성공해도 자동 MSRP가 이전 판매가에 묶여 있었다. 사전 재현에서 판매가 6,750원·MSRP 8,780원을 판매가 9,000원으로 수정하면 MSRP 8,780원이 남았다. 낮은 MSRP 때문에 저장이 차단된다는 가정은 재현되지 않았다.

명시적인 2단계 판매가 저장에서 자동 권장소비자가를 함께 계산한다. 같은 저장 작업에 정확히 연결된 canonical·Hub 가격 필드를 반영하며, 서버가 현재 상품의 저장 가격 정책으로 다시 계산한 결과와 요청을 대조한다. 원가·SKU·재고·등록번호·다른 옵션·일반 최초 초안·기존 명시 재계산 산식은 바꾸지 않는다.

직접 수정한 옵션별·공통 권장소비자가, 명시적 공란과 복원 입력은 보존한다. MSRP가 있는 양식의 독립 OSRP를 같이 바꾸지 않으며, OSRP-only 양식은 기존의 정확한 fallback 연결을 사용한다. 새 자동 계산값에는 기존 견적 JSON 안에 카테고리별 근거를 기록해 재조회·재개 후 다음 판매가 수정에도 자동 계산을 이어간다. 직접 수정한 금액을 단순히 자동값과 숫자가 같다는 이유로 자동값으로 취급하지 않는다. 7단계에서 같은 금액을 명시 입력해도 자동 계산 근거를 해제한다.

기존 상품을 읽는 것만으로 가격을 보정하거나 데이터를 저장하지 않는다. 새 근거가 없는 과거 수동값은 그대로 수동값이다. 추가 DB 테이블·migration은 없다. 저장 응답이 유실되면 실제로 전송한 판매가와 파생 MSRP 전체를 명시적 재조회로 대조하며, 확인 전 중복 저장은 막는다.

가격표의 행 마진도 원본처럼 소수 금액을 표시한다. 예를 들어 실제 2,999.5원은 행에서 2,999.5원으로 표시하며, 원본이 별도로 정수 반올림하는 요약 평균 표시는 유지한다. 가격 계산이나 저장 금액을 표시용 반올림으로 바꾸지 않는다.

## 구현 경계와 검수

현재 상품에 보관된 배수·가격 단위로 자동값을 계산한다. 원본의 현재 workspace 설정 참조, 변경 없는 전체 행 저장, 기존 수동 MSRP 무조건 덮어쓰기까지 동일하게 만들었다는 주장은 하지 않는다. 기존 작업 상품과 직접 수정값 보존을 유지하면서 명시 판매가 수정의 자동값 연결을 보완한 범위다.

검수는 합성 회원·상품·카테고리, 실제 자체 React callback·API 핸들러, 메모리 SQLite와 보관 공식 Excel/R2 fixture를 사용한다. 실제 1688 수집·외부 번역·운영 상품 수정·Supplier Hub 접수 완료를 검증한 결과와 구분한다. 원본 코드를 실행하지 않았고 원본 조사는 정적 근거다.

이번 운영 화면 확인은 기존 Chrome에 만든 앱 검수 탭에서 Cloudflare 인증 화면까지 도달했다. 새 권한을 승인하지 않았으며 해당 검수 탭을 닫았다. 사용자의 쿠플러스·Hub 작업 탭과 기존 상품은 제어하지 않았다. 운영 로그인 후 화면이나 최종 접수 검증을 완료한 것으로 보고하지 않는다.

실제 신규 1688 전체 SKU·이미지, 전 카테고리 공식 양식·기본값, 남은 편집·번역 기능과 Hub 동의·최종 접수번호/SKU 대조는 전체 완료 조건으로 남는다. 운영 전송 gate와 `SINGLE_DOCUMENT_LIVE_VERIFIED=false`를 유지한다.
