# 실제 수집·등록 실행기 연결 계약 — 2026-09-26

## 현재 확인한 구현
- `app/sourcing.ts`: URL을 정규화하고 카테고리·기본설정·특징·키워드·목표 단계를 수집 요청에 보관한다. awaiting_connector는 수집 실행 상태가 아니다.
- `app/collection-result.ts`: schemaVersion 1, 원문 URL/수집시각/공급원/제목/설명/속성/SKU/이미지를 검증한다. SKU별 실제 단가 CNY와 최소주문수량이 필요하다. 재고 미확인은 null이며 임의 0으로 치환하면 안 된다. 이미지는 HTTPS Alibaba CDN으로 제한된다.
- `app/api/collection-jobs/[id]/result/route.ts`: 인증된 소유자의 요청만 받고 512KB 제한을 적용한다. 취소 요청 또는 다른 원문 재수신은409. 응답에 productCreated:false, executionStarted:false를 명시한다.
- `app/collection-delivery.ts`: 검증된 원문을 수신 API에 전달하고 동일 응답 확인 후 상품·이미지 반영을 실행한다. 페이지 접근·추출 기능은 없다.
- `app/collection-product.ts`: 요청 당시 가격 정책으로 모든 SKU 가격을 계산하고 원문 옵션을 생성한다. 최소주문량과 판매 구성 수량을 구분한다. 당시 기본설정의 제조사/수입사/연락처 및 명시 공란을 보존한다.
- `db/collection-products.ts`: 원문과 요청 맥락이 동일한 경우 D1 batch로 상품/가격/옵션/콘텐츠/요청 연결을 원자적으로 저장한다.
- `app/api/supplier-hub/route.ts`: POST는 무조건501. 실제 전송 요청, 파일 검증, 접수번호 저장은 이 API에 없다.

## 다음 구현에 필요한 실제 관찰
1. 지정 상품813724060928에서 표시되는 제목, SKU 식별자/옵션 조합, SKU별 가격 및 가격구간, 최소 주문량, 재고, 옵션 이미지와 상세 이미지를 대조한다. 페이지 구조 확인 전 DOM 선택자나 비공개 API를 추측하지 않는다.
2. 쿠플러스의 동일 상품 추가를 관찰해 카테고리코드/선택경로/견적 양식의 연결 및 기본값을 확인한다. 1~7단계별 저장 결과와 수동 수정 우선순위를 대조한다.
3. Supplier Hub의 현재 등록 화면에서 첨부·검증·접수 흐름을 확인한다. 기존 화면 관찰은 대량등록 UI의 존재와 파일명 일치 조건을 확인했지만, 쿠플러스가 해당 경로를 쓰는지 또는 실제 API 계약까지 확인하지 않았다.
4. 실제 수집 결과를 위 기존 전달 함수에 연결하고, 요청 ID→원문 수신→상품 ID→번역 결과→견적 필드→첨부 파일→접수 결과를 한 상품으로 추적한다.
