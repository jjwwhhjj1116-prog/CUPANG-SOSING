# 6단계에서 직접 비운 기본값의 저장·견적·전송 연결

## 재현한 문제

저장된 표시사항이 공란인 상품에 6단계 기본설정 채우기를 사용하면 제조사·수입원·연락처와 관찰된 카테고리 기본값이 편집 초안에만 들어온다. 이를 첫 저장 전에 지우면 입력값이 기존 저장값과 같아졌다. 다시 채우기는 이를 미작성으로 판단했고, 그대로 저장해도 기존 비교 방식이 `unverified`를 유지해 견적서의 설정값이나 참조 기본값이 되살아날 수 있었다. 기존 자료와 예전 저장본을 지원하는 경로에서 발생하는 문제다. 현재 URL 수집은 일부 표시사항을 먼저 저장하므로 모든 신규 수집 상품에 같은 문제가 발생한다고 주장하지 않는다.

실제 React 편집기를 사용한 추가 회귀를 수정 전에 실행하여 다시 채우기 후 제조사가 복원되는 실패를 확인했다.

## 수정

- 편집기는 사용자가 공란으로 만든 표시사항의 ID를 초안에 보관한다. 자동 채우기가 이 목록을 지우거나 다시 채우지 않는다. 다른 단계 이동 및 저장 실패에도 보존하고, 해당 항목에 다시 내용을 입력하면 제거한다.
- 모든 자동 입력을 비워 최종 텍스트가 기존 공란과 같아도 미저장 수정으로 판단해 저장과 단계 이동 검사가 작동한다.
- 콘텐츠 요청의 `labelClears`는 함께 저장하는 공란 표시사항 ID만 허용한다. 중복·없는 필드·값이 있는 필드·누락된 저장값·품명 직접 비움과 SEO 연동 켜짐의 충돌은 거절한다.
- 서버가 명시적인 비움을 `manual` 공란으로 기록한다. 다른 변경 없는 필드의 출처는 바꾸지 않는다. DB 스키마 변경 없이 기존 저장 형식을 사용한다.
- 저장 성공 후 초안의 비움 목록을 정리한다. 품명을 다시 SEO와 연결하면 그 항목의 비움 의도를 해제한다. 견적 필수값 검사는 그대로 유지하여 직접 비운 제조사를 설정값으로 대체하지 않는다.
- 7단계의 검토한 공통값·개별값은 기존 우선순위를 유지한다. 쿠플러스 가격 계산식 및 참조 기본값 자체는 변경하지 않았다.
