# 실제 화면에서 확인한 수집·메뉴 오류 보완

## 수집 카드가 0개로 표시된 원인

사용자 화면에는 상품이 있는데 YOOFAM 패널은 로드된 카드 0개로 표시했다. 기존 코드는 카드 안에 `detail.1688.com/offer/...` 링크가 있어야 상품을 인정했다. REA로 확인한 설치 RS 카드 구조에서는 링크가 상품번호 없는 `dj.1688.com` 추적주소이며, 번호는 카드의 별도 속성에 있었다.

카드 내부의 complete/expose 상품번호, renderkey, aplus object_id, data-extra offerId와 직접 상세주소를 대조하도록 바꿨다. 번호가 일치할 때만 정규 상세주소를 만들며 추적주소를 요청하거나 따라가지 않는다. 같은 카드의 형제 요소에 충돌하는 번호가 있는 경우도 제외한다. 카드 클래스가 다른 경우에는 가까운 상품 카드의 이미지·가격·번호를 확인한다. 가격의 판매량 숫자가 합쳐지지 않도록 가격 요소만 읽는다.

RS 근거는 `ev_8ce4ee626fe7fd24ec20eec15e74fdddb1599b85814c2afb21378611082423f0` 및 `ev_26d16cff845ade6fe476e028be0d598d3cded79e725401cdfe0363a6bbdcd3dc`다. 보관 구조를 재현한 검사는 실제 1688 페이지 읽기나 저장 성공 증명이 아니다.

## 메뉴와 수집 버튼

앱과 운영관리의 왼쪽 메뉴를 로켓배송, 상품소싱/분석, 판매/분석, 손익계산, 물류의 공통 접이식 메뉴로 통합한다. 사용자 지정 하위 메뉴와 기존 물류 항목을 유지하고 그룹별 컬러 SVG 아이콘을 사용한다.

운영관리에서 기존 AI상품등록 링크를 직접 눌렀는데도 `/operations?view=keyword`에 남는 현상을 브라우저에서 재현했다. 페이지를 이동하는 링크를 일반 링크로 바꾸며, 상품관리에는 명시적 URL을 사용한다. 전송 잠금·저장 중인 작업·수정 중인 입력을 보호하는 이동 검사는 유지한다.

상세 상품 수집기는 기존 Y/민트 잎 브랜드를 둥근 YFS 버튼으로 표시하고, 그 위에 간결한 ‘상품 수집’ 버튼을 둔다. 기본 펼침, 접기/펼치기, 키보드 접근과 버전 표시를 제공한다. 상품 수집·원문 저장·중복 방지·기한 검사는 바꾸지 않는다.

## 원래 문서 읽기 복구

886 원래 견적의 저장된 세 옵션과 가격·첨부 연결을 다시 읽었다. 원래 요청의 읽기 복구는 ‘예약한 같은 문서의 새 전용 탭에서 현재 본문·전체 파일의 읽기 확인을 계속’ 응답으로 끝났다. 웹 예약이 없어 기존의 세션 기반 복구 버튼이 보이지 않는 실제 결함을 확인했다.

같은 상품·요청·문서에 대한 검증된 닫힘 응답이 있을 때만 읽기 탭 복구 버튼을 제공한다. 복구 후 실제 후속 체크포인트와 현재 본문·파일 증거를 대조하고 보통 읽기 복구까지 성공한 뒤에만 원래 웹 예약을 복원한다. 검사 메타데이터나 오류 응답만으로 세션을 만들지 않는다. 문서 생성·파일 업로드·본문 재전송은 이 복구 경로에 포함되지 않는다.

예약했던 읽기 탭까지 닫힌 경우도 보완했다. 명시적 읽기 복구에서 닫힘을 실제 확인한 경우에만 그 증거를 이력으로 보존하고, 새 읽기 탭 요청을 먼저 원자적으로 예약한 뒤 탭 한 개를 연다. 생성 응답이 불명확한 경우 재생성하지 않는다. 원래 문서·본문·파일·감사 기록을 유지하고 현재 저장본 전체 검증 후에만 연결한다. 보통 읽기나 이미 연결 완료된 탭의 닫힘을 추가 생성 근거로 쓰지 않는다.

Couplus의 보관 전송 handler는 새 문서 생성→본문 저장→2~5단계 검증→중간저장 문서 선택→단계별 동의·제출→완료 문구 순서다. 기존 문서 2347603에는 새 생성 handler를 반복할 수 없다. 근거 `ev_17ed0cebd00b285e0bc489221547e437d2b3f69d9b636a813eb942a0a2a3a49a`.
