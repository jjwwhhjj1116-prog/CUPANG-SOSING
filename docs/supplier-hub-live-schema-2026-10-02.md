# 선택 카테고리 상세 양식 → 수정 가능한 견적 초안 연결 — 2026-10-02

## 근거와 실제 확인 범위

548에서 확보한 공개 [Supplier Hub 등록 프런트엔드](https://supplier.coupang.com/sr/registration)의 코드 계약을 추가로 분석했다. 원본 main.5239dce6.js는 SHA-256 `6fc9c0fae51702e62e2d1376ac8854d0d97c0035b0bf96afeb42069c2a5abe11`이다. 인증 정보 없이 확보한 원문을 AST로 읽었으며, 공급자 코드를 실행하거나 저장소에 복사하지 않았다.

- 최종 표시 분류코드로 GET `/sr/schema/api/get-default-schemaform?internalDisplayCode=...&useCustomizedJsonSchema=true`를 호출하며 응답의 `schemaString`을 JSON으로 해석한다.
- 공개 프런트엔드의 `convertAllOfToItems`는 이름/값 두 속성을 가진 `allOf[].contains.properties` 배열을 입력 항목으로 변환한다. 노출·비노출 속성과 상품고시 배열의 그룹을 구분한다.
- 표시 분류코드, kanCategoryId, scopeType, noticeNumber, version은 별개 식별값이다. 코드 또는 경로 이름으로 다른 식별값을 추측하지 않는다.
- 실제 로그인 계정의 schemaString을 이번 작업에서 수집한 것은 아니다. 앞서 익명 조회는 302였고, 아래 테스트의 상세 양식은 공개 구조에 맞춰 만든 합성 fixture다. 특정 실제 카테고리의 전체 필수 규칙·최종 접수 증거가 아니다.

## 구현

확장 0.2.36은 상품추가 카테고리 선택 완료 시 실제 최종 분류를 다시 확인한 뒤 상세 양식을 읽는다. 요청한 원래 앱 탭의 승인 회원과 회사정보를 대조하고 같은 Chrome 창에 열린 허용된 Supplier Hub 등록/조회 탭에서 GET만 수행한다. 회사는 와이홉 A01464742 또는 유앤채 A01526306이다. 회사/회원/탭이 조회 도중 바뀌면 결과를 사용하지 않는다. 새 창·프로필 생성, 기존 상품/견적 폼 쓰기, 쿠키·토큰 추출은 없다.

원문 양식·회사·최종 코드·전체 경로·조회 시각과 허용된 버전 메타데이터를 카테고리 설정에 보관한다. 원문 응답은 512KiB, schemaString은 UTF-8 200,000바이트, JSON은 12,000노드/24깊이, 입력 항목은 400개로 제한한다. 서버는 저장 시 같은 승인 회사와 경로를 다시 검사하고 입력 항목을 원문에서 재생성한다. 호출자가 보내는 임의 필드 목록을 신뢰하지 않는다.

상세 양식의 항목 이름·필수 여부·enum·숫자/길이 제한·선언된 기본값을 견적 초안에 연결한다. 카테고리 고유 항목은 그룹/원본 경로/선택 이름으로 안정된 ID를 가지므로 같은 이름의 노출·비노출·고시를 섞지 않는다. 공통 항목의 의미는 같은 구역/그룹의 완전한 이름으로만 연결한다. 원문 선택값이 기존 정적 양식과 달라지면 예전 선택값을 그대로 남기지 않는다.

쿠플러스에서 확인한 이름/값 배열 초기화 규칙에 따라 노출·고시는 해당사항없음, 비노출 속성은 빈 wire 값으로 초안을 초기화한다. null enum이 해당사항없음으로 표현되는 경우에는 실제 빈 코드를 사용한다. 상품정보·저장된 옵션·기본설정이 있으면 그 값을 우선하며, 사용자의 수정값과 명시적으로 비운 값이 가장 우선한다. 색상·수량·사이즈와 확인된 공통 고시 이름만 공유 의미로 연결하고, 다른 고유 속성은 이름이 정확히 맞는 수집값 또는 수동 입력으로 연결한다. 기본값은 실제 상품 증빙 확인을 뜻하지 않는다.

상품 수집 시 선택한 양식을 수집 컨텍스트에 고정한다. 이후 카테고리 설정을 새 양식으로 갱신해도 기존 작업 상품의 항목·선택값·기본값을 바꾸지 않는다. 견적 화면, 수정 API, 출력 행과 출력 식별값이 이 고정 양식을 사용한다. 최신 Excel 파일/열 연결을 사용하면서도 상품의 선택값 검증은 수집 당시 양식으로 일치시킨다.

기존 카테고리의 양식을 갱신할 때 원본 Excel·수동 열 연결을 유지하고 저장 버전 충돌을 검사한다. 고유 항목은 Excel 연결 메뉴와 정확한 머리글 제안에 포함되며 출력 값에도 기록된다. 같은 이름의 중복 머리글은 자동 연결하지 않는다. 원본 파일 지문·카테고리 코드·수정 공란·선택값 출력 규칙의 기존 검사는 유지한다. 화면 렌더마다 원문을 열 수만큼 다시 해석하지 않고 해석 결과를 재사용한다.

## 적용 및 남은 검증

기존에 로드한 확장 폴더를 새로고침하고 앱 페이지를 새로고침해야 상세 양식 조회가 적용된다. 기존 오른쪽 Chrome 및 Couplus 작업 상품은 변경하지 않았다. agent는 이 확장으로 기존 Chrome 도구의 전체 탭 조회 거절을 우회해 실행하지 않았다.

`$ref`, 조건부 스키마, 추가 배열 제약, pattern 등 현재 해석하지 못하는 규칙은 미확인으로 표시한다. 공통 이미지/인증/물류 항목은 기존 구현을 유지하며, 상세 양식의 모든 규칙을 지원한다고 선언하지 않는다. 동적 고유 항목을 별도의 번역 연결 규칙 API에 저장하는 기능도 아직 모두 확장하지 않았다.
