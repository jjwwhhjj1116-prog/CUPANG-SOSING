# Step638 — 옵션 번역 사실, 수동 모델명의 공식 열, 파일·SKU 결과 저장

1688 수집 초안에서 내부 옵션 ID의 숫자가 상품 수치로 인정되거나, 직접 입력한 모델명이 원본 Excel 열에 반영되지 않거나, 파일 조회가 동시에 저장된 새 SKU 관찰을 덮는 경우를 수정했다. 운영 앱과 확장 0.2.64를 함께 배포한다. 이 단계의 검증은 로컬 합성 상품과 기록된 공식 원본 계약을 사용하며 새로운 실상품 수집·Hub 접수를 완료했다는 의미는 아니다.

## 수정 동작

- `option:collected-1`, `option-color:collected-1` 같은 내부 연결 이름은 판매자 원문 사실이 아니다. 원문 `红色`에 없는 `1cm`를 번역 결과에 넣으면 해당 옵션 속성을 보류한다. 정상 SEO와 다른 정상 속성은 유지하며, SEO 자체의 원문에 없는 수치는 계속 거부한다. 판매자의 실제 속성 이름에 있는 `IP68`, 원문 값의 `005`·`12cm`는 유지한다. 저장된 v6 결과를 읽을 때도 같은 속성 검사를 적용하고 원본 저장 자료를 다시 쓰지 않는다.
- 사람이 직접 입력한 모델명에는 상품명 제안의 50자 규칙을 적용하지 않는다. 실제 양식의 입력 규격에 맞는 모델명을 보여주고, 정확히 연결된 공식 `모델명/품번`과 비교한 뒤 명시적으로 적용할 수 있다. 직접 입력한 별도 값·직접 공란·옵션별 수동값을 덮지 않는다. 최신 초안과 현재 옵션 범위를 다시 확인하고 기존 저장 버튼 한 번으로 모델명과 공식 열을 확정한다.
- 원래 등록 탭의 일반 파일 관찰도 IndexedDB의 원자 비교 후 저장(`file-observe`)을 사용한다. 읽은 결과 이후 SKU 관찰이 저장되었다면 파일 관찰은 교체하지 않는다. 별도 검증 복구·과거 접수 조회는 기존 계약을 유지한다. 명시적인 파일 반려·진행 상태는 계속 갱신할 수 있으며, 이전 전송에 없는 옵션 수·아직 배정되지 않은 접수 ID는 추정하지 않는다.
- 앱은 새 파일 관찰 기능을 확인한 확장에만 일반 전송 및 현재 파일 조회를 허용한다. 전송 함수의 직전 확인에서도 이 기능을 다시 검사하여 파일 읽기·동의 전달 전 확장이 바뀐 경우를 차단한다. 기존 결과·과거 접수 읽기는 유지한다. 새 디스크 스크립트가 주입되더라도 실제 설치 manifest가 0.2.64 미만이면 해당 기능을 광고하지 않는다. 확장 권한·허용 사이트는 바뀌지 않았다.

## 검증

최종 변경 코드의 중복 없는 **23개 시험 파일, 403개 시험**이 모두 통과했다(실패·취소·skip 0).

| 범위 | 파일 수 | 통과 |
|---|---:|---:|
| 앱·설치 확장의 기능 확인 | 2 | 49 |
| 원래 파일 조회의 저장 경쟁 및 기존 저장 | 3 | 34 |
| 팝업·전송·검증 복구 | 3 | 65 |
| 번역·초안 수집·수동 수정 보존 | 11 | 134 |
| 수동 모델·상품명 제안·편집기·원본 Excel | 4 | 121 |

타입 오류 0, lint 오류 0(기존 경고 8), 운영 빌드 완료. sourceflow / sourceflow-db / ASSETS 및 기존 18개 마이그레이션을 유지한다.

같은 Chrome의 로컬 검수에서 실제 `observeSupplierHubResult`와 `transferRecord`를 실제 IndexedDB에 연결했다. 양사 각각 새 SKU 경쟁 저장 보존, 동일 snapshot의 8개 동시 교체 중 한 번만 저장, 명시적인 파일 반려 갱신을 확인했다(6건 모두 통과). API는 외부 실행을 지원하지 않는 합성 모형이다.

실제 `QuotationFieldsEditor` 화면에서 57자 모델명을 직접 입력하고 공식 모델 열 적용을 누른 뒤 저장했다. 기록된 유앤채 Single69900v188 계약과 원본2624.xlsx를 로컬 메모리에서 연결하여 dataStartRow 9, 0-based column 11의 6개 셀을 대조했다. 명시 저장 1회·변경 항목 2개, 입력한 모델과 원본 6셀 일치, 모델의 EXCEL_FIELD_UNMAPPED 해소를 확인했다. 원문·카테고리·옵션·가격·콘텐츠·이미지 풀·R2 바이트는 보존됐다. 와이홉의 모델 시험은 이 공개 양식 계약을 분리된 계정 fixture에 재사용한 것이며 새 와이홉 공식 양식 캡처를 뜻하지 않는다.

양사와 Google Free/Workers AI의 합성 수집 시험 및 같은 Chrome의 직접 수집 버튼 4개에서 정상 SEO·다른 옵션·실제 12cm를 유지하고 잘못된 1cm 옵션만 보류하는 동작을 검사했다. 실제 수집 경로·API·SQLite·견적 React UI·XLSX를 사용하여 두 옵션의 가격·수량·판매자 SKU·재고·이미지·원문을 대조했다. 각 fixture의 번역 작업은 한 건이고 실제 번역 서비스 비용·외부 호출이나 Supplier Hub 업로드를 실행하지 않았다. 모델의 새로고침 직후 이전 버튼 콜백은 즉시 차단하고, 성공·실패·폼 종료 뒤에도 기존 입력을 보존하는 회귀시험과 별도 독립 재현도 통과했다.

## 배포 및 남은 실제 검수

0.2.64 ZIP: 41개 파일, 531,123바이트, SHA256 `e4037d76f97e0e7ca3867f4f65f9a41fc2071ae381203f64a14dc7624e84e0af`. 이미 공개된 0.2.61·0.2.62·0.2.63 ZIP은 변경하지 않았다. 현재 Chrome에서 확인한 설치 버전은 0.2.60이므로 새 확장의 실제 적용은 별도 확인이 필요하다.
