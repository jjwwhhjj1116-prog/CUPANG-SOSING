# Step716 — 기본설정 이미지·최소 마진 선택·접수 증거 보존

기준은 `9f0cdaaba67d157d4fc2b247a592ebc04c8aa59b`다. 기존 작업 상품과 저장 설정을 변경하지 않고, 원본에서 확인한 기본설정 동작과 자체 접수 결과 보존 문제를 수정한다.

## 기본설정의 이미지 입력

같은 Chrome의 쿠플러스 기본설정 화면을 열어 현재 표시 항목과 값을 읽고 저장 없이 닫았다. 등록 목록의 상품·구매링크·각 단계는 열지 않았고, 필터·설정값도 바꾸지 않았다. AX 기록은 ignored `outputs/step716-live-couplus-settings.txt`에 있다. 캡처는 CDP 시간 초과로 저장되지 않아 픽셀 동일성 증거로 표현하지 않는다.

보관 원본을 REA로 대조한 결과, 상·하단 이미지 선택·드롭·붙여넣기는 로컬 미리보기와 대기 파일만 바꾼다. 실제 업로드는 ‘설정 저장’에서 수행한다. 파일 선택·제거가 이미지 사용 토글을 자동으로 바꾸지 않는다. 자체는 선택 즉시 업로드하고 토글까지 변경했으므로 이 경계를 맞춘다. 원본의 이미지 URL만 제거하면 변경 없음으로 판단하는 약한 분기까지 복제하지는 않는다. 원본 근거와 알려지지 않은 부모 lifecycle은 [별도 감사](step716-settings-parity-audit.md)에 구분했다.

## 새 상품의 최소 마진 선택

기본설정의 최소 마진 보장 ON·0원을 새 상품 정책에 넘길 때 독립 선택값이 빠져, 2단계가 금액 0만 보고 OFF로 표시했다. 원본 pricing 작업자는 정책을 `info`에 별도로 보관하며 ON과 0을 각각 유지한다. 새 URL 초안과 수동 생성 정책에 같은 선택값을 저장하도록 수정했다.

최초 계산식은 그대로다. 초기 정책에는 재계산 모드를 넣지 않고, 기존 정책을 읽을 때 자동으로 선택값을 추가하지 않는다. 기존 상품의 가격·정책·옵션·수동 견적값도 자동 변경하지 않는다. 사용자가 2단계에서 명시적으로 재계산할 때만 기존의 ON·0 계산 규칙을 사용한다. OFF의 숨겨진 음수 입력을 무시하는 식으로 유효성 검증을 완화하지 않았다.

새 검사는 두 회사 × 일반/통합 환율 × ON/OFF의 8개 실제 격리 receipt/import→PriceEditor→재계산 API·재열기와 기본 와이홉 fixture의 수동 상품 생성 4개다. 12/12가 통과했고 고정된 가격 예시, 원문 receipt·설정·옵션·내용 및 기존 보호용 합성 상품의 불변을 검사한다. 회원 인증과 원문은 합성이며 실제 두 회원 로그인이나 실제 1688 수집 증거는 아니다.

## 접수 결과 연속성

같은 원문·견적서 ID의 검증완료 결과에 이미 SKU가 있어도, 더 최신의 단순 pending 조회나 일부 SKU만 담긴 결과가 들어오면 기존 근거를 지울 수 있었다. 합성 관찰값으로 실제 자체 receipt API·격리 SQLite를 사용해 재현했다. 기존 SKU 증거가 있는 결과를 바꿀 때 동일 원문의 단순 대기 회귀와 SKU 누락을 구분해 보호한다. 명시적 반려와 동일 SKU의 상태 변경은 별도 의미를 유지한다. 이 수정은 새 접수나 성공 결과를 만들어내지 않는다.

## 검증 경계

실제 신규 상품의 원문 전체와 Supplier Hub 신규 접수번호는 아직 검증하지 못했다. 이전에 거절된 1688 읽기를 다른 도구·앱·확장·CLI로 우회하지 않는다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 전송 gate를 유지한다. 모든 카테고리·번역·화면·최종 접수가 동일하게 완성됐다는 주장은 하지 않는다. 준비한 확장 버전과 실제 설치 버전도 구분한다.

## 최종 검사와 배포

- 최종 관련 31개 파일 **415/415 통과**, fail/cancel/skip/todo 0, 146.30초. 신규 검사는 이미지 14·최소마진 12·접수 보존 14의 40개이며 집중 검사와 반복 실행은 합산하지 않았다. 소스·설정·테스트 1,295개 SHA가 실행 전후 동일했고 추가·삭제도 없었다. 전체 저장소 suite라는 의미는 아니다.
- 첫 회귀는 415개 중 405개 통과·10개 실패했다. 초기 고시와 라벨을 혼동한 4개, D1 테스트 어댑터의 `RETURNING` 결과 누락 2개, 접수 SKU 보존의 변경된 의미 2개, 화면 테스트의 `useLayoutEffect` 수명 연결 누락 2개를 고쳤다. 고시·D1 문제는 HEAD에서도 재현했으며 로그를 보존했다. 앱 검증 완화 없이 명시 공란·수동 견적 우선·등록번호와 카운터의 원자적 rollback 검사를 유지·강화했다.
- 타입·앱/DB lint·변경 MJS lint·schema(44 tables, 17 indexes, 29 modules)·운영 빌드·diff 검사가 통과했다. 기본설정·가격·접수·기존 fixture 수정은 별도 독립 읽기 검토를 받았고 잔여 지적은 없었다. `outputs/step716-final-verifier.mjs`가 원본 범위·증거·소스/검사 SHA와 배포 ID를 대조한다.
