## 사진 순서 변경과 응답 유실 복구

선택 옵션의 추가·상세 사진을 드래그해 순서를 바꿀 수 있다. 기존 위아래 이동 버튼도 유지했다. 드롭은 편집 중인 로컬 순서만 변경하며 명시적 저장 전에는 PUT이나 번역 요청을 하지 않는다. 다른 패널·외부 URL·이전 드래그·옵션 또는 원문 변경·처리 중인 상태는 적용하지 않는다. 사진 선택·수동 HTML·다른 옵션·공통 배너를 보존한다.

브라우저의 드래그 종료에서는 payload를 읽어 정리하지 않는다. 드래그 데이터는 dragstart·drop 외 이벤트에서 보호 모드가 된다는 [HTML 표준](https://html.spec.whatwg.org/multipage/dnd.html)에 맞게, 자신의 시작 요소와 편집 맥락으로 종료 표시를 정리한다. 취소·외부 패널 drop·선택 전환에 대한 실제 이벤트 회귀를 검사했다.

저장 응답이 유실됐거나 복원 뒤 확인 조회가 끊기면 명시적 재확인은 GET으로 정확한 저장 결과를 대조한다. 원래 편집 기준과 일치하는 한 번의 저장만 인정한다. 아직 저장되지 않은 동일 기준이면 편집값을 보존하여 다음 명시적 저장을 허용하며, 그 외 변경은 미확정 상태로 남긴다. 저장 응답을 받지 못했다는 이유로 같은 PUT을 다시 만들지 않는다.

두 회사의 실제 로컬 API·D1·R2·XLSX·ZIP fixture에서 드래그 전후 명시적 저장 전 요청과 저장 자료가 변하지 않는 것을 확인했다. 응답 유실을 포함한 사용자 저장 7회에 PUT 7회만 발생했다. 원본 이미지 바이트, 수동 HTML, 다른 옵션, 가격·포장·고시 값을 유지했다. 운영 상품에 사진 변경을 수행한 검사는 아니다.
