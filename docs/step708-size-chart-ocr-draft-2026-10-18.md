# Step708 — 저장 이미지의 사이즈표 추출·번역·검토 초안

기준 `c3c4ddd4a0c6a4a5b70f40074706186a4db85588`. 원본 REA 근거는 [추출 경로 대조](step708-size-chart-extraction-parity-audit.md)다. 원본을 실행하거나 공유 Chrome·기존 상품을 조작하지 않았다.

## 기능과 원본 대조

Couplus의 보관된 현재 페이지는 서버 AI 경로를 선택한다. 설치 확장에는 별도 Gemini 사이즈표 추출 함수가 있지만 해당 전용 함수의 background receiver 연결은 확인되지 않았다. 서버 내부 공급자·프롬프트·실행 품질은 공개 클라이언트 코드만으로 알 수 없다. 따라서 자체 경로를 원본 서버의 복사라고 표현하지 않는다.

자체에는 저장한 원본 사진의 문구를 읽고 사이즈표 초안을 만드는 경로가 없었다. 기존 앱 파일 조회·로컬 Tesseract·Workers AI 텍스트 모델·Google 번역 기능을 재사용해 다음을 연결했다.

1. 사이즈표 편집기의 ‘이미지에서 사이즈표 초안 만들기’를 연다.
2. 본인 상품에 저장된 사진 한 장과 중국어/영어를 선택한다.
3. 원문 문구를 읽고 표에 해당하는 줄을 확인·선택한다.
4. 선택한 원문으로 표 초안을 작성한다. 측정 항목명만 한국어 번역을 시도한다.
5. 사진과 행·열·숫자·단위를 비교하고, 검토한 표를 수동 편집기로 가져온다.
6. 기존 Step707 정보 저장·PNG 생성·견적서 연결을 직접 진행한다.

현재는 한 번에 선택한 사진 한 장을 처리한다. 원본의 상세 사진 최대30장 자동 검색, 혼합 행별 단위의 완전한 원형 보존·변환과 동일하다고 주장하지 않는다. ‘표 없음’과 오류는 구분하며 기본 치수를 만들어 완료 처리하지 않는다.

## 원문과 저장값 보호

새 읽기 전용 `/size-chart-draft`는 승인 회원·회사·상품 소유자와 현재 파일 pool을 확인한다. 원본 선택 시 실제 저장된 PNG/JPEG/WebP 바이트·크기·SHA를 읽는다. 기존 이미지 편집기의 역할 검증을 완화하지 않으며, 픽셀 로더 호환용 `detail` 값이 실제 역할을 지정하지 않는다. 목록 조회는 추출 영역을 열 때만 시작하며, 실패한 조회는 별도 버튼으로 다시 시도한다.

브라우저는 앱에 포함된 Tesseract worker/core/언어 자산으로 OCR을 수행한다. 이는 서버가 이미지에서 직접 읽은 사실의 증명이 아니라, 해당 이미지 SHA에 연결된 사용자 단말의 인식 후보다. 표시 방향이 바뀐 JPEG도 처리하도록 원본 크기와 같거나 정확히 뒤바뀐 표시 크기를 전달하고 그 좌표 안에서만 OCR 영역을 허용한다.

AI는 새 수치나 완성 문구 대신 입력 OCR 토큰의 ID로 각 셀을 선택한다. 같은 원문 줄에서 연속된 토큰을 순서대로 선택해야 하며, 셀 간 중복 사용·없는 토큰·교차 줄·잘못된 열 수는 거절한다. 실제 표시값은 원문 substring으로 다시 구성한다. 측정값의 소수점·범위·부호·공백을 환산하거나 번역하지 않는다. 토큰 검증은 숫자가 OCR에 존재함을 확인하지만, 모델이 잘못된 행·열에 배치하지 않았다는 증명은 아니다. 원본 대조와 수동 검토가 필요하다.

단위 검사는 모델이 선택하지 않은 헤더를 포함한 전체 선택 OCR 원문을 본다. `40cm`처럼 숫자에 붙은 단위도 검사한다. 혼합·미확정·지원하지 않는 단위는 자동으로 cm를 넣지 않고 직접 확인하게 한다. Google 번역은 행 이름에만 적용하고 원문의 숫자·단위 의미가 바뀌면 번역을 버리고 원래 이름을 보존한다. 사이즈명과 측정값은 번역하지 않는다.

결과는 초안만 반환한다. 상품·콘텐츠·표·이미지·작업 job을 자동 저장하지 않는다. 요청 전후 승인 회원·회사·상품·콘텐츠·pool과 실제 이미지 SHA를 다시 확인한다. 편집기로 가져오기 직전에도 원본을 재조회한다. 응답의 표는 OCR 참조와 번역 증거로 다시 구성해 검증한다. 미저장 표·PNG 작업·취소·언마운트·늦은 응답은 기존 입력을 덮어쓰지 않는다.

기존 Workers AI 설정과 공유 일일 요청 예약을 재사용한다. 요청당 모델 호출1회·30초 제한이며 자동 재시도·새 유료 공급자를 추가하지 않는다. OCR은 기존60초·10MB·1,200만 픽셀·100줄/20,000자 한도를 따른다. 자체 추출 한도는 1,200토큰·64KiB 참고자료·10개 사이즈열·20개 측정행·200셀이다. 이 한도를 원본 서비스의 제한이라고 주장하지 않는다.

## 검수 경계

검수는 양사 격리 계정·유효 합성 PNG·실제 자체 API/SQLite/R2 모형·React callback·OCR 결과 파서를 사용한다. Tesseract 엔진의 영상 인식, 이미지 decode/canvas, 모델, Google 응답은 테스트에서 대체한다. 원문에 없는 값의 반환, 혼합 단위, EXIF 표시 좌표, 잘못된 회사·이미지·원본 변경, 한도, 표 없음, 조회 재시도, 취소와 늦은 응답을 검증한다. 별도 기존 표 저장→PNG 재생성→Single URL·packet 검수도 유지한다.

실제 브라우저 OCR 정확도·현재 모델의 표 구조화 품질·실제 Google 응답·원격 이미지 가용성·새1688 수집·Supplier Hub 최종 접수 검증을 완료한 기록은 아니다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 전송 gate를 유지한다. 최종 검사·빌드·배포 증거는 `outputs/step708-final-validation.json`과 HANDOFF Step708에 기록한다.
