# 견적 이미지 첨부 내용 대조 — 2026-10-01

## 문제와 재현

견적 Excel은 준비 목록의 바이트 수와 SHA-256을 검증했지만 상품 이미지와 표시사항 라벨은 파일명·존재 여부·ZIP CRC만 검사했다. 이미지 바이트를 같은 길이의 다른 값으로 바꾼 뒤 ZIP을 다시 만들면 정상 CRC가 기록되어 기존 구현은 이를 전달 대상으로 인정했다. 상품 이미지 교체, 라벨 교체, 확인값 누락/잘못된 형식의 신규 시험 3개가 수정 전에 모두 실패했다(`outputs/step533-before-fix.log`).

## 적용한 변경

- `loadAttachments`가 소유·상품 연결·개수·합계 용량·실제 이미지 형식을 검증하고 저장소에서 읽은 각 이미지 바이트의 SHA-256을 계산한다. 전송 ZIP의 역할별 목록에 실제 바이트 수와 SHA-256을 기록한다. Excel이 없는 오프라인 필드 안내 생성은 유지하되, Excel을 포함한 전송 자료는 참조 이미지 확인값 없이 생성하지 않는다.
- 확장의 공통 `prepareAttachments`가 모든 참조 이미지의 바이트 수와 SHA-256을 대조한다. 목록이 없거나 내용이 다르면 명확한 오류로 중단한다. 한 파일이 상품 이미지·라벨에 함께 사용되면 SHA 계산은 재사용하고 각 역할의 확인값은 따로 대조한다.
- 앱 등록전송은 Hub 조회·전송 기록 보관·파일 입력 전에 검사한다. 준비 패키지 팝업은 활성 탭 확인 후 Hub 스크립트·패키지 소비·전송 기록 보관·파일 입력 전에 검사한다. 수동 ZIP 선택도 같은 검사를 사용한다.
- 확장 0.2.31은 `imageIntegrityBinding`을 알리고 앱은 새 파일 준비/전달 전에 이를 요구한다. 이전 준비 ZIP에는 이미지 확인값이 없으므로 앱에서 다시 준비해야 한다. 이전 버전의 전송 결과 조회와 중복 전달 방지 기록은 바꾸지 않는다. 기존 0.2.30 다운로드 파일도 보존한다.

이 검사는 ZIP 안의 준비 목록과 첨부 바이트의 일치 확인이다. 준비 목록과 파일을 동시에 변경하는 공격에 대한 전자서명 검증이 아니며, 이미지 글자·판매 분류·표시사항의 법적 적합성을 증명하지 않는다. DB·비밀 설정·공개 이미지 Worker·유료 자원은 변경하지 않는다.

## 검증 범위

- 정상 ZIP과 Excel 전달, 상품/라벨 교체 후 정상 CRC ZIP 거절, 누락·소수/잘못된 바이트 수·잘못된 SHA 형식 거절, 두 역할이 같은 파일을 사용한 경우의 대조를 검사한다.
- 앱/팝업 각각 상품 이미지·라벨 교체 4경로는 Hub 스크립트와 영구 전송 기록이 생기지 않는지 검사한다. 예전 확장에는 PING 한 번 이후 새 파일을 전달하지 않는다.
- 와이홉 A01464742·유앤채 A01526306 각각 실제 API와 임시 SQLite로 원문 수집→6옵션→내용/이미지/표시값/판매가 수정→견적 Excel/ZIP 생성→확장 파서를 실행한다. 모든 Excel·상품 이미지·라벨의 실제 SHA와 길이, 전달 바이트, 회사 및 옵션 수가 일치한다. 판매가 20000원이 Excel 6행에 반영되고 교체 ZIP 거절 후 저장 지문과 상품 미전송 상태가 유지된다.
- 기록 원문은 지정된 813724060928 선글라스 자료다. 80719는 관찰한 폼 계약의 시험용 연결이며 선글라스의 실제 판매 분류가 아니다. 인증·AI·이미지·공식 Excel·Chrome API는 fixture이고 실계정 Supplier Hub에는 쓰지 않는다.
