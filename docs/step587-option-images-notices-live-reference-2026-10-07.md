# Step 587 — 옵션 이미지·상품고시 편집과 실제 쿠플러스 대조

기준 커밋: `08e3620ebcb9ab4896ee49462197325e816be6ba` (step586).

## 구현

- 선택 SKU의 추가 이미지와 상세 이미지를 저장한 상품 파일 중 선택·제거·재정렬한다. 정확한 Supplier Hub primary wire와 같은 옵션의 canonical 요약을 함께 저장한다. 직접 비운 값과 공통·자동값 복원을 구분하며 다른 SKU와 공통 자료를 바꾸지 않는다.
- 추가 이미지는 왼쪽 후보 목록·오른쪽 큰 미리보기·번호 목록, 상세 이미지는 세로 이미지 목록·사진별 이동/제거·접을 수 있는 후보 목록으로 배치했다. 상세 HTML 직접 입력과 공란을 유지한다. 이미지 순서 변경만으로 직접 작성한 HTML을 덮어쓰지 않는다.
- 두 이미지 단계는 별도 편집 인스턴스를 계속 유지한다. 단계 이동이나 다른 단계 저장 후에도 미저장 입력을 보존하며 기존 닫기·견적 진입 검사에 각각의 원천 단계와 저장 상태를 제공한다. 공통 이미지 편집과 번역은 별도 펼침 영역에 유지한다.
- 새 선택 옵션 **상품고시** 편집기는 7단계에 연결한다. 카테고리의 실제 고시 필드만 수정하고, 정확한 named Hub wire와 canonical 고시 필드를 같이 저장한다. 인증 번호, 비슷한 항목명, 다른 옵션 값을 수정 대상으로 추정하지 않는다.
- 저장된 선택 옵션의 상품고시로 PNG를 만들고 선택 옵션 견적 라벨에 연결할 수 있다. 업로드 후 실패해도 저장한 파일을 재사용하며, 이미 상속한 동일 이미지가 연결돼 있으면 중복 업로드/수정하지 않는다. 이것은 쿠플러스 6단계의 제품 라벨 9항목을 복제한 결과가 아니다.
- GET 원천 버전, PUT revision+1/상품 시각 증가, 항목 연결과 전체 수동 수정값을 검사한다. 응답 유실 뒤 명시적 읽기 복구와 null 복원값 검증을 추가했다. 자동 저장·자동 재전송·유료 번역 호출은 추가하지 않았다.

## 실제 Chrome 대조

- 기존 와이홉 Chrome의 최신 `openTabs()` 결과에서 `providerTabId`를 포함해 탭을 claim하자 쿠플러스와 로그인된 YOOFAM PLUS UI를 읽을 수 있었다. 이전 탭 오류를 사이트 차단 또는 로그아웃으로 해석하지 않는다. 새 Chrome 창·프로필을 열지 않았다.
- 쿠플러스 기존 작업 상품의 옵션 목록과 4·5·6단계 팝업을 읽고 스크린샷을 `outputs/step587-couplus-{additional,detail,label}.jpg`에 보관했다. 값 변경, 저장, 재작성, AI 처리, 삭제, 다음 버튼, 등록 전송은 실행하지 않았다.
- 4단계의 모든 이미지 후보/큰 미리보기/현재 추가 이미지 순서 목록과 5단계의 세로 이미지/위·아래/삭제/사진별 번역 버튼을 확인했다. 참조 5단계 상단 이미지는 잠겨 있었으나 현재 견적의 평탄한 이미지 배열에서 첫 항목을 임의로 잠그지는 않았다.
- 실제 6단계 결과는 제품명, 제조원, 수입 및 판매원, 제조국, 내용량, 원료명 및 성분명(재질), 상품 유형, 사용 시 주의사항, 사용 기준의 **제품 라벨 9항목**이었다. 카테고리별 상품고시와 분리돼 있었다. 현재 공통 제품 라벨 편집/조판이 이 9항목의 이름·순서·옵션별 저장 방식과 완전히 같다고 주장하지 않는다.
- 양쪽 와이홉 설정에서 브랜드/제조사/수입판매원/AS 연락처, 박스 SKU 50, 환율 350, 공급 마진 50%, 쿠팡 마진 40%, 최소 마진 3,000원, MSRP 1.3배를 읽어 대조했다. 9위안 옵션의 쿠플러스 공급가 6,300원·판매가 10,500원도 읽었다. 이 사례는 저가 최소 마진 경계값 및 모든 반올림 사례를 검증한 것이 아니다.
- 쿠플러스에는 비활성 상태인 통합통관 환율 기능과 `(위안가 × 통합통관환율 + 200 + 100) × 1.1` 안내가 보였다. 이를 현재 앱에 구현했다고 주장하지 않는다.
- 앱의 원본 이력은 937건/표시 옵션 합계 7,859개로 표시됐다. 이는 부분 원본 이력 보관이며 전부를 완성된 전송 가능 견적으로 복제한 의미가 아니다.

## 검증 범위와 남은 작업

새 편집기의 실제 API 핸들러·임시 SQLite·양회사·가상 공식 XLSX/ZIP 검사는 선택한 값, 명시 공란, 이미지 순서와 HTML, PNG가 해당 SKU에만 반영되는지 확인한다. 합성 PNG/양식과 저장한 1688 원문을 사용하는 로컬 검증이며 실제 Worker 캔버스 생성 또는 Supplier Hub 접수 성공의 증거가 아니다.

이번 변경은 확장 0.2.53, D1 migration 15개, 기존 R2/Access 바인딩과 무료 번역 주소를 유지한다. 운영 상품 수정·실제 Hub 제출은 하지 않았다.

다음 필수 사항은 6단계 제품 라벨 9항목의 독립 옵션 저장·조판, 설정 상단/하단 이미지 구분, 개별 견적 참조 이미지의 번역 적용, 모든 카테고리 기본값, 실제 공식 Excel 및 Supplier Hub 접수/SKU 결과 확인이다. 지정 검증 상품의 포장 g/mm 값은 실제 측정값 없이 추정해 넣지 않는다.

## 배포 후 실제 앱 읽기

기존 와이홉 앱 탭 727924317의 열려 있던 저장 작업 공간과 설정을 닫고 갱신했다. 이전 미저장 탭 727924101은 갱신·닫지 않았다. 회원 이메일·1개 검증 상품·6개 옵션·원본 URL·25개 저장 이미지 후보·추가 이미지 7개·상세 11개·옵션별 공급가/판매가·7단계 네비게이션을 실제 로그인 DOM에서 확인했다. 공급가 4,260/4,930원, 판매가 7,100/8,220원이 옵션별로 표시됐다.

실제 앱 화면 캡처는 일반/클립/문서화된 기본 Tab API에서도 5초 타임아웃으로 끝나 앱 JPG 결과를 보관하지 못했다. 쿠플러스 참조 JPG는 보관됐다. 읽기 제어까지 사이트 차단 또는 로그아웃으로 해석하지 않는다.

초기 DOM 클릭 검수는 팝업이 닫히면서 완료되지 않았다. 문서화된 기본 Tab 접근성 API로 새 상태의 버튼을 선택해 검수를 이어갔다. 추가 이미지 후보 2를 해제해 7→6개, 상세 단계에서 11개 독립 선택 유지, 추가 단계로 돌아와 미저장 6개와 활성 저장 버튼 유지, 견적 진입 시 ‘추가 이미지에 저장하지 않은 입력’ 안내를 실제 Chrome에서 확인했다. 입력 취소·다시 조회 후 저장본 7개와 dirty=false로 복원했다. 저장·업로드·전송은 실행하지 않았다. 초기 클릭 차이의 원인을 앱 결함 또는 도구 문제로 단정하지 않는다.

이어서 선택 옵션 7단계에서 새 상품고시 편집기, 카테고리 선글라스의 실제 8개 고시(종류·소재·치수·제조자/수입자·제조국·취급주의·보증·AS)와 원래 저장된 기본값, 미저장값 없이 비활성인 저장 버튼 및 PNG 미리보기 버튼을 확인했다. 실제 공식 양식의 포장 g/mm 필수값은 비어 있음을 유지했으며 임의의 값으로 보완하지 않았다.

동일 옵션의 ‘상품고시 PNG 미리보기’를 실행해 실제 브라우저의 PNG 이미지·blob 다운로드 링크·견적 연결 버튼 표시까지 확인했다. R2 업로드와 견적 연결 저장은 실행하지 않았다. 다운로드 도구는 15초 뒤 결과 파일 없이 종료했으므로 실제 PNG 파일을 보관했다고 주장하지 않는다. 앱 탭에는 미리보기를 남겼다. 이는 7단계 상품고시 검토 PNG이며 6단계 9항목 제품 라벨과 다르다.
