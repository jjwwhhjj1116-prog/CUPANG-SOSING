# Supplier Hub 전송 경로의 회사 메뉴 검수 — 2026-10-03

카테고리 → 1688 URL → 수정 가능한 1~7단계 초안 → 견적서 전송 → 접수·SKU 조회의 마지막 구간을 검수했다. 기존 쿠플러스 작업 상품을 변경하지 않았다.

## 재현한 전송 오류

새 등록 탭과 견적서 조회 탭의 준비 검사가 회사코드 표시를 요구했다. 실제로 관찰한 Supplier Hub 회사코드는 닫힌 회사 메뉴 안에 있다. 준비 검사 다음에 있는 회사 확인 함수가 메뉴를 열기 전에 검사 시간이 만료되는 순서였다. 새 탭의 입력 양식이 준비되면 기존 회사 확인 함수로 메뉴를 열고, 정확한 회사코드를 검증한 뒤 첨부 또는 견적서 ID 검색을 진행한다.

필수 서류의 `해당함` 선택, 서류 `해당없음` 선택과 가격·라벨 연락처 동의 클릭도 회사 메뉴를 닫을 수 있다. 기존 구현은 그 뒤 숨겨진 회사코드를 오류로 처리했다. 첨부와 검증 함수가 이미 연결된 회사명 버튼 하나만 다시 열고 최대 2초 기다린다. 실제 표시된 코드·화면 주소·첨부 기록을 다시 검사하며, 동의·파일명·필수 서류 검사는 그대로 적용한다. 회사명만으로 전송을 허용하지 않는다.

메뉴가 열리기를 기다리는 동안 사용자가 직접 추가한 파일을 덮어쓰는 경우도 재현했다. 첫 업로드 이벤트 직전에 현재 파일 입력과 화면의 기존 첨부 파일명을 다시 확인한다. 대기 중 추가된 수동 파일은 보존하며, 파일 전달 없이 `partial` 결과를 반환한다. 그 결과를 업로드나 등록 성공으로 표시하지 않는다.

## 확장 버전 연결

확장 `0.2.40`의 메뉴 처리 기능을 PING 응답의 `companyMenuRecovery`로 확인한다. 앱 등록전송, 기존 첨부의 검증 재개, SKU 조회는 이 기능이 있는 확장을 요구한다. 구형 확장은 업로드·검증·검색 메시지를 보내기 전에 중단한다. 저장된 결과 읽기, 단순 파일 준비와 URL 수집은 기존 호환 범위를 유지한다.

매니페스트·콘텐츠 브리지·세 다운로드 링크를 같은 버전으로 맞췄다. 확장 권한·허용 호스트는 변경하지 않았다. 이미 로드된 확장에는 폴더 갱신과 확장 새로고침, 앱 페이지 새로고침이 필요하다. 기존 Chrome 창·프로필을 사용한다.

## 검사 근거

- 직렬화한 실제 준비·회사 확인 함수로 두 회사 × 등록/조회 양식 4건의 수정 전 실패를 재현했다. 입력 양식이 미완성인 화면과 잘못된 회사는 계속 중단한다.
- 회사 메뉴가 실제 컨트롤 클릭 뒤 닫히는 합성 DOM에서 두 회사의 첨부·동의 처리를 검사했다. 잘못된 코드, 중복 코드, 모호한 버튼, 변경된 기록·화면·파일·동의, 메뉴 시간 초과에는 업로드·검증 요청을 하지 않는다.
- 지연 중 수동 파일이 FileList에 들어간 경우와 파일명이 이미 화면에 표시된 경우 모두 보존했다. 업로드 이벤트 수는 0이다.
- `0.2.39`에서 메뉴 처리 기능이 없거나 `false`·문자열인 응답은 PING만 보낸다. `0.2.40`은 정상 검수 흐름에서 전송·검증·조회 메시지를 한 번 보낸다.
- 집중 검사 56개(탭 준비·전송), 56개(첨부·동의), 31개(수동 파일 보존 재검사), 66개(브리지·앱 호환)가 각각 통과했다. 검사 간 중복이 있어 합산하지 않는다.
- URL 수집·초안·Workers AI 요청·임시 SQLite 반영의 집중 검사 88개가 통과했다. 기록된 지정 상품의 요청은 3,014 UTF-8 바이트·42개 속성이다. 이 경로의 AI 응답은 fixture이며 현재 운영 AI 출력 검증으로 해석하지 않는다.

실제 1688 지정 상품 수집 결과는 [앞선 최종 검수 기록](registration-final-audit-2026-10-03.md)에 있다. 이번 전송 검사에서 실제 Hub에 파일을 업로드하지 않았다.
