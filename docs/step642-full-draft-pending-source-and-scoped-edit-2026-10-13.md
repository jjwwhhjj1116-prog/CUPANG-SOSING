# 새 상품 초안·대기 원문 복구·상세 이미지 편집 — Step642

상품 추가는 선택한 Supplier Hub 카테고리와 현재 계정 설정으로 편집 가능한 초안을 준비한다. 사람의 검토와 명시적인 등록전송 전에는 Supplier Hub 접수를 실행하지 않는다. 기존 실상품·복구 초안·회사 기본설정과 Couplus 업무 자료는 수정하지 않는다.

신규 계정 또는 저장된 대기열이 없는 첫 상품추가의 기본 목표를 `work`로 바꾸었다. SEO·가격 준비에 더해 원본 대표·추가·상세·옵션 이미지의 역할을 연결한다. 이 연결은 이미지 번역·가공 성공이나 견적서 접수 완료를 의미하지 않는다. 저장된 `collect`·`price`·`work`·`transmit` 목표는 그대로 복구하며 조회만으로 초안이나 설정을 저장하지 않는다.

Workers AI 결과에 한글 상품명·옵션이 있지만 원문에 있던 상품 설명의 번역이 빠진 경우, 유효한 상품명과 옵션은 반영하고 설명 원문은 보존한다. Google과 동일한 현재 원문·번역 이력에 연결된 설명 누락 검수로 `reviewRequired`를 표시한다. 중국어 수집 설명으로 만들어진 자동 상세 HTML에도 기존 `needsReview` 안내를 전달한다. 직접 저장한 설명·HTML·명시적 공란은 유지하며 임의 설명을 만들어 채우거나 번역을 재호출하지 않는다.

기존 대기 요청의 카테고리·작업 목표·특징·키워드·설정은 새 입력과 다르더라도 덮어쓰지 않는다. 미등록 요청은 명시적으로 원문을 준비한 뒤 현재 입력의 새 초안을 검토하는 경로로 연결한다. 이미 상품이 연결된 요청에는 수집이나 상품 반영을 다시 실행하지 않는다. 기존 원문 준비 단계에서는 이미지 다운로드·SEO·Hub 전송을 실행하지 않는다. 수정하지 않은 최초 원문 상품에서만 별도 원문 URL 방식을 명시적으로 선택할 수 있으며, 새 초안을 생성한 다음 그 새 초안에서 이미지·SEO 준비를 진행한다. 수정값·전송 이력이 있는 일반 상품은 기존의 저장 이미지 검사를 유지한다. 조회 응답이 유실되거나 미리보기 창이 닫히면 같은 확인값과 원문으로 복구하며 닫힌 창의 오래된 콜백은 쓰기를 실행하지 않는다.

5단계 상세사진 카드의 `편집하기`는 해당 옵션·사진 위치를 그대로 수동 편집기에 연결한다. 원본 조회 이후 문구·사각 영역·브러시를 직접 편집하고 미리보기를 확인한 뒤 명시적으로 적용한다. 편집 진입만으로 OCR·번역·AI·저장을 실행하지 않는다. 성공한 이미지 저장이 외부 편집 잠금 중 새 상품 버전을 알리는 경우 조회가 건너뛰어져 옛 카드가 남던 오류를 수정했다. 잠금이 해제되면 최신 카드 조회를 재개하며, 동일 버전의 중복 조회와 미저장·응답 미확인 옵션 초안 덮어쓰기를 방지한다. 자르기·크기 변경까지 Couplus와 모두 같다는 검증은 이 범위에 포함하지 않는다.

현재 Chrome의 Couplus 기본설정을 읽기 전용으로 다시 확인했다. 기본 등록 정보·가격설정 방법·이미지 작업 설정·AI 설정, 상단·하단 이미지, 번역·카피라이트·누끼, 비노출 속성 설정을 대조했다. 해당 화면에는 통합통관 환율 290원이 표시됐다. 이는 그 계정 화면의 관찰값이며 본 앱의 자동 환율 공급 서비스가 검증된 것은 아니다. 계정 설정을 다른 계정으로 복사하거나 Couplus 설정을 저장하지 않았다. 근거는 Git 제외 `outputs/step642-couplus-settings.txt`와 `.jpg`에 보관했다.

최종 코드 검사 22개 서로 다른 파일의 282개 시험을 통과했다: 신규 초안 기본값·이미지 역할 21, 설명 번역 누락 76, 수동 이미지 편집·잠금 해제 후 조회 124, 기존 대기 원문 복구·별도 초안 61. 실패·취소·건너뜀은 0이다. 전체 TypeScript 오류 0, ESLint 오류 0과 기존 경고 8, 운영 빌드 성공을 확인했다. 배포 대상과 기존 확장 0.2.64·이전 공개 ZIP·18개 마이그레이션은 보존했다.

같은 Chrome에서 양사의 로컬 합성 상세사진을 직접 편집·미리보기·적용했다. 실제 React 컴포넌트·API·SQLite·PNG 저장으로 두 번째 상세사진만 교체되고 양쪽 사진·순서·수동 HTML·원본 R2 바이트와 메타데이터·다른 옵션이 보존됨을 확인했다. 저장 후 별도 수동 재조회 없이 카드에 새 파일이 표시됐다. 실상품은 접근하거나 수정하지 않았으며 외부 모델·Supplier Hub 호출은 0이다.

대기 원문 복구 검수는 실제 `IntakeQueuePanel`과 로컬 API·SQLite·기록된 공식 원본 2624/카테고리 69900을 사용한다. 와이홉 검수는 같은 기록 양식을 회사만 격리해 재사용한 계약 시험이며 새 와이홉 공식 파일을 캡처한 것은 아니다. 원문 URL·수집 시각·기존 요청/설정·원문 준비 시 최초 상품의 값을 보존한 뒤 현재 입력으로 별도 상품을 생성한다. 생성 후 SEO·이미지 다운로드는 이 네이티브 복구 시험에서만 비활성 fixture로 대체하며, 해당 단계의 성공을 주장하지 않는다.

양사 대기 원문 복구 화면에서도 새 상품 생성 후 공식 9~14행의 카테고리·상품명·브랜드·제조사가 7단계 미리보기와 일치했다. 원래 대기 요청·컨텍스트, 최초 준비 상품, 원문 URL 두 개와 수집 시각, R2 원본은 보존됐다. 같은 Chrome에서 확인한 상세사진·대기 원문 검수와 운영 배포 보존 조건 총 15개를 통과했다. 로컬 합성 화면의 스크린샷은 브라우저 캡처 제한 시간으로 확보하지 못했으며 DOM·API·SQLite·원본 셀 근거로 검수했다. 운영 화면은 실제 스크린샷을 저장하고 직접 열어 확인했다.

운영 Worker `sourceflow` 버전 `c2deda30-dff0-410f-858e-f029f10258d9`로 반영했다. 배포 전후 기존 상품 1행과 목록 입력 29개, 계정 기본설정 입력 35개, 복구 대기 입력 10개 및 대기 창 전체 문구가 동일했다. 설치된 확장 0.2.64와 실제 로드한 JS/CSS 파일도 확인했다. 확장 업데이트·회사 설정 저장·실상품 수정은 수행하지 않았다.
