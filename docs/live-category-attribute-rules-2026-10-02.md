# 실제 카테고리 고유 항목의 속성 연결 규칙 — 2026-10-02

## 수정한 누락

견적 화면은 수집 당시 실제 Hub 상세 양식으로 항목을 구성하지만, 속성 연결 규칙 저장 API와 다음 URL의 번역 반영은 기록된 정적 양식만 검사하고 있었다. 따라서 새 분류의 `live_<category>_<id>` 항목은 화면에서 선택할 수 있어도 서버에 규칙을 저장하지 못했다.

이제 규칙 조회/저장은 상품 식별값과 사용자가 직접 프로필을 선택한 경우에만 해당 프로필 식별값을 전달한다. 서버는 승인 회원 회사와 소유 상품/프로필을 확인하고, 상품에 연결된 수집 컨텍스트의 원문 양식으로 항목을 검증한다. 이후 프로필 양식이 변경되거나 프로필이 삭제돼도 수집 당시 양식을 사용하는 작업 상품은 유지된다. 수집 컨텍스트가 없는 이전 상품은 직접 선택한 소유 프로필을 사용할 수 있고, 제품 맥락 없이 호출하는 이전 API는 정적 항목만 허용한다. 호출자가 보내는 임의 양식/필드 목록은 채택하지 않는다.

규칙에는 정확한 원문 속성명·견적 항목 ID·전체 항목 서명만 저장한다. 상품 원문값·번역값·견적 수정값은 저장하지 않는다. 중복/형식/64KiB/50연결/현재 선택값 검사와 owner/category별 revision 충돌 검사를 유지한다. 회사/카테고리/프로필 불일치, 다른 소유자 상품, 변경된 항목 서명은 거절한다. 데이터 조회 실패는 503으로 반환하며 저장하지 않는다.

다음 URL의 속성 번역 반영도 같은 수집 당시 양식을 사용한다. 실제 필드에 정확히 맞는 텍스트/선택값만 연결하고, 이름이 비슷하다고 다른 고유 항목이나 상품고시로 이동하지 않는다. 직접 입력한 상품/옵션 값과 명시적 공란이 우선하며, 비노출 자동 생성이 꺼져 있으면 숨은 속성 규칙은 건너뛴다. 숫자/인증/임의 단위 변환 지원을 새로 추가한 것은 아니다.

## 지정 URL의 실제 수집 확인

이 PC에서 제품에 사용하는 `collectAlibabaMobileProduct`를 번들해 [사용자가 지정한 상품](https://detail.1688.com/offer/813724060928.html)의 현재 공개 응답을 읽었다. 파일이나 상품을 운영 DB에 저장하지 않았고, Chrome 탭/프로필/쿠키를 사용하지 않았다. 일반 공개 MTop 클라이언트의 일회성 익명 요청만 사용했으며 로그인/검증 화면을 우회하지 않았다.

- 모바일 상품 페이지: HTTP 200 `text/html;charset=utf-8`.
- 공개 SKU 요청 두 건: HTTP 200 `application/json;charset=UTF-8`.
- 상품 페이지가 참조한 상세 텍스트: HTTP 200 `text/plain; charset=UTF-8`.
- 원문 상품명 `太阳眼镜木纹腿男女复古墨镜高级感潮遮阳防紫外线太阳镜复古墨镜`, **6옵션·19이미지**로 파싱 성공.

이 결과는 지정 URL의 실제 읽기 전용 수집 성공이다. Cloudflare 운영 Worker/로그인 UI에서 단계1~7·운영 AI·이미지 저장을 수행하거나 Hub 최종 접수를 확인한 결과는 아니다. 다른 상품/전체 1688 상품의 접근 성공도 의미하지 않는다. 익명 응답의 임시 토큰/쿠키는 로그나 저장소에 보관하지 않는다. 근거 로그와 번들은 `outputs/step551-live1688*` 및 `outputs/step551-mobile-live-bundle.mjs`이며 Git 제외다.
