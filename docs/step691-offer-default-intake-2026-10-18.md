# Step691 — 옵션 구분 없는 상품의 기본 초안

2026-10-18 KST. 카테고리·회사 설정과 연결된 정상 상품 응답에서 `productSkuInfos: []`가 명시돼 있으면 상품 자체를 기본 옵션 한 개로 반영한다. 기존에는 이 응답도 옵션 누락 오류로 거절했다. 실제 제공되지 않은 공급자 SKU는 공란과 `unverified`로 유지하며, 상품 가격표의 원래 첫 행 가격·상품 MOQ·재고·이미지·설명을 사용한다.

쿠플러스의 실제 분기와 공개 REA 업데이트를 대조한 근거는 [기능 감사](step691-offer-default-parity-audit.md), [공개 스킬 확인](step691-open-source-skills-audit-2026-10-18.md)에 있다. 기존 REA 6.4 MCP를 유지하면서 격리된 공식 npm REA 6.5.0 CLI로 보관된 `processOptions` 한 파일을 새로 분석했다. 다른 11개 파일은 분석 범위 밖이다. 정적 분석을 실제 상품 수집·서버 실행 증거로 확대하지 않는다.

## 반영 계약

- 기존 OpenAPI 성공 envelope·offer ID·상품명·양수 MOQ·Alibaba HTTPS CDN·설명과 속성 크기 검증을 유지한다. `productSkuInfos` 누락·null·다른 자료형 또는 손상된 비어 있지 않은 배열은 기본 옵션으로 바꾸지 않는다.
- 원가는 `productSaleInfo.priceRangeList[0].price`의 유효한 양수만 사용한다. 가격표 정렬·다음 행·최저가격·headline·다른 SKU 가격으로 대체하지 않는다. 확인된 재고 0과 미확인 null을 구분하며 음수·소수·잘못된 값은 거절한다.
- `offerDefault`는 정확한 7개 필드의 `1688-openapi-offer-default-v1` 자료다. provider·offer·원래 SKU 개수0·원가 출처·원가·MOQ·재고를 원문 옵션 한 개에 결합한다. 기존 SKU별 가격 근거와 동시에 사용할 수 없다.
- 이 계약이 있을 때만 원문 옵션 SKU `''`를 허용한다. 옵션명은 원문 상품명, 이미지 번호는 첫 대표 이미지0이어야 하며 색상·크기를 추측하지 않는다. 일반 수집 결과의 빈 SKU는 계속 오류다.
- 상품 옵션의 내부 ID는 기존 결정적 `collected-1`이다. `offerId`나 시간 기반 값을 공급자 SKU로 만들어 넣지 않는다. 원문 상품명·원가·MOQ는 수집 사실, SKU와 번역명은 미확인으로 시작한다. 기존 canonical SEO가 만든 번역명·견적 제목과 수동 수정 규칙을 재사용한다.
- 기본 옵션의 대표 이미지는 선택된 공통 대표 이미지를 사용한다. 실제 SKU에만 적용하는 옵션별 이미지 자동 연결 조건은 완화하지 않았다. 이미지 저장 시 비어 있는 SKU를 ‘누락된 실제 SKU’로 집계하지 않아 허위 연결 경고가 반복되지 않는다.
- 현재 모바일 보완 계약은 실제 SKU가 있어야 하므로 이 원문에서 자동으로 다른 SKU 원문을 다시 가져오지 않는다. 선택적 설명·속성 누락은 그대로 표시하며, 새 공급자 identity를 추측하지 않는다.

원가 근거 화면에는 상품 가격표 첫 가격과 공급자 SKU가 제공되지 않았다는 사실을 표시한다. 상품·견적서에 가짜 원격 ID를 표시하지 않는다. 원문 수신 자체는 상품 생성 또는 Supplier Hub 등록 완료가 아니다.

## 실제 검수 경계

신규 합성 상품 `90000000691`과 두 회사의 독립 임시 SQLite·파일 저장소로 실제 원문 result POST, 상품 import, canonical SEO, 이미지 저장, 견적 조회·내보내기와 수동 수정 후 동일 원문 재처리를 검사한다. 인증·AI 응답·CDN 파일은 fixture다. 실제 1688·쿠플러스·Supplier Hub·운영 DB 또는 기존 작업 상품에 요청하지 않았다. 새 브라우저를 열거나 로그인 계정을 바꾸지 않았다.

원문 가격4.5 CNY, MOQ2, 재고0, 기본 옵션 한 개와 공통 대표·추가·상세 사진이 보존됐다. 관찰 가격 설정에서 공급가4580·판매가7630·MSRP9920, canonical SEO와 한글 표시사항·견적서 항목 연결을 확인한다. 수동 제목·옵션 번역명·재질·판매가·상세 HTML·추가 이미지 공란을 수정한 뒤 같은 원문 재처리가 그 값을 덮지 않고 추가 이미지 다운로드·AI 생성을 하지 않는지 검사한다.

독립 코드 검토에서는 기본 옵션명과 원문 상품명의 불일치 수신, 지원 불가능한 모바일 보완 자동 호출 두 문제를 재현했다. 정규화 시 이름 일치 조건과 기본 옵션 보완 금지를 추가한 뒤 두 재현이 차단됨을 확인했다. 최종 소스와 검토 범위는 `outputs/step691-independent-review.json`에 기록한다. 이 독립 단언은 릴리스 테스트 개수에 중복 합산하지 않는다.

## 최종 검수와 배포

관련 고유 **12개 테스트 파일153개**가 통과했다. 신규 기본 옵션 검사14개(모델·정규화·SSR10개, 실제 API4개), 기존 원문·가격·상품·이미지·보완 회귀101개/7파일, 확장 오프라인 검사38개/3파일이다. 신규 테스트 파일 목록에 포함된 공유 helper는 테스트 파일 수에 합산하지 않았다. 초기 기대값 조정이나 중복 재실행을 추가 통과 개수로 더하지 않았고, 저장소 전체 테스트를 실행했다는 뜻도 아니다.

두 회사의 전체 초안·수정·재처리 검수는 회사당 실제 API 핸들러34회, 총68회다. 각 회사에 상품1·원문1·사진3·canonical SEO1이 저장됐으며, 원문 재처리 후 DB·사진 바이트·생성/다운로드 횟수가 유지됐다. 별도 unknown stock/null·선택적 설명·속성 누락의 collect-only 검사는 모바일 보완 호출0·AI0을 확인했다. 위에 쓴 공급가·판매가·MSRP는 이 합성 원문과 검수 설정의 결과이며 모든 상품의 고정 가격이 아니다.

`outputs/step691-offer-default-{tests,regressions}.log`, `step691-offer-default-api-proof.json`, `step691-independent-review.json`, `step691-final-validation.json`에 실제 요청·소스 SHA·자료형·버전과 검사 범위를 보관했다. 두 회사의 격리 API 검수와 SSR 확인이며 이번에 실제 브라우저 화면 캡처를 수행한 것으로 표현하지 않는다. 최종 TypeScript·변경 파일 lint·44테이블/17인덱스/29모듈 스키마 메모리 검사·bounded Worker 빌드는 exit0이다.

최초 빌드는 변경된 공유 수집 validator와 기존 확장 번들의 불일치를 정확히 거절했다. 공유 모듈을 재생성하고 배포 확장을 **0.2.73**으로 올린 뒤 두 산출물 `--check`와 Worker 빌드가 통과했다. 실제 설치된 Chrome 확장은 바꾸지 않았다. 네 다운로드 링크는 버전·경로 문자열만 바꿨고 확장 권한·host permissions·검증 게이트는 유지했다. 기존0.2.72 ZIP도 그대로 보존했다. 새 ZIP52파일/704943bytes, SHA256 `9b12dc2d3a5bd71d412abb9b1f4074a84a6857ad91a5152f15aa4490e7bf70db`이며 달라진 ZIP 항목은 manifest와 공유 mobile bundle 두 개뿐이다.

기존 무료 Worker에 배포 완료했다. 주소는 <https://sourceflow.jjwwhhjj1116.workers.dev>, version `928d3f8d-6f99-4a8b-ae3e-28ccfd2ca564`, 배포 로그는 `outputs/step691-deploy.log`다. 새 DB migration·유료 자원·계정 또는 OAuth 범위 변경은 없다.

실제 공급자 응답 호환성·전체 SKU 수집·전 카테고리 공식 양식·Hub 동의와 최종 접수번호 대조는 별도 미완료 조건이다. 이번 추가는 검증된 OpenAPI 후보 응답의 명시적 빈 배열 경로이며, 공개 모바일 수집기가 SKU를 확인하지 못한 경우에 임의 기본 옵션을 만들지 않는다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 전송 gate는 유지한다.
