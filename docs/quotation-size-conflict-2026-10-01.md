# 옵션 사이즈 충돌을 공통 번역값으로 숨기지 않음

## 재현한 문제

헬스보호대 `81452`와 스포츠장갑 `81221`은 구매 옵션의 사이즈를 패션잡화 사이즈 선택값과 정확히 대조한다. `S`, `M`, `L`, `XL`, `Free Size`, `XXS`, `XS`, `XXL이상`은 연결하고, `Medium`, `Free`, 물리 치수는 임의 변환하지 않는 기존 동작이다.

그러나 옵션 사이즈가 선택지와 다를 때 반환한 공란을 일반적인 미입력으로 취급했다. 상품 공통 번역 속성에 `패션잡화 사이즈: M`이 있거나 이 값을 지정한 속성 연결 규칙이 있으면, 그 값이 개별 옵션의 공란을 대체하면서 선택지 불일치 오류까지 사라졌다. 서로 다른 SKU의 사이즈를 하나의 상품 공통값으로 잘못 연결할 수 있었다.

새 회귀 두 개는 수정 전 `M !== ''`로 실패했다. 81452와 81221 모두 같은 문제를 재현했다.

## 변경

자동값에 오류가 있으면 상품 공통 번역 속성이나 참조 기본값을 채우지 않는다. 오류 없이 값이 없는 항목은 기존 자동 연결을 유지한다. 실제 옵션값, 수동 공통값과 옵션별 견적서 수정의 우선순위도 유지한다.

잘못된 구매 사이즈는 노출 사이즈에 원문을 보존하고, 별도 패션잡화 선택 항목은 미선택 공란과 수정 오류를 유지한다. 이 공란은 `해당사항없음`을 선택한 것으로 표시하거나 내보내지 않는다. 사용자가 7단계에서 실제 확인한 선택값을 입력하면 그 값이 적용되며, 명시적으로 선택한 공란도 기존 방식대로 유지한다.

이번 변경은 선택지 목록이나 초기 기본값을 새로 정의하지 않는다. 기존 쿠플러스/Supplier Hub 관찰 항목과 기존 자동 사이즈 대조 결과를 공통 번역값이 덮어쓰지 못하게 한다.

## 검증

카테고리 견적서 검사 **184/184**를 통과했다. 추가 순수 회귀 4개는 다음을 확인한다.

- 두 카테고리의 잘못된 별칭·물리 치수를 공통 번역 제목이나 명시적 속성 연결값이 가리지 않는다.
- 화면에는 미선택 공란을 표시하고, 내보낸 `selectedEmptyChoices`에 잘못된 사이즈 공란을 넣지 않는다.
- 원래 옵션 문자열을 유지하고, 유효한 옵션 사이즈·직접 지운 옵션 사이즈·견적서 공통/옵션별 수정값을 보존한다.
- 조회와 내보내기는 입력 원본을 변경하지 않는다.

`tests/fashion-size-intake-linkage.test.mjs`는 두 회사와 두 카테고리 조합 4건에서 실제 앱 API·임시 SQLite·Excel 생성·전송 준비 컴포넌트를 연결한다.

1. 선택한 카테고리에서 기록된 1688 원문을 수집하고 옵션 6개 중 하나를 제외한다.
2. 옵션 하나에는 `Medium`, 다른 옵션에는 유효한 사이즈를 저장하고, 상품 공통 번역 `M`의 시험 상태를 저장한다. 이 공통 번역 상태는 합성 자료이며 실제 AI가 해당 결과를 반환했다는 뜻은 아니다.
3. 견적서 미리보기에서 해당 SKU의 패션잡화 사이즈 오류가 정확히 한 개 남고, 필요한 선택을 해도 등록전송 버튼이 활성화되지 않는다.
4. 사용자가 해당 옵션은 `L`, 다른 옵션은 명시적 공란으로 수정하면 오류가 해소된다. 원래 노출 사이즈·나머지 옵션과 제외 상태를 그대로 보존한다.
5. 재시도는 원문 재조회·AI 재실행 없이 저장한 수정값을 유지한다.
6. 실제 생성한 Excel 5행과 ZIP의 회사·카테고리, 실제 전송 준비 컴포넌트에서 로컬로 포착한 전송 데이터의 포함 옵션 수를 확인한다.

와이홉 `A01464742`, 유앤채 `A01526306` 각각 두 카테고리를 검사했다. 지정 선글라스 `813724060928`의 기록된 공개 원문을 사용하며 81452/81221은 관찰 폼 시험 계약이지 이 상품의 실제 판매 분류가 아니다. 인증·AI 응답·이미지 바이트·공통 번역 상태·Excel 양식·최종 전송은 격리된 시험 자료다. 실계정 Hub에는 등록하지 않았고 최종 상품 상태는 `미전송`이다. 최초 통합 시험은 필수 열이 누락된 합성 Excel을 전체 시험 열로 보정한 뒤 통과했다.

## 빌드·배포

추가 회귀 8개를 포함한 전체 테스트 **1,505/1,505**, TypeScript, 변경 파일 lint 오류/경고 **0**, Cloudflare 운영 빌드·산출물·diff 검사를 통과했다. 전체 저장소 lint나 전체 카테고리 대조 완료를 의미하지 않는다.

운영 앱 `https://sourceflow.jjwwhhjj1116.workers.dev`에 버전 `5b111aa0-6e2b-496a-8ad3-d45c10bcf363`을 배포했다. 앱 새로고침으로 적용된다. 확장 0.2.29는 변경하지 않았고 빌드 시 30개 파일/366,181바이트/SHA-256 `80a1d38d37bcd65b6b6d8e83e7c268d289b95320f00c91d0ae80147b21684444`를 확인했다. DB·비밀 설정·공개 이미지 Worker·유료 자원 변경은 없다.

앱·확장 ZIP·원문 수집 API의 익명 요청 3건은 기존 Cloudflare Access 호스트로 HTTP 302를 반환했다. 이 검사는 인증한 운영 앱·다운로드 바이트·Supplier Hub 접수 성공을 확인한 검사가 아니다. 기존 Chrome 바인딩의 탭 목록은 빈 목록이었다. 기존 창 목록에서 지정 우측 쿠플러스/Hub 창을 특정할 수 없어 입력하지 않았으며 새 창·프로필을 열거나 기존 작업 상품을 변경하지 않았다. 사이트 차단/로그아웃으로 해석하지 않는다.

## 남은 확인

실제 지정 Chrome의 URL→1~7단계 초안, 전체 카테고리 쿠플러스 기본값·공식 양식 대조, 운영 이미지 번역·법적 서류 첨부와 두 회사의 최종 견적 접수·SKU 확인은 남아 있다. 이번 수정으로 전체 시스템이 완성됐다고 보고하지 않는다.
