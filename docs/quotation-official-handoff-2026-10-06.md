# 공식 견적서·표시사항·포장 입력 연동 검수 — 2026-10-06

## 확인한 문제와 수정

실제 69900 카테고리의 노출 속성은 `color`·`size` 고정 ID 대신 Supplier Hub의 정확한 named wire ID를 사용한다. 견적서에는 옵션별 수정값이 저장됐지만 표시사항 PNG 계획에는 포함되지 않아, 색상을 수정해도 예전 PNG를 재사용할 수 있었다. 표시사항 계획과 HTML 검토 자료가 같은 필드 선택 함수를 사용하도록 바꿨다. 상품 정보의 노출 속성 경로에 있는 named 항목만 추가하며 비노출 속성과 가격은 포함하지 않는다. 직접 비운 값은 공란으로 유지한다.

공식 원본 XLSX에 대응 열이 없는 선택형 OSRP 자동값은 견적 전송 준비를 항상 막았다. 내보내는 실제 원본 바이트를 회사·카테고리 전체 경로·Single 원문 지문·Kan/Notice/version·시트·헤더·입력 시작 행과 다시 대조한 경우에만, 정확한 선택형 `productPage.commonAttributes.osrp`의 자동 가격값을 검토 항목으로 처리한다. 값은 JSON/CSV 검토 자료에 보존하고 MSRP 열에 대체 기록하지 않는다. 수동 금액·수동 공란·필수 항목·다른 경로·증거 누락이나 위조는 계속 오류다. 별도 Excel JSON 상세 양식을 검증한 것으로 표시하지 않는다.

포장 무게는 내부 숫자 항목과 공식 양식의 숫자 문자열 항목이 같은 물리값을 표현한다. 7단계에서 한쪽만 수정하면 다른 쪽 필수 누락이나 Excel 공란이 남는 문제를 확인했다. 정확한 `logisticsPage.skuUnitBoxWeight`와 내부 `packagedWeightG`가 각각 하나이고 공통 물류 항목·g 단위·숫자 문자열 조건이 모두 맞을 때만 입력을 연동한다. 옵션 수정값을 공통값보다 먼저 적용하며, 같은 층의 서로 다른 직접 입력은 각각 유지해 충돌 검사를 통과시키지 않는다. 직접 비운 값과 수정 해제를 구분한다. 저장된 원문이나 별도 override 행을 복사·변경하지 않고 서버 해석과 저장 전 편집 화면이 같은 함수를 사용한다. 연동값에는 실제로 존재하지 않는 수정 해제 버튼을 표시하지 않는다.

## 검증 자료의 범위

API·임시 SQLite 시험에서는 원문 6옵션, 양사 회사정보, 공식 파일과 옵션별 직접 수정값을 사용한다. 시험용 포장 치수·무게와 인증·첨부 데이터는 운영 상품에 입력하지 않는다. 표시사항 픽셀 시험의 Canvas 명령은 PNG로 렌더링하고 ZIP/XLSX의 실제 파일명·바이트를 대조하지만 실제 Chrome 글꼴 검수와 구분한다.

포장 입력은 저장 전 편집 화면 2사 및 원본 XLSX 2사의 네 가지 실패를 수정 전 재현했다. 수정 후 관련 277개 검사에서 공통→옵션 우선순위, 한쪽 공란, 같은 층 충돌, null 복원, 실제 XLSX 6행과 전송 준비의 무게 오류를 확인했다. 원문·옵션·가격정책·수집 컨텍스트와 기존 override ID는 유지됐다. 이 시험의 Google 429는 합성 응답이며 운영 무료 서비스 성공으로 보고하지 않는다.

공식 원본 handoff 회귀에서는 실제 원본·기록 Single을 임시 DB에 연결하고, 명시적인 전송 준비 UI에서 준비 1회·전송 1회와 회사 불일치 거절을 검사했다. 직렬화된 확장 첨부 함수가 Excel·상품 이미지·표시사항의 세 파일 영역에 정확히 전달하는 것도 확인했다. 실제 Supplier Hub 접수 서버를 호출한 시험은 아니다. 비공개 원본이 없는 CI에서도 합성 공식 파일 계약으로 OSRP 대응 열·필수값·Single 지문 위조 검사가 실행된다.

표시사항 회귀는 새 옵션별 노출값으로 6개의 PNG를 생성한 뒤 색상을 바꿨을 때 해당 옵션 1개만 추가 생성되는지 검사했다. 제외 옵션·수동 공란·이전 라벨을 유지하며, 최종 ZIP의 PNG 바이트와 XLSX 라벨 파일명을 대조했다. 관련 50개 검사와 OSRP 관련 99개 검사는 일부 범위가 겹치므로 전체 검사 수에 더해 합산하지 않는다. 독립 읽기 검토에서 세 수정의 추가 확정 결함은 없었다.

전체 검사 중 이전 무게 테스트 2개가 과거의 한쪽 공란 동작을 기대하던 점을 발견했다. 명시 공란은 정확한 두 무게 항목에 함께 반영되므로 연결 누락으로 오진하지 않고 필수 공란 오류를 유지하도록 기대값을 갱신했다. 같은 무게가 실제 Excel에 출력돼도 overrides CSV와 경고는 ‘미연결’로 표시하는 별도 진단 오류도 양사에서 수정 전 재현했다. 출력과 진단이 같은 보수적인 연결 판정을 사용하게 했으며 제외·비활성 옵션, 가려진 공통값, 값 불일치는 여전히 미연결이다. 관련 14개 검사와 독립 검토를 통과했다.

첫 전체 실행의 기본 병렬 실행에서는 새 공식 handoff UI 시험 2개가 5초 제한에 걸렸다. `npm test` 동시 파일 수를 4개로 제한한 재검사는 2,228개 중 2,227개 통과, 취소·건너뜀 0, 533.005초였으며 실제 원본을 다시 처리하는 UI 시험 1개의 5초 시간초과가 남았다. 앱·API 오류 대신 시험 helper의 독립 poll 제한에서 종료됨을 확인했다. helper 기본 5초는 유지하고 이 양사 원본 통합시험만 30초로 지정한 뒤, 기존 전송·접수 시험을 포함해 62/62를 재검사해 통과했다. 앱의 제한·검사·권한·실제 전송 동작은 변경하지 않았다. 중단한 첫 실행이나 시간초과가 있던 전체 실행을 단일 2,228/2,228 통과 실행으로 보고하지 않는다.
