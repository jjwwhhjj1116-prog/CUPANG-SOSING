# Step614 — 이미지 색상 브러시 편집

## 구현 결과

대표·추가·상세 이미지의 문구 편집 원본 위에 색상 브러시를 추가했다. 사용자가 브러시 모드를 켜고 지름과 색상을 선택하여 원본 위에서 그린다. 완료한 획 하나는 선택 가능한 레이어 하나이며, 선택 해제·색상 변경·앞뒤 이동·삭제·되돌리기·다시 실행이 가능하다. 경로·지름에서 계산한 사각형과 문구·글꼴을 직접 변경하여 브러시의 범위를 우회하지 못하도록 해당 입력을 비활성화한다.

실제 Canvas 출력은 둥근 끝과 연결을 가진 선 또는 한 점의 원이다. 경로의 바깥을 사각형으로 채우지 않는다. 현재 레이어 배열 순서로 그려 글자·사각형 지우기·브러시 사이의 앞뒤 순서를 PNG에 반영한다. 이 기능은 선택 색상으로 덮어쓰는 브러시이며 AI 배경 복원이나 자동 물체 제거로 설명하지 않는다. 사용자가 최종 미리보기를 검토한 후에만 저장한다.

## 포인터·보존 조건

- 원본 이미지와 SVG를 같은 비율의 사각형으로 표시한다. 표시 좌표를 원본의 정수 픽셀로 변환하고 가장자리에서 제한한다. 투명한 전체 SVG 사각형으로 아무 획이 없는 부분에서도 그릴 수 있다.
- 주 포인터와 왼쪽 버튼에서만 시작하며, pointer capture로 움직임을 수집한다. pointerup에서 한 번만 완료한다. 이동 중에는 임시 표시만 바뀌고 저장 영역·편집 기록·서버 PNG를 변경하지 않는다.
- 포인터 취소·capture 상실·버튼 해제·화면 스크롤 또는 크기 변화·원본/옵션/역할/버전/편집 세대 변화·화면 닫힘은 미완성 획을 취소한다. 과거 콜백과 같은 포인터 ID의 새 획을 혼동하지 않는다.
- 그리는 동안 번역·미리보기·저장·옵션 선택·영역 수정·되돌리기·원본 선택을 잠근다. 초안 지우기와 대상 변경에서는 미완성 획이 취소되고, 늦게 도착한 완료 이벤트를 적용하지 않는다.
- 지름 1–200 원본 px, 획당 최대 2,048점, 저장 영역 전체 최대 8,192점, 전체 영역 100개를 제한한다. 점 수를 초과한 미완성 획을 잘라서 저장하지 않는다. 완료한 경로는 연속한 동일 점만 제거하고 다른 순서·재방문은 유지한다.
- 이미지는 변당 최대 16,000 px와 총 1,200만 픽셀을 제한한다. 모든 점은 원본 내부의 정수여야 한다. 반지름을 포함하여 계산하고 원본으로 자른 경계와 전달된 사각형이 정확히 일치해야 렌더링한다.
- 브러시 경로는 되돌리기 기록에서 깊게 복사하고 같은 값의 경로는 구조적으로 비교한다. 원본 파일·상품 버전·원본 증명·최종 견적서 연결 증명·옵션 선택·응답 미확인 PNG는 기록에 포함하지 않는다. 이 값들을 되돌리거나 바꿔 실패한 저장을 재시도하지 않는다.
- 글꼴을 불러오기 전에 선택 영역의 ID·색상·문구·모드·크기·사각형을 복사하고, 검증한 브러시 경로를 별도로 복사한다. 대기 중 호출자가 원래 객체를 변경하여 검토된 획을 사각형 지우기로 바꾸거나 이미지 전체를 덮어쓰지 못하도록 한다. 수정 전 전체 이미지가 덮이는 실패와 수정 후 경로·색상·문구·영역 밖 픽셀 보존을 회귀 테스트로 확인했다.

## 검증

편집·이미지 회귀 **172/172**, 견적서·전송 회귀 **118/118**, 합계 **290/290** 통과했다. 실패·건너뛰기·취소는 0이다. TypeScript 오류 0, ESLint 오류 0과 기존 경고 8을 확인했다. 검사 로그는 `outputs/step614-*-tests.log`, `step614-types.log`, `step614-lint.log`, `step614-build.log`에 보관한다.

모델 테스트는 크기·좌표·형태·중복점·경계·총량을 검사한다. 실제 컴포넌트 회귀는 표시 축척·가장자리·pointer capture·합쳐진 움직임 이벤트·취소·미완성 획·오래된 콜백·화면 닫힘·한 번의 기록·기존 저장 보호를 검사한다. 렌더러 회귀는 원·선·선택 해제·레이어 순서·클리핑·영역 밖 픽셀과 원본 보존, 잘못된 입력의 Canvas 생성 전 거절을 검사한다. 히스토리는 경로 복사·복구·같은 값의 다시 실행 보존을 검사한다.

API 테스트는 실제 경로와 SQLite/R2를 거쳐 원형 PNG의 저장 응답 유실 후 동일 PNG·증명 재시도, 최종 owned 이미지 SHA, 다른 역할과 원본 파일 보존, 견적서의 직접 입력한 대표·추가·상세·HTML·공란 보존을 검사한다. 이 테스트의 Canvas는 모의 구현이며 실제 브라우저 래스터 검사와 구분한다.

별도로 기존 Chrome 검수 탭에서 실제 React 컴포넌트와 실제 Canvas로 합성 이미지 PNG **10개**를 확인했다. 첫 6개는 브러시·글자 겹침 순서와 삭제·복구, 다음 3개는 실제 클릭으로 원형 획 생성·되돌리기·다시 실행, 마지막 1개는 모든 기존 영역을 지운 뒤 빈 원본 위 클릭이다. 경로 픽셀은 민트·주황·흰색으로 지정 순서대로 변했고, 경로 바깥 모서리와 원본·영역 밖 픽셀을 보존했다. 외부 수집·번역·실상품 저장은 사용하지 않았다. 기록은 `step614-native-render-result.json`, `step614-native-dot-result.json`, `step614-native-blank-result.json`이다.

검수용 로컬 서버는 종료하고 검수 탭을 운영 앱으로 복원한다. 기존 사용자 탭은 새로고침하거나 입력하지 않고, 그 탭의 63개 비밀번호 제외 입력과 상품 행 및 검수 앱의 29개 입력과 행을 배포 전후 대조한다. 이번에 다른 브라우저 세션이 사용 중인 Couplus 탭은 제어하지 않았다. 신규 확장·마이그레이션·계정·결제 변경은 없다.

## 미완료 범위

색상 브러시와 편집 PNG 연결이 이번 완료 범위다. Couplus 전체 카테고리의 실사이트 기본값 대조와 새로운 1688 상품의 1–7단계 초안·수동 검토·실제 Supplier Hub 접수·SKU 확인까지 이어지는 전체 경로는 검증 완료로 간주하지 않는다. 기존 중국어 원문 초안의 `SEO 입력됨`은 입력 존재 표시이며 번역 완료의 증거가 아니다. 핵심 경로 읽기 검수에서는 새 확정 결함을 발견하지 못했고, 신규 실제 경로의 증거 연결이 다음 우선순위다.
