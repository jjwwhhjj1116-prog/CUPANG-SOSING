# 견적 라벨 생성 중단·재개와 저장본 연결 (2026-10-01)

7단계에서 옵션 라벨을 일괄 생성하다 중단하면 완료된 옵션은 서버에 저장되지만, 기존 패널은 중단 결과를 상위 편집기에 전달하지 않았다. 편집 화면이 이전 revision/fingerprint를 유지해 다음 수정 저장이 충돌할 수 있었다. 단순히 저장본을 전달하면 패널의 기존 key에 따라 재마운트되면서 업로드 기록이 사라져, 재개 시 완료된 PNG를 다시 만들 수도 있었다.

실제 패널 코드로 실행한 수정 전 회귀에서 저장 결과 callback `0 !== 1`, 재마운트 후 업로드 키 `undefined !== saved.png`를 확인했다. 기존 단일 함수의 중단·재개 시험은 동일 Map을 직접 재사용해 부모/자식의 이 경로를 검사하지 않았다.

## 변경

- 정상 중단에도 완료된 옵션이 있으면 확인된 최신 저장본과 완료/전체 건수를 편집기에 전달한다. 완료 0건의 중단은 저장 완료로 알리지 않는다. 상위 화면은 중단된 작업임을 표시한다.
- 업로드 Map과 생성 계획의 signature를 견적 편집 폼의 ref에 둔다. 이미지 저장·일반 견적 수정에 따른 패널 재마운트와 같은 폼 내 옵션 전환에서 유지한다. React 렌더에서 ref 값을 읽거나 props를 수정하지 않고 이벤트 처리 중에만 ref를 사용한다.
- signature에는 상품, endpoint, 카테고리 context, 포함 옵션 ID와 실제 PNG 계획을 모두 사용한다. 같은 계획의 완료 파일을 재사용하고, 품명·모델·법적 표시값·카테고리·포함 옵션 등이 달라지면 이전 PNG를 재사용하지 않는다. 가격처럼 PNG에 표시하지 않는 값의 수정은 재개를 막지 않는다.
- 부모와 자식의 기존 key 및 미리보기 무효화는 유지한다. 기존 라벨을 삭제하거나 다른 옵션으로 바꾸지 않는다. 캐시는 해당 폼 세션의 메모리이며 전체 페이지 재접속에 대한 영구 복구 기능은 아니다. 일반 실패의 저장본 갱신이나 모든 운영 오류 복구를 완료했다는 주장도 아니다.
