# 상세 작업공간 파일 검증 병렬화 — 2026-11-04

## 확인한 지연

파일 36개가 있는 새 양말 작업공간에서 사진 원본 조회 한 번에 전체 파일 검증이 반복됐다. 이전 구현을 고정한 실제 처리기·로컬 SQLite/R2 재현에서 작업공간 GET은 R2 GET 36회, 사진 메타데이터 GET은 146회, 새 Vision POST는 366회였고 동시 읽기는 한 개였다. 이 재현은 외부 모델을 호출하지 않는다. 고정 재현은 `outputs/step936-workspace-proof-amplification.mjs`와 그 로그에 보관한다.

운영의 같은 양말·연회색 옵션·같은 BODY 사진 메타데이터 GET은 수정 전에 200 응답까지 29,505ms가 걸렸다. 이는 원본 조회 자체의 한 번 측정이며 이미지 파일 다운로드·모델 실행·전체 상품 소싱 시간을 뜻하지 않는다.

## 변경과 보존한 조건

공통 `fileProofs`만 두 파일씩 읽도록 바꿨다. 기존 전체 검증 횟수를 줄이거나 결과를 캐시하지 않는다. 소유권, 원본/현재 파일 중복 제거·순서, 실제 byte 수·SHA·파일 형식·크기, 파일당 10MiB 및 합계 30MiB 조건을 그대로 검사한다.

각 두 파일의 선언 크기를 먼저 합산한 뒤 본문 읽기를 시작한다. 현재 두 읽기가 모두 끝나야 다음 두 파일을 시작하며 오류도 원래 키 순서로 결정한다. 본문 읽기 전 실패·중단이면 이미 받은 미사용 본문을 취소하고 정리가 끝날 때까지 기다린다.

두 개의 10MiB 파일과 스트림 병합/해시 복사를 고려한 애플리케이션 버퍼 작업량은 약 40MiB다. R2·해시 구현 내부의 메모리와 GC 시점은 이 계산에 포함되지 않는다. 최종 결과에는 파일 bytes 대신 작은 검증 정보만 보관한다.

## 검증 범위

동시성·정확한 30MiB 경계·스트림 초과·오류 순서·중단/취소를 다루는 새 검사 7개와 기존 작업공간·배너 재설정·첨부·이미지 편집·최종 저장 검사 59개를 통과했다. TypeScript와 diff 검사도 통과했다. 운영에서의 실제 조회 시간 비교는 별도로 기록하며, 이 변경만으로 전체 번역이나 신규 Supplier Hub 접수가 끝났다고 보고하지 않는다.

새 양말은 소재·필수 사이즈표·상품별 제출 서류 해당 여부 확인이 남아 있다. 원래 미응답 Vision 기록과 이미 접수된 문서 2347603은 변경하지 않는다.

## 운영 배포 후 한 쌍의 측정

Worker `8f2a7adc-c45c-406c-bba5-73fa2dec5842` 배포 뒤 같은 사진 원본 조회는 200, 25,015ms였다. 수정 전 29,505ms와 비교해 4,490ms 짧았으며 응답의 원본 식별 정보 전체가 동일했다. 파일 검증이 사라지거나 다른 원본으로 바뀐 결과가 아니다. 각각 한 번의 운영 관측이므로 전체 번역 성능이나 일정한 개선율을 보장하지 않는다. 아직 조회 자체가 느리며 반복되는 전체 파일 검증 횟수는 그대로 남아 있다.

실제 BODY 일괄 준비는 첫 사진의 미접수 기록을 보존하고 다음 사진으로 진행했다. 한 장의 원본 보존 결과를 확인했고, 다른 사진들의 영역/한국어 검증 실패와 실제 Vision 시간 초과가 남았다. 시간 초과 요청은 원래 결과의 읽기 조회로만 복구했으며, 결과를 새로 요청하거나 최종 상세 사진/견적서를 덮어쓰지 않았다. 이 상태는 전체 35장 번역 완료가 아니다.
