## 저장 동작

- 기존 합치기 미리보기와 선택 옵션만 적용하는 기능을 유지하고, 미리보기 아래에 `상세 저장`을 추가했다. 검토 체크에는 공통 항목, 모든 저장 옵션, 견적 제외 옵션 포함, HTML 비우기를 명시한다. 미리보기 준비만으로 업로드하거나 저장하지 않는다.
- 공통 계층과 실제 저장된 모든 옵션 UUID에 정확한 상세 이미지·HTML 필드를 적용한다. 이름이 비슷한 필드를 추정하지 않고 기존 canonical/exact-primary 연결을 사용한다. 다른 SEO·가격·라벨·대체 텍스트·포장 필드와 원본 상품 내용은 유지한다.
- 새 API `/api/products/:id/detail-save`는 저장된 원본 이미지 바이트·크기·순서, 선택 옵션, 카테고리와 입력 지문으로 미리보기의 결정적 업로드 번호를 다시 계산한다. 저장한 PNG의 소유자·형식·해시·크기·800px 너비를 확인하며 임의 URL을 읽지 않는다.
- 이미지 풀의 새 파일 연결, 공통·전체 옵션 수정, 수정 전 수동 값과 저장 영수증을 같은 D1 트랜잭션으로 반영한다. 상품 동반 갱신이 실패하거나 무시되면 CHECK 검증으로 전체 작업을 되돌린다. 다른 카테고리의 수동 값도 보존한다.
- 백업은 기존 견적 payload에 카테고리별로 추가한다. 이전 수동 값의 부재는 `null`, 직접 저장한 공란은 `''`로 구분한다. 기존 백업을 자동 삭제하지 않으며 카테고리별 5개 또는 전체 payload 512KiB를 넘으면 변경하지 않고 거절한다. 전체 저장 상태는 기존 자료 다운로드의 `quotation-saved-scopes.json`에도 포함된다. 별도 자동 복원 UI는 추가하지 않았다.
- 같은 의도의 POST 반복은 현재 저장 상태·영수증·파일이 정확히 일치할 때 기존 결과를 반환한다. 응답 유실 복구는 GET만 수행하며, 다른 편집·회사·분류·옵션 변경이 있으면 성공으로 채택하거나 다시 쓰지 않는다.
- 클라이언트는 시도 자료를 상품·옵션·분류·미리보기·원본 지문에 묶는다. 저장 응답의 전체 수정값, 모든 행의 값과 수동 출처, 그 밖의 필드 보존, 백업 전후 revision과 최종 조회까지 확인한다. 숨겨진 단계에서 끝난 저장은 명시적인 결과 확인을 거친다. 두 저장 방식은 같은 미리보기에서 혼용하지 않는다.
