# 판매량 조회·상품 수집 통합 2.1.0

## 구현

- 사용자가 개발한 판매량 조회 2.0.5의 자체 모듈을 기존 상품 수집·견적서 확장에 통합했다. RS 코드나 자격증명은 포함하지 않는다. 판매량 계산·캐시·Wing 요청 모듈은 원래 동작을 유지한다.
- 단일 MV3 worker가 `YF_SALES_*`와 `YOOFAM_*` 메시지를 각각 구분한다. 쿠팡에서는 판매량 UI, 1688 상품 본문에서는 직접 클릭하는 수집 버튼, 자체 앱에서는 회원별 저장 bridge가 실행된다.
- 권한은 기존 두 확장의 합집합이다. Wing 쿠키는 Wing 조회에만 쓰고, 현재 상품 본문 수집과 자체 서버 저장에는 쿠키를 전달하지 않는다. nativeMessaging·유료 API·추가 서버는 도입하지 않았다.
- 수집한 페이지는 회사별 원문 보관소에 저장되고, AI상품등록의 같은 14열 표에 자동 표시된다. 별도 상품을 임의의 가격으로 생성하지 않는다. 원가·공급가·판매가가 없는 수집 행은 가격이 미정이며 일괄 전송 대상에서 제외한다.
- 저장 확인 이벤트, 탭 복귀, 회원별 목록 갱신으로 수집 행을 반영한다. 앱 시작 시 같은 회원·회사의 확장 보관본을 전달한다. 계정 변경과 취소 이후의 늦은 응답은 이전 회원의 행을 게시하지 못한다.
- 수집 행의 SEO·단계 버튼에서 카테고리 선택으로 진입한다. 옵션 버튼은 원문 검토를 연다. 카테고리 선택 뒤 수집정보를 확인·수정할 수 있고, 필수 원문이 준비된 뒤 저장 원문으로 기존 초안 작성과 1~7단계 편집에 연결한다.
- 기존 작업 상품과 같은 URL의 수집 행은 중복 표시하지 않는다. 수집 행 삭제는 수집함 soft archive에만 연결하며 기존 상품 편집·삭제 API를 호출하지 않는다.

## 검증

- 관련 자동검사 302개 통과: 판매량 조회 회귀 검사, 출처·회원·회사 확인, 저장 ACK 유실과 재시도, 중복 보존, 수집 행 표시·카테고리·검토 연결, 가격 편집·단계 이동, 실제 API와 SQLite를 이용한 새 초안 생성, 양사 카테고리별 견적서 연결, 전송 worker 라우팅과 결과 보존.
- 수집 버튼 검사는 배포하는 `page-collector.js`를 합성 DOM에서 실행한다. 상품 초안 검사는 자체 API·SQLite와 합성 원문을 사용한다. 이 검사를 실상품 접수로 표현하지 않는다.
- 확장 모듈 그래프·파일 이름·아이콘·권한 합집합·ZIP 원본 일치 검사 통과. TypeScript, 변경 파일 lint, 운영 빌드 통과.
- 이전 대시보드로도 동일하게 실패하던 기존 견적서 이동 검사 3개는 이미 구현돼 있는 “수집 당시 카테고리는 queryless 상품 컨텍스트로 조회” 계약에 맞춰 수정했다. 생산 코드의 카테고리 선택 정책은 바꾸지 않았다.

## 확인되지 않은 범위

- 이 검수에서 실상품 1688 수집과 Supplier Hub 실제 접수는 실행·확인하지 않았다. 지정됐던 상품 주소는 앞선 브라우저 안전 게이트 거절 대상이므로 앱·확장·서버를 통해 우회 조회하지 않았다.
- 현재 회원의 운영 수집함은 0건이다. 새 실상품의 수집 저장, 필수 원문과 포장정보 검토, 전송 결과의 실제 접수 ID 확인이 남아 있다.
- 개별·전체 상품 문서 전송의 `SINGLE_DOCUMENT_LIVE_VERIFIED` / `PRODUCT_DOCUMENT_LIVE_VERIFIED`는 계속 false다. 이 배포는 해당 검증을 대체하거나 실제 접수를 보증하지 않는다. 기존 파일 첨부·검증·접수 조회 경로의 보호 규칙은 유지했다.
