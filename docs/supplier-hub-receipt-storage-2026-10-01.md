# Supplier Hub 전송 결과 보관과 복원

2026-10-01, 단계 537.

## 수정한 문제

Supplier Hub 파일 검증 및 옵션별 SKU 조회 결과가 Chrome 확장에만 남아 있었다. 상품 목록에는 결과가 표시되지 않았고, 화면 재접속의 복구도 확장 저장본에 의존했다.

이제 회원별 전송 결과를 D1에 보관하고 상품 목록에 견적서 ID, 회사, 옵션별 SKU 확인 수, 반려 여부와 조회 시각을 표시한다. 기존 편집 초안의 진행 상태와 별도로 `최근 전송한 견적서 기준`임을 표시한다. 같은 검토 파일을 다시 열면 서버 보관본을 복원하고 중복 파일 전송을 차단한다.

## 보관 계약과 초안 보호

- `supplier_hub_receipts`의 키는 회원 소유자·상품·견적서 fingerprint다. `owner_id`, `product_id`, `fingerprint`, `observed_at`, `evidence_order`, `payload` 여섯 열을 사용한다.
- 결과 API GET/POST는 운영 인증과 상품 소유자를 확인한다. POST는 실제 저장된 카테고리 양식, 회사, 포함 옵션 수와 견적서 fingerprint를 다시 계산한다. 임의 회사·다른 옵션 수·다른 견적서 ID·최종 승인 주장·중복 SKU는 거절한다.
- SQL 저장 시 상품 수정 버전, 이미지 키, 가격 정책, 콘텐츠/옵션 버전, 계정 기본설정, 카테고리 프로필과 수집 스냅샷, 견적서 revision을 함께 대조한다. 결과 저장은 기존 상품·가격·초안 버전이나 XLSX fingerprint를 바꾸지 않는다.
- 새 조회 시각을 우선하고 같은 시각에는 더 강한 결과를 유지한다. 이미 알려진 견적서 ID가 달라지면 덮어쓰지 않는다. 파일 검증만 다시 조회한 결과가 기존 옵션별 SKU/반려 결과를 지우지 못한다. 캐시된 SKU 결과는 자체 조회 시각을 유지한다.
- `파일 검증 중`, `견적서 접수`, `SKU ID 확인`, `파일 반려`, `상품 반려`를 구분한다. 포함된 모든 옵션의 고유하고 생략되지 않은 SKU ID가 있어야 `SKU ID 확인`으로 표시한다. 추가 페이지가 남은 결과는 완료로 간주하지 않는다.
- 보관 증거는 `chrome-observation`이며 `registered:false`다. 브라우저에서 관찰한 접수/조회 결과를 서버의 독립적인 최종 승인 증명으로 표현하지 않는다.
- 서버 결과 저장이 일시 실패해도 Chrome 결과와 중복 전송 보호를 유지하며 SKU 조회를 계속한다. 저장 오류는 별도로 표시하고 이후 성공하면 해제한다. 읽을 수 없는 저장 결과는 상품 목록을 중단시키지 않는다.

## 검증

두 회사 A01464742·와이홉 및 A01526306·유앤채에 대해 실제 React 패널, API 요청 처리, 임시 SQLite와 원자적 저장 조건을 사용했다. 기록된 813724060928 원문에서 여섯 옵션 초안과 수동 수정, 검토 파일, 전송 경계, 결과 보관, 상품 목록/상세 요약, 재마운트 복원과 중복 전송 차단을 검사했다. 상품/초안/가격의 저장 버전과 기존 견적서 fingerprint가 바뀌지 않는 것도 확인했다.

오래된 조회, 같은 시각의 부분 결과, 반려 결과 보존, 다른 견적서 ID, 수동 초안 수정 경쟁, 다른 회원, 인증 이전 본문/DB 접근, 잘못된 저장본, 결과 저장 503 후 조회 지속을 검증했다. 인증·AI·이미지·공식 Excel 양식·최종 Hub 전달은 시험 자료다. 80719는 관찰한 폼의 시험 계약이며 지정 선글라스의 실제 판매 분류로 주장하지 않는다. 운영 상품이나 실제 Hub 견적서는 이 시험에서 수정하지 않았다.

- 전체 검사: 1,639/1,639 통과(182.960초, 이전 단계보다 9개 추가).
- 마지막 결과 정규화와 오류 표시 분리 이후 관련 검사: 48/48 통과(19.512초).
- TypeScript, 변경 파일 ESLint, Cloudflare 운영 빌드와 확장 산출물 검사 통과. 저장소 전체 lint 통과로 일반화하지 않는다.
- DB 계약: 24개 테이블, 13개 인덱스, 16개 런타임 DDL 모듈. 기존 레코드 보존과 스키마 재적용 검사 통과.

로컬 검증 기록은 `outputs/step537-*`이며 Git에서 제외한다.

## 아직 실제로 확인하지 못한 범위

단계 시작의 기존 Chrome 바인딩 탭 목록은 빈 목록이었다. 이를 사이트 차단이나 로그아웃으로 판단하지 않았고 새 Chrome/프로필을 만들거나 다른 창의 개인 자료를 읽거나 기존 Couplus 작업 상품을 수정하지 않았다. 추가 승인/로그인 요청도 하지 않았다.

모든 실제 카테고리의 Couplus 기본값과 Supplier Hub 공식 양식 대조, 지정 Chrome에서의 실제 1688 신규 수집과 운영 이미지 번역/서류 처리, 두 회사의 실제 최종 Hub 접수 및 SKU 확인은 남아 있다. 이 단계의 시험 통과나 배포를 전체 완벽 구현 완료 또는 근거 없는 완성률로 표현하지 않는다.
