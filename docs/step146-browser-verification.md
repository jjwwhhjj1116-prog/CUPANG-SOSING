# 수집 결과 편집 이동·옵션 이미지 견적 반영 검증

검증일: 2026-09-24. 기준 커밋: b71dc99. 실제 Chrome UI와 로컬 개발 서버를 사용했다. 모의 훅 테스트 결과와 구분한다.

## 환경

- 최초 localhost:3000 접속은 ERR_CONNECTION_REFUSED였다. 개발 서버를 실행한 뒤 접속했다.
- 연결된 Chrome의 최초 탭 목록은 비어 있었다. 새 탭을 생성해 검증했다. 이 결과로 Couplus/Supplier Hub 로그인 여부를 판단하지 않는다.
- 로컬 데모 계정의 기존 LOCAL TEST 상품만 사용했다. 운영 Cloudflare 데이터는 수정하지 않았다.

## 확인한 절차와 결과

1. `[LOCAL TEST] XLSX·옵션·첨부 통합 검증 — 실상품 아님`을 열었다. 상품 ID는 `e84e6250-5db0-4b64-a832-4d7308cbc8d0`이다.
2. 옵션·사이즈표에서 옵션 1의 이미지를 업로드 이미지 1에서 2로 바꾸고 옵션 저장·가격 계산을 눌렀다. 저장 버전은 3에서 4로 증가했고 저장 완료 메시지가 표시됐다.
3. 7 견적서 → 대표 이미지 구역 열기를 눌렀다. 편집 대상은 로컬 검증 옵션이며 대표 이미지 출처는 저장 옵션이었다. 값은 `local-demo/40308f30-7fc0-4b05-a77b-dc20b090868b-LOCAL-TEST-guarded-image.png`였다. 이미지 2가 선택됐고 견적 수동 수정은 0개였다.
4. 옵션 이미지 선택을 업로드 이미지 1로 복원하고 저장했다. 같은 견적 구역에서 `local-demo/525d8d20-d106-4a30-a2a4-a78bab26a81b-LOCAL-TEST-pixel.png`와 이미지 1 선택을 확인했다. 별도 견적 저장 없이 옵션 저장값을 다시 반영했다. 저장 이력·리비전 증가는 되돌리지 않았다.
5. 작업 공간을 닫고 상품 대기열 → 수집 원문 확인 → 옵션 이미지 편집을 눌렀다. `[LOCAL TEST] 수집 원문 상품 반영 검증`의 옵션·사이즈표가 열렸고 TEST-A/TEST-B 두 옵션을 확인했다.
6. 닫은 뒤 같은 수집 요청의 이미지 배치 편집을 눌렀다. 동일한 상품의 3/7 대표 이미지 화면이 열렸다. 이 상품은 저장된 이미지가 0장으로 표시됐다. 파일 수집이나 업로드를 수행하지 않았다.

## 범위와 남은 작업

- 확인: 실제 로컬 브라우저에서 저장 옵션 이미지의 견적 반영·복원, 수집 결과와 대상 상품 편집 화면 연결.
- 추정하지 않음: 로컬 결과만으로 운영 배포 환경이나 외부 서비스의 정상 작동을 판단하지 않는다.
- 미확인: Couplus 전체 카테고리 기본값, 공식 Supplier Hub Excel 대조, 실제 1688 수집, 유료 이미지 번역, Hub 접수. 해당 기능의 완료 증거가 아니다.
- 새 소스 변경 없음. 기존 563개 테스트를 이번 검증으로 다시 실행한 것으로 보고하지 않는다. 브라우저 동작 회귀 검증이며 이미지 픽셀 품질 검사는 아니다.
- 다음 우선 작업: 실제 Couplus/Hub 접근 상태와 공식 카테고리·양식 자료 확보를 확인하고, 기존 수집 공급원 미연결 및 Hub POST 501 경로를 실제 연결 계약에 맞춰 구현한다. 기존 BrowserUse 정책 차단을 우회하지 않는다.
