## 실제 화면 코드에서 확인되는 순서

1. 카테고리 선택/하위 목록 요청은 `GET_CATEGORY_INFO` 메시지에 회사코드와 분류코드를 전달한다. 검색 결과의 `internalCategoryCode` 또는 트리 결과의 `displayItemCategoryCode`와 분류 경로를 유지한다.
2. 상품 초안 요청은 이미 수집한 원문·번역 상품명, 키워드, 특징, 선택 분류, 회사코드를 `GET_PRODUCT_INFO`에 넣는다. 응답의 `rocketRegInfo.schemaString`과 `createResult`가 견적서 구조를 결정한다. 표시 분류코드와 내부 `kanCategoryId`는 별도 값이다.
3. `initializeCoupangDoc`/`extractAndApplySchema`는 선택 분류의 필수 페이지와 필드, 명명된 배열 항목을 만든다. 옵션마다 같은 분류 구조를 사용하고 기존 옵션 문서가 있으면 병합한다.
4. `createCompleteArrayStructure`는 이름이 열거된 배열 항목을 순서대로 만들며, 비노출 속성의 초기 값은 null, 그 밖의 이름 있는 배열 값은 해당사항없음이다. 화면의 저장 처리도 비노출 속성의 빈 값/해당사항없음을 null로 정규화한다.
5. `applyDefaultSettings`는 브랜드·제조사·거래타입·수입여부, A/S 연락처, 박스 수량·소비기간·취급주의와 배너 설정을 적용한다. 이 설정 적용과 사용자 수정은 양식의 초기 기본값과 구분된다.

단일 문자열의 선택지/숫자/불리언 초기화 규칙도 공개 코드에 있지만, 각 카테고리의 실제 `schemaString`에서 필수 여부·선택지를 확보하지 않은 공통 인증/물류/이미지 항목에 이를 무차별 적용하지 않았다. 공개 프런트엔드 분석은 쿠플러스의 비공개 상품 수집 서버 구현이나 실제 로그인 응답을 확인한 것과 다르다.

## 이번 변경

- 이전에는 80719만 초안의 해당사항없음 기본값을 지원했다. 기존에 기록한 Supplier Hub 제품 필드/선택지/상품고시 및 쿠플러스 분류 양식에 위 배열 초기화 규칙을 적용했다. 범위는 기록된 주방수납 22개와 80719·81452·64497·103495·77442·81221, 합계 28개다. 새 카테고리코드를 추측하거나 전체 목록 검증 상태를 바꾸지 않았다.
- 비노출 속성의 null 초기값은 로컬 문자열 모델의 빈 값으로 표현한다. 선택형은 실제 빈 선택지인 해당사항없음으로 표시한다. 텍스트형은 해당사항없음 placeholder를 표시하며, 견적서 데이터/Excel 연결에는 빈 값을 사용한다. null/해당사항없음이라는 문자 자체를 비노출 기본값으로 내보내지 않는다.
- 원문에서 확인한 옵션/콘텐츠, 번역하여 연결한 분류 속성, 기본설정 및 견적서 공통/옵션 수정값이 우선한다. 직접 비운 값과 유효하지 않아 수정이 필요한 입력도 기본값으로 덮지 않는다. 자동 기본값은 `couplus-default` 출처와 상품 확인 필요 상태를 유지한다.
- 카테고리 선택 미리보기, 입력 화면 및 자동값/수정값 비교에서 같은 기본값 표시를 사용한다. 사용자가 텍스트 값을 직접 지우면 공란으로 유지한다.
- 포장 치수·무게, 실제 이미지/인증번호, 미확보 분류의 양식은 이번 규칙으로 생성하지 않는다. 다른 분류에 80719의 개별 표시사항/공통 스칼라 기본값을 복사하지 않는다.
