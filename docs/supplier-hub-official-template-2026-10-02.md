# 선택 카테고리의 공식 Excel 자동 연결 — 2026-10-02

## 확인한 계약

인증·쿠키 없이 공개 [Supplier Hub 견적 등록 페이지](https://supplier.coupang.com/qvt/registration)를 HTTPS GET으로 읽었다. 이 페이지의 `/qvt/resources/20261001171235/dist/main.js`는 7,139,840바이트, SHA-256 `946350c602452505d1ce84ddeaf99a81991980033a8065d71b5b2da21cf23862`이다. AST로 요청 계약만 분석했으며 원본 코드를 실행하거나 제품 저장소에 복사하지 않았다.

`CategoryDownloader.retrieveUrl`은 선택한 말단 항목의 `categoryId` 목록과 `locale=ko`로 다음 공식 빈 견적 양식을 요청한다.

```text
GET /qvt/v3/kan-categories/download-quotation?leafKanCategoryIds=<kan>&locale=ko
```

상품 등록 표시 분류코드와 이 요청의 칸 코드는 구분해야 한다. 상세 양식 메타데이터의 `kanCategoryId` 또는 `categoryId`를 사용하며, 둘 다 있으면 서로 같아야 한다. 표시코드를 다운로드 코드로 추측하지 않는다. 기존 실제 바스켓 원본에서는 표시코드 `80719`와 칸 코드 `6269`가 대응한다.

## 구현된 흐름

확장 0.2.37의 TEMPLATE 요청은 기존 SCHEMA 조회와 같이 원래 앱 회원·승인 회사, 같은 Chrome 창의 Supplier Hub 탭과 실제 루트/부모/최종 분류를 확인한다. 상세 원문과 메타데이터가 직전 선택 결과와 같을 때만 공식 빈 XLSX를 GET한다. 조회 전후 회사/회원/페이지가 바뀌면 반환하지 않는다. 새 창/프로필, 기존 상품/견적 수정, 제출, 쿠키/토큰 추출은 없다.

파일 다운로드는 35초, 5MB로 제한한다. 로그인 HTML·리다이렉트·잘못된 MIME·ZIP 헤더를 거절한다. 확장은 원본 바이트·SHA-256·크기·선택 코드/전체 경로/회사/칸 코드를 전달하고, 앱은 이를 다시 대조한다. 파일은 소유자의 `/api/category-profiles/official-template`에 올리며 서버에서 상세 양식과 회사, 다음 원본 계약을 재검증한다.

- `Retail_Categorized_Excel:Kan:<kan>:Notice<n>:Version<v>` 서명과 고시/버전 메타데이터.
- 5행 머리글, 6행 필수 표시, 7행 안내, 8행 예시, 9행 상품 작성 구조.
- 카테고리 열의 실제 정적 드롭다운에서 선택한 표시코드와 전체 경로가 정확히 일치하는 값 하나.
- 상품명·공급가·카테고리 필수 연결과 정확한 필드명에 의한 고유 속성/고시 연결. 중복/모호한 머리글은 자동 연결하지 않는다.
- 원본 드롭다운과 전체 선택값을 대조한 코드 또는 표시 문구 출력 형식.

검증된 원본은 소유자 범위의 R2에 그대로 보관한다. 상품추가 카테고리에 Excel 연결이 없을 때 파일·작성 시트·열 연결을 함께 저장한다. 기존 수동 연결은 자동 다운로드로 바꾸지 않는다. 기존 프로필 갱신은 revision 충돌을 검사하며 취소/늦은 결과가 URL 수집을 시작하지 않게 했다.

원본에 연결되지 않은 필수 열이 남으면 기존 견적 검토/출력 검사가 계속 이를 표시한다. 다운로드 성공이나 부분 매핑 성공을 제출 완료 또는 모든 필드 확인으로 처리하지 않는다. 수집 당시 상세 양식과 상품/옵션 수동 수정·명시적 공란은 이후 설정 변경에도 유지된다.

## 검증과 한계

전체 테스트 **1,770/1,770** 통과(258.898초), 신규 공식 양식 8개와 카테고리 선택/확장 버전 포함 집중 **33/33** 통과. TypeScript 오류 0, 변경 파일 lint 오류 0/기존 intake `onBusy` effect 경고 1. 전체 저장소 lint 통과를 주장하지 않는다.

두 회사 와이홉 A01464742·유앤채 A01526306 각각 실제 API/임시 SQLite를 사용해 분류 선택 → 공식 형식 파일 연결 → 기록된 813724060928 원문 → 6옵션 초안 → 제목/고유 속성/한 옵션 고시 공란 수정 → XLSX 출력까지 검사했다. 선택 코드 991234, 상세 양식과 파일은 합성 fixture이며 인증/AI/이미지/Hub 응답도 fixture다. 실제 판매 카테고리/1688 실시간 수집/Hub 접수를 검증한 것은 아니다. 출력 후 상태는 미전송이고 실제 접수 호출은 0건이다.

이전에 내려받은 실제 `supplier-basket-A01464742.xlsx`는 SHA-256 `c6069ceab0e81a93834b2d56af0f918102c55e5f711d0df5cc3ba281c447d3cb`이다. 이를 수정하지 않고 새 검사 함수로 읽어 실제 80719/6269 대응, 고시17·버전190, 74머리글·9행 작성 구조를 확인했다. 이 검사에 입력한 최소 상세 양식은 합성이므로 해당 분류의 실제 전체 스키마/모든 열 연결을 확보했다는 증거가 아니다. 원본 파일과 분석 outputs는 Git에 포함하지 않는다.

확장 원본/번들/ZIP 일치 검사 통과: **0.2.37**, 36파일, 416,522바이트, SHA-256 `f8e634ac918b61a15ea0c7174a28db74572393f462199cfc99492949ef1c2914`. 기존에 로드한 확장 폴더와 앱 페이지를 새로고침해야 한다. 권한/호스트·DB 마이그레이션·비밀 설정·이미지 Worker·유료 자원 추가는 없다.

운영 빌드·11개 마이그레이션 검사를 마치고 [기존 운영 앱](https://sourceflow.jjwwhhjj1116.workers.dev)에 Worker 버전 `2d4d90bb-21c4-41cc-8203-409bdb719974`를 배포했다. 익명 앱·카테고리 컨텍스트·더미 접수 API의 Access 302 세 건을 확인했으며 인증 운영 화면 검증을 대신하지 않는다.

실제 승인 계정에서 새 다운로드를 실행한 결과, 모든 분류의 상세 양식/공식 Excel, 운영 번역/필수 서류와 두 회사 최종 접수번호·SKU 대조는 남아 있다. agent는 기존 Chrome 전체 탭 조회 거절을 이 확장으로 우회하지 않았고, 기존 오른쪽 Chrome과 Couplus 작업 상품을 변경하지 않았다.
