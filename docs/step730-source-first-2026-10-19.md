## 새 수집 진입 순서

원래는 서버 `/collect`의 최대 30초 조회가 실패한 뒤에야 Chrome 수집이 시작됐다. 새 경로는 사용자가 새 URL 수집을 시작한 직후 현재 Chrome 창에 이미 열린 정확한 상품 탭의 지원되는 완전한 JSON-LD만 먼저 확인한다. 새 `PROBE` 명령은 다른 창·새 탭·이동·모바일/외부 요청·상품 저장에 진입하지 않는다. 전체 worker 확인은 1초, 앱의 확장 확인은 750ms, 응답 대기는 1.5초로 제한한다. 페이지·창·앱 이동과 취소를 전후로 확인하고 늦은 응답은 추가 읽기나 저장을 유발하지 못한다.

이 기능은 실제 설치 manifest 0.2.81 이상에서만 광고한다. 구버전·미설치·불완전 원문·읽기 실패는 기존 서버 조회로 돌아간다. 새 명령을 구버전에 보내 새 탭 수집으로 잘못 해석하게 하지 않는다. 기존 일반 `CAPTURE`의 모바일·탭 수집 동작은 그대로 유지한다.

기존 탭에서 사용할 원문을 얻으면 `/browser-capture` 저장 한 번만 실행한다. 그 응답이 불분명하면 같은 요청의 `/result` GET 한 번으로 복구하며 다른 `/collect` 쓰기를 경쟁 실행하지 않는다. 명시적인 거절, 다른 상품 응답, 잘못된 저장 시각은 성공으로 복구하지 않는다. 선택적 상세/속성/이미지 공백은 검토 안내로 남기고 즉시 모바일·새 탭 수집을 반복하지 않는다. 사용자의 별도 원문 보완 동작은 유지한다. 이미 상품이 연결되거나 원문이 저장된 기존 작업에는 새 probe를 적용하지 않는다.

이는 지원되는 원문이 이미 열린 경우의 지연 개선이다. 임의의 1688 데스크톱 hydration 형식을 추가하거나, 비공개 서버 API 또는 모든 신규 URL의 정상 수집을 검증한 구현은 아니다.
