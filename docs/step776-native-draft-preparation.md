## 해결한 전송 경로 문제

기존 전체 문서 전송 경로는 실제 접수 검증을 마치기 전까지 `start`를 모두 차단했다. 따라서 새 문서를 생성하고 원본 파일과 저장값을 대조하는 현장 검증도 시작할 수 없었다. 이번 변경은 새 초안 준비를 약관 동의·최종 제출과 분리한다. 실제 접수 검증을 완료했다는 뜻으로 release gate를 바꾸지 않는다.

현재 회원·회사·전체 옵션·저장 본문을 확장이 독립적으로 다시 읽고 native 원본 파일 계획을 확인한 경우에만 `새 견적 초안 만들기 · 제출 안 함`을 제공한다. 이 버튼은 새 문서 한 개를 생성하고 현재 원본 이미지 첨부, 정확한 본문 저장값 대조, 2~5단계 검증, 새 초안 목록과 본문 재조회를 수행한다. 마지막 읽기까지 일치해야 `초안 저장·검증 완료 · 미제출`로 표시한다. 문서 화면 이동·약관 선택·최종 제출·접수 결과 생성을 수행하지 않는다.

준비 요청은 기존 회원/회사/상품 단위 lane과 immutable checkpoint, Web Locks 예약을 사용한다. 결과가 불확실하면 재생성이나 재업로드 대신 `같은 초안 저장 결과 확인 · 읽기 전용`으로 복구한다. 읽기로 확인된 미완료 단계만 별도의 명시적인 계속 버튼으로 진행한다. 최초 요청·준비 계속은 유효기간을 검사하고, 만료 뒤에는 동일 요청 UUID와 동일 본문으로 검토 envelope만 갱신한다. 읽기 복구만 만료된 원래 요청을 허용한다. 일반 전체 제출과 초안 준비 checkpoint는 서로 혼용하지 않는다.

앱의 선택/회사/검토 대상 변경, 오래된 callback, 중복 클릭, 누락/잘못된 ACK, 다른 문서·원본·옵션 응답을 거절한다. 검증 반려는 원래 요청의 읽기 확인 후에만 기존 반려 기록 방식으로 수정 잠금을 해제한다. 초안 검증 성공 후에도 중복 생성을 막는 예약과 원본 편집 잠금은 남긴다. 외부 검토창 닫기 허용과 원본 편집 허용은 구분한다.

## 6단계 표시사항 보완

단계가 숨겨진 뒤 보관된 생성·입력·저장·PNG callback이 실행될 수 있던 결함을 고쳤다. 같은 단계로 되돌아와도 이전 활성 epoch의 callback은 무효다. 수동 입력은 유지하고 늦은 AI/PNG 응답은 채택하지 않는다. 이미 전송한 텍스트 PUT을 화면 전환만으로 취소하지 않으며, 다음 명시적 저장에서 먼저 GET으로 정확한 저장 결과를 확인하여 중복 PUT 없이 후속 PNG 연결을 복구한다.
