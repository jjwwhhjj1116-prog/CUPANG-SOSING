# Step710 — 표시사항 드래그 순서와 최종 라벨 미저장 선택 보호

기준 커밋 `9269d061b4b42661da53205b3d2bc19c37b90883`. 원본의 관찰 가능한 조작 계약은 `step710-label-interaction-parity-audit.md`, 실제 자체 API 검수는 `step710-label-order-persistence-2026-10-18.md`, 자식 연결 편집 상태는 `step710-label-reference-draft-isolation-2026-10-18.md`에 구분했다. 기존 작업 상품·계정·공유 Chrome을 조작하지 않았다.

## 구현

- 주 표시사항 편집기에 행별 드래그 손잡이를 추가했다. 필수 제품명도 이동할 수 있고 삭제 보호는 유지한다. 위·아래 버튼은 키보드 대체 조작으로 남긴다. 이름·내용·사용자 항목 ID·명시 공란을 유지하며, 순서 변경은 정보 저장 전까지 로컬 초안이다.
- 기존 구조 저장 경로를 그대로 사용한다. 저장 후 재조회와 PNG 생성은 같은 항목 배열 순서를 따른다. 실제 출력 행의 순서가 달라진 기존 PNG는 다시 생성·연결해야 한다. PNG에 출력하지 않는 빈 행만 이동하면 출력 recipe는 같을 수 있다.
- 현재 목록에서 시작한 드래그만 받는다. private gesture와 DataTransfer nonce를 함께 확인하고, 원문·상품·옵션·카테고리·단계 활성 상태·잠금·요청·저장본·초안이 바뀌면 이전 제스처를 무효화한다. 실패한 같은 버전 조회도 이전 제스처를 되살리지 않는다. 이것은 자체 편집 보호이며 원본이 같은 내부 방식을 사용한다는 주장은 아니다.
- 최종 라벨 제외·전체 교체 선택과 저장 불확실 상태를 부모 편집기에 즉시 전달한다. 미저장 선택 중에는 주 표시사항 수정·재정렬·PNG 생성·연결을 막되 자식의 선택 저장·취소·읽기는 계속 가능하다. 부모 콜백은 같은 상태 보고를 중복 처리하지 않아 렌더 반복을 만들지 않는다.
- Dashboard에서 표시사항 단계의 활성 여부를 전달한다. 숨은 단계에서 보관된 옛 드래그가 이후의 편집에 적용되지 않는다. 손잡이·행 강조는 기존 레이아웃의 데스크톱/좁은 화면 배치에 맞췄다.

## 검사 방법과 범위

신규 `product-label-drag-editor.test.mjs`는 실제 주 컴포넌트의 JSX 이벤트 함수를 실행한다. 테스트 scheduler는 React와 같은 `Object.is` dependency 비교를 사용한다. 필수 행 이동·명시 저장/재조회/PNG 순서, 미저장 사용자 항목·공란, 외부 전송/다른 nonce/자기 위치, 원문/옵션/활성·잠금 왕복, 실패한 읽기, 미저장 최종 라벨과 이전 콜백·unmount를 검수한다. API·PNG/첨부는 이 UI 검사에서 합성이며 브라우저 포인터와 픽셀 동일성을 증명하지 않는다.

신규 순서 전용 API 검사는 양사 격리 SQLite/D1·R2 어댑터와 자체 route handler·renderer·Single packet을 실행한다. `changes:[]` 순서 저장, 공통/개별 값 보존, 기존 PNG stale 판정, 각 옵션 PNG 재생성·정확한 최종 공개 URL/바이트를 확인한다. 합성 원문·canvas/PNG이고 실제 Supplier Hub 접수가 아니다.

최초 드래그 UI 실행의 실패4개는 VM realm 배열 비교와 변경 배열 순서 기대의 오류였다. 실제 비교 경계를 정리한 뒤7개가 통과했다. 독립 읽기 검토 이후 source 변경 중 자식 요청 취소의 busy 보고도 추가 점검했다. 최종 소스·고유 테스트 수·타입/린트/스키마/빌드·배포 결과는 `outputs/step710-final-validation.json`에 고정한다. 반복 실행은 새 통과 수에 합산하지 않는다.

최종 관련 검사는 **11개 고유 파일71/71 통과**, 실패·취소·건너뛰기0,30.10초다. 신규15개(주 UI7+순서 API2+자식6)를 포함하며 별도 focused 실행은 중복 합산하지 않는다. 실행 전후 소스·설정·테스트1273개 SHA가 일치했다. 과거 Step704 hook 증거는 원본 바이트·mtime을 복원하고 이번 출력은 별도 보관했다. 전체 타입 검사768MiB, 앱/DB·변경 테스트 린트384MiB, 스키마 검사44테이블17인덱스29모듈, 제한 메모리 운영 빌드가 모두 통과했다. 전체 저장소 테스트를 실행했다는 뜻은 아니다.

후속 회귀는 부모가 이전 source 콜백의 idle 보고를 거절하는 조건에서 지연 GET/PUT을 각각 검사한다. 새 현재 source가 직접 idle을 보고한 뒤 미저장 선택을 유지하며 요청을 자동 재시작하거나 PUT을 복제하지 않는다. 최초 독립 읽기 검토에서 이 경우를 놓친 사실과 이후 수정·재검수는 구분한다.

## 완료 판정의 경계

이번 변경은 6단계 편집 조작과 미저장 참조의 충돌 보호다. 완료 이미지의 영속 ‘재작성’ 초기화, 원본 drag 라이브러리의 애니메이션·touch 임계값과 픽셀 동일성을 구현했다고 주장하지 않는다. 기존 원본 코드·상표·상품 자료를 배포물에 복사하지 않는다.

카테고리→URL→수집→SEO/옵션/이미지 초안→1~7 편집 진입의 기존 연결은 읽기 감사에서 확인했다. 이번 작업을 실제 신규 1688 전체 수집, 전 카테고리 공식 양식 확인 또는 Supplier Hub 접수/SKU 발급 완료로 확대하지 않는다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 전송 gate를 유지한다. 확장·ZIP·DB schema·공급자·유료 플랜 변경은 없다.
