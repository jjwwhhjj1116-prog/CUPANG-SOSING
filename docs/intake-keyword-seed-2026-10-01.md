# 상품추가 타겟 키워드와 SEO 검색어 초안 연동

2026-10-01, 작업 535.

## 재현과 관찰 근거

`docs/couplus-new-intake-observation-2026-09-27.md`의 독립 신규 상품 관찰에서는 상품추가 타겟 키워드에 `상품`을 입력해도 원문에 따른 SEO와 7단계 검색태그가 생성됐다. 기존 작업 상품을 수정하거나 시험 분류로 전송한 관찰이 아니다.

YOOFAM PLUS는 `prepareCollectionProduct`에서 타겟 키워드를 `manual` 검색어로 저장했고, `translationBatchAdoption`은 수동 검색어를 무조건 제외했다. 따라서 모델이 검색어를 생성해도 저장된 초안과 견적서에는 `상품`만 남았다. 신규 회귀 시험에서 수정 전에 단위 두 건 및 두 회사의 실제 API/SQLite 흐름 두 건으로 재현했다. 시험 로더의 TextEncoder 누락을 보완한 뒤의 회귀 결과만 재현 근거로 사용한다.

## 변경

- 새 상품의 비어 있지 않은 타겟 키워드에만 서버가 `intakeKeywordSeed`를 기록한다. 초기 검색어 자체는 입력값으로 남아 원문/AI 요청 실패 시 입력이 보존된다.
- 저장 당시 검색어 배열·검색어 수정 시각·수집 요청/URL 원문 참조·번역 요청의 타겟 키워드가 모두 일치하는 경우, 첫 검색어 초안의 변경값을 반영할 수 있다. 원문 참조 문자열은 생성과 검증 요청에서 같은 함수를 사용한다.
- 검색어를 명시적으로 저장하면 입력값이 같거나 빈 배열이어도 표식을 제거한다. 이후 자동 초안은 그 수동 선택을 유지한다. 상품명/라벨/이미지만 저장하면 검색어 표식을 유지한다.
- 표식은 편집 API의 허용 필드가 아니다. 기존 문서는 표식을 추정하거나 추가하지 않으며 모든 기존 수동 검색어를 그대로 보호한다. DB 마이그레이션이나 기존 상품 일괄 수정은 없다.
- 기존 통합 저장의 원문/상품/콘텐츠 버전, 카테고리 연결 및 미리보기 fingerprint/트랜잭션 검사는 유지한다. 금액 계산과 카테고리 기본값, 전송 동의, 접수 판정은 바꾸지 않는다.

## 검증

신규 `tests/intake-keyword-seed.test.mjs` 9건은 첫 생성값 반영, 같은 값의 수동 확인, 다른 수동 값, 빈 값, 다른 단계 편집, 원문/키워드/시각 불일치, 기존 문서 보호 및 편집 API의 표식 재생성 거절을 검사한다.

두 회사 A01464742·와이홉 / A01526306·유앤채에 대해 지정 813724060928의 기록된 원문으로 실제 수집/SEO/콘텐츠/견적서 API와 임시 SQLite를 실행했다. 타겟 `상품`을 원문 참고로 보내고 모델 응답의 `선글라스, 우드 패턴, 남녀공용`을 저장해 7단계 모든 행에 연결했다. 검색어를 수동 수정한 뒤 URL 작업을 다시 실행해 원문 조회/AI 호출 추가 없이 유지되는지 확인했고, 생성된 실제 XLSX의 여섯 SKU 행에서 수정 검색어·카테고리 코드·원문 URL을 읽어 대조했다.

인증, 모델 응답, 이미지 바이트, Excel 양식은 시험 자료다. 80719는 관찰된 폼 계약 시험 분류이며 선글라스의 실제 판매 분류가 아니다. 운영 상품이나 실제 Supplier Hub에 쓰지 않았고 전송 상태는 `미전송`이다. 이 시험은 실제 AI 품질이나 Hub 최종 접수 증거가 아니다.

## 운영 반영과 남은 검증

앱 배포 `0c5d01bb-fc5b-4b44-83ae-0efdd4978ca5` / https://sourceflow.jjwwhhjj1116.workers.dev 완료. 익명 앱/수집 API GET 두 건은 기존 Access 보호 302를 유지한다. 이는 로그인된 UI나 운영 저장/접수 검사가 아니다. 기존 이미지 Worker, DB, 비밀 설정, 유료 자원은 변경하지 않았다. 앱을 새로고침한 뒤 생성하는 새 상품 초안에 적용되며 기존 수동 검색어를 소급 교체하지 않는다.
