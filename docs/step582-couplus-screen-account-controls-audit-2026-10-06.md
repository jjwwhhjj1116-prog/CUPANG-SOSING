기본설정은 회원 ID의 `owner_id`에 저장한다. 설정 GET/PUT은 현재 인증을 한 번 해석하고 고정 이메일·역할·회사와 승인된 회원을 확인한다. GET 응답에 계정 범위를 추가했고, 편집창에서 불러온 범위를 저장 요청의 `expectedOwnerId`로 보낸다. 다른 계정 범위나 native 계정의 범위 누락은 DB/배너 저장 전에409로 거절한다. 잘못된 범위로 읽은 설정은 편집창에 넣지 않는다. 페이지도 회원 ID로 구분한다.

운영 관리자 설정에 과거 와이홉 값이 남아 있어, 사용자 지정 회사 매핑에 따라 **관리자 설정1행의 브랜드·제조사·수입 및 판매원3개 값만** 조건부로 수정했다. 기존 소유자·회사·이메일·역할·상태·이전값·수정시각을 모두 비교한 UPDATE이며 결과는 `rows_written:1`이었다. 적용시각은2026-10-06T10:08:28.740Z. 와이홉 설정 행과 수정시각은 그대로였고 가격·이미지·번들 등 다른 설정도 보존됐다. 기존 상품의 등록설정 스냅샷은 바꾸지 않았다. 제조사 협력사 문구는 편집 가능한 기본 템플릿이며 실제 제조공장 확인을 뜻하지 않는다.

## 등록표·삭제·접수 상태

순서: 등록번호, 상품이미지, 상품명, 구매링크, SEO설정, 가격설정, 대표이미지, 추가이미지, 상세이미지, 사이즈표, 한글표시사항, 견적서, 등록상태, 관리. 체크박스 열은 데이터14개에 포함하지 않는다.

저장 SEO 상품명과 현재 연결된 대표이미지가 목록에 반영된다. 구매링크는 별도 열의 체인 아이콘이며 실제 원본 URL을 `noopener noreferrer` 새 탭으로 연다. 모든14개 열을 선택 표시하고 고정할 수 있다. 관리에는 삭제만 둔다. 현재 단계 셀은 기존 단계 편집창을 연결한다. 쿠플러스의 옵션 목록을 거쳐 단계에 들어가는 모든 진입 방식이 완전히 일치한 것은 아니다.

등록상태는 `hub_receipt`에서 관찰된 상태가 있을 때만 해당 결과를 표시하고, 없으면 `등록대기`다. 원문 수집·로컬 편집 완료·직접 입력한 전송 문자열을 실제 견적 접수로 표시하지 않는다. 확인된 견적서 ID·회사·발급 SKU수·관찰시각은 같은 전송 결과에 함께 표시한다.

삭제는 실제 데이터 제거 대신 `product_removals` 표시를 추가한다. AI 등록 목록에서 숨기며 `삭제된 상품`에서 복원한다. 상품·옵션·이미지 파일·콘텐츠·견적서·접수 자료는 삭제하지 않는다. 삭제/복원은 로그인 소유자와 상품 수정 버전을 비교하고, 복원은 삭제 시각도 비교한다. 중복·오래된 요청409, 다른 소유자404, 잘못된 본문400/413, 인증 실패503을 검증했다. 성공 응답을 확인하기 전에는 화면 행을 없애지 않으며 실패하면 선택/행을 유지한다.

운영에는 검토한 `0015_product_removals.sql` 한 개만 적용했다. 새 테이블과 인덱스 생성이며 기존 테이블 ALTER/백필/상품 삭제는 없다. 실제 배포 UI에서 삭제 목록 조회와 `삭제된 상품이 없습니다` 응답을 확인했다. 기존 상품을 삭제·복원하는 운영 시험은 하지 않았다.

## 상세이미지·표시사항

상세 상단/본문/하단 각 이미지에 중국어→한국어 번역, 영어→한국어 번역, 편집, 위/아래 이동, 삭제를 연결했다. 삭제는 현재 상세 역할의 초안에서 해당 이미지 연결만 제거한다. 같은 파일을 쓰는 대표/추가 역할과 원본 파일은 유지한다. 다른 단계의 미저장 입력도 유지한다.

번역 버튼은 정확한 소유 이미지와 언어를 기존 이미지 처리 편집기에 전달한다. 요청 중·서버 실행 중·초안 충돌·다른 상품 이미지는 선택하지 않는다. 사용자가 작성한 요청을 보존하고 언어 지침을 넣으며,4,000자 제한을 초과하면 선택을 함께 거절한다. 버튼 자체는 외부 호출이나 자동 저장/실행을 하지 않는다.

6단계의 `한글 표시사항 번역` 버튼은 이미 마운트한 번역 패널을 그대로 보여준다. 수집한 상품 속성의 완료된 번역을 표시사항 항목과 연결하고 현재값/변경값을 확인한 뒤 저장하는 기존 경로를 사용한다. 직접 편집한 값과 공란, 상품 버전·콘텐츠 리비전 검사, 저장된 값으로 PNG 생성·첨부하는 기존 경로를 유지한다. 상품을 바꾸면 번역창 펼침 상태가 초기화된다. 임의의 표시사항 문장을 직접 번역하거나 이미지에서 OCR로 읽는 새 기능은 아니다.

배포 후 와이홉 검수 상품에서 상세 번역·삭제 버튼과6단계 번역 진입을 직접 확인했다.6단계에는 수집 속성24개와 원문이 나타났다. 이 확인에서는 번역 요청 준비·승인·실행·적용과 견적 전송을 하지 않았다. 이미지 서버 설정이 필요한 상태는 여전히 남아 있다. 새 버튼을 실제 번역 이미지의 완성으로 계산하지 않는다.

## CLI 판정

별도 [CLI 분석 문서](step582-cli-role-audit-2026-10-06.md)에 공식 공개 v1.3.24 배포물을 실행하지 않고 확인한 근거를 기록했다. Couplus CLI는 로컬 요청 실행·계정 세션/작업 중계·자동 시작/업데이트·MCP를 지원한다. 현재 우리1688 수집과 Hub 첨부는 확장에 구현돼 있어 이 두 기능에 별도 프로그램이 반드시 필요한 근거는 없다.

우리 상품관리(신규)는 현재 가져온 회사별 DB 값을 표시한다. 쿠팡의 최신 SKU·재고·가격을 읽어 동기화하는 연동은 남아 있다. 공개 archive에 SKU/재고 이름이 없다는 이유로 Couplus에도 없다고 단정하지 않는다. 서버가 주는 catalog/recipe는 확인하지 않았다. 이번에는 CLI 설치·실행·Startup 변경·프로세스 종료·인증 데이터 접근을 하지 않았다.
