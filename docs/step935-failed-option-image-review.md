# 실패한 옵션 이미지 검토 연결 — 2026-11-04

## 실제로 재현한 문제

새 양말 초안 `865ff938-1f6e-42cd-bcfe-863cba84eb09`(등록번호 `261103002001`) 한 건에서 대표 이미지 부분 작업을 실행했다. 옵션 1~4는 현재 원본의 실물 인쇄 보존 증거가 확인됐고, 옵션 5 `collected-5`는 문구 판독 불가로 멈췄다. 원본은 유지됐으며 완료로 처리되지 않았다.

이후 **대표 이미지 검토 열기**를 누르면 실패한 연회색 옵션 대신 상품 공통 이미지 편집창이 열렸다. 실패 결과에는 완료된 Vision 검토 자료가 없어서 기존 공통 편집 경로로 돌아가는 것이 원인이었다. 옵션 목록을 통해 직접 연회색 사진을 열어 희미한 실물 인쇄가 있는 원본을 확인했다. 이를 자동 판독 성공으로 바꾸거나 원본을 지우지는 않았다.

## 변경

- 대표·추가 이미지의 확정 실패에는 검토할 옵션·원본·슬롯을 별도로 보존한다. 완료된 인식 결과를 만들지 않는다.
- 검토 버튼은 해당 옵션의 사진을 수동 편집으로 연다. 기존에 완료된 인식 검토 자료가 있으면 기존 경로가 우선한다.
- 검토 대상을 보존한 뒤에는 뒤의 슬롯을 처리하지 않아 같은 작업이 검토 대상의 저장 버전을 바꾸지 않는다.
- 회사·회원·상품 버전·현재 원본 연결이 다르거나 추론/저장 결과가 미확정이면 검토 연결을 거절한다. 열린 편집기의 미저장 값도 유지한다.

## 확인과 한계

관련 다섯 검사 묶음 228개 통과 후, 슬롯 중지 보완에 대한 최신 회귀 검사 10개와 TypeScript·변경 파일 ESLint·diff 검사를 통과했다. 별도 검토에서 남은 지적은 없었다. 추가로 실행한 수동 편집기 검사 15개는 기존 HEAD에서도 `reviewFixture is not defined`로 구성 단계에서 실패함을 격리 재현했다. 이를 이번 변경의 성공 검사로 세지 않았다.

현재 새 양말의 상세 3개 합성 PNG는 저장된 첨부 자료이며 전체 중국어 번역 완료 증거가 아니다. 원본 BODY 35장을 대상으로 하는 별도 상세 작업 구성을 보존한다. 실제 Aside의 대표→상세 단계 이동은 `Input.dispatchMouseEvent` 시간 초과가 났고, 이후 같은 탭 읽기도 `Runtime.evaluate` 시간 초과가 발생했다. 새 코드의 운영 브라우저 검토 연결과 전 상세 번역·신규 접수 완료는 아직 확인되지 않았다.

Supplier Hub 홈은 유앤채로 로그인된 상태를 확인했다. 새 양말에는 필수 사이즈표와 상충하는 소재 정보, 상품별 서류 해당 여부의 확인이 남아 있다. 이 실행은 새 Hub 문서를 생성·업로드·접수하지 않았다. 이미 접수된 886 상품과 문서 `2347603`은 다시 생성·저장·전송하지 않았다.

## 상세 번역의 미실행 요청 분류

별도 새 검수 탭에서 연회색 옵션의 상세 단계를 직접 열면 BODY 35장과 상단 배너 한 장이 정상 표시됐다. 편집 구성을 보관한 뒤 **모든 이미지 AI 처리**를 실행했다. 첫 BODY 사진이 다른 요청과 충돌해 새 요청은 접수되지 않았지만, 서버의 일반 409 오류를 클라이언트가 새 요청의 응답 유실로 분류해 나머지 34장까지 멈췄다.

읽기 전용 D1 조회와 원본 SHA·회사·모델·언어·정책의 해시 대조로, 같은 첫 사진의 `foreign-text-inspection-v1` 요청 한 건이 11월 3일 07:21 UTC부터 `running`이고 `provider_requests`는 NULL임을 확인했다. 이 기록을 삭제·만료·완료 처리하지 않았다. 새 요청의 원본 검사 정책은 `product-text-preservation-v2`다.

원자적 요청 접수가 **성립하지 않은 것으로 확인된 분기만** `IMAGE_VISION_NOT_ADMITTED`, `uncertain:false`를 반환한다. 그래서 해당 사진은 원본 유지/실패로 남고 다른 원본 사진은 이어 준비할 수 있다. 같은 UUID가 이미 실행 중인 경우, 접수 응답 자체가 유실된 경우, 실제 추론 결과가 불명확한 경우에는 기존 미확정 분류와 중복 방지를 유지한다. 구형 정책의 완료 결과를 현재 정책의 증거로 사용하지 않는다.

관련 검사 40개와 TypeScript·변경 파일 ESLint·diff 검사를 통과했다. 실제 SQLite→라우트→클라이언트→본문 일괄 작업을 연결한 회귀 검사에서 구형 진행 중 기록 보존, 새 미접수 UUID의 행/추론 생성 0회, 다음의 서로 다른 사진만 1회 분석, 최종 견적·이미지 업로드 0회를 확인했다.

실제 React 19.2.6/ReactDOM과 합성 호스트 DOM으로 공통 대표 검토→닫기→옵션 대표→상세 왕복도 별도로 재현했다. 저장된 36개 사진이 모두 마운트되고 요청 수가 안정화됐으며 React 오류·반복 렌더는 재현되지 않았다. 이 검사는 네이티브 이미지 디코딩·레이아웃·브라우저 합성을 대체하지 않으므로 앞선 실제 탭 시간 초과의 원인을 단정하지 않는다.
