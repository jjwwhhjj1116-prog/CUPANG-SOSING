# Step785 · 수집 앱 연결과 옵션 재선택

기존 실상품·설정·수집본을 수정하지 않고 수집 전달과 원문 검토의 두 결함을 보완했다. 이 기록은 실상품 수집 또는 Supplier Hub 접수 완료를 뜻하지 않는다.

## 변경

- 같은 Chrome 창에 앱 탭이 없으면 고정된 운영 앱 주소를 한 번 연다. 승인된 회원·회사 문맥이 확인된 뒤에만 클릭 당시 고정한 원문을 기존 회원별 수집함에 보관·전달한다. 회사가 충돌하거나 창·출처가 달라지면 중단한다.
- 로그인 확인은 최대 12초다. 확인 전에는 소유자를 추정하거나 수집 완료로 표시하지 않는다. 로그인에 시간이 더 필요하면 열린 앱에서 로그인한 뒤 수집을 다시 눌러야 한다. 미확정 원문을 다음 로그인 사용자에게 자동 귀속하는 별도 보관함은 만들지 않았다.
- 정확한 저장 응답을 받은 뒤 수신 앱 탭을 활성화한다. 탭 활성화 실패가 이미 확인된 저장 성공을 실패로 바꾸지는 않는다. 저장 응답이 불확실하면 기존 불변 원문 보관본을 유지한다.
- 같은 소스 탭에서 진행 중인 수집을 재사용할 때도 창·URL·상품 번호·원문 지문이 모두 일치해야 한다. 다른 상품에 이전 상품의 완료 응답을 전달하지 않는다.
- 원문 검토 창은 최초 원문의 모든 옵션을 원래 순서로 표시한다. 저장한 검토값은 동일 옵션 key로 복원하고, 체크 상태만 이전 선택에 맞춘다. 제외했던 옵션을 다시 선택할 수 있으며 원문·이미지·속성은 보존한다.
- 확장 2.1.20에 반영한다. 추가 권한·호스트 권한은 없다. 다운로드·준비된 폴더 버전과 Chrome에서 실제 응답한 버전은 별도로 기록한다.

## 검증 범위

새 옵션 회귀는 양 회사에서 제외→검토 저장→재열기→재포함과 검토값 보존을 확인한다. 새 확장 회귀는 가짜 Chrome API를 사용해 앱 생성·준비 대기·시간 초과·회사 충돌·창 이동·동시 수집·잘못된 완료 응답 방지를 확인한다. 실제 소스 페이지를 읽거나 Supplier Hub에 쓰지 않는다.

실제 Chrome의 별도 localhost 검수에서는 생산 SourceInboxPanel과 실제 API handler·메모리 SQLite를 사용했다. 합성 옵션 두 개 중 하나를 제외해 저장(HTTP200, revision2), 다시 열어 이전 수정값과 제외 행을 확인한 뒤 재포함해 저장(HTTP200, revision3)했다. 카테고리 선택 callback은 두 옵션을 받았다. 원문 지문과 상품·옵션·작업·파일 테이블은 유지됐고 외부 소스·AI·Hub 요청은 0회다. 이는 전체 대시보드나 실제 접수의 증거가 아니다.
