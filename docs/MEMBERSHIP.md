# YOOFAM PLUS 회원 로그인

- `/login`: 이메일·비밀번호 로그인 / 회사코드·회사명을 포함한 가입 요청.
- `/account`: 본인 계정 확인, 로그아웃. 관리자는 가입 요청 승인·거절, 회원 이용 정지, 본인 회사정보 저장 가능.
- 계정은 요청 시 `member/pending`으로 생성한다. 요청 본문의 관리자/승인 값은 사용하지 않는다.
- 관리자 포함 승인 계정 최대2명. 조건부 SQL로 승인 한도를 검사한다. 관리자 승격 API는 없다.
- 승인 전/거절/이용 정지 계정은 상품 데이터에 접근할 수 없다. 회사코드를 데이터 소유자 ID로 사용하지 않는다. 회사가 같아도 회원 자료는 분리된다.
- 회사코드·회사명은 신청자가 제출하고 관리자가 검토한다. Supplier Hub의 실제 회사 소속을 자동 인증한 것은 아니다.
- 세션은 8시간, HttpOnly, SameSite=Strict, HTTPS에서 Secure. DB에는 세션 토큰의 SHA256만 저장한다. 매 요청마다 승인 상태를 확인한다.
- 비밀번호는 개별 salt + 서버 pepper HMAC + Workers WebCrypto PBKDF2-SHA256(100000회)로 저장한다. pepper는 Worker Secret에만 배포한다. DB 덤프와 pepper를 함께 보관하지 않는다.
- 로그인/가입은 IP와 이메일별 15분 요청 제한을 사용한다. 가입 중복 요청은 기존 암호·회사정보·권한을 바꾸지 않는다.

## 운영 활성화

1. `db/migrations/0009_members.sql` 적용.
2. 관리자를 서버에서 생성. 공개 가입으로 관리자를 만들 수 없다.
3. `YOOFAM_PASSWORD_PEPPER`와 `YOOFAM_AUTH_ENABLED=true`를 Worker Secrets에 설정.
4. 기존 Cloudflare Access 게이트가 있는 경우 관리 콘솔에서 새 회원 인증과 연결을 정리해야 한다. 새 로그인만으로 외부 게이트를 통과한 것으로 처리하지 않는다.

2026-09-27 관리자 생성과 Secret 활성화, 첫 코드 배포 완료. 기존 Cloudflare Access 게이트 때문에 실제 브라우저의 새 로그인 진입은 아직 확인하지 못했다. 배포용 OAuth로 Access 조직 API는403, 앱 목록은빈 배열이었다. 기존 Chrome에서 Cloudflare 계정 로그인이 필요하여 사용자에게 알렸다.

비밀번호·pepper·세션 토큰은 저장소와 진단 로그에 넣지 않는다. 현재 비밀번호 재설정/이메일 인증/이메일 알림 발송은 구현하지 않았다. 관리 화면에서 요청을 조회한다.

관리자는 /account에서 회원 회사코드·회사명을 수정할 수 있다. 변경된 계정의 세션만 즉시 폐기하며, 관리자 본인 변경 시에도 재로그인한다. 동일한 값 저장은 세션을 폐기하지 않는다. 변경은 member_audit에 기록한다. 거절·정지 계정도 재승인할 수 있으나 관리자 포함 승인 2개 제한과 회사정보 필수 조건은 동일하다. 이 기능은 회원 관리이며 Supplier Hub의 회사 소유권 검증 또는 실제 전송 구현을 의미하지 않는다.
