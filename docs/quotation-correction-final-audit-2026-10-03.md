# 견적서 수정·원본 확인·조회 복구 검수 (2026-10-03)

## 이번에 재현하고 수정한 문제

1. 가격 정책이나 옵션명·수량을 수정한 뒤 대표 이미지 단계에 방문하면, 견적서 진입 시 저장하지 않은 가격 수정값을 이미지 단계로 안내했다. 그 단계에는 가격 저장 버튼이 없었다. 실제 가격 폼과 옵션의 이미지/나머지 수정값에 각각 출처 단계를 붙여, 가격·옵션 수정은 2단계, 이미지 수정은 3단계에서 저장하도록 연결했다. 저장 함수·계산식·기본값·수동 공란은 바꾸지 않았다.
2. 파일 검증 반려 또는 SKU 행의 명시적인 반려가 확인돼도 필수 서류 편집이 잠겼다. 해당 반려 기록에만 서류 편집을 허용한다. 대기·검증 완료·응답 미확인 전송은 기존 보호를 유지한다. 서류를 교체하면 견적 지문과 동의가 갱신되어 새 검토가 필요하며, 이전 지문의 재전송은 계속 금지된다. 이전 접수 기록·서류 원본과 다른 수동 수정값을 보존한다.
3. 첨부 목록에는 남아 있으나 저장소에서 사라진 필수 서류를 등록 전 검사에서 찾지 못했다. 원본을 다운로드하지 않는 HEAD 검사로 누락, 크기/명시적 MIME·SHA·상품 기록 불일치, 저장소 오류를 구별한다. 최대 3개를 동시에 검사하며, 이전 원본에 확인 기록이 없는 경우는 검토 사항으로 남긴다. 해당함 선택의 원본만 검사하고, 해당없음으로 보존된 참조는 검사하지 않는다. 견적서 출력 시 실제 원본 바이트·크기·형식·SHA 검사는 계속 별도로 수행한다.
4. 이미 확인한 견적서가 파일 검증 목록에서 잠시 사라지면 로컬 접수 기록과 견적서 ID가 지워져 이후 SKU 조회가 막혔다. 동일한 회사·상품·카테고리·지문·옵션 수로 확인한 완료 기록은 목록 부재만으로 덮지 않는다. 기존 확인 시각과 상품별 결과를 보존하며, 새로운 성공이나 재전송으로 처리하지 않는다. 명시적인 대기·반려 결과 및 다른 식별값은 기존 방식대로 처리한다.

## 검증 범위

- 실제 프로젝트 API, 임시 SQLite, 기존에 기록한 1688 상품 813724060928, 합성 Excel/PDF/이미지/Hub DOM 및 로컬 Chrome API 모형으로 두 회사의 수정→새 지문→명시적인 동의→정확한 서류 전달→중복 방지를 검사했다. 합성 80719 양식은 출력 계약을 시험하기 위한 자료이며 해당 선글라스의 실제 판매 카테고리로 판단한 것이 아니다.
- 원본 누락 2개 회사, 저장소 오류·명시적 메타데이터 모순·이전 메타데이터 부재, 수동 공란과 단계 간 편집값 보존을 수정 전 실패하는 테스트로 재현했다. 접수 조회 복구는 실제 observe/read-validation/app-registration 함수를 사용하며 원격 Hub 요청을 보내지 않는다.
- 별도의 읽기 전용 검토에서 원본 HEAD 동시 조회 상한, MIME 대소문자·매개변수, 입력 불변성 및 검사 중 서류 수정 시 기존 revision 검사 409 응답을 확인했다. 실제 원본의 바이트 검사를 사전 HEAD 성공으로 대체하지 않는다.
- 2026-10-03 02:35 KST에 기존 운영 수집 함수로 지정 공개 URL 813724060928을 다시 읽었다.
