# Step867 — 단계 오류 표시와 접수 결과 복구

2026-10-30. 범위: 기존 업무 상품을 수정하지 않고 자동 작업의 실패 표시, 원래 요청 조회, 접수 결과 UI를 보완했다.

## 변경

- 선택 작업의 running/failed/blocked 결과를 같은 회원·회사·설정·선택·실행 회차·원본 버전 범위에서 보드 셀에 반영한다. 모달을 닫아도 현재 범위의 오류를 볼 수 있다. 서버 저장 근거 없는 완료는 표시하지 않는다. 새로고침 후 지속하는 서버 실패 이력이 아니라 현재 세션의 실행 피드백이다. 원본/범위 변경이나 오래된 응답은 폐기한다.
- 접수 관찰 결과를 저장할 때 표시 중인 전체 상태와 receipt를 함께 갱신한다. 같은 요청/문서/본문/검증 토큰·관찰시각을 확인하고 lifecycle 증거를 보존한다. 오래된 pending 화면에 최신 REJECTED 이력이 저장되어 창이 잠기던 경우를 수정했다. Hub API나 저장·제출 순서는 변경하지 않았다.
- 원래 요청 조회 전 PING으로 확장 버전과 명시적 지원 capability를 확인한다. 지원하지 않는 2.1.59에서는 처리하지 않을 명령을 보내고 30초를 기다리는 대신 업데이트 안내를 표시한다. 조회 자체는 확장 보관함 읽기 전용이며 복구 실행 권한을 만들지 않는다.
- 연결 진단에서 Qwen 이미지 문구 인식·번역과 별도 이미지 생성·배경 복원을 구분했다. 설정 확인은 실제 추론 성공으로 표시하지 않는다. DB 준비 검사는 체크인된 52개 테이블을 모두 확인하며 SELECT만 사용한다.
- Workers AI `AI.run`의 세 번째 인자에 `rejectIfBusy:true`를 전달한다. 정확한 3040 용량 거절만 CAPACITY/HTTP429로 분류하고 현재 단계의 나머지 이미지 요청을 중단한다. 일반 429·유사문구·상충/상속 속성·응답 불명은 uncertain을 유지한다. 확정된 용량 거절만 이후 사용자의 명시적 실행에서 새 UUID를 허용한다. 모델·본문·60초 제한·늦은 원래 응답 관찰·CAS·과거 TIMEOUT 기록은 유지한다. 자동 재시도는 없다.

공식 용량 거절 문서: https://developers.cloudflare.com/workers-ai/features/reject-if-busy/ . 실제 SDK의 오류 객체 형태를 관측한 것은 아니므로 일치하지 않는 형태는 미확정으로 보존한다. 호출 시도는 1회로 기록하며 거절의 비용이 0원이라고 주장하지 않는다.
