# Step640 — 쿠플러스 2단계 재계산과 단계별 저장 자료

쿠플러스의 2단계 ‘일괄 재계산’과 신규 초안의 계산 경로가 서로 다른데 앱이 두 경우를 동일하게 계산하던 차이를 수정했다. 단계별 저장 후 늦은 조회가 새 상품정보·대표이미지·가격을 되돌리는 문제도 수정했다. 7단계 작업창은 보관한 쿠플러스 화면의 제목·단계명·진행 막대 형태로 정리했다.

## 가격 재계산

기록된 쿠플러스 공개 클라이언트의 `updatePricing → recalculateOption`과 2단계 화면 안내를 대조했다. 최소 공급 마진 보장 시 이 명시 재계산은 판매 묶음 원가에 최소 마진액을 직접 더한다. 중앙 worker가 신규 초안에 쓰는 비율/최소액 비교와 같은 분기가 아니다. 기존 원본 코드를 앱에 복제하지 않고, 관찰한 계산 계약을 앱의 가격 함수로 구현했다.

25.6 CNY·환율350·공급마진50%·쿠팡마진40%·최소액3000·10원 반올림·MSRP1.3 예시에서 신규 초안은 17,920/29,870/38,830원을 유지한다. 사람이 **일괄 재계산 → 이 가격 저장**을 실행한 경우 공급가/판매가/MSRP는 **11,960/19,930/25,910원**이다. 5.23 CNY 예시는 양쪽 모두 4,830/8,050/10,470원이다.

- 버튼은 현재 미저장 정책의 다른 입력을 유지하며 기록된 반올림 방식을 미리보기에 적용한다. 버튼만 눌러서는 서버에 저장하지 않는다.
- 명시 저장한 정책에만 optional `recalculationMode: couplus-stage-two-v1`을 보관한다. 이 표시와 양수 최소액이 있을 때만 원가+최소액을 사용한다. 이전 정책과 신규 수집의 JSON·계산 분기는 유지한다.
- 저장된 같은 정책을 옵션 가격·7단계·원본 Excel에 사용한다. 구성 수량과 통합통관의 묶음당 고정 비용 계산을 유지하며 기존 수동 가격·직접 공란을 덮지 않는다.
- 알 수 없는 재계산 값은 거부한다. 재계산 버튼 이후 사용자가 직접 고른 기존 ‘올림’은 계속 사용할 수 있다. 그 수동 조합은 쿠플러스 원본의 반올림 사례와 같다고 주장하지 않는다.
- 확인한 통합통관 환율의 명시 입력 계약은 유지한다. 타사의 자동 통합 요율 조회까지 구현 완료한 것은 아니다.

## 단계 저장과 작업창

SEO 저장 후 첫 상품 조회를 지연시키고 대표이미지를 저장하여 두 번째 조회를 먼저 완료한 뒤 첫 응답을 돌려주면, 이전에는 목록과 열린 편집기가 이전 시각·대표이미지로 되돌아갔다. 마지막 시작한 상품 조회만 적용하고 선택 상품의 navigation과 현재 저장 시각도 확인한다. 초기 조회·오래된 실패·최신 실패·닫기·다른 상품 이동·직접 가격 저장 뒤의 지연 응답을 검사했다. 회원 설정과 카테고리의 기존 조회 순서 보호는 유지한다. 편집기 key를 바꾸거나 미저장 입력을 지우지 않는다.

작업창 제목을 `상품 등록 진행: …`으로 표시하고 SEO 설정·가격 설정·대표 이미지·추가 이미지·상세 이미지·한글 표시사항·견적서 작업 순서와 얇은 연속 진행 막대를 적용했다. 등록번호·등록일·원본 URL은 기존 ‘카테고리 · 수집 자료’에 보관한다. 원본 링크와 단계 이동 handler는 유지하며 진행 막대는 입력 위치를 나타낸다. 보조 작업으로 이동해도 마지막 등록 단계의 표시를 유지하고, 접수 완료 상태로 계산하지 않는다.
