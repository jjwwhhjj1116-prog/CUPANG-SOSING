# Step707 — 수동 사이즈표 편집과 단일 견적 이미지 연결

기준 `4cd1a2dafc42633636192629e052cdb06b828e71`. 원본 근거는 [사이즈표 대조](step707-size-chart-parity-audit.md)다. 보관된 Couplus 코드와 REA Evidence를 사용했으며, 기존 운영 상품이나 공유 Chrome 탭을 조작하지 않았다.

## 변경한 동작

원본에는 사이즈별 열·측정 항목별 행을 직접 작성하는 편집기가 있다. 자체는 옵션의 가로·세로·높이·무게·수량을 고정 6열로 조판할 수 있었지만, 총장·가슴둘레처럼 자유로운 측정표를 작성·저장할 수 없었다. 새 주 편집기에 사이즈 유형, 단위, 쉼표로 나눈 사이즈 열, 측정 행 추가·삭제, 셀 내용, 저장·재조회·입력 취소를 연결했다. 사이즈표가 미사용인 옵션의 버튼도 SEO가 아니라 해당 옵션 편집기로 연결한다.

저장 모델은 선택적 `ProductContent.manualSizeChart`다. 이전 자료에는 이 값을 추가하지 않으며, 없으면 기존 옵션 치수 표를 유지한다. 단위는 원본의 `cm/mm/inch/㎡`를 사용하고 값은 문자열로 보존한다. 숫자 환산, 임의 실측값, 카테고리 예시 치수 주입은 없다. 직접 표를 해제해 기존 옵션 치수 표로 돌아가는 것도 명시 저장이다. 자체 한도는 20열·60행·항목명/열 이름80자·셀200자·64KiB이며 원본의 서비스 한도로 주장하지 않는다.

표가 실제로 바뀌면 이전 사이즈표의 활성 연결을 해제한다. 원래 파일과 다른 이미지 역할은 보존한다. 같은 표를 다시 저장하면 활성 연결도 유지한다. 표 변경과 사이즈 이미지 지정을 한 요청에 섞어 낡은 PNG를 재연결할 수 없다. 원래 콘텐츠 revision과 이미지 pool을 SQL 저장 조건에 함께 넣어, 같은 상품 시각에 발생한 이미지 변경도 놓치지 않는다.

저장한 수동 표는 PNG 계획에 반영된다. 긴 표 제목·열 제목·셀은 줄바꿈하고 전체 높이 제한을 적용한다. 단위도 표시하며, 정확한 빈 셀은 `-`, 공백 셀은 원문 공백을 유지한다. 원본의 600px HTML/scale2 픽셀을 그대로 복제한 결과는 아니며, 원본에서 빠져 있던 top-level 단위는 자체 출력에 분명히 표시한다.

재생성 PNG를 첨부할 때 활성 사이즈표를 한 장으로 교체한다. 이전 append 경로는 정상 재생성을 두 번 하면 두 장이 되어, 확인된 Single 한 URL 형식과 충돌했다. 이전 파일은 상품 pool과 저장소에 남는다. 표시사항의 기존 복수 첨부 동작과 견적서에서 직접 정한 옵션별 사이즈 이미지·공란은 유지한다.

편집 중에는 PNG 생성·첨부를 막는다. 외부 저장으로 버전이 바뀌어도 입력을 유지하고, 최신 저장본을 명시 조회한 뒤 저장하게 한다. 저장 응답이 유실되면 정확한 다음 revision·요청 표·다른 콘텐츠 보존·활성 이미지 해제를 GET으로 확인한다. 이를 확인하지 못하면 입력을 남기고 오류를 표시한다. 이전 요청·언마운트 응답은 저장 완료로 인정하지 않는다.

## 검수와 범위

검사는 합성 계정·카테고리 schema·이미지·원문을 사용하는 격리 환경에서 실제 자체 React callback, content/attachment API, SQLite, R2 모형과 Single 자료 준비 경로를 실행한다. 양사에서 직접 표 저장→PNG 두 번 생성·첨부→정확한 단일 공개 이미지 URL→한 옵션 Single packet까지 확인한다. 공개 URL은 로컬 media handler가 반환한 실제 fixture 바이트와 대조한다. 실제 CDN 가용성·브라우저 글꼴 픽셀·1688 수집·Supplier Hub 원격 접수 증거는 아니다.

원본 AI의 상세 이미지 측정표 검출·번역은 별도 기능이며 이번 수동 편집 변경으로 완성됐다고 보고하지 않는다. 모든 카테고리의 최신 필요 여부·공식 양식, 새 실상품의 전체 SKU/가격/이미지 수집, 실제 Hub 접수번호와 SKU 대조도 남아 있다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 전송 gate를 유지한다.

최종 11개 고유 파일의 **131개 검사**가 모두 통과했다. 신규20개(수동 모델/API9·편집기/PNG/Single10·옵션 진입1)를 포함하며, 개별 반복 실행과 수정 전 중단 실행은 합산하지 않았다. 1,251개 소스·설정·테스트 파일의 실행 전후 SHA가 동일했다. 타입·app/db lint·변경 MJS lint·schema fresh/repeated memory·운영 빌드도 통과했다. 최초 UI 검사에서는 새 버전 GET을 기다리지 않던 fixture와 이미 줄바꿈된 셀을 한 draw-call로 가정한 fixture를 바로잡았으며, 긴 제목/헤더와 모든 셀 문자열 보존 단언은 유지했다. 초기 타입 표기 오류도 최종 검사 전에 수정했다.

최종 검사·배포 결과는 HANDOFF의 Step707과 `outputs/step707-final-validation.json`에 기록한다. 전체 저장소 테스트나 전체 기능 동일성·완료율100%를 주장하지 않는다.
