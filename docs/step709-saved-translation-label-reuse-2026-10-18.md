# Step709 — 완료된 수집 속성 번역을 표시사항에서 재사용

기준 `4d77641`. 기존 단계의 표시사항 구조·빈행 PNG·AI 세 필드 초안은 유지한다. 이번 확인은 자체 저장/조회 경로의 실제 기능 누락이며, 관측하지 못한 Couplus 서버 구현을 추정한 결과가 아니다.

## 확인한 문제

정상 URL 초안은 수집 원문을 번역하고 SEO/옵션에 적용하면서 상품 버전이 전진한다. 완료된 번역 이력은 생성 당시 버전을 보관하며 `/translation` 조회가 이를 현재 버전으로 바꾸지 않는다. 그런데 기존 표시사항 연결 UI와 순수 helper는 `job.productVersion === currentVersion`을 요구한다. 따라서 같은 상품의 같은 수집 원문에서 이미 번역한 속성도 다음 표시사항 단계에서 재사용할 수 없었다.

`outputs/step709-settings-label-clock-before.json`은 양사 격리 fixture의 실제 intake→번역 완료→SEO/옵션 적용→현재 원문 조회 경로를 보관한다. `用途=运动`은 이미 `용도=운동용`으로 번역되어 있지만 초기 표시사항의 사용 기준은 `14세이상`이며, 명시 연결을 시도하면 버전 불일치로 거절된다. 원문 reference는 현재 수집 요청과 정확히 같다. 실패 원인을 분리하기 위한 진단 복제본에서만 버전을 바꿔 계획을 계산했으며 실제 저장이나 저장 이력 수정은 하지 않았다.

## 별도 표시사항 전용 경로

`GET /api/products/:id/translation-labels?jobId=...&profileId=...`는 현재 상품·회원 회사·카테고리와 연결된 완료 번역의 공급자 원문을 검증한다. 기존 `intakeSupplierSourceMatches`로 제목·설명·reference·카테고리·캡처한 안내·공급자 속성 전체를 현재 불변 수집 자료와 대조한다. 옵션 전용 번역, 다른 상품/회사/카테고리와 달라진 원문은 사용할 수 없다. 원래 job의 버전을 현재 버전으로 위장하거나 저장하지 않는다.

응답은 현재 콘텐츠 버전과 fingerprint, 원문/번역 sourceIndex, 연결 가능한 고정 표시사항, 현재값 및 보호 사유를 제공한다. 내용에서 직접 저장한 값과 공란, 주 제품 라벨의 공통 직접 수정값은 보호한다. 옵션별 라벨 수정값은 유지된다. 원문 식별 필드와 다른 항목으로 자동 추천하지 않으며 여러 후보가 있으면 첫 값을 선택하지 않는다. 사용자는 원문·번역·현재값을 보고 연결 항목을 고른다. 새로운 AI 호출이나 별도 승인 checkbox는 필요하지 않다.

`POST`는 현재 상품/콘텐츠 버전·fingerprint와 선택한 sourceIndex/대상 필드만 받는다. 값은 저장된 번역에서 서버가 다시 읽는다. 클라이언트가 새 번역값을 보내지 않으며 동일 값/중복/보호 항목은 거절한다. 성공 응답은 `{view, applied}`다. 기존 일반 SEO 적용, 옵션·일괄 번역 helper의 버전 검사는 완화하지 않았다.

## 저장과 보존

기존 테이블만 사용한다. 하나의 guarded D1 batch에서 콘텐츠의 선택한 label 필드와 상품 버전/견적 대기 상태만 전진한다. 현재 콘텐츠/옵션/견적/주 라벨 원문 payload, 가격 정책·설정·프로필, 수집 원문, 완료 translation review/result, 승인 회원 회사 상태를 비교한다. 내용 저장을 DB trigger가 무시하는 경우 마지막 제약 검증이 전체 batch를 rollback한다. 다른 화면의 같은 시각 콘텐츠 변경은 보존하고 요청을 거절한다.

저장된 번역 이력·수집 원문·옵션·가격·설정·파일 pool과 PNG는 변경하지 않는다. 새 표시사항은 주 라벨의 해석값 및 PNG 생성 계획에 전달된다. 기존 PNG를 자동으로 새 이미지라고 취급하지 않으며, 사용자가 기존 흐름으로 다시 생성·연결해야 한다. 카테고리 상품고시와 Supplier Hub 전송은 이 작업이 수정하지 않는다.

## 검수 경계

신규 backend 단위4/API3, 총7개가 통과했다. 양사 실제 로컬 API/SQLite intake와 저장된 원문/번역/옵션 보존, 주 라벨 PNG 계획의 변경값 연결, 보호된 공통 공란, 다른 소유자의 번역, 수집 원문 변경, 같은 시각 CAS 및 콘텐츠 저장 무시 시 원자 rollback을 확인했다. 자동 추천의 중복 원문/번역 heading 반례도 검사했다. UI/클라이언트와 최종 관련 회귀 수치는 부모 작업의 최종 보고에서 별도로 집계한다.

공급자 원문·회원·이미지·AI 응답은 격리된 합성 fixture다. 재사용 GET/POST 중 provider 호출은0이며 실제 외부 요청, 사용자 Chrome 제어, 기존 운영 상품 또는 Supplier Hub 변경은0이다. 새로운 schema/migration/유료 서비스/리소스/확장/전송 gate 변경은 없다.

## 화면과 저장 결과 확인

현재 버전의 기존 표시사항 연결은 유지하고, 완료 번역이 과거 상품 버전에 묶였을 때만 별도 재사용 영역을 보여준다. 불러오기 버튼이 현재 수집 원문·카테고리와 저장한 번역을 조회한다. 원문 속성명/값, 한국어 이름/값과 현재 표시사항을 나란히 보고 연결할 항목을 선택한다. 중복 연결과 보호된 수동값은 저장할 수 없다. 같은 값인 항목은 변경에서 제외하며 추가 번역 요청·동의 checkbox는 없다.

Dashboard의 선택한 카테고리 프로필은 재사용 GET·POST·복구 GET까지 전달된다. 프로필이 바뀌면 이전 자식 컴포넌트를 해제하여 옛 요청이 새 카테고리에 적용되지 않는다. 재사용 중에는 부모의 다른 번역 요청과 적용 버튼도 함께 잠그되 자식 자신의 응답을 잘못 무효화하지 않는다. 완료 후 남아 있는 예전 버튼 callback도 재저장하지 않는다.

POST 응답은 선택한 필드의 실제 저장값과 나머지 값, 버전·revision·원문·카테고리를 검증한다. 응답이 유실되거나 잘못된 ACK가 오면 완료로 표시하거나 자동 재전송하지 않는다. ‘최신 상품·표시사항 저장 결과 다시 조회’는 검증된 GET만 수행한다. 커밋 전503처럼 버전이 그대로면 최신값으로 다시 검토하여 직접 저장할 수 있고, 버전이 바뀌었으면 현재 저장값을 확인하고 부모 상품을 새로 읽는다. 이 동일 버전 복구는 독립 검토에서 발견한 잠금 결함을 고친 것이다.

추가 UI 검사11개와 부모 요청 검사33개가 통과했다. UI 검사에는 양사 실제 intake·로컬 API·SQLite → 화면의 연결 선택 → 서버 표시사항 저장 → 주 라벨 PNG 조판 계획의 ‘사용 기준=운동용’ 연결이 포함된다. 원문·기존 다른 상품·다른 표시사항·옵션·가격·이미지를 보존한다. 별도 HTTP 대체 검사에서 실패 조회 재시도, 잘못된 원문 ID/시각, 중복·수동값·공란, 미저장503/커밋된 ACK 유실의 구분, 잘못된 ACK, 비활성/닫힘/늦은 callback을 검사했다. 실제 사용자 브라우저 픽셀·실제 OCR·외부 번역 품질이나 Supplier Hub 접수 증거는 아니다. 최종 관련 묶음은 `outputs/step709-related-final-proof.json`에 기록하며 반복 검사 개수를 합산하지 않는다.
