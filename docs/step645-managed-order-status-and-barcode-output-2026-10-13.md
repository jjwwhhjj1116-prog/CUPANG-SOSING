# Step 645 — 상품관리 발주가능상태와 저장 바코드 출력

상품관리(신규)의 발주가능상태 전용 필터와 바코드출력 버튼을 연결했다. 등록 상품의 원본 SKU·바코드·상품명·저장된 표시사항을 사용하며, 기존 상품이나 견적서를 변경하지 않는다.

## 확인한 쿠플러스 동작

- `outputs/step643-couplus-management-current.txt`: 상품관리의 22개 열과 발주가능상태 전용 버튼.
- `outputs/step630-couplus-management-contracts.json`, `outputs/step630-couplus-management-public-methods.json`: 원본 상태별 필터, 상품/SKU/바코드 출력, 표시 폭 300px·바코드 높이 50·수량 1·간격 0. 실제 래퍼는 JsBarcode의 CODE128을 사용하며, 별도의 미사용 MSI 설정을 적용하지 않는다.
- 공급자 공개 코드는 동작을 읽는 참고 자료로만 사용했다. 실행하거나 구현 소스로 복사하지 않았다. 현재 쿠플러스 상품관리 계정에는 등록 상품 DB가 없어 실제 행의 인쇄 결과와 용지 치수는 확인하지 못했다.

## 구현

### 발주가능상태

로그인 회원의 승인된 회사에 속한 전체 저장 상품에서 상태별 건수를 집계한다. 페이지·검색 조건으로 집계 범위를 축소하지 않는다. 원문을 trim하거나 이름을 바꾸지 않으며 공란과 공백이 있는 문자열을 구분한다. 상태 선택은 검색·기본 필터·열 필터·정렬과 AND로 조합되고 상품DB 다운로드에도 동일하게 적용된다. 선택 후 페이지는 1로 돌아간다.

쿼리를 생략하면 전체, `orderStatus=`는 명시적인 공란, 그 외는 원본 문자열과 정확히 일치하는 상품이다. 최대 200가지 상태와 문자열 길이 2000자를 지원한다. 초과·손상·중복 조건에서는 부분 목록을 완성된 목록으로 보여주지 않는다. `발주불가`의 기존 의미인 `정상` 외 상태는 유지한다.

### 바코드출력

해당 행의 버튼이 회사·계정·SKU를 고정한 조회 창을 연다. CODE128은 [공식 JsBarcode](https://github.com/lindell/JsBarcode) 3.12.3을 정확한 버전으로 추가해 인코딩한다. 원문 문자열의 앞자리 0과 공백을 보존하며, 빈 바코드·지원되지 않는 문자·128자 초과는 출력하지 않는다. 새로운 바코드를 발급하지 않는다.

폭 300px, 높이 50px, 수량 1, 간격 0으로 시작한다. 상품 자체에 저장된 표시사항이 있으면 기본 미리보기에 포함한다. 같은 바코드와 연결된 저장 구매정보의 표시사항도 선택할 수 있다. 다른 바코드의 구매 행은 출력 후보에 넣지 않는다. 회사명·제조국·KC 인증·식품용 마크 등을 추정하거나 쿠플러스의 상호를 기본값으로 삽입하지 않는다.

바코드 미리보기를 확인한 뒤 PNG 다운로드 또는 인쇄를 직접 누른다. PNG는 한 장이고 인쇄 수량은 인쇄에만 적용된다. 인쇄 문서는 앱 표와 분리한 프레임에 라벨만 담는다. 출력은 로컬에서 처리되며 외부 이미지/폰트/번역 요청을 만들지 않는다. 용지와 배율은 브라우저 인쇄창에서 확인할 수 있다.

인쇄 항목은 제품명·수입원/판매원·제조원·제조국·내용량·재질·상품유형·주의사항·사용기준·기타 표시사항이다. 저장된 KC/식품용 불리언과 확장 메타데이터는 보관하면서 인쇄 텍스트에서 제외한다. `kc인증: false` 같은 설정 문구를 소비자 라벨에 찍지 않는다. KC/식품용 그래픽 표시와 실제 용지별 프린터 검수는 아직 완료하지 않았다.

출력 직전 원본 상품과 구매정보 버전을 다시 조회한다. 계정·승인 회사·원본·표시사항이 바뀌면 409와 재조회 잠금으로 이전 미리보기의 출력을 막는다. 입력 변경 후 남은 이전 버튼 콜백, 중복 클릭, 지연 응답, 계정 변경, 컴포넌트 종료도 검증한다. 바코드 GET은 SELECT만 수행하며 조회를 위해 테이블을 만들거나 상품을 쓰지 않는다.
