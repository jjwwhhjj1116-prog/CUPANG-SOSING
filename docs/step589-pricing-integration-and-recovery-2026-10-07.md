# Step 589 — 통합통관 원가와 옵션 가격 저장 복구

기준 커밋: `02a440faf09edf2084c6be3b604614fd005df1c5` (step588).

## 확인한 계산 계약

보관한 쿠플러스 기본설정 화면과 공개 클라이언트 함수의 제한된 가격 경로를 대조했다. 통합통관 매입가는 `(단품 CNY × 판매 구성 수량 × 통합통관 환율 + 포장검수 200원 + 바코드 100원) × 1.1`을 **원 단위로 먼저 반올림**한다. 고정 비용은 구성품마다 반복하지 않고 판매 묶음당 한 번 적용한다. 번들 수량 선택은 원본처럼 일반환율로 계산하며, 최종 묶음 원가에 통합 요율을 적용한다.

기존 일반환율 계산, 공급/쿠팡 마진, 최소 마진 비교, 최종 가격 처리 단위와 MSRP 배수는 유지한다. 실제 관찰된 25.6 CNY → 공급 17,920원·판매 29,870원·MSRP 38,830원 및 5.23 CNY → 공급 4,830원·판매 8,050원·MSRP 10,470원 예시를 회귀 검사한다. 원본 내부의 다른 가격 편집 경로에는 최소 마진 분기가 다르므로 모든 쿠플러스 경로의 결과를 동일하다고 확정하지 않는다.

쿠플러스 원본의 통합 요율 조회 응답은 확보하지 않았다. 타사 로그인 API를 앱의 가격 제공자로 연결하거나 일반환율을 통합 요율이라고 표시하지 않는다. 이번 기능은 **확인한 별도 통합 요율의 명시적 입력**을 지원한다. 쿠플러스의 자동 요율 조회와 동일한 기능은 아니다.

## 구현

- 회원 기본설정과 상품 가격 단계에 통합통관 사용/환율 입력을 추가한다. 활성화할 때 양수의 유효한 별도 요율이 필요하며 요율이 없으면 가격을 만들거나 저장하지 않는다. 원가 변환은 유리수로 계산하여 중간 부동소수점 오차를 방지한다.
- 신규 URL 수집 요청은 당시의 활성 설정을 저장하고 해당 상품의 옵션·견적 계산에서 같은 정책을 사용한다. 회원 설정을 바꾸어도 기존에 저장한 상품 정책을 덮어쓰지 않는다. 가격 정책이 없는 이전 상품도 새 통합 모드를 소급 적용하지 않는다.
- 비활성 정책에서는 새 가격 키를 직렬화에서 제외한다. 비활성 기본값 추가 때문에 이전 설정 지문이나 수집 요청 식별값이 바뀌지 않도록 한다. 관찰된 일반환율 프리셋을 적용하면 통합 모드를 끄고, 입력해 둔 비활성 요율은 설정 입력란에 보존한다.
- 수동 옵션 가격 저장은 가격 항목의 정확한 연결, 전체 수동 수정값, 옵션·카테고리·상품 저장 시각·원천 버전과 응답의 저장 결과를 확인한다. 불완전한 성공 응답으로 입력을 지우지 않는다. 저장 후 응답이 유실되면 명시적으로 최신 저장본을 읽어 동일 저장을 확인하고, 다시 PUT을 보내지 않는다.
- 가격 정책 저장은 JSON 본문 8KB 제한과 같은 사이트 요청 검사를 사용한다. 클라이언트가 전송한 계산 총액이나 추가 필드는 받아들이지 않으며 저장된 원가에서 계산한다. 저장 전후 사이에 제거된 상품은 원자적 SQL 조건에서 가격·정책 쓰기를 중단한다.

## 전체 완료와 구분하는 범위

실제 통합 요율 제공자의 자동 조회, 모든 카테고리 기본값·편집 경로의 전수 대조, 공식 Excel 및 Supplier Hub 최종 접수 검증은 별도 남은 작업이다. 이번 가격 변경으로 실제 회원 설정이나 작업 상품의 가격을 자동 수정하지 않는다.
