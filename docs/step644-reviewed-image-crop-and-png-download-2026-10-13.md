# Step644 — 이미지 잘라내기와 PNG 다운로드

카테고리 선택 → 1688 URL → 편집 가능한 1~7단계 초안 → 검토·수정 → 명시적 Supplier Hub 등록전송 흐름에서 이미지 편집 기능을 확장한다. Step643에서 읽기 전용으로 확인한 Couplus 대표사진 편집 화면의 잘라내기·다운로드 도구를 이번 구현 범위의 근거로 삼았다. 기존 상품·대기열·계정 기본설정·Couplus 작업상품을 수정하거나 전송하지 않는다.

대표·추가·상세 이미지 편집에서 원본 픽셀 좌표의 사각형을 드래그하거나 숫자로 입력해 남길 영역을 선택한다. 문구·지우기 영역·브러시는 원본 전체에 먼저 렌더하고 마지막에 영역을 자른다. 잘라내기만 단독으로 미리보기할 수도 있다. 도구를 닫거나 브러시로 전환해도 선택 영역을 유지하며, 잘라내기 초기화는 선택 영역만 제거한다. 기존 문구·브러시 되돌리기/다시 실행은 유지하되 이번 범위에서 잘라내기를 해당 이력에 통합하지 않는다.

좌표를 수정하면 기존 미리보기 참조와 적용·다운로드 경로를 즉시 무효화한다. 잘못된 좌표는 수정할 초안으로 보존하고, 미리보기와 서버 저장에서 거절한다. 원본·회사·옵션·견적서 위치·버전이 바뀌거나 드래그 중 화면 위치가 바뀌면 미완성 선택을 새 대상에 적용하지 않는다. 같은 원본을 다시 확인하면 문구·영역을 유지하며, 다른 원본 바이트에 자동으로 옮기지 않는다. 저장 응답이 불명확한 경우 새 잘라내기나 새 PNG로 교체하지 않고 동일한 원본 증거·잘라내기·PNG 지문으로 저장 결과를 조회하고 명시적으로 재시도한다.

검토한 PNG는 브라우저의 해당 Blob URL에서 명시적인 다운로드로 저장한다. 서버 적용과 별개의 로컬 작업이며, 오래된 미리보기·미저장 결과가 불명확한 상태·다른 대상에서는 다운로드를 막는다. 적용 API는 정수 좌표·원본 표시 크기·PNG 실제 가로세로와 선택 위치를 검증하고, 잘라내기 증거를 결과 키·메타데이터·응답·복구에 연결한다. 잘라내기가 없는 기존 키·결과·복구 계약은 유지한다.

최종 시험은 서로 다른 21개 파일의 265/265개가 통과했다. 코어·PNG 검증·API/SQLite/XLSX 복구 검사 152개와 화면·정확한 옵션 위치·기존 편집 보호 검사 113개로, 중복 파일을 두 그룹에서 집계하지 않았다. 새 잘라내기 검사 34개는 코어 19개, 화면·포인터 9개, 양사 3단계 연결 6개다. 타입 오류 0개, lint 오류 0개와 기존 경고 8개, 운영 빌드가 통과했다. 기존 이미지 용량 경계 시험은 50개를 최대라고 가정했지만 HEAD에서도 실제 최대 150개로 동작했으므로 선언된 한도에서 시험하도록 보정했다. 한도 도달 시 400·버전 변경 시 409·쓰기 0회와 원본 보존 검사들을 유지했다.

같은 지정 Chrome에서 격리된 실제 DetailPanel/이미지 편집기/API/SQLite의 6사례(유앤채·와이홉 × 대표·추가·상세)를 검수했다. 합성 160×96 원본의 x=16, y=8, 가로100, 세로64를 잘라낸 뒤 각 옵션의 정확한 사진 위치에 적용했다. 각 사례 14개 검사 모두 통과했다. 원본과 출력 PNG를 실제 디코딩해 네 모서리 픽셀과 100×64 크기를 대조했고, 다른 사진의 순서·다른 옵션·가격·회사·원본 바이트 및 메타데이터가 보존됐다. 현재 화면 카드도 저장한 참조와 일치했다. 각 사례의 명시적인 적용 POST는 1회였으며 OCR·번역 모델·실제 1688·Supplier Hub 전송은 없었다.

와이홉 대표사진 사례에서는 다운로드 버튼을 직접 눌러 1,150바이트 PNG 파일이 실제 저장된 것을 확인했고, 서버에 적용한 PNG의 SHA256 `d94374c35986f9ac4e455f804c61943aef63a79630690aa1204b5e99b8545304`와 동일했다. 브라우저 도구의 다운로드 이벤트는 제한 시간 내 반환되지 않아 해당 파일의 존재·크기·지문으로 결과를 확인했다. 로컬 편집 화면 스크린샷은 캡처 제한 시간으로 저장되지 않았으므로 화면 캡처 성공을 주장하지 않는다. 실제 PNG와 검수 JSON은 Git 제외 outputs/step644-crop-*에 저장했다.

운영 Worker `d219b6ad-f834-4bb9-8abe-bf066540abd1`로 배포했다. 실제 페이지에 `dashboard-client-D_WLognJ.js`가 로드됐으며 배포 전후 기존 상품 표 1행·입력 29개, 계정 기본설정 35개, 복원된 대기열 입력 10개와 내용이 완전히 일치했다. 설치된 확장 0.2.64와 배포 ZIP은 그대로이며 확장 새로고침이 필요하지 않다. 운영 화면 스크린샷을 저장하고 직접 확인했으며, 배포 검수 14개가 모두 통과했다.

전체 카테고리 동등성·전체 외부 이미지 편집기 도구 동등성·새 실상품 1688 수집과 Supplier Hub 접수 완료까지 검증했다고 표시하지 않는다. 잘라내기 이력의 문구 이력 통합, 매직 지우개의 AI 복원, 상품관리(신규)의 원격 DB 갱신·허용 스토어·바코드 출력 등도 남은 별도 범위다. 상품관리 22열 순서는 기록된 Couplus 화면과 맞지만 현재 목록 새로고침은 가져온 로컬 DB 조회다. 기존 등록심사 조회를 재고·공급가·판매가·리뷰 등의 원격 상품 수집이라고 표시하지 않는다. 발주가능상태는 원본 값의 전용 필터, 바코드는 저장된 값의 미리보기·명시적 출력부터 별도 구현할 수 있음을 읽기 감사로 확인했다.
