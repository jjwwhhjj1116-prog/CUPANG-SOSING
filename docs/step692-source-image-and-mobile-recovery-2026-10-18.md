# Step692 — 옵션 원본 사진 연결과 Chrome 수집 재시도 복구

2026-10-18 KST. 기준은 Step691 `9e3ea252179b46e678a7a46ae7aecf90ad44eb4e`다. 이번 범위는 URL로 받은 원문의 옵션 사진을 초안에 연결하는 규칙과, Chrome 공개 수집 준비가 일시 실패한 뒤 사용자가 다시 시도하는 경로다. 기존 작업 상품·쿠플러스 저장값·Supplier Hub·운영 DB는 수정하지 않았다.

## 쿠플러스와 맞춘 사진 선택

보관된 `processOptions`는 실제 SKU의 첫 속성 사진, 둘째 속성 사진, 상품 갤러리 첫 사진 순서로 옵션 원본 대표사진을 정한다. 첫·둘째 속성의 사진 주소도 각각 보관한다. REA Evidence와 원본 범위·SHA, 자체 수정 전 재현은 [원본 대조](step692-intake-parity-audit.md)에 기록했다. 기존 REA6.5 분석을 재사용했으며 같은 분석을 새로 실행한 것으로 표현하지 않는다.

기존 앱은 모든 속성 사진을 검색했고 없으면 옵션의 원본 사진 연결을 생략했다. 견적서는 공통 대표사진을 대신 표시하므로 처음부터 사진이 보이지 않았다는 뜻은 아니다. 해당 SKU의 SEO 원문 사진과 명시적 원본 연결이 없고, 공통 사진을 나중에 바꾸면 옵션 사진도 함께 바뀌는 차이가 있었다.

`parseAlibabaProduct`에서 첫 두 속성의 유효 사진 후보를 모두 보관하고, 선택 우선순위를 적용했다. 두 후보가 없으면 이미 등록한 갤러리 첫 사진의 index0을 쓴다. 세 번째 이후 속성 사진은 옵션 사진 선택·후보에 사용하지 않는다. 다른 속성의 이름·값·색상·사이즈는 기존 규칙을 유지한다. 동일 URL의 갤러리/옵션 사진은 재사용하며 별도 상세 이미지 역할은 보존한다.

최초 수정은 선택한 첫 사진만 보관해 둘째 후보를 잃는 문제가 있었다. 독립 검토에서 확인한 뒤 첫 두 후보 보관을 복원했다. 명시된 후보가 잘못된 주소면 조용히 다른 사진으로 바꾸지 않고 거절한다. HTTPS Alibaba CDN·실제 SKU 연결·이미지 크기/상한·수동 공란/번역 사진 보존 조건을 완화하지 않았다. Step691의 공급자 SKU 없는 기본 옵션은 계속 공통 사진을 사용하며, 과거 원문에 index를 소급 추가하지 않는다.

이 변경은 검증된 API 후보 응답의 정규화 경로다. 실제 OpenAPI 계정이나 수집 서비스의 응답 호환성을 새로 검증했다는 뜻이 아니며, 공개 모바일 원문에 이 API 형식을 임의로 붙이지 않는다.

## 일시적인 Chrome 초기화 실패 복구

`mobile-transport.mjs`는 확장 시작 시 자신에게 속한 미완료 임시 규칙을 정리한 Promise를 Chrome API 객체별로 공유한다. 기존에는 이 준비가 실패한 Promise까지 영구적으로 재사용했다. 그 결과 일시적인 Chrome 서비스 오류 한 번으로 이후 새 수집 요청도 같은 오류로 실패하며, 다시 초기화를 검사하지 않았다.

실패한 **동일 Promise만** 공유 캐시에서 제거했다. 현재 대기 중인 요청들은 모두 원래 실패를 받는다. 자동 반복·추가 fetch를 하지 않는다. 사용자의 이후 명시적인 수집은 규칙 조회·정리를 다시 통과해야 한다. 성공한 준비의 공유, 다른 확장의 규칙 보존, 작업 취소·현재 앱 확인, 익명 요청 조건과 정리 실패 시 결과 반환 금지는 그대로다.

이것은 접근 차단 화면이나 인증을 우회하는 수정이 아니다. 실제 새 상품 페이지·네트워크·계정·Chrome 창에 접근하지 않고 모의 Chrome API와 모의 fetch로 실패와 다음 시도만 재현했다. 성공한 준비 이후의 개별 요청 정리 오류를 모두 해결했다고 확대하지 않는다.
