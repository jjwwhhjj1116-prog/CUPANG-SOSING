## 가져오기와 데이터 보존

상품관리 앱 경로는 승인된 로그인 계정의 회사 확인 → XLSX 미리보기 → 원본 회사 명시 확인 → 가져오기이다. 파일에 회사코드 열이 있으면 로그인한 회사와 일치해야 하며, 실제 저장은 미리 본 파일 SHA와 일치해야 한다.

`managed_products`는 **owner·회사코드·SKU**를 복합 키로 사용한다. 같은 자료를 다시 가져오면 중복 행을 만들지 않고 최초 이관 정보도 유지한다. 같은 회사·owner·SKU의 원문이 실제로 달라지면 해당 상품관리 행만 갱신한다. 기존 `products`, 수동 콘텐츠, 수집 작업, 이미지 작업, 견적·Hub 접수 기록과 분리했다.

이번 실제 이관은 앱 업로드 UI와 같은 XLSX 파서 및 DB 가져오기 SQL을 재사용한 `scripts/prepare-managed-product-import.mjs`로 준비했다. SQL 길이를 제한한 작은 묶음으로 나누고, 모든 INSERT에서 정확한 owner·회원 이메일·`member` 역할·승인 상태·와이홉 회사코드와 회사명을 다시 확인했다. 생성된 SQL은 무시 대상인 `outputs`의 전용 비공개 폴더에만 저장했다. 비밀번호나 로그인 비밀정보는 포함하지 않는다.

생성기의 미리보기·검증 SQL은 SELECT만 수행한다. 원격 실행 후 D1 조회와 실제 상품관리 화면에서 위 개수를 확인했다. **앱의 파일 선택·미리보기·업로드 전체 과정은 운영 브라우저에서 별도 재검수할 항목**이다.

## AI 등록 원본과 부분 견적

초기 이관에서는 `step573-couplus-ai-page1.json`의 100개, `step573-couplus-ai-page2.json`의 77개, `step573-couplus-running-vest-quote.json`의 부분 견적 1개를 보관했다. 초기 등록 177개에는 서로 다른 1688 URL 128개가 있었고 표시 옵션 합계는 1,270개였다. 이 수치는 초기 보존 이력이며 현재 전체 집계가 아니다. 빈 배열인 `step573-couplus-ai-all-page1.json`은 이관 자료로 사용하지 않았다. 이 파일들은 모두 비공개 `outputs`에 보관한다.

추가 확인한 10페이지의 원본 939행에서 이미 보관한 등록번호 177개와 충돌 2행을 제외하고 신규 760개만 추가했다. 기존 177개는 재촬영된 화면과 달라도 수정하지 않았다. 중복 원문 차이는 176개가 공백 차이이고 1개가 태그 차이였다. 신규 행 760개는 원본 행 객체 전체를 그대로 보관했다.

등록번호 `260719005001`은 같은 원본 페이지의 25행과 40행에 서로 다른 URL, 표시 옵션 수 2개와 46개로 존재했다. 운영 Chrome DOM에서 다시 확인했으며, 하나를 임의 선택하거나 인위적인 등록번호를 붙이지 않고 **두 행 모두 이관에서 제외해 별도로 보존**했다.

비공개 `outputs/private-historical-ai-delta-c6dc279a-583a-4488-821f-0fe81679f949/provenance-and-overlap-report.json`에 원본 10개 파일의 SHA, 원본·추출 행 매핑, 기존 177개와의 차이, 충돌 2행의 전체 원문을 보관했다. 원본 파일 자체는 변경하지 않았다.

최신 파서는 실제 화면에서 관찰한 태그와 두 칸 이상 공백으로 구분된 옵션 표시, 등록번호의 최대 두 개 접미사도 지원한다. 표시값 추출을 위해 원문 셀이나 등록번호를 다시 쓰지 않는다. 같은 URL로 여러 번 등록한 기록도 등록번호별로 유지한다. 목록의 셀·링크·이미지 참조와 원본 등록 상태를 보존하며, UI에서도 원본 상태와 부분 견적자료로 표시한다. `등록완료` 등 원본 문구를 이 앱에서 실행한 새 등록·전송의 증거로 사용하지 않는다.

부분 견적의 79개 입력은 원본 옵션번호·카테고리·관찰 시각과 함께 보관한다. 명시적 빈칸과 체크 해제값도 유지한다. 이관된 원문은 새 상품 초안이나 완성된 견적으로 자동 승격하지 않는다.

AI 원본 API는 승인된 와이홉 지정 계정만 허용한다. `historical_ai_records`는 owner·회사·자료 종류·등록번호·옵션번호로 구분한다. 같은 원문은 중복 저장하지 않으며, 같은 키의 다른 원문 또는 부모 등록 목록이 없는 견적은 거절한다. 충돌이 있는 배치의 일부만 추가하거나 기존 원문을 덮어쓰지 않는다.

추가 이관의 두 번째 원격 SQL 실행은 인증 오류 `10000`으로 일시 실패했다. 계정 인증 상태를 `whoami`로 다시 확인한 뒤 같은 중복 방지 SQL을 재실행해 완료했다. 최종 읽기 전용 조회에서 등록 937개·표시 옵션 합계 7,859개·부분 견적 1개와 staging 테이블 0개를 확인했다.

운영 저장 및 상품관리 목록 검수와 다음 작업은 구분한다.

- 제외한 충돌 2행의 처리와, 확인한 기간 밖에 추가로 필요한 AI 원본 자료가 있는지 확인한다.
- 하위 옵션별 견적, 이미지 파일 등 아직 확보하지 않은 자료를 확인한다. 현재 부분 견적 1개가 전체 하위 견적을 대체하지 않는다.
- 상품관리의 운영 파일 업로드 UI를 재검수한다.
- 새 상품의 1~7단계 초안 검토, 공식 견적 출력과 실제 Supplier Hub 접수를 별도로 검증한다. **이 자료 이관은 원격 Hub 접수 완료가 아니다.**

기존 상품을 임의로 변경하거나 완성하지 않은 단계·접수 상태를 완료로 표시하지 않는다.
