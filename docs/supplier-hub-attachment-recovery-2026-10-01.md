# 견적서 부분 전송 복원과 중복 전달 차단

2026-10-01, 단계 526. 등록전송 뒤 부분 첨부·응답 유실이 발생했을 때 같은 견적서의 결과를 재첨부 없이 조회하도록 수정했다.

## 재현한 문제

앱 전송은 업로드 전에 영구 전송 시도를 보관했지만, 등록 탭과 상품을 연결하는 `attempt:<tabId>`는 첨부 성공 응답을 받은 뒤에 저장했다. 일부 첨부나 응답 유실은 재전송을 막는 기록만 남겼다. 그 기록으로 앱을 다시 열어도 결과 조회가 원래 등록 탭을 찾지 못했다.

앱에서 준비한 패키지를 팝업으로 전달하는 경로는 준비 패키지를 한 번 소비했지만 앱 전송과 같은 영구 전송 시도를 보관하지 않았다. 부분 첨부에는 조회용 연결도 없었다. 파일을 다시 준비하거나 전달 경로를 바꾸면 같은 견적서를 별도로 전달할 여지가 있었다. 추가한 회귀 시험에서 기존 구현의 조회 연결 누락과 경로 간 중복 차단 실패를 확인했다.

## 변경한 동작

- 앱 전송은 정상 화면 사전 검사·최신 저장본 확인·영구 전송 시도 획득 후, 실제 파일 전달 전에 조회용 연결을 저장한다. 연결 저장 실패는 업로드 전에 중단한다.
- 팝업 전달도 사전 검사로 기존 첨부를 보호하고 같은 영구 전송 기록을 사용한다. 부분 첨부·응답 유실은 각각 `partial`·`unconfirmed`로 남긴다. 앱과 팝업은 같은 창별 전송 잠금을 사용하고 모든 종료 경로에서 잠금을 해제한다.
- 이전 버전의 영구 전송 기록만 남은 경우 정확한 출처·상품·카테고리·저장 지문·회사코드/회사명·옵션 수·탭·창·시도 상태·시각을 대조한다. 같은 회사 화면과 정확한 견적서 파일명을 조회한 뒤에만 연결을 복원한다.
- 복원은 기존 연결을 바꾸지 않는 IndexedDB 원자적 `claim`을 사용한다. 새 작업이 먼저 탭에 연결되면 복원을 중단하고 조회 결과도 저장하지 않는다. 기존 영구 시도 기록이 없는 과거 팝업 작업은 상품이나 회사를 추정하지 않는다.
- 복원된 연결은 기존 파일 검증 조회와 견적서 ID별 상품/SKU 조회에 사용한다. 복원·조회로 파일을 재첨부하거나 파일 검증을 다시 요청하지 않는다. SKU 발급은 검수 승인·최종 등록 완료와 구분한다.
- 새 전달에는 확장 0.2.30의 `durableAttachmentRecovery` 기능을 요구한다. 이전 버전의 보관된 시도/결과 읽기는 유지한다. 앱 다운로드 링크와 배포 ZIP을 0.2.30으로 연결했다.

## 검증

두 회사 `와이홉 A01464742`, `유앤채 A01526306` 각각 앱/팝업 전달의 부분 첨부·응답 유실을 시험했다. 실제 패키지 해석·SHA-256 검사·최신 앱 저장본 확인 함수·전송/조회 구현을 호출하고, Chrome API·첨부 바이트·Hub 표 응답은 시험 자료로 제공했다. 이후 파일 검증 → 정확한 견적서 ID의 두 SKU 조회로 이어지고, 업로드가 한 번이며 복원 중 검증 요청이 없는지 확인했다.

기존 버전 기록 복원, 다른 회사/창/상품/파일 거부, 새 작업 연결 보호, 복원 저장 시점 경합, 앱/팝업 동시 전달 차단과 잠금 해제도 시험했다. 보관소 구현은 직렬 트랜잭션 IndexedDB 시험 모델로 8개 동시 요청 중 하나만 기록되는지 확인했다. 실제 Chrome 프로필 보관소 검증과 구분한다.

- 전체 시험: **1,529/1,529 통과**, TypeScript 오류 0.
- 변경 코드 lint: 오류 0, 기존 `intake-queue-panel.tsx`의 `onBusy` effect 의존성 경고 1개 유지. 이번 변경은 그 컴포넌트의 다운로드 링크만 변경했다.
- 확장 0.2.30: 31개 파일, 372,193바이트, SHA-256 `0f00ea99098e3d7a034992cd640b82f9127cde92466168bc732c8e19275ed661`. 정규 UTF-8/LF 원본과 ZIP 일치 검사를 통과했다.
- 운영 빌드·배포: `100bcdd4-039b-44ec-91ae-91b667183921`, https://sourceflow.jjwwhhjj1116.workers.dev.
- 앱·확장 ZIP·원문 수집 API의 익명 요청 3건은 기존 Access 호스트로 HTTP 302 보호를 유지했다. 인증한 운영 화면이나 다운로드 바이트 검사는 아니다.

## 적용 및 남은 확인

기존 로드한 확장 폴더를 갱신한 뒤 해당 확장과 앱을 새로고침해야 적용된다. 새 창·프로필·다른 계정을 만들지 않는다. DB·비밀 설정·공개 이미지 Worker·유료 자원은 변경하지 않았다.

이번 연결의 기존 Chrome 탭 목록은 빈 배열이었다. 기존 Windows 창 목록에서도 지정 우측 쿠플러스/Hub 작업 창을 특정하지 못해 해당 사이트나 기존 작업 상품에 입력하지 않았다. 사이트 차단·로그아웃·승인 부족으로 판정하지 않았다.

전체 카테고리의 실제 쿠플러스/Hub 기본값 대조와 실제 계정의 최종 견적서 접수는 여전히 미검증이다. 이번 모의 전송/조회 결과를 실제 상품 등록 완료나 전체 복제 완료로 해석하지 않는다.
