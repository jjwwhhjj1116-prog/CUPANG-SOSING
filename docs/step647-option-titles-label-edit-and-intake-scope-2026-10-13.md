# Step 647 — 옵션별 견적 상품명·라벨 수동 편집·수집 계정 분리

상품추가와 1~7단계 연결에서 확인한 세 가지 차이를 수정했다. 기존 운영 상품·견적서·회사 기본설정이나 쿠플러스 작업 자료를 수정하지 않는다.

## 옵션별 자동 상품명

기록된 쿠플러스 `convertToJsonDocument`는 선택 옵션의 저장된 한국어 이름이 있으면 SEO 상품명 뒤에 쉼표와 해당 이름을 붙인다. 이전 앱의 7단계 자동값과 공식 원본 Excel에서는 여러 옵션의 상품명이 같았다. 이 규칙을 7단계 자동값과 이전 형식 견적 출력에 같은 함수로 적용했다.

기본 상품명과 저장된 한국어 옵션명이 둘 다 있는 경우에만 `상품명, 옵션 한국어명`으로 연결한다. 원문 옵션명·색상·공급자 SKU를 대신 붙이지 않으며, 임의로 자르거나 중복 문구를 제거하지 않는다. 1단계 공통 SEO 상품명과 법적 품명·모델명은 그대로다. 7단계에 직접 저장한 공통/옵션 상품명과 명시적 공란은 기존 우선순위를 유지한다. SEO 상품명을 직접 비운 경우도 옵션명만으로 되살리지 않는다.

## 6단계 최종 라벨 편집

`최종 라벨 N 문구 영역 편집` 버튼이 수동 편집 의도를 전달하지 않아 편집기의 원본 조회가 실행되지 않고 영역 추가가 비활성화되는 문제를 재현했다. 이 버튼에만 기존 이미지 편집기의 `manual` 진입을 연결했다. 중국어/영어 번역 버튼은 기존 동작을 유지한다.

수동 진입은 해당 옵션·라벨·슬롯·원문 버전을 확인한 뒤 원본을 불러온다. OCR·번역·AI·저장은 자동 실행하지 않는다. 문구/영역 편집과 PNG 미리보기 후 명시적으로 적용하면 그 슬롯 한 장만 교체한다. 원본 파일과 다른 라벨 순서·다른 옵션·직접 견적 입력을 유지한다. 입력 변경, 옵션 변경, 오래된 콜백, 잠금과 창 닫기 보호를 검사했다.

## 일반 수집의 계정 전환

별도 원문 초안 작업만 계정 변경 시 중단하고 일반 URL 수집은 계속되던 차이를 수정했다. 기존 실제 컴포넌트의 지연 수집을 재현했을 때 이전 계정 결과가 같은 행 ID를 가진 새 입력에 표시되고 이전 상품 편집기로 이동했다. 이는 UI 결과 채택 오류의 재현이며 다른 회사 DB에 저장됐다는 증거가 아니다.

계정 변경의 layout 단계에서 진행 중인 일반 수집/요청도 중단한다. 로그인 회원과 진입 세대를 고정해 계정이 A→B→A로 돌아와도 이전 응답·시작 버튼·행 수정 콜백을 받지 않는다. 늦은 작업 종료는 새 작업의 잠금을 풀지 않는다. 정상 종료 후 React가 처리하는 행 업데이트는 같은 계정이면 저장 상태를 반영하며, 계정이 바뀌었으면 현재 수동 입력을 보존한다. 기존 원문이나 완료된 서버 결과를 삭제하지 않는다.
