# 견적서 입력 검사와 등록전송 차단 수정

기존 검사에는 저장값으로 해결할 수 없는 두 가지 차단이 있었다. `resolveQuotationFields`의 카테고리 관찰 근거와 접수 전 안내를 `inspectSubmission`이 모두 `QUOTATION_CONSTRAINT` 오류로 처리했다. 또한 상품에 정상 연결된 이미지에 비공개 저장소 참조라는 이유로 `FIELD_INVALID`를 추가했다. 파일명으로 이미지와 라벨을 함께 전달하는 현재 Excel/첨부 ZIP 경로에서도 오류 수가 항상 남아 등록전송 버튼을 활성화할 수 없었다.

수정 전 HEAD 코드를 격리 검사 로더로 실행해 재현했다. 80719 합성 양식, 포함 옵션 6개, 대표/추가/상세/라벨 이미지가 모두 준비된 두 회사의 API 검사에서 각각 안내 2개와 이미지 안내 24개, 총 26개의 잘못된 차단이 발생했다. 수정 후 같은 저장 입력의 미리보기와 실제 생성 ZIP `submission-review.json`은 오류 0개이며 확인 안내는 유지한다. 필수 포장 무게를 비우면 오류 1개와 다른 자료 지문이 발생한다.

해결 방식:

- 전체 견적 결과에 `validationIssues`와 `reviewMessages`를 추가하고 기존 `issues` 합계는 유지한다. 카테고리/옵션 한도/가격 설정/이미지 목록 파싱 오류는 실제 제약으로 남긴다. 이 구분이 없는 이전 자료의 `issues`는 계속 오류로 취급한다.
- 카테고리 관찰 근거와 접수 전 안내는 `QUOTATION_EVIDENCE` 확인 항목이다. 알려지지 않은 카테고리는 별도의 `SCHEMA_UNCONFIRMED` 오류로 차단한다.
- 편집 화면과 서버 resolver가 정상 이미지 연결을 확인 항목으로 처리한다. 소유권, 누락 파일, 실제 첨부 바이트의 형식/크기, 지원하지 않는 상세 GIF, Excel 필수 셀/연결 오류는 그대로 차단한다. 저장소 자료를 공개하지 않는다.
- 오류 0개는 입력 검사의 결과다. 필수 동의, 회사코드와 최신 자료 지문, 중복 전송 보호 및 확장 내 첨부 검사는 그대로 적용한다. `submissionReady:false`와 외부 등록 결과의 `registered:false`를 유지한다.

검사 범위:

관찰한 28개 카테고리(기존 목록 27개와 81221 장갑)의 공통 근거 안내가 입력 오류를 만들지 않는 것을 resolver 검사로 확인했다. 수집→수동 수정→Excel→ZIP까지는 기록된 1688 원문과 실제 API 처리기/격리 SQLite를 사용해 A01464742·와이홉, A01526306·유앤채를 각각 검사했다. AI·인증·이미지 바이트·Excel 원본은 합성 자료다. 선글라스 수집 원문에 80719를 적용한 것은 이전에 관찰한 양식의 연결 시험이며 실제 판매 분류가 아니다. Supplier Hub로 전송하지 않았다.

이 수정은 모든 카테고리의 기본값을 새로 추정하지 않는다. 실제 Hub 최종 등록 및 전체 카테고리의 Couplus 자동 기본값/공식 양식 일치는 추가 검증이 필요하다. 앱 변경만 있으므로 확장 0.2.26을 다시 설치할 필요는 없다.
