# Step580 URL 재사용·접수 복구 감사 — 2026-10-06

역사 AI 등록 자료의 **「이 URL로 상품 추가」** 버튼을 기존 상품 추가 흐름에 연결했다. 이전 원본 937건 및 일부 견적의 조회를 유지하며, 버튼은 정확한 `https://detail.1688.com/offer/{상품ID}.html`만 허용한다. 빈 값·잘못된 URL은 비활성화한다. 클릭 시 목록을 다시 읽어 현재 회사·불투명한 계정 문맥·원본 행 ID·URL을 확인한다. 콜백에는 URL, 원본 행 ID, 회사, 계정 문맥만 전달하고 제목·견적·가격·카테고리·등록 상태는 주입하지 않는다. 예전 GET 응답에 계정 문맥이 없으면 성공한 재조회가 먼저 필요하다.

상품 추가 창에서 사용자가 현재 카테고리와 프로필을 선택하면 기존 입력 행을 보존하고 URL이 채워진 새 초안 한 행을 추가한다. 특징·키워드는 빈 값이다. 역사 자료를 등록 완료로 승격하거나 원본·견적·기존 상품 DB를 수정하지 않는다. 사용자가 작업을 시작하기 전에는 수집·번역·Hub 등록 POST를 실행하지 않는다. 회사·계정 변경, 목록 재조회·검색·페이지 이동, 미결 작업, 403, 취소·언마운트, 바뀐 URL seed ID는 늦은 콜백을 막는다. 부모 콜백도 최신 참조로 확인한다. 개발 환경 effect cleanup/setup에서 카테고리 선택이 사라지는 결함을 별도로 재현한 뒤 생명주기 보호를 수정했다.

접수 복구는 서버에 이미 보존된 accepted 접수와 로컬 확장의 `validation-pending`/`not-found` 충돌을 처리한다. 회사·원본·파일·옵션 수·확인 가능한 프로필·견적 ID가 일치할 때만 IndexedDB 한 트랜잭션에서 예상 로컬 값과 비교해 `promote`한다. 더 최신 accepted/rejected 관측은 덮어쓰지 않는다. 복구를 위한 업로드·재등록은 하지 않는다. 전송 전 검사 실패로 로컬 잠금만 남은 경우에는 현재 원본과 두 접수 저장소를 다시 확인해 시도와 결과가 모두 비어 있을 때만 잠금을 해제한다. 오류 응답이나 실제 시도·결과가 있으면 유지한다.
