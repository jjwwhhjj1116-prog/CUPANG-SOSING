# 1688 상품조회 연결 설정

## 현재 상태

URL 등록의 `POST /api/collection-jobs/[id]/collect`에 공식 API 수집 경로를 연결했다.
운영에는 아직 자체 API 키와 조회 권한이 없으므로 이 경로는 활성화하지 않았다.
테스트는 합성 응답이다. 실제 1688 응답, 모든 가격 유형, 모든 상품 지원을 검증한 것은 아니다.

서버 설정이 활성화되면 기존 수집 요청의 원본 URL로 서명된 조회를 실행하고,
상품번호·옵션·가격·이미지를 검증한 원문을 저장한다. 기존 클라이언트가 이 원문을
상품 초안 및 이미지로 반영한다. 이 요청은 Supplier Hub 전송을 실행하지 않는다.

## 필요한 서버 바인딩

| 이름 | 내용 |
| --- | --- |
| `ALIBABA_PRODUCT_API_ENABLED` | 문자열 `true`만 활성화. 미설정/빈 문자열/`false`는 기존 공개 페이지 수집 |
| `ALIBABA_APP_KEY` | 이 배포 소유자의 앱 키 |
| `ALIBABA_APP_SECRET` | 해당 앱 비밀키 |
| `ALIBABA_ACCESS_TOKEN` | 상품상세 API 조회 권한이 있는 토큰 |

비밀키와 토큰은 Cloudflare Worker Secrets로 설정한다. 공개 vars, Git,
클라이언트 환경변수, 채팅, 상품 데이터에 넣지 않는다. 발급된 값은 보안 입력으로
등록하며 본 문서에는 값을 기록하지 않는다. 활성화 스위치도 Worker Secret로
설정하면 현재 빌드의 vars를 수정하지 않고 사용할 수 있다.

예: `npx wrangler secret put ALIBABA_APP_SECRET --config dist/server/wrangler.json`

자체 권한을 발급받고 테스트용 환경에서 실제 응답을 검증한 뒤 활성화한다.
쿠플러스 설치 코드에 포함된 다른 주체의 키는 사용할 수 없다.

## 실패 처리와 남은 검증

- 활성화했으나 설정이 불완전하면 503이며 외부 요청이나 원문 저장을 하지 않는다.
- 조회·응답 변환 실패는 422다. 공개 페이지 수집으로 자동 전환하지 않는다.
- 원문이 있으면 기존 값을 반환한다. 재시도가 원문·수동 편집을 교체하지 않는다.
- 현재 변환기는 명시적 SKU `price`와 `minOrderQuantity`를 요구한다. 가격 구간,
  프로모션·대행 가격 해석과 단일 옵션 없는 응답은 추가 검증이 필요하다.
- 대표/추가/상세 이미지 배치는 보존하지만 이미지 번역은 실행하지 않는다.
- 토큰 발급·갱신 자동화와 Supplier Hub 제출 어댑터는 아직 구현되지 않았다.

## 수집 후 초안 반영 (397 기준)

검증된 원문으로 상품·옵션·가격을 저장한 뒤, 이미지 다운로드 전에 SEO·옵션 초안을 준비한다.
상품추가 목표는 원문 반영에서 끝나며 AI 작업을 만들지 않는다. 그 외 목표에서
Cloudflare Workers AI 자동 초안 설정이 활성화된 경우 생성 결과를 검증하고 저장한다.
다른 제공자는 준비된 검토 요청을 남기며 실행 완료로 표시하지 않는다.

이미지와 SEO 저장을 순서대로 실행하여 버전 충돌을 피한다. 이미지 실패 시 저장된
상품과 SEO를 보존하고 남은 이미지 반영을 재시도한다. 재시도는 저장된 수동 수정값을
덮어쓰거나 Supplier Hub에 전송하지 않는다.

통합 테스트는 실제 라우트·DB 저장·견적서 출력 함수를 사용하지만 1688·AI·이미지
응답은 합성 자료다. 상품명·검색어·판매가·이미지 제외·상세 HTML·재질·포장정보의
수정값이 재시도 후 최종 출력에 유지되는 것을 검증했다. 실제 1688 조회 성공이나
공식 Excel 적합성·Supplier Hub 등록 완료의 근거는 아니다.

## Chrome 수집 0.2.25와 공개 응답 진단 (2026-09-30)

서버 공개 조회와 Chrome JSON-LD 조회는 `product-jsonld.mjs`의 같은 상품/옵션
해석기를 사용한다. Chrome은 페이지 로딩 완료 후 최대 10초 동안 SKU별 CNY 원가와
최소 주문량이 나타나는 것을 기다린 뒤 500ms 동안 같은 원문이 관찰되어야 반환한다.
앱의 취소는 해당 수집 요청에 전달되며, 같은 Chrome 창의 중복 요청은 거절한다.
기존 탭, 사용자가 활성화한 탭, 다른 창/URL로 이동한 탭은 자동으로 닫지 않는다.

`node scripts/check-public-product.mjs`로 지정 URL `813724060928`을 인증정보 없이
직접 조회했다. HTTP 200, `text/html;charset=UTF-8`, 2,909바이트 응답이었으나
JSON-LD Product/Offer가 없어서 현재 공개 수집기는 원문을 만들지 못했다. 상태코드
200을 상품 수집 성공으로 취급하지 않는다. 진단은 HTML 구조·스크립트 길이와 필드명만
출력하며, 판매자 스크립트 실행·로그인정보·쿠키·DB 저장을 사용하지 않는다.

추가 통합 시험은 서버 공개 응답 실패 → 지연된 Chrome 원문 → owner/job에 연결된
원문 저장 → 옵션·이미지 반영 → Workers AI SEO 초안 → 수동 수정 → 카테고리 견적서
출력을 재현했다. 재시도에서 수집과 원문 저장이 반복되지 않고 수정값을 보존한다.
Chrome/1688/AI/R2 응답은 합성 자료이며 실제 지정 상품의 성공이나 전체 카테고리
지원, Supplier Hub 최종 접수의 증거는 아니다. 공개 JSON-LD가 없는 페이지의
렌더링 데이터 해석과 실제 데이터 공급원 검증은 여전히 필요하다.

## 초안의 원본 이미지와 견적 이미지 선택 분리 (508 기준)

2026-09-27 Couplus 신규 SEO+가격 초안 관찰에서는 수집 원본이 존재해도 대표/추가
견적 필드는 비어 있었고, 상세 이미지에는 계정의 기본 배너만 연결되어 있었다.
YOOFAM PLUS 상품추가도 원본 파일은 상품 이미지 목록에 보관하되, 대표·추가·상세
배치와 옵션 대표 이미지는 자동 선택하지 않는다. 원문 SKU와 이미지 번호의 관계는
수집 원문에 그대로 남는다. 사용자가 3~5단계에서 파일을 선택·저장하면 7단계와
최종 Excel에 해당 선택이 반영된다. 설정의 상세 상단/하단 배너와 기존 수동 선택은
원본 저장·재시도에서 유지한다.

기존 수신 결과 패널의 명시적 이미지 반영은 이전 계약을 유지한다. 상품추가의
이미지 요청만 `assignToStage:false`를 전달한다. 서버는 새 파일 보관과 옵션/역할
선택을 같은 저장 경로에서 분리하며, 재시도는 이미 보관한 파일을 다시 내려받거나
선택값을 변경하지 않는다. 기존 저장 상품의 이미지 선택을 소급 변경하지 않는다.

이 변경의 통합 시험은 합성 원문을 사용한다. 실제 1688 수집 성공, 상세 HTML의
전체 Couplus 일치 및 모든 카테고리/최종 Supplier Hub 접수 검증을 대신하지 않는다.
