# 상품등록 흐름 최종 검수 — 2026-10-03

대상 흐름은 카테고리 선택 → 지정 1688 URL 수집 → 1~7단계 초안 → 직접 확인·수정 → 등록전송 → Supplier Hub 견적서 ID·SKU 확인이다. 이번 검수에서 실제로 재현한 오류와 수정 범위, 실제 사이트 확인 여부를 구분한다.

## 재현한 오류와 수정

### 새 상품의 카테고리 규칙

기존 프로필에 공식 양식이 있으면 원문 양식·메타데이터·회사만 비교해 재사용했다. 따라서 양식 원문이 같아도 `draftInitialization`, `inputBindings`, `settingsInitialization`이 구버전인 프로필이 그대로 선택될 수 있었다. 이제 세 규칙 버전과 카테고리 코드·전체 경로까지 비교하고, 저장 응답에도 같은 규칙이 보존됐는지 확인한다. 관찰 시간만 달라진 경우에는 불필요하게 저장하지 않는다.

같은 원문 양식의 입력 연결 버전만 바뀌면서 내부 필드 ID가 달라지는 경우도 확인했다. 같은 회사·카테고리·전체 경로·원문·메타데이터에서만 정확한 `hubWire` 경로와 배열 이름을 통해 연결을 변환한다. 새로 선택한 프로필에는 현재 규칙을 적용하고, 기존 작업 상품의 출력에서는 해당 상품의 수집 당시 규칙으로 연결을 해석한다. 열 위치·수동 연결·선택값 출력 방식·고정값은 유지한다. 실제 공식 양식이 달라진 경우에는 이 버전 변환을 적용하지 않는다.

### SEO와 한글표시사항의 연결

6단계에 처음 진입해 자동 작성된 품명을 아직 저장하지 않은 상태에서 1단계 SEO 상품명을 수정·저장하면, 6단계 품명에 이전 상품명이 남아 저장 검증에 실패했다. 초안이 상품명 연동 상태인 경우 새 SEO 상품명을 반영한다. 사용자가 직접 고친 품명, 명시적으로 지운 빈칸, 다른 표시사항의 미저장 수정은 유지한다. SEO 저장만으로 미저장 표시사항을 서버에 저장하지 않는다.

### 이미 확인한 SKU 결과의 재조회

서버에서 SKU 결과를 복원한 뒤, 해당 Chrome에 결과가 없거나 더 오래된 결과만 있는 상태로 파일 검증 결과를 다시 조회하면 화면에서 SKU가 사라졌다. 같은 회사·파일·옵션 수·견적서 ID가 확인된 파일 검증 조회에 한해, 이미 복원된 더 최신 SKU 결과와 원래 관찰 시간을 유지한다. 실제 SKU 상태를 새로 조회한 응답은 빈 결과라도 최신 응답으로 반영한다. 재조회로 파일을 다시 업로드하지 않는다.

### 가격 계산 확인

가격식은 변경하지 않았다. 첨부된 쿠플러스 화면의 원가 25.6 CNY·환율 350·공급 마진 50%·쿠팡 마진 40%·10원 반올림·시장가격 배수 1.3 예제는 기존 가격 회귀검사에 포함돼 있다. 계산 결과는 공급가 17,920원·판매가 29,870원·권장가 38,830원이다. 최소 공급 마진 적용 후 반올림하는 순서와, 예전에 명시적으로 저장한 올림 정책을 보존하는 검사도 유지한다.
