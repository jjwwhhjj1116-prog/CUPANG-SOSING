# AI 텍스트 정책·공유 한도 점검

2026-10-31 소스 코드만 확인했다. 이번 작업은 문서화이며 AI 정책 구현, 모델·요금·호출 한도 변경, 유료 기능 활성화, 배포를 하지 않았다. 환경변수 시크릿·실제 사용량·청구 정보는 읽지 않았고 외부 요청도 실행하지 않았다. 원래 Supplier Hub 문서 2347603의 문제 해결을 우선한다.

## 공유 40회의 정확한 범위

`db/quotation-ai-jobs.ts:34,104–110`과 `db/migrations/0020_quotation_ai_jobs.sql:19`의 `quotation_ai_daily` 기본키는 **`day` 하나**다. 예약 함수에는 회원 ID 인자가 없고 날짜는 `new Date().toISOString().slice(0,10)`으로 구한다. 따라서 같은 DB를 사용하는 회원들은 **UTC 날짜별 제공자 호출 40회**를 공유한다. 회원별 40회나 상품 40개 제한이 아니다. 예약은 한도 조건이 있는 원자적 UPSERT이며 이 성질은 보존해야 한다.

회원이 늘면 표시사항·견적·포장 등의 공유 호출이 서로 영향을 줄 수 있다는 것은 소스에 따른 추론이다. **현재 실제로 40회를 소진했는지, 어느 회원·상품이 얼마를 사용했는지, 이 한도가 원래 886 상품의 실제 중단 원인인지는 측정하지 않았다.** 이번 점검을 실제 사용량 진단이나 과금 내역으로 제시하면 안 된다.

## 무료 표기와 실제 과금 제어의 차이

`deployment/cloudflare-config.mjs:36–38,55,79–84`는 견적 AI를 켤 때 `FREE_ONLY=true`만 허용하고 이를 산출물에도 기록한다. 그러나 이 플래그는 애플리케이션의 활성화 조건이다. 위 실행 경로는 최종적으로 `AI.run`을 호출하며, Cloudflare 계정의 요금제·남은 무료 할당량·실제 비용을 검증하거나 제공자 과금을 차단하는 절차는 확인되지 않는다. **40회 호출 수만으로 무료 사용을 보장할 수도 없다.** 그러므로 Workers Paid에서도 과금이 없다는 뜻으로 `freeOnly:true`나 기존 “무료 공유 요청” 안내를 사용하면 실제 제어 범위보다 강한 설명이 된다.

반대로 이 플래그만 `false`로 바꾸면 배포 구성 검사가 거절되고 표시사항·견적·포장 AI의 설정 검사도 통과하지 못한다. 현재 구조는 사용자가 승인한 유료 Qwen 텍스트 정책을 전체 단계에서 일관되게 표현하지 못한다. 이는 설정·정책 설계상의 차이이며 이번 문서에서 요금제나 모델을 바꾸지는 않았다.

## 후속 구현 제안 — 이번에는 미적용

1. **명시적 유료 텍스트 정책을 추가한다.** 기존 무료 플래그·Llama 경로는 이전 요청 호환용으로 유지한다. 유료 모드는 별도 과금 허용 값과 유효한 회원별 일일 호출 상한이 함께 있을 때만 활성화하고, 누락·잘못된 값·상충 설정은 실행 전에 거절한다. 무료 할당량과 자체 호출 제한은 구분해 표시한다.
2. **인증된 회원별 원자적 상한을 둔다.** 새 카운터의 키는 서버에서 확인한 `owner_id + UTC day`로 하고 유료 텍스트 목적 전체가 같은 회원 예산을 공유하게 한다. 클라이언트가 회원·한도·목적별 별도 예산을 정하지 못하게 한다. 실제 `AI.run` 직전에 예약하며, 일반 Qwen 번역도 포함한다. 한도를 소진한 요청은 제공자를 호출하지 않는다. 이미 요청됐거나 결과가 불확실한 호출을 자동 환급·재실행하지 않는다. 이것은 호출량 제한이며 금액 상한 보장은 아니다.
3. **신규 요청에 모델·정책 스냅샷을 보존한다.** 견적·표시사항 실행 상수만 Qwen으로 치환하지 않는다. 신규 요청의 검토·지문·실행·결과에 모델을 연결하고 Qwen의 실제 응답 계약을 검증한다. 보관된 Llama 요청은 기존 모델·검증 규칙으로 계속 읽으며 새 모델로 재해석하거나 자동 재실행하지 않는다. `quotation-ai/route.ts:31,113`, `quotation-ai.ts:254,315`, `product-label-draft.ts:8,118,143,151`, `seo-generation-client.ts:22–26`의 모델·결과 검사가 이 변경의 경계다.
4. **최소 회귀를 먼저 작성한다.** 회원 A의 소진이 B를 막지 않음, 같은 회원의 마지막 한 자리를 동시 요청해도 한 호출만 허용됨, 잘못된 유료 설정과 소진은 제공자 호출 0회, 기존 무료 40회·Llama 요청 유지, 원본·회원 변경 차단 유지, 불확실한 제공자 결과의 자동 재시도 없음, 저장된 모델과 실제 호출·결과 모델 일치를 검사한다.

현재 턴에는 이 제안의 구현·활성화나 한도 값 선택을 수행하지 않는다. 실제 사용량 소진과 비용에 대한 결론도 유보한다.
