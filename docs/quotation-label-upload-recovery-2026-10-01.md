# 페이지 재접속 후 옵션 라벨 저장 복구 (2026-10-01)

531의 메모리 캐시는 열린 폼 안에서 단일·전체 생성의 업로드를 공유했다. 페이지를 닫으면 캐시가 사라졌으며, 업로드가 실제 저장된 뒤 응답이 유실되면 파일 키도 알 수 없었다. 같은 라벨을 다시 생성해 업로드하고 견적에 중복 추가했다. 실제 부모/자식 폼을 닫고 새 hook/ref로 여는 신규 통합 회귀 8건에서 최초 6옵션 업로드가 7회로 늘어나는 문제를 재현했다.

## 변경

- 생성 라벨에 상품 ID·견적 endpoint·카테고리 연결·옵션 ID·PNG 조판 계획을 묶은 SHA-256 업로드 번호를 부여한다. renderer 변경 시 갱신할 recipe 버전을 포함한다. 가격·revision·숨긴 안내·다른 옵션 수정처럼 해당 PNG 계획에 없는 변경은 번호를 바꾸지 않는다. 다른 상품·양식·카테고리·옵션이나 보이는 모델/법적 항목/사용자 안내가 달라지면 다른 번호다.
- 인증된 파일 소유자 아래 고정 PNG 경로와 업로드 번호·파일 바이트 SHA-256을 R2에 함께 저장한다. `/api/files?labelUploadId=...`는 현재 회원의 해당 경로 하나만 조회하며 다른 소유자·임의 키·추가 쿼리·잘못된 번호는 받지 않는다. 모든 조회 응답은 `no-store`이고 운영 인증 확인을 거친다. 파일 목록이나 다른 회원의 파일을 조회하지 않는다.
- 단일 연결과 전체 생성은 메모리에 키가 없으면 서버 파일을 조회한다. 명시적인 `{key:null}`만 새 파일 생성으로 이어진다. 조회 실패·잘못된 응답은 업로드로 대체하지 않는다. 이미 저장된 파일은 실제 상품 첨부/옵션 견적의 최신 상태를 다시 읽고, 아직 끝나지 않은 연결만 이어간다. 상품·견적 CAS, 계획 변경 검사, 기존 첨부 보존, 중지와 한도 검사를 유지한다.
- 같은 번호와 동일한 파일 바이트의 재요청은 저장된 키를 반환한다. 다른 바이트는 HTTP 409로 거절하고 이전 파일을 보존한다. `If-None-Match: *` 조건부 쓰기로 두 요청이 동시에 기존 파일을 못 찾았더라도 최초 파일을 덮어쓰지 않는다. 조건부 쓰기 실패 후 다시 조회해 동일 파일 재사용 또는 충돌을 구분한다. [Cloudflare R2 Workers API의 조건부 쓰기 문서](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)를 확인했다.
- 일반 이미지 업로드의 기존 임의 키 경로는 유지한다. 새 식별 번호가 붙은 생성 PNG에만 이 복구를 적용한다. 이전 버전의 임의 키 파일을 자동 추정/삭제/이관하지 않는다. 단일 PNG 미리보기를 사용자가 새로 열면 조판은 수행할 수 있지만 서버 파일 연결은 재사용한다. 전체 생성에서는 서버 키를 찾은 옵션의 조판도 생략한다.

서버는 파일 형식·크기·소유·저장 메타데이터·바이트 일치를 확인한다. 번호를 서버에서 견적 내용으로 재계산하거나 PNG의 글자를 분석해 해당 상품/법적 표시사항과 일치함을 증명하지 않는다. 기존의 명시적 검토·전송 절차를 유지하며 라벨 복구가 Supplier Hub 전송을 자동 실행하지 않는다. DB migration·비밀 설정·확장·이미지 Worker·유료 자원을 추가하지 않는다.

## 검증

와이홉 A01464742와 유앤채 A01526306 각각 업로드 응답 유실, 상품 첨부 응답 유실, 견적 라벨 PUT 응답 유실, 정상 단일 연결 후 완전한 폼 재개 네 경로를 검사했다. 실제 QuotationFieldsEditor/QuotationLabelPanel의 hook/effect·key 재마운트 모델, 실제 수집·콘텐츠·견적·업로드·첨부·Excel·ZIP API와 임시 SQLite를 사용한다.

폼을 닫고 새 ref로 전체 생성을 실행해 최초 6옵션 조판/업로드 각 6회만 발생하는지 확인했다. 다시 재접속·판매가 20,000원 저장 후 반복해도 추가 파일이 없다. 첫 옵션 모델 수정 시 조판/업로드가 한 번만 증가하고 나머지 5옵션 키는 그대로다. 다시 재접속한 뒤에도 7회로 유지된다. 기존 라벨과 두 버전 라벨을 삭제하지 않으며 409·UI 오류가 없다.

URL 재시도는 원문·AI 요청을 추가하지 않는다. 6행 Excel의 옵션별 라벨 파일명/JSON 매핑과 첫 옵션 가격을 대조했다. 전송 준비 UI에서 로컬로 포착한 회사 코드·이름·옵션 수·XLSX 및 8개 라벨 이미지 바이트는 검토 ZIP과 같다. 상품 상태는 미전송이며 실계정 Hub 견적에 쓰지 않았다.

추가 API 검사는 동시 동일/변경 PNG 요청, R2 저장 후 응답 유실, 잘못된 업로드 번호·multipart·Origin, 다른 회원 조회, 운영 인증 부재, 잘못된 저장 메타데이터와 저장소 오류를 검사한다. 클라이언트 검사는 가격/숨김값에 대한 번호 유지, 상품·옵션·가시 내용 변경에 대한 번호 분리, 실패 응답에서 새 업로드 금지, 이미지 50개·옵션 라벨 30개에 도달한 상태의 저장 키 복구를 검사한다. 관련 단위 31/31, 초기 라벨 통합/관련 검사 43/43, TypeScript와 변경 파일 lint 오류/경고 0을 확인했다. 전체 저장소 lint 통과를 주장하지 않는다.

최초 전체 검사는 1583/1591 통과했다. 기존 중지/실패 복구 시험 8건이 임의 키의 옛 파일명 `sourceflow-quotation-label.png`를 전제로 비교해 실패했다. 두 기존 시험 파일을 새 고정 키 및 실제 R2의 업로드 번호·바이트 SHA-256 확인으로 갱신했다. 업로드 횟수·옵션별 첨부·견적/Excel/ZIP/전송 파일 바이트 검사는 유지한다.

최종 전체 검사 1591/1591(178.802초), TypeScript 오류 0, 변경 파일 lint 오류/경고 0, Cloudflare 운영 빌드·산출물·diff 검사를 통과했다. 신규 검사 20건을 추가했으며 확장 0.2.30은 기존 31파일/372193바이트/SHA-256 `0f00ea99098e3d7a034992cd640b82f9127cde92466168bc732c8e19275ed661`과 같다.

기록 원문 813724060928과 80719 관찰 폼 시험 계약을 사용한다. 80719는 선글라스의 실제 판매 분류가 아니다. 인증·AI·PNG 조판·이미지·Excel 양식·최종 Hub 전달은 시험 자료다. 시험 renderer는 PNG 헤더와 계획 자료를 반환하며 실제 브라우저 canvas 픽셀이나 법적 적합성 검증이 아니다. 기존 지정 Chrome 바인딩의 탭 목록은 빈 목록이며 이를 사이트 차단·로그아웃으로 해석하지 않았다. 새 Chrome/프로필·기존 작업 상품 조작·추가 승인/로그인 요청은 없다.

전체 실제 카테고리의 Couplus 기본값/공식 양식 대조, 지정 URL의 실제 1~7단계 작업, 운영 이미지 번역·법적 서류 첨부, 두 회사의 실제 최종 Supplier Hub 접수·SKU 확인은 미검증이다. 전체 완성률 또는 완벽 구현 완료를 주장하지 않는다. `outputs/step532-*`는 Git에서 제외한 로컬 검사 자료다.
