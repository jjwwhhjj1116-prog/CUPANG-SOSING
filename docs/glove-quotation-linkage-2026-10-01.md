# 스포츠장갑 단계 입력과 견적서 연결

## 확인한 문제와 수정

스포츠장갑 `81221`은 쿠플러스 견적서 항목과 Supplier Hub 카테고리 경로·선택값을 이미 기록하고 있었지만, 네 가지 고시 항목의 값 연결이 빠져 있었다. 색상과 6단계 크기·중량/KC 정보/상품별 세부 사양을 저장해도 7단계와 견적 파일에 반영되지 않았다.

| 견적서 항목 | 입력 출처 |
| --- | --- |
| `glove_noticeColor` 색상 | 포함 옵션의 저장한 색상 |
| `glove_noticeSizeWeight` 크기, 중량 | 6단계 크기·중량 |
| `glove_noticeKc` KC 인증정보 | 6단계 KC 인증정보 |
| `glove_noticeSpecifications` 상품별 세부 사양 | 6단계 상품별 세부 사양 |
| `glove_fashionSize` 패션잡화 사이즈 | 옵션 사이즈 중 관찰한 선택지와 정확히 일치하는 값 |

`S`, `M`, `L`, `XL`, `Free Size`, `XXS`, `XS`, `XXL이상`은 패션잡화 사이즈로 연결한다. `Medium`, `Free`, 물리적인 치수 문자열을 다른 선택지로 추정하지 않는다. 선택지와 다른 값은 검토 오류를 남기며, 기존 자유 입력 노출 사이즈에는 저장한 원문을 유지한다. 옵션 사이즈가 없을 때 상품 치수를 스포츠장갑 구매 사이즈로 대신 넣던 동작도 제거했다.

견적서에서 직접 입력한 공통값·옵션값은 단계 입력보다 우선한다. 옵션별 공란, 직접 지운 색상·고시·사이즈를 기본값으로 되돌리지 않는다. 예전 저장 자료에 KC/세부 사양 필드가 없으면 공란을 유지한다. 상품과 옵션 원본을 견적서 조회 과정에서 변경하지 않는다.

항목 이름과 순서의 근거는 `app/couplus-glove-schema.ts` 및 [Supplier Hub 81221 공식 미리보기 기록](supplier-hub-81221-preview-2026-09-27.md)이다. 공식 미리보기의 고시 12개 이름은 쿠플러스 기록과 같았다. 그 기록의 빈 셀은 쿠플러스 초기 기본값이나 인증 해당 여부를 입증하지 않는다. 이번 변경으로 다른 카테고리의 해당없음 기본값을 스포츠장갑에 새로 적용하지 않았다.

## 검증

새 순수 연동 회귀 3개는 수정 전 모두 실패했고, 값 연결 수정 후 기존 견적서 스키마 검사와 함께 180/180을 통과했다. 관찰된 카테고리의 자동 입력 연결을 검사하는 기존 목록에 누락돼 있던 `81221`도 추가했다.

`tests/glove-intake-linkage.test.mjs`는 실제 수집/콘텐츠 저장/옵션 저장/견적서 수정/견적 생성 API와 임시 SQLite를 사용한다. 와이홉 `A01464742`, 유앤채 `A01526306` 각각에서 다음을 확인했다.

1. 선택 카테고리 `81221`과 프로필 `cat`이 수집·SEO 요청·견적서까지 유지된다.
2. 옵션 6개를 저장한 뒤 하나를 제외하면 XLSX와 전송 준비에는 포함 옵션 5개만 들어간다.
3. 6단계 고시와 옵션 색상·사이즈가 7단계 자동값, 실제 생성한 XLSX 셀까지 동일하게 전달된다.
4. 7단계에서 직접 수정한 색상과 직접 지운 세부 사양이 단계값보다 우선한다.
5. 수집 재시도는 원문 재조회·AI 재실행 없이 수동 입력값과 제외 옵션을 보존한다.
6. 필요한 과세·인증·물류 입력을 시험에서 명시적으로 저장하면 입력 오류는 0개다. 상품·양식·이미지의 검토 사유는 여전히 남는다.
7. 실제 전송 준비 컴포넌트, ZIP 해석, 앱/확장의 최신 원본 검사와 동의 전달을 거쳐 로컬로 포착한 전송 패키지에 회사·카테고리·포함 옵션 수·견적 파일이 유지된다.
8. 전송을 로컬로 포착해도 실제 Hub 영수증이 없으므로 상품 상태는 `미전송`이다.

기록된 1688 공개 원문은 지정 선글라스 상품 `813724060928`이고 스포츠장갑 상품은 아니다. 이 시험에서 81221은 관찰한 폼 연결의 시험 계약이며 실제 판매 분류가 아니다. 인증·AI 응답·이미지 바이트·Excel 양식·최종 Hub 전송은 격리된 시험 자료다. 실계정 견적서에 시험 상품을 등록하지 않았다. 초기 통합 시험의 실패는 누락된 필수 과세 시험 입력, 패키지 옵션 수 위치와 XLSX 시험 헤더의 예상값을 바로잡은 뒤 통과했다.

추가 회귀 5개 포함 전체 **1,489/1,489**, TypeScript, 변경 파일 ESLint 오류/경고 0, Cloudflare 빌드·산출물·diff 검사를 통과했다. 전체 저장소 lint나 전체 카테고리 기본값 검증 완료를 주장하지 않는다.

## 운영 반영과 남은 확인

기존 운영 앱 https://sourceflow.jjwwhhjj1116.workers.dev 에 배포했다. Worker 버전은 `7a1807ea-e9d1-4ee9-98b1-b69e28a40e44`다. 앱 새로고침으로 반영된다. 확장 0.2.29는 변경하지 않았고 빌드에서 30개 파일/366,181바이트/SHA-256 `80a1d38d37bcd65b6b6d8e83e7c268d289b95320f00c91d0ae80147b21684444`를 다시 확인했다. DB 마이그레이션·비밀 설정·공개 이미지 Worker·유료 자원은 변경하지 않았다.

배포 후 앱·확장 ZIP·수집 API의 익명 HTTP 302 Access 보호를 확인했다. 인증한 운영 화면·다운로드 바이트·실제 Hub 접수 성공을 검사한 것은 아니다.

기존 Chrome 제어 바인딩의 탭 목록은 `[]`였다. Windows 컴퓨터 제어에서도 열려 있는 창 목록을 확인했지만, 사용자가 지정한 쿠플러스·Supplier Hub의 오른쪽 Chrome 창을 목록만으로 특정할 수 없어 입력하지 않았다. 새 Chrome·프로필을 열거나 기존 쿠플러스 작업 상품을 변경하지 않았고 추가 로그인·승인을 요청하지 않았다. 사이트 차단·로그아웃으로 해석하지 않는다.

실제 지정 Chrome에서 URL→1~7단계 초안 확인, 전체 카테고리의 쿠플러스 기본값·공식 양식 대조, 운영 이미지 번역과 법적 서류 첨부, 두 회사의 실제 견적서 접수·SKU 확인은 남아 있다. 전체 완료율은 산정 근거 없이 숫자로 표시하지 않는다.
