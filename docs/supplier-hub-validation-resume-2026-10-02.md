# 첨부한 견적서의 검증 재개

YOOFAM PLUS의 등록전송에서 파일 전달은 완료됐지만 파일명 표시가 늦거나 ‘파일 검증하기’ 버튼이 아직 비활성화되면, 견적서를 다시 보내지 않고 검증 요청을 재개한다. 사용자가 앱의 ‘첨부 파일 확인 후 검증 재개’를 눌렀을 때만 실행한다. 기존 URL 수집, 카테고리 선택, 수동 수정 및 등록전송 흐름은 유지한다.

## 원래 첨부와의 연결

- 최초 전송 시 원본 앱 origin, 상품, 카테고리, fingerprint, 견적 양식 profile, 회사코드/회사명, 옵션 수, 파일명 목록, 필수서류 여부, 원래 Chrome 창/Hub 탭을 저장한다. 파일 내용이나 계정 세션을 재개 메시지에 넣지 않는다.
- 재개 요청은 앱 origin와 송신 프레임을 확인한다. 원래 창과 원래 등록 탭, 탭별 첨부 기록이 모두 일치해야 한다. 다른 탭 조회·탭 생성·파일 입력 변경·ZIP 재출력·다운로드·재첨부는 하지 않는다.
- 최신 저장본과 서버 접수 기록을 첨부 확인 전과 검증 요청 직전에 다시 확인한다. 회사코드 A01464742(와이홉) 또는 A01526306(유앤채), profile, 옵션 수와 fingerprint가 달라지거나 기존 접수/검증 결과가 있으면 요청하지 않는다. 서버 조회 실패를 미접수로 해석하지 않는다.
- 실제 실행 화면의 확장 첨부 marker, 전체 파일명 목록, 회사코드, 필수서류 원본 목록을 대조한다. 이미 검증 요청한 marker나 현재 보이는 같은 견적서의 검증 결과 행이 있으면 새 요청 대신 조회 단계로 돌아간다.
- 새로고침 후에는 저장된 전송 기록으로 재개 가능 여부를 복원하고 사용자가 필수 선택값을 다시 확인해야 한다. 부분 첨부, 시작 중인 전송, 원래 파일 목록이 없는 과거 버전의 기록은 추측하여 재개하지 않는다.

## 요청 유실과 중복 방지

같은 창의 전송 잠금을 공유하고 검증 실행 직전에 별도 영구 claim을 남긴다. 검증 함수는 화면이 검사 시점의 marker와 정확히 같으며 회사·파일·필수 선택값이 유지되는지 다시 확인한다. 실제 버튼을 누르기 전에 marker를 `validation-requested`로 변경한다.

파일명이 아직 표시되지 않으면 파일을 그대로 유지한다. 버튼 비활성화는 실행 함수가 실제로 클릭하지 않았다는 `validationNotStarted` 응답을 반환한 경우에만 다시 시도할 수 있다. 실행 응답이 없거나 예외가 발생하면 claim을 미확인 상태로 보존한다. 다음 요청에서 클릭된 marker가 확인되면 결과 조회로 이어가고, 클릭 여부를 알 수 없으면 추가 클릭을 하지 않는다. 기다렸다가 자동으로 업로드하거나 검증을 재시도하지 않는다.

앱에서는 기존 필수 가격정보/라벨 연락처 동의와 서류 해당함/해당없음을 사용한다. 미확인 추가 동의나 문서 항목을 임의로 선택하지 않는다. 필수 항목이 해결되지 않은 경우 Supplier Hub의 기존 첨부를 보존한다.

## 근거와 검증 범위

검증 재개는 기존 공개 `/qvt` 코드에서 확인한 버튼/필수서류 구조와 이미 사용 중인 화면 검사 함수 위에 연결했다. 공개 배포 파일의 존재 또는 합성 DOM을 실제 로그인 화면의 최종 접수 증거로 취급하지 않는다.

두 회사 및 서류 해당함/해당없음, 파일 표시 지연, 비활성 버튼, 실제 직렬화 함수의 클릭 후 응답 유실, 실행 전 응답 유실, 동시 요청, 원래 창/탭/회사/카테고리/파일 변경, 서버 조회 실패, 저장된 결과, 검증 표의 기존 행, 동의 변경 중 회사/첨부 변경을 테스트했다. 앱 UI는 재개 시 ZIP 재출력·재첨부가 없고 새로운 수동 선택이 필요하며, 저장값이 바뀌면 요청하지 않는지 검사했다. 콘텐츠 스크립트→worker 명령 전달과 capability/식별값 응답 검사도 포함한다.

테스트는 임시 저장소와 합성 Hub DOM에서 실제 프로젝트 함수로 실행했다. 실제 Hub의 원격 검증/견적 접수 호출은 실행하지 않았다. 전 카테고리별 추가 필수서류 및 기본값 대조, 운영 환경 AI/이미지 번역과 두 회사의 실제 접수번호·SKU 확인은 별도로 남아 있다. `validation-requested`는 상품 등록 완료를 의미하지 않는다.

확장 0.2.39는 기존 로드 폴더와 앱 페이지 새로고침이 필요하다. 신규 Chrome 프로필, 권한/호스트, DB migration, 비밀 설정 또는 유료 자원을 추가하지 않는다.
