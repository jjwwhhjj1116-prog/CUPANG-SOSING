## 상품 설명 번역의 완료 판정

제목과 옵션 번역이 성공하고 설명만 HTTP 400·네트워크 오류·잘못된 응답·5,000자 제한으로 누락되면, 이전에는 전체 초안 완료로 표시할 수 있었다. 저장된 설명과 견적서 HTML에는 원문이 남아 있었다.

서버는 최초 canonical Google v6 작업과 현재 콘텐츠 revision을 확인해 설명 누락 근거를 돌려준다. 클라이언트는 작업 ID·revision·불리언 값·미리보기 지문을 검증한다. 누락된 설명은 검토 필요로 남기며 성공한 제목과 옵션 초안은 반영한다. 원문, 직접 수정한 설명과 명시적 공란, 가격·사진·라벨·견적서 수정값은 보존한다. 재개할 때 같은 외부 번역을 다시 요청하지 않는다. 미리보기 뒤 수동 수정이 발생하면 기존 CAS가 적용을 거절한다. options-only와 일반 번역 요청, 429·5xx 중단, 취소와 응답 미확인 계약은 유지한다.

## 기본설정의 조회·저장 순서와 계정

설정 저장 이전이나 저장 중 시작한 조회가 늦게 도착해, 새로 저장한 브랜드·환율을 과거 값으로 되돌리는 문제를 실제 Dashboard 콜백에서 재현했다. owner·mount·operation epoch를 확인해 오래된 조회와 저장 응답이 현재 계정의 상태를 덮어쓰지 못하도록 했다. 저장 실패·취소 뒤 새 조회와 성공 후 새 조회는 사용할 수 있다.

상품추가 창의 명시적 설정 재조회도 현재 로그인 owner scope와 조회 토큰을 검증한다. 다른 계정·누락되거나 잘못된 scope·저장 이전의 늦은 응답은 적용하지 않는다. URL·카테고리와 처리 대상은 보존하며 실패 응답을 성공 안내로 표시하지 않는다. 유앤채와 와이홉의 기존 서버 소유권·카테고리 회사·expectedSettings 검사를 유지한다. 기존 상품의 수집 당시 설정이나 가격은 재계산하지 않는다.

## 견적서 조합 조건

원본 JSON Schema의 객체 enum·const를 자식 필드로 평탄화하면 필드별로는 맞는 값이라도 허용되지 않은 조합을 확정할 수 있었다. name/value 배열 전체의 enum·const와 allOf 항목의 contains enum·const도 같은 조건 유실을 재현했다. 지원하지 않는 전체 조합 조건은 원본 경로에서 unsupported로 표시한다. 초안과 수동 편집은 유지하되 견적서 출력·최종 전송 검사는 해당 조건을 확인했다고 취급하지 않는다. 정상 scalar enum과 기본값, 직접 입력한 공란, 관측한 name/value 배열 형식은 유지한다. 실제 Hub의 모든 카테고리에 이 조건이 존재한다고 주장하지 않는다.
