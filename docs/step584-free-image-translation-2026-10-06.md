# Step 584 — 무료 이미지 문구 번역과 삭제 옵션 초안 재개

## 구현한 흐름

이미지 역할에 저장한 원본을 선택해 **문구 인식 → Google 한국어 번역 → 원문·번역·영역 수정 → PNG 미리보기 → 명시적 적용**을 진행할 수 있도록 연결했다. 상세 이미지의 중국어/영어 번역 버튼은 원본과 실제 상세 역할을 이 편집기에 전달한다. 버튼 진입과 원본 선택만으로 OCR·외부 번역·저장은 실행하지 않는다. 기존 유료 AI 도구는 별도 접힌 영역에 유지하며 이 번역 진입에서 실행하지 않는다.

각 문구의 선택 여부, 원문, 한국어, 사각 영역, 배경색, 글자색, 글자 크기를 수정할 수 있다. 낮은 OCR 신뢰도 문구는 기본 선택하지 않는다. 선택한 사각 영역에만 단색 배경과 맞춤 크기의 문구를 그리며 바깥 픽셀은 유지한다. 사진 배경의 AI 복원이나 쿠플러스와 동일한 조판 품질을 주장하지 않는다. PNG를 적용할 때 원본 파일을 보관하고 해당 공통 이미지 역할의 원본 위치를 교체한다.

현재 적용 범위는 상품 공통 `main`, `additional`, `detailTop`, `detail`, `detailBottom`이다. SKU의 `imageKey`는 변경하지 않는다. SKU에만 연결되고 상품 공통 역할에 없는 원본은 이 API로 번역할 수 없다. 표시사항 라벨·사이즈표를 이 이미지 API의 적용 역할에 추가하지 않았다.

## 원본·저장·편집 보호

- 같은 상품·회사 소유의 현재 역할에 있는 파일만 읽는다. 원본 증명에는 상품 ID/버전, 콘텐츠 리비전, 파일 키/SHA-256, 역할, 원본 크기를 고정한다. 받은 파일의 SHA를 확인하고 JPEG EXIF를 반영한 표시 크기로 OCR과 합성을 진행한다.
- 원본/결과는 10MB 이하, 1,200만 픽셀 이하이다. 문구는 최대 100개 영역·총 20,000자이며 영역마다 5,000자 이하이다. 결과의 원본 증명, 정확한 문구 ID와 요청 원문을 확인한다. 순서가 바뀌어도 ID로 연결하며 손상·누락 결과는 완성된 번역으로 채우지 않는다.
- 저장 응답의 결과 키는 정해진 원본 증명의 해시와 PNG 해시로 검증한다. 저장은 상품 버전·콘텐츠 리비전·원본 파일 목록을 함께 비교한다. 실패하거나 충돌하면 기존 역할을 덮어쓴 것으로 표시하지 않는다.
- 저장 응답이 유실되면 같은 PNG와 원본 증명을 유지한다. 사용자가 같은 결과의 저장 상태 확인을 선택할 때만 다시 보낸다. 재확인 성공은 원본 증명·결과 키·현재 역할에 적용된 동일 결과를 확인해야 한다. 자동 재저장·자동 번역 재호출은 없다.
- 직접 수정한 번역과 공란은 후속 번역으로 채우지 않는다. 같은 이미지 재선택은 문구를 유지한다. 다른 이미지·역할 선택과 OCR 재인식은 명시적 초안 지우기 전까지 기존 문구를 보존한다.
- 다른 단계 저장으로 상품 버전이 바뀌어도 원문·한국어·공란·영역을 유지하고 미리보기를 무효화한다. 명시적 원본 상태 재확인에서 같은 SHA·표시 크기·키·역할일 때만 최신 저장 증명으로 연결한다. 다른 원본이면 초안을 보존하고 적용을 막는다.
- 취소·교체·닫기는 진행 요청을 중단하고 늦은 결과를 무시한다. 작업 중·미저장 상태는 기존 화면 전환/견적서 검사에 연결된다. Blob URL은 현재 Blob에만 표시하고 교체·종료 시 해제한다.

## 로컬 OCR 및 무료 번역

Tesseract.js/core **7.0.0**, 중국어/영어 모델과 라이선스·검증 manifest를 같은 사이트에 보관한다. 정적 자산은 **17개, 49,515,369 bytes**이다. 실행 시 외부 모델 CDN에서 받지 않으며, 빌드 전 고정 버전과 자산 체크섬을 검사한다. Git 속성으로 이 경로의 줄바꿈 변환을 끄고 실제 스테이징된 17개 파일의 SHA·크기까지 검사하여 다른 PC에서도 같은 원본 바이트를 유지하도록 했다.

브라우저의 한 WebWorker를 생성부터 종료까지 직접 소유한다. 고정된 7.0.0 worker protocol의 `load`, `loadLanguage`, `initialize`, `recognize` 응답을 구분하며 오류·취소·시간 제한에 worker를 종료한다. SDK가 초기화 이후에만 핸들을 반환하고 일부 초기화 실패에서 대기가 끝나지 않는 문제를 피했다. 전역 Worker 교체, 다른 worker 내부의 추가 worker, 유료 OCR 서버는 사용하지 않는다. 문구 인식은 한 엔진씩 진행한다.

문구 번역은 사용자가 요청한 `https://translate.googleapis.com/translate_a/single`의 `client=gtx` GET 방식을 유지한다. 텍스트만 전송하며 이미지 파일은 Google에 보내지 않는다. 식별자가 있는 요청 묶음, 원문 숫자/미번역 검사, 429/5xx 이후 중단과 부분 결과 보존을 적용한다.

## 삭제 옵션 재개 수정

상품 옵션을 삭제한 뒤 완료된 기존 수집 번역을 재사용하면, 삭제된 옵션 ID를 포함한 저장 결과 때문에 재개가 막히는 버그를 수정했다. 검증된 canonical intake 결과의 **계획용 복사본**에서만 현재 없는 옵션의 연결을 제외한다. 저장된 원문·번역 결과는 변경하지 않고 삭제 옵션을 복원하지 않는다. 일반 번역 요청의 누락 옵션 거부와 수동 옵션명·색상·공란·제외·리비전 보호는 유지한다.

두 회사의 기록 원문 fixture로 69900 카테고리, Google 2회/42필드, 옵션·이미지, 수동 삭제/제외/공란과 견적 XLSX 연결을 실제 핸들러·메모리 SQLite에서 검사했다. 합성 Excel 검사를 실제 공식 양식이나 Supplier Hub 접수 근거로 계산하지 않는다.
