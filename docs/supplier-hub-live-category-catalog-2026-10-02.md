# Supplier Hub 카테고리 조회와 상품추가 연결 — 2026-10-02

## 확인한 공개 계약

로그인 정보 없이 공개 HTML/JS를 HTTPS GET으로 읽어 분석했다. 기존 Chrome 세션·쿠키·토큰이나 Couplus 비공개 API를 사용하지 않았다. 원본 코드는 실행하거나 저장소에 복사하지 않았다.

- HTML: https://supplier.coupang.com/sr/registration — HTTP 200, SHA-256 `57bc98da8b500cedebb8ec99394415d7b884ec5038f107224ed969b79b142f3f`.
- JS: https://supplier.coupang.com/sr/static/js/main.5239dce6.js — HTTP 200, 4,346,727바이트, SHA-256 `6fc9c0fae51702e62e2d1376ac8854d0d97c0035b0bf96afeb42069c2a5abe11`.
- 카테고리 대분류: GET `/sr/category/api/`.
- 하위 분류: GET `/sr/category/api/find-by-parent-category-code?categoryCode=...`.
- 프런트엔드의 카테고리 변환은 배열의 `leaf`와 `displayItemCategoryDto.displayItemCategoryCode/name`을 사용한다. 이름이나 마지막 경로만으로 코드를 추정하지 않는다.
- 상세 양식은 별도 GET `/sr/schema/api/get-default-schemaform?internalDisplayCode=...&useCustomizedJsonSchema=true`로 가져온 `schemaString`을 사용한다. 저장 견적을 불러올 때에는 별도 `kanCategoryId`, `scopeType`, `noticeNumber`, `version`도 사용한다. 표시코드와 칸 ID를 같은 값으로 간주하지 않는다.
- 익명 카테고리·80719 상세 양식 GET은 HTTP 302였다. 실제 로그인 응답·전체 카테고리·상세 schemaString을 확보한 것은 아니다. 기존 Chrome 도구의 전체 탭 조회 거절을 다른 경로로 우회하지 않았다.

## 구현

상품추가의 카테고리 선택 창은 Supplier Hub 목록을 단계별로 읽는 화면을 기본으로 열며, 기존 저장 목록과 연결된 양식도 사용할 수 있다. 같은 앱 Chrome 창의 Supplier Hub 등록/조회/개별등록 탭에서 공식 카테고리 GET만 수행한다. 탭·창·프로필을 생성하지 않고 기존 상품·파일·등록 입력 폼을 수정하지 않는다. 필요한 회사 메뉴 클릭만 기존 검증 함수를 사용한다.

`/api/supplier-hub/catalog-context`는 현재 승인된 회원의 소유 ID와 승인 회사코드·회사명만 반환한다. 관리자 회원 목록·이메일·비밀번호를 반환하지 않는다. 확장은 원래 앱 탭에서 이 정보를 확인하고, Supplier Hub 화면 회사코드와 대조한다. 조회 후 앱 회원·회사·탭이 바뀌면 응답을 사용하지 않는다.

각 하위 조회는 루트부터 부모 경로를 다시 읽어 이름·표시코드·최종 여부를 대조한다. 사용자 입력 경로를 공식 경로로 가정하지 않는다. 최대 상위 10단계, 응답 512 KiB, 단계당 1,000개, 조회 20초를 제한한다. 로그인 HTML/리디렉션/잘못된 코드/중복 코드/순환 경로는 채택하지 않는다. 쿠키나 토큰 값을 읽거나 앱으로 전달하지 않는다.

최종 선택을 완료하기 직전에 분류를 다시 확인하고, 전체 경로+표시코드로 기존 견적서 프로필을 재사용하거나 새 빈 프로필을 만든다. 다른 경로의 같은 이름, 다른 코드 또는 여러 견적 설정을 임의로 합치지 않는다. 기존 프로필·Excel 열 연결은 덮어쓰지 않는다. 선택한 분류는 기존 1688 URL 입력과 초안 작성 경로에 연결된다.

조회 취소/늦은 응답을 무시하고, 실패한 부모 경로로 재시도한다. 회원·회사 변경 시 이전 트리를 비운다. 카테고리 목록의 확인은 상세 양식·기본값·칸 ID·공식 Excel 검증과 구분한다. 미확보 분류는 기존 7단계의 `unconfirmed` 상태를 유지한다.

## 검증과 적용 범위

새 검사에서 공식 공개 계약을 모델링한 합성 카테고리 응답, 실제 앱 함수/API, 임시 SQLite를 사용했다. 두 회사의 원래 창/회사 확인, 조작된 상위 경로, 응답 거부, 탭/회원 변경, 재시도/취소, 최종 선택 재확인을 검사한다. 새 미확보 분류를 프로필로 저장→기록된 813724060928 상품 원문 수집→6옵션 초안→견적 상품명 수정까지 연결하며 코드·전체 경로와 미확보 양식 상태가 유지되는지 확인한다. AI·인증·이미지와 카테고리 응답은 fixture다. 합성 분류를 실제 선글라스 판매 분류로 보고하지 않는다. Hub 접수 API 호출은 없다.

확장 0.2.35에서 카테고리 조회 기능을 제공한다. 기존 확장 폴더를 새로고침하고 앱 페이지를 새로고침해야 적용된다. 확장 권한·호스트 허용 범위를 늘리지 않았다. DB 마이그레이션·비밀 설정·유료 서비스 변경은 없다.

아직 남은 핵심은 로그인 운영 환경에서 실제 카테고리 응답 대조, 상세 `schemaString`/칸 ID와 공식 제출 양식의 자동 연결, 운영 이미지 번역·필수 서류와 두 회사의 최종 접수/SKU 검증이다. 전체 카테고리 또는 최종 등록 완료를 주장하지 않는다.
