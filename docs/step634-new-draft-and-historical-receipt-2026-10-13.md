# Step634: Saved-source drafts and historical quotation results

The selected category determines the Supplier Hub form used for a product. When a URL already belongs to an older request with another category or form revision, ordinary intake retains that request. This change provides an explicit **저장 원문으로 새 초안** action instead of silently replacing the existing product or recollecting its source.

The preview shows the approved company, target category and original collection time. Creation uses the reviewed source fingerprint and a fresh request UUID. The new product receives the saved raw source, original image objects, current category contract and current account defaults. Previous manual SEO, option edits, quotation overrides and transmission receipts remain on the original product. The original collection time remains unchanged. Missing or unfinished original images and unsettled translation/image operations prevent creation. The normal intake pipeline then prepares the new editable draft; it does not transmit a quotation.

Company approval, the current URL claim, original job/context/result, product version, content/options/quotation revisions and payloads, image references, price policy, target category revision/payload and account settings participate in the atomic database guard. A lost creation response is recovered with a read-only lookup of the same UUID and fingerprint. The UI does not issue another creation POST. Closing, editing inputs or changing the account prevents late UI adoption. Referenced raw image objects are not physically deleted by existing product image exclusion or soft deletion.

Historical file validation and product registration are separate observations. Refreshing only the original quotation file preserves its previously observed SKU rows and their observation time when the file, company, option count and quotation ID still agree. The UI first confirms the history write, then reads the authoritative receipt using the original product version and quotation identity. A failed or mismatched acknowledgement/read does not replace the displayed receipt. An explicit newer product-registration query may adopt its own validated snapshot; it is not merged with unrelated or incomplete records.
