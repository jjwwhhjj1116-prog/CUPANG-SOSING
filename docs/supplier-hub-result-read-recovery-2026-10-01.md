# Supplier Hub 결과 조회 실패와 기존 전송 복구

2026-10-01, 단계 538.

## 재현과 변경

결과를 수동으로 재조회하면 요청 전에 기존 결과를 지웠다. Chrome 응답 시간 초과 시 이미 확인된 견적서 ID와 SKU 표가 없어졌고 상품별 조회 버튼도 비활성화됐다. 서버 보관 결과의 GET이 일시적으로 실패하면 기존 Chrome 전송 기록도 확인하지 않아 재접속 후 결과 조회를 이어갈 수 없었다. 신규 회귀 세 건 중 두 건이 수정 전에 실패했다.

- 정상적인 재조회 결과를 받기 전까지 기존 결과·조회 시각·SKU 확인 요약을 유지한다. 시간 초과나 전송 오류는 기존 관찰 결과를 지우지 않는다. 새로 확인된 정상 결과는 기존 화면을 교체하며, 최신 조회에서 SKU가 사라진 경우 이전 SKU 확인 요약도 해제한다.
- 회사·파일명·옵션 수·견적서 ID 또는 결과 계약이 잘못된 경우 `SupplierHubResultInvalid`로 구분해 결과와 조회 요약을 제거한다. 초안이 변경되면 기존처럼 준비본 전체를 무효화한다. 오류를 무시해 다른 상품/회사의 결과를 유지하지 않는다.
- 서버 기록 조회의 네트워크 오류, 408·429·5xx에서는 같은 Chrome의 기존 전송 기록을 확인한다. 회원 회사와 옵션 수, 검토한 파일, 현재 저장본을 다시 대조한다. 확인된 기존 시도나 결과가 있을 때만 중복 전송을 막은 상태로 읽기 조회를 재개한다. 결과가 있으면 서버 보관도 다시 시도한다.
- 서버 조회 실패와 Chrome 기록 부재를 미전송으로 간주하지 않는다. 두 기록의 부재를 정상 조회로 확인하기 전에는 새로운 파일 전달을 허용하지 않는다. 자동 재첨부나 재전송은 없다.
- 인증·400·404·409 등 입력/출처 오류에서는 대체 기록을 조회하지 않는다. 결과 API의 기존 인증 실패 503에 `AUTH_REQUIRED`를 추가해 일시 장애와 구분한다. 인증 이전 DB/본문 접근 차단은 유지한다.
- 취소된 복구는 늦게 도착한 보관 응답으로 새 전송을 활성화하지 않는다.

## 검증

와이홉 A01464742와 유앤채 A01526306 각각 실제 TSX와 결과 API·임시 SQLite를 사용했다. 기록된 813724060928의 여섯 옵션 초안, 수동 수정, 생성 XLSX와 첨부 전송 경계, 파일/SKU 관찰 결과, 서버 보관 뒤 재접속을 연결했다. 서버 기록 읽기/쓰기를 503으로 실패시키고, Chrome에 남은 여섯 SKU를 복원한 후 수동 조회 응답을 유실시켰다. SKU 표·견적서 ID·재조회 가능 상태가 유지되고 복구 후 저장 오류가 해제됨을 확인했다.

전송/Excel 준비는 각각 한 번이며 추가 첨부 준비는 없다. 기존 상품 행, 초안 버전, fingerprint 및 D1 보관 결과가 바뀌지 않는다. 미확인 기존 시도의 결과 조회 재개, 잘못된 회사·옵션 수·조회 중 초안 수정, 인증 503과 다른 4xx, 느린 수동 조회 및 시간 초과도 검증했다.

인증·AI·이미지·양식·Hub 전달과 관찰 결과는 시험 자료다. 80719는 관찰 폼의 시험 계약이며 지정 선글라스의 실제 판매 분류가 아니다. 운영 상품과 실제 Hub 견적서를 이 시험에서 수정하지 않았다. 모든 결과는 `registered:false`이며 실제 최종 승인을 주장하지 않는다.
