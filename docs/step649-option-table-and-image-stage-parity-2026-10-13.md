## Observed behavior and implementation

The Couplus option dialog has twelve data columns: option number, option name, SEO, pricing, main image, additional images, detail images, size chart, Korean label, quotation, stock/prices, and management. Its page-size choices are 10/25/50/100, initially 50, with column visibility, column pinning, and height Y/N controls. YOOFAM PLUS now provides these controls. Selection survives pagination; the header checkbox operates on the current page. Search and page-size changes start at page one. Opening and closing an option's seven stages retains the table instance, page, query, columns, pin, height, and selection. When a saved reorder moves that option, return focus follows its exact ID within the retained search. Deliberately hidden columns are not reopened automatically.

The main-image editor now has work, saved main selection, option images, and saved detail-layout tabs. Grouping uses the existing read-only content/options endpoints and requires the same product, option, and content revisions as the quotation snapshot. Removed or foreign keys are excluded. This does not classify every original 1688 gallery image: the tab labels state when grouping represents saved roles. Unclassified and edited files remain in the full work library. A failed or delayed grouping request cannot block normal full-library selection, explicit saving, or acknowledgement recovery. Switching tabs retains the final selection and pending edits.

Reference detail banners supplied by basic settings have no edit/translate/delete controls. The content response now optionally identifies a banner using the exact owner-linked collection context, approved company, captured setting, current saved role, and owned image pool. Only a proven matching key is treated as a settings banner. Unknown, legacy, disabled, replaced, or foreign-context evidence leaves normal image editing available. The detail preview preserves banner viewing/downloading and disables movement; its edit, translation, deletion, and reassignment paths cannot change a proven banner. A manually uploaded or different-key top image remains editable. Selecting the same captured key manually is indistinguishable from retaining that banner; the descriptor makes only a source-key claim. This is a UI behavior rule, not an authorization boundary or a new server-side restriction on the existing content PATCH contract.
