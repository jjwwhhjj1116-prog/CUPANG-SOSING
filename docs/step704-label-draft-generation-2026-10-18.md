## 바로잡은 작업 흐름

이전 주 표시사항 편집기의 ‘한글 표시사항 생성 시작’ 버튼은 저장된 행을 PNG로 그리는 동작만 했다. 원본 버튼은 상품명·수집 속성·묶음 정보를 사용해 `KOREAN_LABELS` 작업을 요청한다. 원본 prompt의 출력은 `content/material/type` 세 문자열이며 다른 표시사항·법적 고시나 이미지/OCR 입력이 아니다.

새 버튼은 현재 상품·옵션·카테고리에 연결된 원문과 저장된 최종 SEO 제목으로 **내용량·재질·상품 유형** 초안을 요청한다. 세 필드의 원래 값과 제안값을 비교하고 편집할 수 있다. 응답은 local draft에만 들어가며 정보 저장하기를 누를 때 기존 표시사항 PUT·저장 버전 대조를 사용한다. 취소하면 기존 저장본을 다시 읽는다. 저장한 표시사항을 그리는 동작은 별도 ‘저장한 표시사항 PNG 미리보기’로 분리했다. 이미지 업로드·견적서 연결·Supplier Hub 전송을 자동 실행하지 않는다.

자체 prompt에는 설명·카테고리·선택 옵션의 원문/번역명도 추가 참고 자료로 포함한다. 명시적 공란 최종 SEO 제목은 `productName:''`로 유지하고 원문 제목을 별도 `originalTitle`로 전달한다. 원본의 `SEO제목 || 원문제목` fallback이나 prompt 문자열을 byte 단위로 동일하게 복제한 것은 아니다. 기존 원문의 연락처·인증·치수나 지시문은 AI가 실행하거나 확인 완료로 취급할 대상이 아니다.

현재 공통/선택 옵션에서 직접 저장한 값과 공란, 콘텐츠에서 직접 확인해 저장한 값, 삭제한 항목은 AI 제안으로 대체하지 않는다. 비공란 중국어 수집 속성이나 자동값은 한국어 제안을 받아 검토할 수 있다. 커스텀 항목·제조원·수입원·제조국·주의사항·사용 기준·인증·법적 고시는 이 요청의 출력 대상이 아니다. AI 제안을 사용자가 확인해 저장하면 기존 수동 표시사항 모델로 보관된다. 별도의 법적 확인 완료 증거로 바꾸지 않는다.

## 원문·회사·요청 범위

`POST /api/products/:id/product-label-draft?profileId=...`는 현재 label revision/input fingerprint와 optionId를 받는다. 기존 product-labels 조회와 카테고리/회사에 연결된 견적 원천, 연결 수집 원문 조회를 재사용한다. 서버에서 상품·옵션·콘텐츠·카테고리 양식·표시사항·회사 정보를 요청 전후 대조하며, 다른 회원/회사/프로필이나 중간 변경이 있으면 결과를 반영하지 않는다. 오래된 수동 상품은 존재하지 않는 1688 수집 자료를 만들어내지 않고 저장된 상품명·설명만 참고한다.

기존 설정된 Workers AI binding·모델·free-only 정책을 사용한다. 새 서비스·유료 플랜·시크릿·리소스는 만들지 않았다. 견적 AI와 동일한 `quotation_ai_daily` 요청 한도 40회를 공유하고, provider 호출 전에 1회를 예약한다. **이 할당량 counter만 서버에 기록**하며 상품·콘텐츠·옵션·표시사항·견적 입력·AI 작업 이력·R2 파일은 초안 요청으로 쓰지 않는다. 이를 DB 전체 무쓰기라고 표현하지 않는다. provider 오류·한도·시간초과는 자동 재시도하지 않으며 30초 제한 후 기존 입력을 유지한다. timeout이 실제 원격 연산 취소를 증명하지는 않는다.

응답은 기존 strict JSON parser와 provider envelope 검증을 재사용한다. 완전한 JSON 객체의 정확한 세 문자열만 허용하고 중복/추가 키·잘린 JSON·설명문·제어문자·길이 초과·다른 provider/회사·옵션·source clock을 거절한다. 원본과 같이 정보 부족 시 `상세정보참조`를 요청하지만 이 문구를 확인된 상품 사실로 취급하지 않는다. provider가 실제 공란을 반환하면 자체 코드가 내용을 추측해 보충하거나 저장값을 지우지 않고 해당 제안을 생략한다.
