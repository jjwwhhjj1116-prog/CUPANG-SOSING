# 카테고리 정의 갱신과 기존 상품 견적서 보존

상품 추가에서 같은 카테고리의 Supplier Hub 상세 양식이 달라지면, 이전 원본 Excel의 Single 지문을 그대로 저장할 수 없어 선택이 실패했다. 기존 설정에 새 지문을 덮어써도 이전 상품이 수집 시점에 보관한 양식과 달라져 견적 출력이 실패했다.

## 변경

- 실제 상세 양식 원문 또는 메타데이터 변경은 별도 카테고리 설정으로 저장한다. 기존 설정, 연결된 상품, 수동 수정값과 공란은 변경하지 않는다.
- `/api/category-profiles/:id/refresh-definition`은 승인 회사, 소유자, 코드, 전체 경로, 부모 저장 버전과 UUID 요청 키를 확인한다. 원본 파일·매핑·검증 근거는 요청 본문에서 받지 않는다.
- 공식 파일은 소유자가 보관한 원본을 읽어 SHA-256, 카테고리 드롭다운, 시트, 머리글, 입력 시작 행과 선택지를 다시 검증한다. 원본 파일을 수정하거나 새 Excel JSON 양식으로 간주하지 않는다. 고시 유형 변경은 이전 파일을 자동 재사용하지 않는다.
- 일반 CSV·TSV·XLSX도 실제 원본 바이트의 지문과 머리글을 확인한다. 같은 머리글·저장 메타데이터만으로 변경된 원본을 재사용하지 않는다.
- 매핑은 같은 Hub 입력 경로와 형식만 이관한다. 고정값, 필수 표시, 선택지 출력 형식은 보존한다. 새 길이 제한은 새 상품 입력에 적용한다. 사라지거나 형식이 달라진 연결은 자동 추측하지 않는다.
- 새 설정 저장은 부모 버전 조건과 함께 원자적으로 실행한다. 재시도는 같은 요청 키와 본문을 사용한다. 확인된 서버 응답을 받기 전에는 URL 행의 카테고리를 바꾸지 않는다.
- 일반 설정 PUT에서도 같은 카테고리의 실제 상세 양식 변경을 거절한다. 관찰 시간과 메타데이터 속성 순서만 달라진 경우는 정의 변경으로 취급하지 않는다. 앱의 입력 연결 규칙만 바뀐 경우에는 기존 경로를 유지한다.
- 원본 Excel의 조건부 필수 항목은 공란을 임의 기본값으로 채우지 않는다. 공란·선택값 모두 원본 안내와 함께 적용 여부 검토에 포함한다. URL 행의 매핑 미리보기에도 조건부 필수를 표시한다.

## 검증

두 회사의 격리된 실제 API·SQLite 테스트로 이전 상품의 수동 공란, 캡처된 양식과 XLSX 출력 유지, 새 설정으로 수집한 상품의 새 입력 제한, 소유권·원본 위조 거절, 재시도·동시 수정·늦은 응답을 검증한다. 기존 견적서 준비와 확장 첨부 검사도 회귀 검사에 포함한다.

최종 회귀 검사 423/423 통과, 실패·건너뛰기 0. 타입 오류 0, lint 오류 0(기존 경고 8), 운영 빌드 통과. 앞선 반복 출력 검사 실패는 테스트에서 파일 근거만 제거하고 그 근거에 의존하는 추가 항목을 남긴 불일치였으며, 일반 양식 테스트 자료를 일관되게 수정했다. 생산 검증기는 약화하지 않았다.

사용자의 기존 Chrome에서 쿠플러스 등록 목록과 옵션 SEO 팝업을 읽기 전용으로 확인하고 화면을 보관했다. 상품 특징·키워드·상품명·검색태그·옵션명을 저장하거나 AI 작업을 실행하지 않았다. 운영 앱에서도 기존 상품과 대기 URL 행을 변경하지 않고 저장 양식 미리보기만 확인한다.

운영 Worker `23111541-3b90-4252-b1b4-2da1ba431592`에 반영했다. 검수 탭에서 최신 대시보드 파일 `dashboard-client-DzUaat1-.js`와 설치지원방식의 조건부 필수 표시를 확인했다. 일반 새로고침에서 이전 화면 파일이 관찰돼 검수 탭의 URL에 배포 버전 쿼리를 붙여 최신 화면을 확인했다. 사용자 원래 탭의 입력·상품 행, 검수 탭의 상품 행 및 대기 URL·특징·키워드·선택 상태는 전후 동일하다. 기존 17개 migration과 확장 ZIP 두 버전의 바이트도 유지한다.

## 남은 실제 검증

신규 1688 상품 수집부터 이미지 편집·번역·사용자 검토·Supplier Hub 신규 접수 번호 확인까지의 실제 연속 작업, 모든 카테고리의 쿠플러스 기본값 일치, 상품관리(신규) 전체 화면 일치와 Codex 플러그인 후속 단계는 완료 판정에 포함하지 않는다. 격리된 데이터와 모의 첨부 성공을 실제 견적서 접수로 보고하지 않는다.
