# 등록전송 이후 검증·SKU 조회 연결

2026-09-30 구현 기록. 실제 Hub 견적서 등록 성공 기록과 구분한다.

- 기존 흐름은 파일 검증을 요청한 직후 결과를 한 번만 읽었다. 처리 중이면 사용자가 검증 결과와 상품별 결과를 따로 다시 불러와야 했다.
- 이제 사용자가 검토한 Excel/첨부와 필수 선택을 `등록 전송`으로 전달하면, 해당 파일의 검증 결과를 반복 조회한다. 검증 완료와 정확한 견적서 ID가 확인되면 같은 회사·Chrome 창의 확장 조회로 상품별 SKU를 확인한다. 이후 조회에는 파일 준비·첨부·동의·검증 요청이 반복되지 않는다.
- 최초 대기 간격은 3/5/10/15초, 이후 30초다. 열린 편집 화면에서 최대 2시간/300회 안에서 조회한다. 이는 관찰된 Hub 검증 최대 2시간 안내에 맞춘 대기 한도이며 실제 처리 속도를 보장하지 않는다. 화면을 닫거나 조회를 일시정지하면 종료한다. `전송 결과 계속 확인`은 조회만 재개한다. 새로고침 후에는 견적서를 준비해 기존 검증 결과를 불러오고 조회를 재개할 수 있다.
- 매 조회 전후 현재 저장본의 상품·카테고리·프로필·자료 지문·파일명을 다시 검사한다. 회사코드/회사명과 전송 옵션 수, 최초 확인한 견적서 ID가 달라지면 결과 확인을 중단한다. 확장 자체의 회사코드/창/전송 기록 검사도 유지한다.
- 저장본 대조는 인증·소유권·수집 당시 분류·서버 자료 지문을 동일하게 사용하는 `quotation` API의 읽기 전용 `source` 요청으로 한다. 두 번 읽은 DB 자료가 같을 때만 식별값을 반환한다. 대기 중 매번 Excel을 만들거나 R2 원본/이미지를 다시 다운로드하지 않는다. 미리보기·패키지 생성의 실제 파일 검사는 기존 경로에 그대로 남는다.
- 검증 또는 상품 상태에 반려가 있으면 상세 결과를 표시하고 중단한다. 응답 오류에는 자동 재전송하지 않는다. 한 화면의 행 수만으로 등록 완료를 판단하지 않는다. 전송 옵션 수와 같은 수의 고유하고 생략되지 않은 SKU ID를 관찰했을 때 `SKU ID 확인`을 표시한다. 검수 승인이나 최종 등록 완료로 바꾸지 않으며, `registered:false` 계약을 유지한다.
- 현재 확장은 결과 표의 현재 페이지를 읽는다. 여러 페이지의 모든 옵션을 대조한 결과는 아니다. 최종 등록 이후 별도 행동이 나타나는지도 실계정 성공 화면에서 확인해야 한다. 이전 관찰은 비어 있는 등록 화면이었다. 미관찰 최종 버튼을 추측해서 실행하지 않는다.

검증: 두 승인 회사의 검증 대기→정확한 ID→새 SKU 조회, 이전 저장 SKU 무시, 반려, SKU 중복/생략/공란, 옵션 수/회사/ID 변경, 조회 중 저장본 수정, 대기 취소·재개, 제한 시간·횟수, 응답 유실을 모의 확장/React 시험으로 확인했다. 실제 DOM·등록·실계정 최종 접수는 이 시험으로 입증되지 않는다. 기존 Couplus 작업 상품은 변경하지 않았다. 서버나 확장의 운영 등록 성공 상태를 만들어 넣지 않았다.
