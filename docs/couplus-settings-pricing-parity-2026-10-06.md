# Couplus 기본설정·가격 대조 — 2026-10-06 (step578)

기록된 실제 기본설정 화면·DOM(`outputs/step492/couplus-settings.png`, `couplus-settings.txt`)과 보관된 공개 청크 `outputs/step556-couplus-chunk.js`·`outputs/step546-couplus-main.js`의 특정 함수를 현재 앱과 대조했다. 기본 등록 정보·가격설정 방법·이미지 작업 설정·AI 설정의 네 카드와 브랜드/제조사/수입원/거래타입/수입여부/A/S/박스 수량, 환율·마진·최소 마진·반올림·MSRP·번들, 이미지·비노출속성 입력이 연결돼 있다. 계정에서 관찰한 사업자 정보나 박스 수량을 다른 사용자의 기본값으로 복사하지 않는다. 이번 감사에서 앱 가격·설정 소스와 테스트는 변경하지 않았다.

기록된 예시는 환율 350·공급 마진 50%·쿠팡 마진 40%·10원 반올림·MSRP 1.3배·최소 공급 마진 3,000원이다. 25.6 CNY의 원화 원가 8,960원, 공급가 17,920원, 판매가 29,870원, MSRP 38,830원이 현재 계산과 일치한다. 5.23 CNY도 공급 4,830원·판매 8,050원·MSRP 10,470원으로 일치한다. 이 계정 사례를 현재 환율이나 모든 계산 경계의 동등성으로 확대하지 않는다.

공개 청크 `processOptions` → `updateOptionPricing` → `calculateBundleQuantity`는 최초 신규 옵션의 번들 수량 선택에 100원 단위를 사용한다. 가격 편집과 중앙 worker의 수량 선택은 설정된 단위를 전달하므로, 관찰된 설정에서는 10원이다. 수량은 1·3·5…21개이며 최종 묶음 가격은 별도 저장 가격 정책으로 계산한다. 현재 앱은 이 구분을 유지하고, 기존 설정 저장만으로 상품 수량·가격을 다시 쓰지 않는다.

최소 공급 마진은 원본 내부에서도 분기가 다르다. 중앙 worker `calculatePricing`는 비율 공급가를 먼저 반올림한 뒤 실제 마진이 최소액보다 작을 때 원가+최소액으로 보정한다. 반면 다른 공개 청크의 `updateOptionPricing`와 가격 편집 `recalculateOption`은 최소 보장이 켜지면 원가+최소액을 직접 사용한다. 따라서 이 분기들을 하나의 동작으로 단정하지 않는다. 현재 앱은 기록된 실제 예시와 기존 저장 정책을 유지하며, 모든 Couplus 편집 경로와 완전히 같다고 확정하지 않는다.

현재 앱에는 공개 청크의 `useIntegratedRate` 기능이 연결돼 있지 않다. 원본 설정 화면은 `쿠패스 통합통관 환율` 스위치와 조회값 표시를 제공하며 해당 환율의 수동 입력란은 없다. `loadIntegratedRate`는 **POST `/api/getExchangeRate`**, 요청 객체 `{}`를 사용한다. 클라이언트는 응답 JSON의 `data.integratedRateFound`와 `data.integratedRate`를 읽어 양수 숫자로 변환하고 캐시에 보관한다. 이는 소비 코드에서 확인한 계약이며 실제 응답·환율값·응답 단위 메타데이터는 실측하지 않았다. 단위는 CNY 원가에 곱하는 계산과 화면 설명상 KRW/CNY로 해석된다.

공개 `purchaseCost`는 통합 모드에서 CNY 원가×통합환율에 포장검수 200원·바코드 100원을 더하고 1.1을 곱해 원 단위 반올림한다. 원본 내부에는 환율 누락 시 일반환율로 계산하는 경로와 설정 활성화 전 오류로 중단하는 경로가 함께 있다. 정확한 실제 환율과 본 앱의 접근 권한을 확보하지 않은 상태에서 타사 API에 종속되도록 연결하거나 쿠패스 값을 임의 환율로 대체하지 않는다. 현재 앱의 일반환율 방식을 유지한다.
