## 수집 → 카테고리 → 개별 초안

기존 대기열은 `전체 시작`을 통해 선택된 여러 행을 처리했다. 따라서 새로 수집한 상품만 진행하려 해도 과거의 미완성 행이 함께 선택돼 시작을 막을 수 있었다. 수집본이 연결되고 아직 상품·이전 요청에 연결되지 않은 각 행에 **이 상품 초안 작성** 버튼을 추가했다.

이 버튼은 해당 행 ID 하나만 기존 `submitIntakeQueue`에 넘긴다. 사용자가 다른 행을 체크하거나 해제한 상태와 독립적이며 다른 행의 내용·선택 상태는 변경하지 않는다. 카테고리 선택·행 추가·화면 mount는 수집·AI·전송을 자동 실행하지 않는다. 기존 전체 시작 기능은 유지한다.

정확한 회사·카테고리 양식·기본설정 revision·불변 수집본 ID/revision/fingerprint 연결을 그대로 사용한다. 오래된 콜백·계정 전환·취소·unmount·실행 중 중복 클릭·알 수 없는 저장 응답은 기존 보호 경로로 막는다. 정상적으로 새 초안이 확인된 단일 상품만 SEO로 연다.

초기 job에 상품 ID가 없더라도 다른 화면이 먼저 같은 상품을 만들 수 있다. `collectIntakeProduct`가 검증한 `reused:true` 응답을 선택적으로 보고하고, 해당 ID를 새 초안 자동 열기에서 제외한다. 기존의 SEO·이미지 쓰기 방지는 유지한다. 상품 생성 경쟁을 새 상품 성공으로 오인하지 않는다.

추천 입력의 상품명은 **추천 검색용 상품명**으로 명확히 표시했다. 이 검색 문구를 고치는 것은 원문·SEO 상품명 수정이 아니며 실제 제목은 이후 SEO에서 수정한다.

## 편집 화면

- 대표 이미지: 기존 4개 탭과 선택 저장을 유지한다. 현재 이미지가 소유 이미지 pool의 정확한 단일 파일일 때만 왼쪽 작은 미리보기를 제공한다. 확대는 기존 읽기 전용 모달·취소·focus guard를 재사용한다. 기존 중국어/영어 번역 동작을 현재 사진 아래로 옮겼으며 새로운 생성형 AI 기능을 구현했다는 의미는 아니다. 오른쪽 큰 사진·수동 편집은 유지한다.
- 추가 이미지: 기존 즉시 저장 모드의 다운로드 안내가 다시 저장하라고 오해시키지 않도록 수정했다. 저장 중·확인되지 않은 응답·유지 중인 수정값에는 각각 실제 상태에 맞는 안내를 보인다. 저장 방식은 바꾸지 않았다.
- 표시사항: `ProductLabelEditor`의 자동값 복원·전체 항목 삭제를 행 위에 노출하고, 행 아래 전체 폭 점선 `＋ 새 항목 추가`를 둔다. 전체 구조 편집은 추가 구역에 남긴다. 기존 확인·잠금·행 ID·PNG·저장·ACK 복구 계약은 유지한다.
- 견적서: 모델명 최대 50자, 40자 초과 주의·45자 초과 강조. 검색태그는 3줄·최대 150자, 120자 초과 주의·140자 초과 강조다. 더 엄격한 카테고리 스키마 길이를 우선하며 기존 초과 저장값을 자동으로 자르지 않는다. 정확한 canonical ID 또는 이름 없는 정확한 wire에만 적용하고, 이름 있는 속성·workbook·충돌 wire는 제외한다. 명시 공란·읽기 전용·다른 옵션 적용·포장 무게 연결·명시 저장 규칙은 유지한다.

## 검수 근거

최종 고유 검증 범위는 **39파일·502건**이다. 최초 39파일 실행은 496건 통과·6건 실패였으며, 실패는 모두 기존 navigation 테스트가 현재 버튼명 대신 옛 문구를 찾은 TypeError였다. 해당 파일 전체 8건을 최초 집계에서 제외하고 selector 문자열 11곳만 갱신한 뒤 8/8 재검사했다. 생산 코드와 원래 검증 의미는 바꾸지 않았다. 나머지 38파일·494건은 바이트가 그대로인 최초 성공 결과를 사용한다. 따라서 단일 Node 실행이 모두 성공했다고 주장하거나 재검사 8건을 502건에 추가하지 않는다.

최종 집계·각 파일·소스 SHA 및 원본 로그의 관계는 `outputs/step770-final-coverage.json`, 최초 실행은 `step770-final-tests.log`, 수정 파일의 재검사는 `step770-navigation-final-tests.log`에서 확인한다. 초기 동결 SHA는 `step770-final-test-source.json`, 최종 동결 SHA는 coverage의 `sourceSha256`이다. 타입·lint·빌드·배포·커밋은 `step770-final-validation.json`에서 확인한다. 타입·운영 빌드는 통과했으며 lint 오류 0·기존 경고 48건이다. 마지막 selector-only fixture도 별도 lint를 통과했다. 집중 검사와 반복 검사를 최종 합계에 더하지 않는다.
