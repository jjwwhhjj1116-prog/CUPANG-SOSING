# 새 상품 초안의 기본설정 선택값 적용

저장한 기본설정이 카테고리 양식의 선택지에 없으면 기존 앱은 그 값을 그대로 넣고 선택값 오류를 표시했다. 쿠플러스 공개 `applySettingWithDropdownCheck`는 첫 선택값을 사용한다. 브랜드에 쉼표가 있을 때 첫 이름을 쓰는 동작도 기존 앱과 달랐다.

## 확인 근거

556에서 인증·쿠키 없는 HTTPS GET으로 확인한 공개 상품등록 청크 `https://couplus.co.kr/js/chunk-e2dd462a.8dc4d2d7.js`의 캐시에서 `applyDefaultSettings`와 `applySettingWithDropdownCheck`를 읽었다. 549198바이트, SHA-256 `38aee73a04100657ed8463a6156cc096ceaf68d4f3d671f34845a9cda515d587`이다. 실행하거나 전체 구현을 복사하지 않았고 비공개 상품 응답을 조회하지 않았다.

공개 코드에서 선택값 확인을 거치는 기본설정은 다음 네 필드다.

| 실제 양식 경로 | 저장한 기본설정 | 초안 적용 |
| --- | --- | --- |
| productPage.brand | 브랜드 | 쉼표가 있으면 첫 이름만 공백 제거 후 사용, 선택값 확인 |
| productPage.businessType | 거래유형 | 선택값 확인 |
| productPage.importType | 수입유형 | 선택값 확인 |
| logisticsPage.specialHandlingReason | 취급사유 | 선택값 확인 |

저장값이 공란이면 초기 양식 값을 유지한다. `dropdown` 배열이 있으면 그 배열, 없으면 `enum` 배열을 사용하며 값의 일치를 정확하게 비교한다. 일치하지 않으면 배열 첫 항목을 사용한다. 첫 항목이 공란/null/0/false이면 공란으로 표현한다. 일반 브랜드의 공백을 임의로 제거하거나 다른 필드의 값도 이 규칙으로 바꾸지 않는다. 실제 양식의 조건과 검토 요구는 유지한다.

## 적용 범위와 기존 작업 보존

새 회사·leaf·전체 카테고리 경로 양식 캡처에만 `settingsInitialization: couplus-options-v1`을 저장한다. 확인된 `inputBindings: couplus-paths-v1` 경로 및 호환 타입에만 선택 규칙을 연결한다. 이전 상품의 저장된 양식에는 규칙을 추가하지 않으며 프로필을 갱신해도 기존 상품의 frozen 양식을 사용한다.

원본 선택값을 보존해 문자열/숫자/boolean/null을 혼동하지 않는다. 잘못된 배열·타입·상충하는 enum/dropdown은 기존 미확인 처리를 유지한다. 공란 첫 선택값은 명시적으로 적용된 설정값으로 남겨 다른 기본값으로 덮지 않는다. 견적서의 수동 공통값·옵션값·직접 공란이 자동 설정값보다 우선하며 잘못된 수동값을 첫 선택값으로 대체하지 않는다.

기본설정 변경은 기존 수집 설정을 덮지 않는다. 저장 소스 지문은 변경되므로 오래된 화면의 수정은 409로 거절하고 새 화면에서 저장한다. 숫자·가격 계산, 고시 N/A, 동의·서류·등록전송 동작은 변경하지 않았다.

## 검사

신규 초기 검사 8개 중 6개가 실패했으며 수정 후 기존 관련 검사와 함께 33개가 통과했다. 이후 원본 선택값의 정확한 비교와 공란 선택 보존 검사를 추가했다. 실제 앱 API/임시 SQLite·두 회사·합성 분류 991234에서 기록 상품 813724060928의 6옵션 초안을 만들고 선택값 적용→설정 변경 후 원래 값 유지→오래된 저장 거절→옵션 수정/공란→최종 출력값을 확인한다. 프로필에 새 규칙을 추가해도 기존 상품을 변경하지 않는 검사도 포함한다.

첫 통합 검사에서는 설정 변경 후 소스 지문도 같아야 한다고 잘못 기대했다. 실제 동시 저장 보호를 확인해 지문 변화와 409를 검사하도록 수정했다. 추가 검사에서 공란 선택값의 필수 입력 오류가 없어야 한다고 잘못 기대한 부분도 수정했다. 공란 초안과 출처는 유지하되 필수값 검토 오류는 계속 표시하며 제품의 검증을 약화하지 않았다.

기록된 1688 응답, 합성 분류/인증/AI·이미지를 사용한 검사이며 실제 상업 분류·공식 견적 양식·운영 AI/번역 또는 Hub 접수 증거가 아니다. 원격 Hub 접수 호출은 0회다. 이번 추가 변경은 기존 Couplus 작업 상품과 Chrome 창/계정을 조작하지 않았다. 실제 모든 카테고리 대조와 양쪽 회사 최종 접수번호/SKU 확인은 남아 있다.
