# Step637 공유사진 단계 편집과 모델명 견적 보완

## 실제 수정

대표·상세에 함께 사용한 기존 사진을 상세 단계의 하단 선택 목록에서 제외하면 서버는 대표 사진을 보존하지만 화면의 대표 사진 초안까지 비워졌다. 저장 후에도 대표 단계에 미저장 입력이 생겨 7단계 진입을 막는 결함이었다. 단계별 카드도 첫 번째 역할만 읽어 상세에 선택한 공유 사진을 미선택으로 표시했다.

이제 카드와 하단 목록의 제외는 현재 역할에만 적용한다. 해제 후 다시 선택할 때도 현재 단계의 기존 사진은 그 역할만 복원한다. 명시적인 역할 드롭다운 이동은 기존 이동 규칙을 유지한다. 다른 단계의 실제 미저장 입력·공유 위치·원본 파일·옵션 정보를 보존한다.

Couplus 공개 `fillMissingModelNumber`는 전송 직전에 비어 있는 `productPage.modelNumber`를 최종 상품명 앞 50자로 보완한다. 신규 초안에서 모델명이 공란인 동작과 별개다. 이 근거로 7단계 빈 모델명에 출처·제안값과 ‘상품명으로 모델명 입력’ 동작을 추가했다. 사용자가 확인하고 클릭하면 초안에만 넣으며 기존 저장 절차로 확정한다. 조회·초안 작성·출력·전송 과정에서 직접 지운 모델명을 몰래 채우지 않는다.

모델 제안은 정확한 모델명·상품명 연결과 항목 제약이 확인되는 경우만 표시한다. 현재 선택한 공통값 또는 옵션의 최신 상품명·수동 수정값을 읽는다. 기존 모델값은 덮지 않으며, 같은 틱에서 먼저 바꾼 상품명도 반영한다. 50자 UTF-16 경계의 Unicode 손상과 제약 위반을 방지한다.

최종 독립 감사에서 기록된 Unand Single69900 v188와 원본 2624.xlsx의 모델명 열 경계를 추가로 재현했다. 화면용 `productPage.modelNumber`만 저장하면 공식 모델명/품번 열이 공란으로 남고 `EXCEL_FIELD_UNMAPPED`가 발생했다. 합성 양식만의 검증으로 이 경계를 확인했다고 판단해서는 안 된다. 원본에서 확인한 정확한 `contentField=model`과 `unexposedAttributes`의 모델명/품번 연결만 같은 명시적 입력 대상으로 묶는다. Excel 매핑을 추측하거나 새로 생성하지 않으며, 별도로 직접 입력하거나 비운 공식값·포함 옵션별 수동층이 달라지는 경우에는 제안을 제한하고 확인 사항을 표시한다.

공통 견적값은 실제 제외 옵션이 아니므로 해당 항목 이동 시 잘못된 ‘제외된 옵션’ 안내도 제거했다. 실제 제외 옵션과 다른 카테고리·삭제된 항목에 대한 확인은 유지한다.

## 검증

- 겹치지 않는 16개 테스트 파일의 312개 검사 통과: 단계 편집 94, 모델명·견적 편집·API·XLSX 148, 검수·목록·이동 70.
- 양사 공유사진의 대표/상세·카드/하단 제외·재선택, 명시적 역할 이동, 저장 실패와 재시도, 실제 다른 단계의 미저장 입력 보존을 확인했다. 공유사진 수정 전 실제 React 처리→API→SQLite에서 잘못된 대표 초안과 7단계 차단을 재현했다.
- 양사 공통·옵션별 모델 제안은 클릭 전 DB 불변, 클릭 후 미저장 초안, 명시적 저장 1회, 모델값·XLSX 일치, 직접 공란·기존 옵션 모델·가격·원문·이미지 보존을 검증했다.
- 모델 신규 14개 검사에는 실제 기록된 유앤채 원본 양식의 회귀 2개가 포함되며, 건너뛴 검사는 없다. 명시 클릭으로 화면 모델명과 정확한 공식 모델명/품번을 한 번의 저장 요청에 함께 반영했다. 원본 입력 시작 행 9부터 옵션 6행의 모델 열(0 기준 11)이 일치하고 모델명 `EXCEL_FIELD_UNMAPPED`가 제거됐다. 같은 틱에 직접 비운 공식값, 독립 공통·옵션 값, 원래 같은 값인 공식 항목, 모순되거나 모호한 연결도 검사했다.
- 지정된 기존 Chrome에서 실제 React 편집기와 격리된 로컬 API·SQLite·XLSX를 사용했다. 공유사진 상세 제외 후 대표 사진 보존과 7단계 진입을 확인했다. 최종 모델명 검수는 기록된 Single과 원본 Excel을 연결하여 명시 저장 1회·모델 두 항목·기존 옵션 모델 보존·원본 6행 출력 일치·모델 연결 오류 제거를 실제 DOM과 저장 결과로 확인했다. 로컬 시험 화면의 스크린샷 도구는 시간초과하여 DOM·API 기록으로 증거를 남겼다.
- 별도 읽기 감사에서 양사 각각 속성 50개·옵션 200개·번역 600항목을 13개 묶음으로 작성했다. 400개 가격 셀이 원가·수량 계산과 일치하며 재개 시 원문·초안 유지와 외부 요청 없음도 확인했다. 이 감사와 별도 실제 원본 모델명 독립 검수는 위 312개 검사에 중복 집계하지 않는다.
- 기존 검수 테스트의 React hook와 preview 상태·참조 모형을 현재 구현에 맞춰 보완했다. 실제 검증 조건이나 요청 출처 확인을 완화하지 않았다.
- 타입 오류 0, 린트 오류 0, 기존 경고 8개 유지. 운영 빌드의 sourceflow/sourceflow-db/ASSETS, 기존 마이그레이션 18개와 발행 확장 패키지는 유지한다.

## 범위

기존 실상품·회사별 기본설정·복구 대기열·Couplus 작업 기록을 수정하거나 전송하지 않는다. 실제 외부 번역·유료 이미지 요청·Supplier Hub 신규 접수는 실행하지 않았다. 양사 시험은 격리된 기록 계약에 대한 검증이며 모든 회사·모든 최신 카테고리의 완전한 동일성이나 실제 신규 1688→Supplier Hub 접수·SKU 발급 완료를 의미하지 않는다.
