## 대조 및 문제

보관된 Couplus 상세 편집 클라이언트는 처리 사진을 이동할 때 URL과 원본 참조·처리 metadata도 함께 옮기며, 수동 편집 결과는 해당 사진의 현재 결과를 교체한다. 자세한 근거와 정적 분석의 한계는 `step685-detail-composition-parity-audit.md`에 있다. 새 REA producer, Couplus·Supplier Hub·1688·외부 provider를 실행하지 않았다.

기존 자체 `editor=saved`는 저장 당시와 현재의 옵션·역할·필드·슬롯이 모두 같아야 했다. 사용자가 정상적으로 이미지 순서를 저장한 뒤에도 같은 사진의 편집값을 다시 열 수 없었다. 기존 방식의 계약은 유지하고, 화면의 명시적 수동 편집에서만 현재 저장 위치를 검증하는 별도 읽기 방식을 사용한다.

## 동작

- 새 `editor=saved-current-target-v1` 요청은 현재 견적서의 정확한 옵션 UUID·역할·주 필드/연결 필드·슬롯에 선택한 결과가 실제로 있는지 먼저 확인한다. 사용자가 아직 저장하지 않은 로컬 이미지 배열을 현재 견적서로 가장하지 않는다.
- 같은 소유자·상품·승인 회사·정확한 카테고리 context·프로필만 허용한다. 이전 문서가 보관된 옵션·역할·필드·슬롯과 달라도, 현재 연결을 다시 확인한 경우에만 원본 배경과 저장한 편집값을 반환한다. 다른 상품, 같은 URL의 별도 상품/가족, 다른 회사·카테고리·프로필의 권한은 승계하지 않는다.
- 결과 PNG와 비공개 sidecar의 실제 바이트·SHA·치수, 최초 배경의 바이트·SHA·치수를 대조한다. 과거 작업 권한을 재사용하지 않고 현재 버전·content/option/견적 revision·fingerprint·선택 값에 새 증거를 발급한다.
- 새 `editorSource.anchorPolicy='current-target-v1'`는 닫힌 값으로만 허용하며 새 작업 identity에 포함한다. 이 필드가 없는 기존 source/key/영수증과 엄격 `editor=saved` 읽기는 그대로 유지한다. 클라이언트는 요청·응답 정책이 다르거나 누락되면 파일을 읽기 전에 거부한다.
- 현재 선택 위치의 사진을 열면 저장 문구·서식·브러시·crop을 최초 배경 위에 복원한다. OCR·번역·미리보기·적용은 자동 실행하지 않는다. 저장 상태 재확인은 선택한 정책과 편집 중 초안을 유지한다.
- 명시적 적용은 현재 선택한 옵션의 정확한 슬롯과 그 연결 필드만 교체한다. 원래 옵션, 다른 역할/사진 위치, 공통값, HTML·ALT·가격·표시사항·수집 원문 및 불변 과거 PNG/문서는 보존한다. 기존 CAS·승인 회원 검사·원자 저장·응답 미확인 시 읽기 복구를 유지한다.
- 구형 결과에 편집 문서가 없다는 명시적 404만 평면 사진 열기로 돌아간다. 일부 증거 누락·해시 변조·403/409/503 등은 조용히 구형 경로로 바꾸지 않는다.
