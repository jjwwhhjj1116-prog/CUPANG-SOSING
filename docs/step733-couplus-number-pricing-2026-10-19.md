# Step733 — 원본 Number 가격 계산과 신규 초안 연결

2026-10-19. 기준 `898b57b741c406fcdba713035454bbd3575d103a`. 기존 작업 상품·저장 가격·회사 설정·운영 견적서를 변경하지 않는다. 이 변경은 새 1688 수집이나 Supplier Hub 실제 접수의 완료 증거가 아니다.

## 확인된 가격 차이

보관된 현재 Couplus main SHA-256 `36a8e3252cba8096da3e9b06eaf3c338699dce35280a0080484a5c7181d20fb7`의 `calculatePricing [164142,166051)`과 `purchaseCost [295962,296209)`, route `chunk-36123f1a.155d5b9e.js` SHA-256 `2fb15d370c331f65d982a886f2888b813ccae67277e87f806182c70032821664`의 2단계 재계산 `[177626,179414)`를 대조했다. 원본 bytes의 정적 관찰과 같은 식을 옮긴 계산이며, vendor 코드를 실행하거나 새 원격 가격을 관찰한 것은 아니다. 기존 REA 단계 분석은 [Step727](step727-rea-stage-contract-2026-10-19.md)을 재사용한다.

자체 계산은 중간값을 십진 유리수로 보존했지만 원본은 JavaScript Number 연산과 Math.round를 사용한다. 지원되는 일반적인 위안 원가에서도 결과가 달랐다. 일반 환율 350, 공급 마진 50%, 쿠팡 마진 40%, 최소 마진 3,000원 켜짐, 10원 반올림, MSRP 1.3배의 예:

| 입력·경로 | 원본 공급가 / 판매가 / MSRP | 이전 자체 계산 |
| --- | --- | --- |
| 8.95 CNY, 초기 계산 | 6,260 / 10,430 / 13,560 | 6,270 / 10,450 / 13,590 |
| 32.3 CNY, 2단계 최소 마진 직접 재계산 | 14,300 / 23,830 / 30,980 | 14,310 / 23,850 / 31,010 |

최소 마진을 끈 0.35 CNY도 공급가 240원과 이전 250원의 차이가 있었다. 원본 초기 계산은 비율 공급가를 먼저 반올림한 뒤, 그 공급가의 실제 마진이 최소액보다 작을 때만 최소액을 더해 다시 반올림한다. 2단계의 명시적 최소 마진 재계산은 바로 원가+최소액을 사용한다. 통합통관은 판매 묶음 CNY에 환율을 곱하고 200·100을 순서대로 더한 뒤 1.1배와 원 단위 반올림을 적용한다.

## 반영 범위

정책의 명시적 `arithmeticMode:couplus-number-v1`과 `roundingMode:nearest` 조합에만 원본 Number 순서를 적용한다. 신규 수집·수동 추가·기본설정 미리보기, 사용자가 직접 요청한 2단계 재계산·번들 견적 계산이 이 경로를 선택한다. 저장된 이전 정책에 표식을 몰래 추가하거나 화면 조회에서 재저장하지 않는다. 표식 없는 정책과 기존 올림 선택은 종전 계산을 유지한다. 일반 옵션 원가·수량 수정 역시 저장된 정책을 그대로 따른다. 지원하지 않는 계산 표식·가격 범위 초과·0원 공급가는 오류로 남긴다.

새 정책은 기존 정책 JSON에 보관하며 DB migration이나 확장 권한 변경은 없다. 계산 방식은 가격 초안 비교에도 포함한다. 저장·미리보기·견적서 compiler가 같은 정책을 받으며 직접 수정값과 공란은 기존 저장 규칙으로 보존한다.

## 실제 검수의 경계

같은 Chrome4에서 자체 앱의 상품 추가 대기열을 열자 기존 입력 초안이 복구되어, 해당 행을 편집·추가·삭제·실행하지 않고 닫았다. 기본설정은 유앤채/A01526306으로 표시됐으며 읽기 확인 후 취소로 닫았다. 원문 조회·상품 수정·설정 저장·전송은 실행하지 않았다.

1688 두 주소는 구체적인 사용자 읽기 재승인 후에도 Step732에서 사이트 안전 정책으로 거절됐다. 이번에는 그 주소나 대체 도구·도메인·확장 수집을 재시도하지 않는다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`, `PRODUCT_DOCUMENT_LIVE_VERIFIED=false`는 계속 유지한다. 실제 새 상품의 원문 수집과 최종 접수는 아직 미검증이다.
