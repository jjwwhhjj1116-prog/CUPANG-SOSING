# Step698 — 정책 저장과 명시 일괄 재계산의 견적서 반영

2026-10-18 KST. 기준 `b3e3d2ebc7c889b7ade5f2bf3547c5784f38a90f`. [보관 REA 원본 대조](step698-pricing-recalculation-parity-audit.md)와 양사 격리 React/API 재현에서 두 저장 경로를 구분했다. 기존 작업 상품·운영 DB·Chrome·외부 사이트는 조작하지 않았다.

## 확인한 차이

쿠플러스의 일괄 재계산은 선택 여부와 무관하게 현재 계산 행 전체의 가격 초안을 바꾸고, 가격 저장 시 견적서에 반영한다. 자체는 상품의 가격 정책만 바꿔 저장하므로 견적서에 직접 저장했던 공급가·판매가·MSRP가 남았다. 또한 앞 단계에서 자동으로 파생한 MSRP도 배수 변경 후 옛값으로 남았다.

사전 재현에서 판매가 9,000원→자동 MSRP 11,700원을 저장한 뒤 정책 배수를 1.5로 바꿔 저장해도 MSRP는 11,700원이었다. 직접 가격 8,000/14,000/18,200원을 저장한 뒤 환율 400·최소액 5,000원·배수 1.5로 일괄 재계산하면 계산 결과는 6,200/10,330/15,500원이지만 실제 견적 가격은 옛값으로 남았다. 이 결과는 합성 원문·실제 자체 callback/핸들러·메모리 SQLite 검증이며 원본 함수를 실행한 결과는 아니다.

## 반영 범위

일반 가격 정책 저장에서는 기존 수동 공급가·판매가·MSRP·공란을 보존하면서, 서버가 기록한 유효한 자동 MSRP만 현재 판매가와 새 상품 정책으로 갱신한다. 자동 근거가 없는 기존 수동값을 숫자 비교로 자동값으로 취급하지 않는다.

‘일괄 재계산’을 명시적으로 누른 후 저장하면 현재 카테고리 견적서의 정확히 연결된 가격 수정값을 해제해 새 정책 계산값을 적용한다. 선택하지 않은 행도 포함하며, 현재 옵션들의 가격을 대상으로 한다. 원문·SKU·재고·구성 수량·포장 실측·견적 포함 여부·등록번호는 바꾸지 않는다. 다른 카테고리, 현재 옵션 목록 밖에 보관된 수정값, 가격 이외의 제목·법적 정보·상세 백업과 독립 OSRP는 보존한다. MSRP가 없는 OSRP-only 양식은 기존의 정확한 가격 연결을 사용한다.

재계산 의사는 가격 정책 JSON에 저장하지 않는다. 버튼을 누른 뒤 같은 정책 값이어도 미저장 변경으로 취급하고, 다른 옵션 저장과 잠금을 공유한다. 실패하면 의사와 입력을 유지하고, 성공 또는 최신 정책으로 취소 시 해제한다. 상품·카테고리를 바꾸면 이전 재계산 의사를 새 대상에 적용하지 않는다. 화면에는 직접 가격도 바뀌며 저장 전까지 기존 가격은 유지된다는 안내를 표시한다.

상품 가격·가격 정책·변경된 견적 자료는 원천과 원본 견적 payload를 검사한 한 DB batch로 저장한다. 한쪽만 저장된 뒤 오류를 내는 방식으로 구현하지 않는다. 기존 상품 버전, 정책, 옵션·내용 revision, 설정, 카테고리·수집 근거와 견적 원본을 대조하고, 경합하거나 동반 저장이 실패하면 부분 변경을 남기지 않는다. 변경 없는 견적 행을 새로 만들거나 읽기만으로 보정하지 않는다.

명시 재계산 또는 기존 자동 MSRP를 검사한 저장은 변경값이 없어도 같은 원천 대조를 사용한다. 견적 변경이 없는 경로는 견적서 insert/revision을 생략한다. 정책·견적 companion이 SQL IGNORE 등으로 생략되면 마지막 제품 UPDATE가 직전 `changes()=1`과 정확 payload를 검사해 기존 NOT NULL 제약으로 batch 내부에서 취소한다. 첫 CAS가 실패했는데 경쟁 저장 timestamp가 이번 계산 timestamp와 같아진 경우도 자체 감사 trigger mutation이 남지 않는 것을 격리 SQLite에서 검증했다. 일반 CAS 충돌은409, 이 예외 충돌/SQL 실패는503이고 자체 부분 변경은 없다.

카테고리 A→B→A 이동 뒤 남아 있던 A의 callback은 scope 문자열만으로 유효해지지 않도록 generation identity도 대조한다. 예전 저장·재계산 callback과 늦게 도착한 응답이 새 대상의 재계산 의사를 저장/해제하지 못한다. 실제 UI 통합 검수에서 발견한 첫 ABA 실패와 수정 전 sentinel 로그는 지우지 않고 보관했다.

원본의 MSRP 배수는 현재 workspace 설정을 먼저 참조하지만, 자체 노출 정책 편집은 현재 상품의 저장 정책을 사용한다. 자체 견적 제외 상태를 원본의 선택 checkbox와 같은 개념이라고 주장하지 않는다. 일반 저장과 명시 재계산을 구분한 구현 범위를 전체 원본 callback과 같다고 확대하지 않는다.

실제 신규 1688 전체 옵션·이미지 수집, 전 카테고리 공식 양식·기본값, 나머지 편집·외부 번역과 Hub 동의·최종 접수번호/SKU 실증은 전체 완료 조건으로 남는다. `SINGLE_DOCUMENT_LIVE_VERIFIED=false`와 운영 전송 gate를 유지한다.
