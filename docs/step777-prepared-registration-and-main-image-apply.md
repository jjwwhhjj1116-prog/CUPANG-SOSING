# Step777 — 준비한 새 견적서 등록전송과 선택 대표이미지 적용

기존 업무 상품을 열거나 수정하지 않았다. 보관한 Couplus Stage3 처리와 Supplier Hub 문서/이미지/동의 계약을 바탕으로 독립 구현을 연결했다. 원본 근거는 `outputs/step777-rea-main-result-adoption.json`, 검수와 배포 결과는 `outputs/step777-final-validation.json`에 기록한다.

## 새 문서 등록전송

2.1.16 통합 확장은 native 원본을 확인한 경우에만 `preparedLifecycleAvailable`을 응답한다. 일반 문서의 `start/resume`을 해제하지 않는다. 준비된 새 문서의 원본 파일 계획, 업로드 응답과 같은 문서 파일 목록, 현재 저장 본문, 회사·회원·전체 옵션, 생성·갱신 기록과 2~5단계 검증을 다시 확인한다. 이 검증 후에만 같은 문서를 등록전송 단계로 전환한다.

앱의 `준비한 새 견적서 등록전송`은 같은 UUID와 pending 예약을 유지한다. 각 단계의 실제 약관 제목·전체 내용을 보여주고 사용자가 현재 단계에서 확인하도록 한다. 이전 체크를 다음 단계로 복사하지 않는다. 최종 제출은 별도 확인이며, 확장의 사용자 직접 확인 경계를 유지한다. 최종 제출 전에도 원본·첨부·본문을 다시 대조한다.

응답 유실 시 읽기 복구만 한다. 동의가 저장됐고 다음 단계 요청이 없다는 확실한 기록이 있을 때 `navigation-ready`를 반환하며, 사용자의 `같은 문서 다음 단계 계속` 클릭에만 진행한다. 이미 요청한 이동·제출을 자동 재시도하지 않는다. 접수 결과는 기존 엄격한 receipt API와 회사·문서·QVT 연결 검사를 거쳐 저장한다. 제출 대기와 파일 처리 완료를 SKU 등록 완료로 표시하지 않는다.

제출 후 새로고침 검수에서, preview가 문서 식별값을 비워 전달해 원래 저장한 접수 이력도 거절하는 연결 오류를 발견했다. preview는 신뢰된 확장 저장소의 정확한 원래 checkpoint를 읽고 검증한 경우에만 그 문서·세션을 사용한다. 화면에서 넘긴 문서 식별값을 신뢰하거나 다른 접수 이력을 허용하지 않는다. 최초 실패 기록과 수정 후 검수를 구분해 보관한다.

## 선택 옵션 대표이미지

3단계의 선택 이미지 AI 작업에서 완료된 결과를 `선택 옵션 대표이미지에 적용`할 수 있다. 원래 회원·상품·옵션·프로필·원본 이미지·본문·작업 버전을 유지하고, 해당 결과 한 장이 추가된 현재 이미지 목록과 실제 저장 PNG의 크기·SHA를 확인한다. 기존 옵션별 이미지 CAS 저장과 ACK/readback을 재사용하며 공통값·다른 옵션·수동 입력을 덮어쓰지 않는다. 불확실한 저장은 같은 시도의 읽기 복구로 확인한다. 유료 생성 실행이나 전체 옵션 적용을 자동으로 하지 않는다.

## 검증 범위

실제 컴포넌트/client/dispatcher/native adapter/앱 API와 SQLite를 사용하는 격리 검수는 합성 Chrome·Hub·상품·약관 확인 경계만 사용한다. 기존 보호 상품·파일·문서 불변을 검사한다. 실사이트 접수 성공이나 전체 카테고리·모든 팝업의 완전한 동등성은 이 검사로 주장하지 않는다.

운영 앱 탭은 Cloudflare Access 로그인 화면이며, 사용자에게 직접 로그인 요청을 전달했다. 이전 거절된 1688 경로를 재시도하거나 우회하지 않았다. 새 자원·DB 마이그레이션·인증 정책·확장 권한을 추가하지 않았다.
