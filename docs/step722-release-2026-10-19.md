# Step722 — 상품명 번역 누락의 완료 판정과 견적 검토

기준 `2ad230bd99830563f37968b3fa59aea9d073120c`. 초기 Workers AI 결과에 상품명은 없고 설명·옵션 번역만 있을 때 원문 상품명이 남아도 SEO 완료로 표시하던 경계를 수정했다. 수집 원문·정상 부분 결과는 보존하며, 누락은 검토 필요로 표시한다. 견적서에도 수집된 중국어 상품명을 확인할 수 있게 안내한다. 수동 제목·명시 공란·공통/옵션 견적 수정값과 기존 필수입력 검사는 유지했다.

이 예외가 실제 쿠플러스에서 어떻게 처리되는지는 아직 확인되지 않았다. 원본의 오류 처리와 동일하다고 주장하지 않는다. Google producer는 빈 필수 상품명을 이미 거절하므로 실제 누락 재현은 Workers 결과에 한정된다. 기본설정, 가격 산식, 수집기, 이미지 처리, DB 스키마, 확장과 전송 프로토콜은 변경하지 않았다.

## 원본과 실제 브라우저 대조

같은 기존 Chrome4에서 검수용 탭만 열어 Couplus `yooandchae/유앤채`의 기본설정과 상품추가→카테고리 선택을 읽고 취소했다. 설정·상품 생성·URL 실행은 하지 않았고 사용자 작업 탭과 상품은 변경하지 않았다. 원본의 저장 환율310/쿠팡 마진45와 자체 관리자350/40은 계정에 저장된 값의 차이이며 산식 결함으로 취급하거나 덮어쓰지 않았다. 16개 최상위 카테고리 화면 확인은 모든 하위 양식의 동일성 증명이 아니다.

REA 보관 원본의 범위·SHA·재사용 증거는 `step722-seo-settings-parity-audit.md`에 있다. 원본 4개 실행 목표와 현재 자체 3개 목표의 차이는 남아 있다. 실제 등록전송을 검증하지 않은 상태에서 자동등록 완료 기능처럼 노출하지 않았다.

별도의 합성 상품은 실제 React `QuotationFieldsEditor`·로컬 API·SQLite와 Chrome4로 확인했다. 초기 메시지의 상품명 누락 안내, 원문 `原文收纳商品` 보존, 견적의 검토 안내가 보였다. 한국어 제목을 입력하면 원문 안내가 사라졌고 공란으로 바꾸면 필수 미입력은6→8개로 늘었다. 저장하지 않은 입력을 폐기한 뒤 원문과 안내가 복원됐다. UI 쓰기 요청0, 콘솔 경고/오류0, 외부 요청0, 실제 접수0이다. 첫 폐기 직후의 비동기 로딩 관측은 별도 intermediate proof로 보존하고, 조회 완료 후 최종 상태를 확인했다.

같은 합성 조회 서버는 실제 사이트·업체·번역 요청을 프록시하지 않았으며 모든 UI 쓰기·수집/전송 경로를 차단했다. 검수 탭과 foreground 서버는 종료했다. 로컬 증거는 `outputs/step722-browser-final-proof.json`, `step722-browser-qa/proof.json`, `step722-browser-title-warning.png`와 단계별 AX 텍스트에 있다.
