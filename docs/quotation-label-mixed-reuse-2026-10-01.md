# 단일·전체 옵션 라벨 생성의 파일 재사용 (2026-10-01)

530의 단일 옵션 캐시와 528의 전체 옵션 캐시는 각각 재시도 파일을 보존했지만 서로 공유하지 않았다. 개별 PNG 연결 후 전체 생성 또는 전체 생성 후 개별 연결을 누르면 같은 옵션·내용의 파일을 다시 업로드했다. 전체 계획 중 한 옵션을 수정해도 모든 옵션의 업로드 기록을 초기화했다.

## 변경

- 부모 폼의 전체 생성 캐시에 옵션별 계획 signature를 기록한다. 상품 ID·견적 endpoint·카테고리 연결·옵션 ID·실제 PNG 계획이 일치해야 개별/전체 생성에서 같은 업로드 키를 사용한다. 단순 상품명이나 이미지 내용 유사도로 다른 옵션의 키를 공유하지 않는다.
- 단일 업로드 성공 시 키를 두 캐시에 기록한다. 그 뒤 상품 첨부나 견적 저장 응답이 유실되더라도 기존 최신 저장본 복구를 거쳐 전체 생성에서 알려진 키를 사용한다. 반대로 전체 생성한 옵션을 선택해 미리보기·연결하면 해당 옵션의 키를 사용한다.
- 아직 업로드하지 않은 단일 미리보기를 전체 생성으로 이어가면 그 옵션의 Blob을 재사용한다. 전체 생성 조판 callback에 옵션 ID를 전달하므로 계획 내용이 같아도 다른 옵션의 Blob을 임의 공유하지 않는다. 전체 옵션 PNG Blob을 메모리에 보존하지 않으며 마지막 단일 미리보기 한 개만 유지한다.
- 전체 계획의 일부가 달라져도 나머지 옵션의 검증된 키는 유지한다. 가격처럼 PNG 계획에 없는 값은 그대로 재사용하며 모델명 등 PNG 내용이 바뀐 옵션만 새로 만든다. 과거 전체 계획으로 되돌린 경우에도 옵션별 signature가 다르면 최근 수정 PNG를 연결하지 않는다.
- 늦게 도착한 단일 업로드 결과는 이미 다른 계획으로 바뀐 캐시를 덮어쓰지 못한다. 캐시 조회·변경은 이벤트 처리에서 수행한다. 기존 최신 견적 검증·파일 소유·옵션 포함 여부·이미지 50개/라벨 30개 한도·중지·공유 작업 잠금·기존 첨부 보존을 유지한다.

캐시는 열린 폼 세션의 메모리다. 전체 페이지 재접속 후 영구 재개, 파일 업로드 응답 자체가 유실되어 키를 모르는 경우, 과거 모든 PNG 버전의 재사용은 구현 범위가 아니다. 실제 라벨 텍스트·기본값·카테고리 규격을 새로 추정하거나 Supplier Hub 전송을 자동 실행하지 않는다.

## 검증

수정 전 실제 부모/자식·API를 실행한 신규 8개 회귀가 모두 중복 조판 또는 업로드로 실패했다. 별도로 옛 전체 계획으로 되돌리는 신규 패널 회귀에서 최근 수정한 PNG 키가 남는 문제를 재현한 뒤 옵션별 계획을 우선 대조하도록 수정했다.

와이홉 A01464742와 유앤채 A01526306 각각 다음 네 경로를 검사했다.

1. 단일 미리보기·연결 후 전체 생성.
2. 단일 미리보기만 연 뒤 전체 생성.
3. 단일 라벨 PUT이 실제 저장된 뒤 응답을 유실하고 최신 저장본을 읽은 후 전체 생성.
4. 전체 생성 후 두 옵션을 차례로 선택해 개별 미리보기·연결.

실제 QuotationFieldsEditor/QuotationLabelPanel의 hook/effect·key 재마운트 모델, 실제 수집·콘텐츠·견적 입력·업로드·상품 첨부·Excel·ZIP API와 임시 SQLite를 실행했다. 기록된 813724060928 원문에서 6옵션 초안을 만들고 각 경로의 최초 조판/업로드 6회와 옵션별 기존 라벨+고유 생성 라벨을 확인했다. 옵션 선택·판매가 20,000원 저장·전체 생성 반복에도 업로드가 늘지 않는다. 첫 옵션 모델 수정 후 조판/업로드는 한 번만 증가하며 나머지 5옵션의 키가 그대로다. 개별/전체 생성 반복에도 최종 파일 업로드·상품 첨부·견적 라벨 PUT은 각 7회이고 409 오류는 없다.
