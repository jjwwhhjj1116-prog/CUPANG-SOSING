# Step633: 상품관리 변경내역 필터

쿠플러스 상품관리(신규)의 실제 공개 모듈에서 확인한 8개 필터 순서와 조건을 적용한다. 확인한 모듈은 `81dd`, 파일은 `chunk-3a508968.eecb7b35.js`이며 기록된 SHA-256은 `35576069a1b5d576b7c45199a3c2ed09ded15e211097bb31957d864282e2c52e`이다. 기존 쿠플러스 상품은 저장하거나 수정하지 않았다.

## 조회 조건

| 필터 | 확인한 조건 |
| --- | --- |
| 전체 | 현재 로그인 계정과 회사가 소유한 전체 상품 |
| 노출ID변경 | 현재 시각에서 달력 기준 7일을 뺀 시각 이후의 원본 `productIdHistory` 기록이 있음 |
| 공급가변경 | 같은 기준의 원본 `priceHistory` 기록이 있음 |
| 타사매칭 | 원본 `otherSellers.hasOtherSellers`의 JavaScript truthiness |
| 아이템루저 | 원본 winner가 LOSER |
| 발주불가 | 원본 발주가능상태가 정상과 다름. 품절·판매중지·공란 포함 |
| 구매정보없음 | 적용 구매정보의 모든 항목이 매칭완료·등록완료인 상태가 아님 |
| 매입정보없음 | 날짜 내림차순 최신 매입가가 없거나 0 이하. 별도로 저장한 최신 매입가가 있으면 그 값을 우선 |

7일 경계는 포함하며 미래 날짜를 임의로 제외하지 않는다. 날짜만 있는 문자열, 날짜 파싱이 가능한 원본 문자열, 숫자 epoch를 인정한다. 이전값이 없는 최신 기록은 변경 필터에서 제외하지 않고 이전값 미확인으로 표시한다. 타사매칭의 문자열 `false`도 확인한 원본 조건에서는 truthy다. 판매자명은 원본 문자열만 표시하고 추정하지 않는다.

최신 매입 기록의 가격이 빈 값이어도 이전 기록의 양수 가격으로 대체하지 않는다. 원본의 캐시된 `latestImportPrice` 셀만으로 매입 기록을 인정하지 않는다. 숫자로 확인되지 않는 가격은 조회 가격을 미확인으로 표시하며, 필터 여부는 확인한 최신 원문 조건으로 따로 계산한다. 수동 가격 업로드의 음수 금지 검증은 유지한다.

## 데이터 보존과 조회

변경내역은 계정·회사·SKU와 원본 payload 및 provenance 전체가 일치하는 파생 조회 캐시로 저장한다. 상품 원문, 구매정보 원문과 별도 저장본, 수동 매입 기록은 변경하지 않는다. 예전 가져오기 자료도 재가져오기 없이 조회한다. 원본이 조회 중 바뀌면 오래된 캐시로 결과를 반환하지 않고 다시 조회하도록 한다.

캐시 준비는 SQL에서 행 수와 바이트를 제한한 묶음으로 처리하여 여러 파일을 가져온 정상 목록도 조회할 수 있도록 한다. 요약 개수, 필터 목록, 페이지 이동, 정렬, 열 필터, 전체 결과 Excel 다운로드에 같은 조건을 사용한다. Excel의 기존 원문 열과 수동 편집 별도 열을 유지하며 다운로드의 5,000개·8MB 사전 제한을 유지한다.

## 검증

최종 테스트는 12개 파일에서 **114/114 통과**했다. 신규 이력·기존 상품/표/매입가/구매정보 66개, 이력 화면·기존 목록/구매 편집 25개, 양회사 통합·Excel/가져오기/구매 흐름 23개다. 중간 진단 실행은 이 수치에 합산하지 않았다. 타입 오류 0, ESLint 오류 0이며 기존 경고 8개는 유지된다.

양회사 각각의 경계값·검색·정렬·페이지·전체 필터 Excel을 검증했다. 정상 파일 여러 개로 5,001개를 누적한 목록은 SQL의 5,000개·8MB 이하 묶음으로 조회되며 전체 다운로드는 413, 필터 결과 다운로드는 200을 확인했다. 누적 원문 8MB 초과 460개 상품의 목록도 정상이며, 전체 다운로드는 원문 행을 materialize하기 전에 거절된다. 조회·캐시 저장 중 원본 또는 승인 회사가 변경되는 경우 409를 확인했다.

같은 Chrome의 별도 합성 SKU 30개 화면에서 8개 필터 개수, 두 번째 페이지의 2개 상품, 이전값 미확인 표시, 전체 필터 결과 다운로드 완료 표시를 확인했다. 이 검수에서 운영 상품이나 외부 사이트 전송은 하지 않았고, 원문·수동 구매정보·매입 기록이 변경되지 않았다. 다운로드의 실제 전체 XLSX 내용은 별도 실제 API 통합검사에서 대조했다.

운영 Worker 버전은 **bf110333-ff86-4524-b51d-ca7174932167**이며 `sourceflow`에 배포했다. 실제 페이지에서 새 8개 필터와 현재 유앤채 계정의 빈 상품 DB 조회 완료를 확인했다. 기존 AI상품등록 표 29개 입력/1개 상품, 기본설정 35개 입력, 저장된 카테고리·URL 초안의 입력과 문구는 배포 전후 동일했다. 운영 검수 결과는 별도 비공개 `outputs/step633-live-verification.json`에 기록했다.

기존 확장 설치 및 배포 ZIP, 의존성, 18개 마이그레이션 파일은 변경하지 않았다. 새 이력 테이블은 현재 계정의 조회 과정에서 준비되는 파생 캐시이며 원본 데이터나 다른 계정의 승인 범위를 변경하지 않는다.

전체 카테고리와 모든 기능의 동일성, 새 실제 1688 상품 수집에서 Supplier Hub 접수번호·SKU 확인까지의 운영 검수는 이 변경만으로 완료된 것으로 간주하지 않는다. 이 단계는 상품관리 조회 조건과 원문 보존에 대한 구현이다.
