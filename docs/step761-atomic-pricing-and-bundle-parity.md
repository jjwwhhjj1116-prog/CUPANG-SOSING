## 함께 편집하고 한 번 저장

가격 2단계는 정책과 옵션 표를 함께 로컬 초안으로 편집한다. 자동 번들 체크·기준·최소액과 환율·마진·반올림 변경이 표에 반영되고, 사용자는 이어 구성 수량과 공급가·판매가·MSRP를 수정할 수 있다. 자동 추천 수량을 수동으로 바꾼 최종 입력을 서버가 다시 자동 수량으로 덮어쓰지 않는다. 기존 독립 `PriceEditor` 경로는 유지한다.

기본 가격 단계의 저장은 새 `GET/POST /api/products/[id]/stage-two-pricing` 경로를 사용한다. 정책, 옵션 행, 명시 가격 수정과 재계산 의도를 하나의 요청으로 보낸다. 정책 저장 후 옵션 저장을 따로 수행하는 방식으로 dirty 잠금만 제거하지 않았다. 저장 중 중복 클릭·오래된 callback·profile 전환·새 부모 버전을 차단한다. ACK를 확인하지 못한 경우 입력과 정확한 시도 내용을 유지하며, GET으로 일치하는 저장 결과를 확인한다. 자동 재POST는 하지 않는다.

`app/stage-two-pricing.ts`는 같은 계획을 클라이언트와 서버에서 사용한다. 명시 재계산 시 현재 카테고리의 직접 가격 수정값을 먼저 복원한 후, 이후 입력한 수동 금액과 판매가 기반 MSRP를 반영한다. 명시 MSRP·공란·복원 입력의 우선순위, 가격 외 수정값, 다른 카테고리의 수정값과 표시사항·포장 기준은 보존한다. 저장 결과의 옵션 ID/순서/수량, 정책, 연동 가격, 등록 표시 번호, source 버전과 fingerprint를 검증한 뒤 화면에 채택한다.

## 원자 저장과 독립 검수

`db/stage-two-pricing.ts`는 정확한 옵션 CAS를 적용 기준으로 삼고, 상품 요약 가격·정책·옵션 등록 번호·견적 수정값을 같은 D1 batch에 저장한다. 저장 전후 owner, 승인 회원·회사, 상품/옵션/견적 버전, 실제 원문·설정·카테고리 payload를 확인한다. 동반 저장이 생략되거나 source가 바뀌면 기존 NOT NULL/CHECK 조건으로 전체 batch를 rollback한다. 기존 포장 확인 수량과 제외 옵션의 사실·provenance를 임의로 보정하지 않는다.

독립 검수에서 발견한 빈 견적 수정 배열의 거절, 회원·회사 fence 누락, 동반 저장 중 clock 변경에 따른 부분 저장을 수정했다. 최종 고정 소스로 같은 집중 검증 6개만 다시 실행했다.

- 정책·수동 가격 함께 저장 및 견적 수정 없이 정책만 저장: `200`, 전체 저장 결과 검증 성공.
- 마지막 조회 후 저장 직전 회원 승인이 바뀜: `409`, 상품·정책·옵션·견적 변경 없음.
- 정책 동반 저장 중 미래 clock 변경, 이전 clock 복원, 가격이 같은 번들 정책만 변경한 상태의 이전 clock 복원: `503`, 관련 자료 전체 rollback.

이는 임시 SQLite와 합성 인증·원문·이미지로 실행한 검증이다. 외부 요청과 실상품 쓰기는 0이다. 초기 실패 로그와 최종 소스 SHA는 `outputs/step761-atomic-review-proof.json`, 서버 범위는 `outputs/step761-stage-two-backend-proof.json`, 클라이언트 범위는 `outputs/step761-client-unified-proof.json`에 있다. focused 결과나 독립 probe를 최종 고유 검사 수에 중복 합산하지 않는다.
