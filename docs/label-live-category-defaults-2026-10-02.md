# 선택 카테고리의 제조년월과 표시사항 연결

상품 추가 시 저장한 Supplier Hub 상세 양식에 제조년월 또는 출시년월이 있어도, 6단계의 빈 표시사항 채우기는 고정 카테고리 목록만 확인했다. 목록에 없는 실제 양식에서는 6단계/표시사항 이미지에 날짜가 빠지고 7단계 견적서에만 기본 날짜가 나타날 수 있었다. 반대로 고정 목록에 날짜가 있는 분류라도 선택한 실제 양식에 날짜 항목이 없다면 날짜를 채우면 안 된다.

## 동작

- URL 수집 초안과 6단계 검토에 상품 추가 당시 저장한 상세 양식을 사용한다. 제조년월/출시년월의 존재 여부를 7단계와 같은 양식 해석으로 판단한다.
- 기본설정의 전월 적용을 켰을 때, 해당 법적 정보 항목이 있는 양식에만 상품 추가 당시 한국 달력의 전월을 넣는다. 상품 수집 완료나 이후 검토 시점으로 월을 바꾸지 않는다.
- 직접 수정한 값, 직접 비운 값, 미저장 수정은 유지한다. 읽기 API는 상품을 저장하지 않는다. 기존 상품을 일괄 갱신하거나 새 카테고리 프로필로 기존 저장 양식을 바꾸지 않는다.
- 실제 양식에서 해당 항목이 없으면 고정 분류의 날짜 추정을 사용하지 않는다. 비슷한 이름이나 상품 속성의 제조년월을 법적 정보 고시로 추정하지 않는다.
- 표시사항 검토 API는 날짜 항목 여부만 반환한다. 양식 원문이나 다른 상품/회사 정보를 추가로 노출하지 않는다. 깨진 저장 양식의 회사·분류·경로 검증을 건너뛰거나 고정 양식으로 대신 처리하지 않는다.

양식이 저장되지 않은 기존 작업은 종전 고정 카테고리 동작을 유지한다. 저장된 값과 수동 공란의 우선순위, 가격 계산, 이미지 번역, 최종 접수 동작은 변경하지 않았다. 이 수정은 제조년월/출시년월 연결이며, 모든 카테고리의 모든 기본값 대조를 완료했다는 뜻은 아니다.

## 확인 근거와 검사 범위

556에서 확인한 쿠플러스 공개 상품등록 청크의 `applyDefaultSettings`가 기본설정의 제조년월 전월 적용과 정확한 고시 이름을 사용한다. 이번에는 이 규칙이 이미 적용되는 견적서와 6단계 입력의 차이를 보완했다. 공개 원본은 `https://couplus.co.kr/js/chunk-e2dd462a.8dc4d2d7.js`, SHA-256 `38aee73a04100657ed8463a6156cc096ceaf68d4f3d671f34845a9cda515d587`이다. 새로운 비공개 API나 기존 작업 상품을 조회·수정하지 않았다.

새 회귀 검사는 두 회사의 합성 카테고리 양식과 기록된 1688 상품 813724060928 응답을 사용한다. 실제 앱 API/임시 SQLite에서 6옵션 초안 → 6단계 표시사항/이미지 입력 → 7단계 값 → 다운로드 CSV 바이트를 대조한다. 월 경계, 뒤늦은 기본설정/카테고리 프로필 변경, 수동 수정·공란, 전월 적용 해제, 날짜 항목 없는 양식, 잘못된 양식의 오류와 편집 화면의 공란 보존을 검사한다.

실제 원격 Supplier Hub 접수 호출은 없다. 합성 분류/AI/인증/이미지/CSV는 공식 양식·운영 AI/번역·최종 접수 증거가 아니다.

## 검증과 배포 결과

- 관련 검사 57/57, 최종 전체 검사 1862/1862(233.584초) 통과. 편집 화면의 첫 진입 요청 의존성을 `useCallback`으로 정리한 최종 코드까지 전체 검사에 포함했다.
- TypeScript와 변경 파일 lint 오류·경고 0. 전체 저장소 lint를 실행했다고 주장하지 않는다. 운영 빌드/11마이그레이션 아티팩트/확장 원본·번들·ZIP/diff 검사 통과.
- 기존 운영 Worker `260c6ec5-464b-4aa4-8107-834e7701dadd` 배포 완료. 익명 앱과 분류 컨텍스트 GET의 Access302 두 건을 확인했다. 로그인 운영 화면이나 접수 검증은 아니다.
- 확장 0.2.39/37파일/436640바이트/SHA-256 `0c9c4a84a17fe55eca66141315bd796ed14b7b11e237c005f770098a70b6f93f` 유지. DB migration/비밀 설정/호스트·권한/이미지 Worker/새 유료 자원 변경 없음. 앱 새로고침으로 적용한다.

기존 Chrome의 문서화된 `tabs.selected()`는 `undefined`였다. 다른 창이나 프로필을 열지 않았고 전체 탭 열거나 이전 거절을 우회하지 않았다. 사이트 자체의 차단·로그아웃 또는 추가 승인 필요로 해석하지 않았으며 로그인/승인 질문을 반복하지 않았다.

모든 카테고리의 실제 쿠플러스 기본값·공식 견적 양식, 운영 URL→AI/이미지 번역·추가 서류와 두 회사 최종 Hub 접수번호/SKU는 별도 실검증이 남아 있다. 검사 수를 완성률로 환산하거나 완전 복제로 보고하지 않는다.
