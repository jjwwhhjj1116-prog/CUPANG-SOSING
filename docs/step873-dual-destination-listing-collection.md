# 1688 다중 담기와 두 목적지

사용자가 요청한 최종 동작은 검색 목록의 여러 상품 선택 → 담기 → **AI상품등록 수집함 / 1688 소싱·로켓 비교함** 중 한 곳 또는 양쪽 선택이다. 개별 상세페이지의 기존 수집 버튼은 목적지 선택 없이 AI상품등록으로 계속 보낸다.

RS 설치 아티팩트의 `rcmp-1688-card` / `rcmp-1688-pick` / `rcmp-bg` 흐름을 REA로 확인했다. 그 기능은 현재 로드된 카드의 요약을 비교 후보함에 보관하며, 상세 SKU·사진 수집과 구분된다. 해당 코드의 복사 없이 YOOFAM용 선택 UI·배치·서버 저장을 새로 구현했다. 같은 아티팩트 해시가 이전 RS 버전에도 있으므로 최근 버전에서 처음 추가됐다고 단정하지 않는다.

REA 근거: `ev_8ce4ee626fe7fd24ec20eec15e74fdddb1599b85814c2afb21378611082423f0`, `ev_26d16cff845ade6fe476e028be0d598d3cded79e725401cdfe0363a6bbdcd3dc`, `ev_270192e108e170fea7a8683276da0cf070cb5f31723cc4bee989e81ad974358b`. 선택한 RS 파일 집합 해시는 `851d627b6529d99bdc5e6402673658fede0f9f47a8163c104a29150ac1fbba0c`다.

## 구현

- 현재 로드된 검색 카드만 선택한다. 전체 검색 결과로 표시하지 않으며 한 배치는 최대 60개다. 재활용되거나 사라진 카드는 선택을 해제한다.
- AI 목적지는 확장이 소유한 비활성 상세 탭에서 기존 원문 수집기를 실행한다. 실제 상세 원문을 기존 회사별 수집함에 저장하고 서버의 버전·저장시각 응답을 확인해야 완료된다. 카드 요약을 옵션·포장정보·상세사진으로 가장하지 않는다.
- 비교 목적지는 카드 상품명·원문 링크·썸네일·표시가격을 회사별 운영관리 후보함에 저장한다. 표시가격 문자열과 확인한 개당 가격을 분리하며 기존 후보의 수정값을 덮어쓰지 않는다.
- 두 목적지의 저장 상태를 별도로 표시한다. 비교함의 성공이 AI 수집 성공을 대신하지 않는다.
- 시작 당시 회원·회사·앱 창을 고정하고 항목마다 재확인한다. 확장이 만든 동일 URL의 비활성 탭만 정리하며 사용자·Supplier Hub 탭은 정리하지 않는다.
- 배치·항목·원문 저장 식별자를 보관한다. 실행 중단이나 저장 응답 유실 시 미확정 요청을 자동 재전송하지 않는다. 수집 전 실패와 저장 결과 미확정을 구분한다.
- `/api/operations/listing-candidates`는 기존 운영관리의 회원 승인 검사·원자적 revision 비교 저장을 사용한다. 같은 원문 요청은 같은 저장 영수증을 반환하고, 같은 식별자의 다른 원문은 거절한다. 새 DB 테이블은 필요 없다.
- 설치 패키지 2.1.62에는 검색 목록의 `s.1688.com` 연결과 다중 담기 실행 파일을 포함한다. 실제 설치 폴더는 백업 후 갱신하며 Chrome에서 새로고침해야 실행 버전이 바뀐다.

## 검증과 한계

실제 SQLite API, 클래식 앱 브리지, 선택 UI, 배치 엔진, 소유 상세 탭 수집기 및 기존 단일 수집의 회귀 검사를 수행한다. 검사 로그와 최종 빌드·패키지 해시는 `outputs/step873-*`에 보관한다. 합성 문서 검사는 실제 1688 수집 성공을 뜻하지 않는다.

최종 16개 테스트 파일 304개 전부 통과했다. 최초 303/304 실행의 실패는 이전 PING 검사가 구버전에도 새 checkpoint 기능을 기대하던 문제였으며, 기능별 버전 경계 검사로 바로잡아 전체를 다시 실행했다. TypeScript·ESLint·운영 빌드와 ZIP 원본 대조를 통과했다. 독립 검수에서 비활성 탭 타이머 지연에 따른 수집 중단(P1), 명확한 시작 거절 뒤 UI 잠금(P2), UUID 배열 강제변환(P2)을 찾아 회귀 검사와 함께 수정했다.

배포 Worker: `9fd88c9b-9241-4da7-a065-9e4bbed51407`. 확장 ZIP은 111파일·1,593,345바이트, SHA256 `7187b83e26411780c80869c02c728803d779d8f4806625deb8996618f68538dd`다. 실제 Chrome이 읽던 2.1.61 폴더를 백업하고 2.1.62 파일과 해시 일치를 확인했다. 사용자가 2.1.62 적용 완료를 회신했다. 현재 제어 연결에는 정상 YOOFAM·Supplier Hub 탭이 보이지 않아 실행 버전과 실제 양쪽 저장은 도구로 확인하지 못했다. 검증용 새 상품 1개의 목적지별 저장 결과 문구를 요청했다.

이번 브라우저 검수는 YOOFAM 탭이 Cloudflare Access로 이동한 뒤 인증 도메인 접근이 자동 승인 검토에서 거절되어 진행하지 못했다. 사용자의 로그인 완료 응답 뒤에도 같은 거절이 유지되어 우회하지 않았다. 확장 2.1.62의 실제 검색 카드 수집과 두 저장 결과는 적용 후 별도 실검수가 필요하다.

886 원래 요청과 문서 2347603의 실제 접수는 미완료다. 이번 다중 담기 구현은 기존 문서 생성·파일 저장·본문 업데이트·제출을 호출하지 않는다. 원래 상품 범위 D1 35개 테이블 47행의 해시는 이전 871 검사와 동일하다.
