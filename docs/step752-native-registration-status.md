# 원래 등록 문서의 상품별 접수 상태 조회

2026-10-20, 기준 커밋 `61790b0`.

저장된 전체 상품 문서 접수 이력에서 **상품별 접수 상태 조회**를 누르면, 원래 등록 요청에 속한 견적서 번호·SKU·검수 상태를 읽는다. 조회로 새 견적서를 만들거나 기존 작업 상품을 수정하지 않는다. 문서 파일 처리 완료와 개별 상품의 검수 완료는 구분한다.

## 구현

- 현재 승인 회원·회사와 인증된 서버 접수 기록을 조회 전후 확인한다. 페이지에서 임의의 Hub 요청번호를 지정할 수 없으며, 선택한 원래 접수의 본문 지문·포함 옵션 수·회원·회사가 일치해야 한다.
- 같은 Chrome 창의 별도 읽기용 WIMS 탭에서 회사코드와 공식 공급사 ID를 확인한다. 원래 사용자 탭의 검색 조건이나 상품은 변경하지 않는다.
- 공식 `vendorSearch`의 모든 페이지를 읽고, 자료형까지 같은 `qvtRequestId`와 `SIMPLE_REGISTRATION` 방식이 확인된 행만 연결한다. 견적서 UUID·estimation ID를 등록 요청번호로 대체하지 않는다.
- 조회는 최대 40페이지·2,000행·55초로 제한한다. 페이지 길이·총건수·모든 행의 중복 식별을 검사한다. 날짜 하한은 나중에 갱신되는 접수 확인 시각 대신 보관된 원래 상품 버전의 한국시간 날짜를 사용한다.
- 견적서 UUID, 양의 숫자 문자열 SKU 또는 명시적 null, 알려진 검수 상태만 표시한다. 결과 행 순서로 원래 옵션과 SKU를 연결하지 않는다.
- 조회 취소·화면 닫기·회사 또는 보관 기록 변경 뒤의 늦은 응답은 표시하지 않는다. 자동 조회·재전송·접수 기록 갱신은 없다.

통합 확장 `2.1.4`에 새 조회 모듈 2개를 포함했다. 추가 권한·계정 변경·DB 마이그레이션·유료 리소스는 없다. 설치 폴더는 이전 버전을 백업한 뒤 갱신했으며, 준비된 파일 버전과 Chrome에서 실행 중인 버전은 구분한다.

## 검증과 근거

- 15개 관련 테스트 파일 **210/210 통과**. 마지막 SKU 형식 정합성 보강 후 해당 클라이언트 6개를 재검사했으며 중복 합산하지 않았다. 타입·린트·운영 빌드·생성 수집 모듈·확장 ZIP 검사 통과.
- 독립 REA 검수에서 등록 방식 누락과 페이지 경계 중복으로 인한 잘못된 결과 없음 처리를 발견해 수정했다. 원문 계약과 범위는 `outputs/step752-native-contract.json`, 검수는 `outputs/step752-native-source-review.json`에 기록했다. 기존 Evidence `ev_05abd95724353b22c4ca14685b3e8dbe88bc4f0cee756eea76a4dd6873b7f42c`를 재사용했으며 새 실접수 실행 증거로 취급하지 않는다.
- 실제 Chrome에서 실제 React 컴포넌트와 클라이언트로 정상 2행 조회, 조회 취소, 회사 불일치를 검수했다. 회원·접수 이력·브리지 응답은 localhost 합성 자료다. 실제 운영 API·1688·Hub 요청과 상품·접수 쓰기는 0이다. `outputs/step752-browser-qa/proof.json`과 스크린샷을 보관했다.
- 로그인된 기존 Chrome의 공식 `/qvt/vendor/id`에서 `A01526306` 표시를 직접 확인했다. 응답 헤더와 WIMS 실제 응답 본문까지 관측한 것은 아니다. 기존 작업 상품은 열거나 수정하지 않았다.

## 남은 검증

이 변경은 상품별 결과를 읽는 연결 기능이다. 새 실상품의 1688 수집부터 1~7단계, 전체 옵션 native 등록, 최종 동의와 실제 SKU 접수까지의 성공을 입증하지 않는다. native live 검증 게이트는 그대로 false이며, 가짜 접수나 옵션별 SKU 연결을 만들지 않는다. required legal-document native transport, 실제 WIMS wire 형식 및 옵션별 연결은 추가 실검증이 필요하다. 정적 계약·합성 검수·실제 접수를 서로 구분하며 전체 동일구현 또는 100% 완료를 주장하지 않는다.

## 배포

기존 무료 Worker `fab1cdd4-0983-44f5-9b60-4ec92d086d77`로 배포했다. 같은 Chrome의 운영 앱에서 관리자 로그인·목록 2행·대기열 1건의 로딩 완료를 확인했으며 기존 상품은 열지 않았다. 확장 ZIP은 84파일·966788바이트, SHA256 `d6daf948ea2c85507bbf3a5fd8bc5261245f1bd1eeb29e7d0b319b9386eabe8b`이다. 실제 실행 버전은 마지막 관측 `2.1.3`으로, `2.1.4` 갱신 적용은 별도 확인이 필요하다.
