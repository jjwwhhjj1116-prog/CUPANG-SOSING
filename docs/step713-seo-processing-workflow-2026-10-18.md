## 맞춘 동작

원본의 1단계 새 SEO 생성 버튼과 내부 실행 조건은 타겟 키워드를 `trim()`한 결과가 비어 있지 않아야 한다. 자체의 Google/AI 새 수동 초안 생성에도 버튼과 실행 시점의 같은 조건을 적용했다. 공란·공백은 입력란에 그대로 유지하며, 임의 키워드로 채우거나 새 요청·복구 정보·job을 만들지 않는다. 브랜드·특징을 새 필수 조건으로 추가하지 않는다.

이미 보관된 요청의 이어 실행·응답 유실 복구·상태 조회는 기존 operation을 확인하므로 과거 타겟 메모가 공란이어도 허용한다. 새 초안 입력으로 기존 요청을 명시적으로 해제한 다음에만 다시 새 타겟 조건을 적용한다. 이 변경은 1단계의 수동 재생성에 한정한다. 상품 추가의 최초 URL 수집·카테고리 선택·초기 초안 경로에 새 필수 조건을 전파하지 않는다. 공통 상품명·검색태그·옵션명의 수동 저장과 명시 공란 보존도 그대로다.

원본은 실제 SEO 처리 중 두 편집 영역 대신 진행 표시를 보인다. 자체 Generator는 실제 생성·통합 검토/적용의 진행을 부모에 올려 생성 입력과 공통 SEO/옵션명·선택 옵션 SEO·보조 이력을 함께 숨긴다. 편집기는 계속 mounted 상태를 유지하며 입력을 초기화하지 않는다. 공통/옵션 편집기에는 실행 시점 잠금도 전달해, 이전에 캡처한 수정·저장·복원·조회·입력 취소·공통 설명 이동 callback으로 잠금을 우회할 수 없게 했다.

최초 자료를 읽는 GET과 기존 요청의 명시적 상태 조회는 새 생성 진행으로 취급하지 않는다. 생성기 자신의 완료·복구를 막는 disabled 되먹임도 없다. 생성 결과는 기존 미리보기·사용자 검토·명시 적용 경계를 유지한다. 원본 저장 실패가 성공 상태로 보일 수 있는 구문을 그대로 복제하지 않으며 자체 실제 저장 확인과 CAS를 보존한다.

## 진행 상태와 수명

각 생성과 통합 적용은 서로 다른 operation token을 사용한다. 부모는 현재 owner·상품·저장 버전에 연결된 별도 token과 현재 operation이 일치할 때만 종료 신호를 받는다. A→B→A로 같은 식별 문자열이 돌아와도 이전 callback이 새 화면을 잠그거나 해제할 수 없다. callback receiver 교체는 기존 신호를 해제하고 같은 활성 operation을 새 receiver에 전달한다.

독립 검토에서 실제 하위 `TranslationIntegratedPreview`는 active/disabled 변화만으로 요청을 중단하지 않는다는 경계를 찾았다. 단계만 잠깐 이동할 때 부모 잠금을 먼저 해제하면 하위 저장은 진행 중인데 다른 입력이 열릴 수 있다. 이를 고쳐 **통합 미리보기·적용의 활성 요청은 단계 이동 중에도 동일한 진행 신호를 유지하고 실제 하위 요청의 finally에서만 해제**한다. 입력 영역은 계속 mounted 상태다. 상품 원천/버전/owner 교체·unmount는 각 실제 수명과 source 검증으로 이전 진행을 폐기한다. 자체 생성 요청의 단계 이동 중 취소와 하위 통합 적용의 수명은 구분한다.

## 검수 경계

신규 검사는 생성기11, 옵션 잠금6, 단계/공통 편집5로 나눈다. 생성기에는 실제 하위 통합 컴포넌트의 미리보기·적용 요청을 각각 보류한 뒤 단계 이동·복귀·실제 완료를 확인하는 두 trace가 있다. 네트워크 결과와 hook scheduler는 합성이므로 사용자 브라우저 포인터나 실제 제공자 동작 검사가 아니다.
