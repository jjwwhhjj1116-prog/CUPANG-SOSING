# 초안 재시도·회사 연결·SKU 조회 복구 검수 (2026-10-03)

## 수정한 문제

1. 첫 AI 작성 중 표시사항의 재질만 저장하면 최초 적용은 충돌로 중단됐으나, 재시도에서는 SEO 제목·설명·카테고리 속성이 빠진 채 성공으로 안내되고 옵션 번역을 위해 AI를 다시 호출했다. 상품에 연결된 정식 최초 작성 작업의 완료 결과를 다시 사용해 아직 수정하지 않은 원문 항목만 채운다. 새로운 콘텐츠 revision을 기준으로 미리보기를 만들고 적용 전에 지문과 DB 조건을 다시 검사한다. 완료 결과가 없는 불확실한 요청은 재실행하지 않는다.
2. 원문과 같은 SEO 값 또는 원래부터 빈 제목·설명·검색어를 직접 저장하면 이전 provenance가 남아 늦은 AI 결과가 바꿀 수 있었다. 명시적으로 저장한 SEO 값은 동일한 값이나 공란이어도 수동 확인으로 남긴다. 표시사항의 기존 명시적 공란 처리와 옵션의 수동 값·제외 선택을 유지한다. 다른 완료 작업의 카테고리 속성 기록도 교체하지 않는다.
3. 회원 승인과 회사정보 변경은 임의의 비어 있지 않은 회사코드·회사명을 허용했으나, 실제 견적서 전송은 허용된 두 회사의 정확한 조합만 받았다. 잘못된 조합이 두 번째 승인 자리를 차지하거나 회사 변경으로 정상 세션을 해제할 수 있었다. 승인·변경·전송에서 같은 조합 판정을 사용한다. 허용 조합은 유앤채 `A01526306`, 와이홉 `A01464742`다. 승인 DB 갱신은 관리자 상태, 조합, 최대 두 계정 조건을 함께 검사한다. 가입 요청은 대기로 보관하고 관리자가 회사정보를 바로잡은 뒤 승인한다.
4. 계정 관리의 회사정보 수정에서 정확한 두 회사 중 하나를 직접 선택하고 회사명은 그 선택과 함께 보낸다. 미설정·불일치 정보는 빈 선택으로 시작하며 첫 회사를 자동 배정하지 않는다. 계정 화면을 떠나면 초기 조회를 취소하고 늦은 응답으로 상태를 바꾸거나 로그인 화면으로 이동하지 않는다.
5. 카테고리 설정 저장 중 편집기를 닫고 다른 편집기를 열면 이전 응답이 새 화면을 닫거나 입력 대기열을 다시 열 수 있었다. 닫은 편집기의 POST·PUT 저장 요청을 취소하고 늦은 성공·실패 응답을 무시한다. 서버에 이미 도착한 저장이 취소됐다고 추정하지 않으며 새 편집 내용과 화면을 보호한다.
6. 마지막 Supplier Hub 탭을 닫으면 인증된 접수 기록이 남아 있어도 SKU 조회를 재개하지 못했다. 정확한 접수 기록과 최신 저장본을 대조한 후 앱과 같은 기존 Chrome 창에 비활성 조회 탭 하나를 준비한다. 실제 로그인·회사코드·창을 다시 확인한 뒤 조회한다. 견적서와 첨부를 다시 제출하거나 기존 수동 작업을 덮지 않는다.

## 검사 방식과 한계

- 지정 상품 `813724060928`의 기록한 원문, 실제 프로젝트 API, 임시 SQLite와 AI 응답 모형으로 양사의 최초 작성 중 재질 편집, 명시적 같은 값·공란, 최신 카테고리 기록, 옵션 수정·제외, 응답 유실, 불확실한 AI 결과, 적용 전 콘텐츠·URL 변경을 검사했다. 초안·견적 필드 연결과 반복 재시도 시 초기 AI 호출 한 번, 원본 작업 결과·수집 설정 보존을 확인했다. 운영 AI 응답이나 운영 견적서 등록을 대신한 검사는 아니다.
- 직접 저장한 빈 검색어에 수집 안내 검색어가 없는 경우도 별도로 재현했다. 변경 전 AI가 빈 검색어를 채웠고, 변경 후 빈 목록과 수동 확인 상태를 보존했다.
- 회사 연결은 실제 API·회원 DB 조건과 React 계정 폼을 검사했다. 잘못된 조합 거부, 양사의 올바른 조합 승인·전송 연결, 조건 갱신 중 정보 변경, 세션·감사 기록 보존, 빈 선택과 정확한 폼 제출을 확인했다. 운영 회원을 새로 승인하거나 관리자 회사를 임의 배정하지 않았다.
- SKU 조회 복구는 실제 접수 기록 API·임시 DB와 Chrome API/Hub DOM 모형으로 양사의 로컬·서버 기록 및 서버 기록만 남은 경우를 검사했다. 잘못된 기록·원문 변경은 새 탭도 만들지 않으며 로그인 만료·다른 창·회사에서는 검색하지 않는다. 모형 SKU를 실제 Hub 발급 번호로 보고하지 않는다.
- 별도 읽기 전용 검토로 최초 작업과 원문·전체 카테고리 경로 연결, 계획용 값의 비저장, 기존 카테고리·옵션 보존, 저장 시 revision·작업·수집 설정 조건을 확인했다. 회사 승인·세션 처리도 독립 검토했다.
- 이번 연결된 기존 Chrome 두 개에서는 허용된 작업 호스트의 대상 탭이 반환되지 않았다. 사이트 차단·로그아웃·승인 거절로 판단하지 않았으며 다른 프로필·새 Chrome 창·기존 Couplus 작업 상품을 조작하지 않았다.
- 실제 모든 카테고리의 Couplus 기본값·Supplier Hub 공식 양식 비교, 운영 AI·이미지 번역, 두 회사 최종 견적서 ID·SKU 확인은 남아 있다. 테스트 결과를 완전 복제 또는 실제 등록 완료로 보고하지 않는다.

- 확장 `0.2.43`을 제공한다. 새 권한·호스트·Chrome 프로필을 추가하지 않는다. 기존 확장 폴더와 앱 페이지를 새로고침해야 마지막 탭 종료 후 조회 복구가 적용된다. 이전 `0.2.42`는 해당 상황에서 안전하게 중단하므로 새 별도 capability를 추가하지 않았다.
