# 파일 첨부 전 서버 전송 기록 대조

2026-10-01, 544단계.

## 문제와 최종 동작

543단계는 로컬에 복구한 접수 결과의 재첨부를 차단했다. 하지만 로컬 전송 기록을 잃은 Chrome에서 아직 결과 조회를 하지 않았다면 서버에 접수 기록이 있어도 앱 등록전송과 팝업 첨부가 다시 실행됐다. 기존 코드로 세 회귀 검사가 실패하는 것을 확인했다.

- 두 전달 경로에서 원래 앱 탭의 회원 소유 접수 API를 읽고, 첨부 직전에 한 번 더 확인한다. 같은 상품·카테고리·확인값의 기록이 있으면 검증 완료뿐 아니라 검증 대기·반려 상태도 복원하고 첨부를 중단한다.
- 서버 기록의 폼·파일명·회사·옵션 수·관찰 시각과 현재 저장본을 대조한다. 불일치, API 오류, 잘못된 응답, 다른 앱 탭/창, 시간 초과를 새 견적서로 취급하지 않는다. 이 경우 worker는 재시도가 가능한 `not-started`로 응답하지 않는다.
- 결과 복원은 원자적 저장으로 기존 결과를 덮어쓰지 않는다. 과거 SKU 행이나 가상의 업로드 시도 기록을 만들지 않는다. 팝업은 준비한 ZIP도 소비하지 않는다. Supplier Hub의 기존 첨부·동의·상품 초안을 변경하지 않는다.
- Chrome 탭 조회는 앱과 같은 창의 Supplier Hub 등록 URL로 제한한다. 팝업도 현재 창의 활성 등록 URL만 조회한다.
- 새 파일 전달은 확장 `serverReceiptReplayProtection` 기능을 요구한다. 기존 결과 조회는 계속 허용한다. 확장 0.2.34와 앱 다운로드 링크를 함께 갱신했다.

## 검증 범위

- 집중 검사 99/99, 신규 12개 포함 전체 1720/1720 통과(212.975초). 와이홉 A01464742·유앤채 A01526306의 임시 SQLite·실제 접수/source API·content script·확장 preflight를 연결해 로컬 기록 없이 세 상태 모두 재첨부를 차단했다. 상품 초안과 옵션 6개가 유지됐고 업로드 claim을 만들지 않았다. 새 견적서는 기록 없음으로 진행 가능하며 조회 실패는 첨부 전에 중단했다.
- 두 전달 경로의 실제 모듈을 연결해 첨부 준비 중 서버 접수 기록이 생긴 경우도 검사했다. worker 응답 오류 코드, 기존 결과를 보존하는 동시 저장, 잘못된 회사/옵션 수/상태/시각/응답 크기, 구버전 확장 기능 검사를 포함한다.
- TypeScript 오류 0, 변경 파일 lint 오류 0/기존 intake `onBusy` hook 경고 1. 운영 빌드와 11개 마이그레이션 산출물 검사 통과. 전체 저장소 lint 통과를 주장하지 않는다.
- 확장 0.2.34, 32파일, 392483바이트. SHA-256 `3d45d09e0bdce344579d2d38d59a3b02a584f96747c097dfc22932e0d209cab5`. 소스·번들·ZIP 일치 검사 통과. 적용하려면 기존 확장 폴더를 갱신하고 해당 확장과 앱 페이지를 새로고침해야 한다.

이는 이미 서버에 저장된 기록의 재전송을 막는 검사다. 서로 다른 Chrome에서 동시에 최초 전송하는 요청을 전역 잠금으로 직렬화하지 않는다. 인증·AI·이미지·Hub 응답은 시험 자료이며 80719는 관찰된 바스켓 폼 계약이다. 813724060928 선글라스의 실제 판매 분류나 실계정의 최종 견적 접수·상품 승인 증거로 해석하지 않는다.

전체 실제 카테고리 기본값/공식 양식 대조, 운영 이미지 번역/필수 서류, 두 회사의 실제 최종 Hub 접수/SKU 확인은 아직 검증되지 않았다. 이번 작업에서 기존 Couplus 상품과 실제 Supplier Hub 견적서에 쓰기를 하지 않았다. DB 마이그레이션·비밀 설정·이미지 Worker·유료 자원 변경 없음.
