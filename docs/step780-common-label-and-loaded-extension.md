# Step780 — 동일 라벨의 전체 옵션 저장과 실제 설치 폴더 갱신

REA로 보관된 Couplus Stage6 `saveManualLabels`를 확인했다. 작성한 표시사항 하나와 PNG 한 장을 상품 공통, 제외 옵션을 포함한 전체 옵션, 각 견적서의 라벨 참조에 반영한다. 근거 파일·SHA·UTF-16 범위와 기존 Evidence ID는 `outputs/step780-rea-label-audit.json`에 기록했다. 원본 코드를 배포하지 않고 기능을 독립 구현한다.

## 이번 구현

한글표시사항 화면에 **전체 옵션에 동일 라벨 저장**을 추가했다. 적용 옵션 수, 각 항목·공란, 덮어쓸 옵션별 기존 내용을 검토하고 저장한다. 취소하면 입력과 저장본이 유지된다. 기존 선택 옵션 저장도 사용할 수 있다.

전체 텍스트는 하나의 버전 확인 PATCH로 저장한다. 현재 사용하는 항목을 공통값으로 두고 현재 옵션의 해당 항목 덮어쓰기만 해제한다. 제외 옵션에도 적용하고, 사용하지 않는 이전 항목과 이전 파일은 보관한다. 같은 저장값으로 PNG 한 장을 생성한 뒤 전체 옵션의 견적서 라벨 참조를 연결한다. 가격·옵션·상품고시·원문은 이 작업에서 바꾸지 않는다.

저장 응답이 유실되면 완료로 표시하지 않는다. 같은 작업의 저장 결과를 먼저 읽고, 확인된 텍스트·이미지 업로드·견적 연결부터 이어간다. 다른 저장이 끼어들거나 옵션·계정·단계가 바뀌면 이전 확인 버튼이 새 작업에 적용되지 않는다.

대표이미지의 AI 가공 버튼은 기존 조회 응답에 현재 상품·버전·이미지 목록과 설정 여부가 확인됐을 때 활성화한다. 무료 중국어/영어 번역과 직접 편집은 사용할 수 있다. 추가 공급자 요청이나 요금 설정은 없다.

## 실제 Chrome 검수와 검사

같은 Chrome에서 새 합성 수집본만 사용하는 별도 Dashboard를 열어 검토·취소·입력 보존, 전체 옵션 저장, 브라우저 canvas PNG 생성·다운로드, 7단계 견적서의 라벨 참조를 확인했다. 공통과 두 옵션에 동일 값이 저장됐고, PNG 업로드는 한 번이었다. 보존 대상 합성 상품·기존 이미지·원문·옵션은 그대로였다. 실제 공급자·Supplier Hub 요청은 없었다. 상세 증거는 `outputs/step780-browser-final-proof.json`과 생성된 `step780-browser-rendered-label.png`다. 화면 캡처 API는 두 번 시간 초과돼 전체 UI 스크린샷 성공으로 기록하지 않는다.

최종 동결 코드에서 22개 파일의 182개 검사가 한 번의 실행으로 통과했다. TypeScript·변경 파일 lint·확장 생성물/ZIP 확인·운영 빌드도 통과했다. 검사 목록과 소스 해시는 `outputs/step780-final-validation.json`에 보관한다. Worker 배포 버전은 `f52abbc9-293f-4675-ab6a-72fe5d1644f9`다.

## 새로고침해도 확장 2.1.4가 유지된 원인

사용자 답변과 운영 앱 조회 모두 현재 실행 버전 2.1.4를 확인했다. `outputs/step752-loaded-extension-preparation.json`에 기록된 기존 판매량 확장 폴더의 manifest가 실제로 2.1.4로 남아 있었다. 개발 폴더의 2.1.18만 갱신돼 기존 설치 폴더에 반영되지 않았다.

기존 설치 경로는 `C:/Users/7500F/Documents/Codex/2026-10-05/new-chat/outputs/YOOFAM-FLUS-v2-2.0.1/YOOFAM-FLUS-v2`다. 이 폴더의 89개 파일을 백업한 뒤 최신 통합 확장의 90개 파일로 갱신하고 바이트 SHA 일치를 검증했다. 기존 테스트 5개는 삭제하지 않았다. 권한·호스트·worker가 동일하며 Chrome 프로필·로컬 저장 기록은 읽거나 수정하지 않았다. 준비 결과는 `outputs/step780-loaded-extension-preparation.json`에 기록했다. 실제 Chrome 적용은 새로고침 후 실행 응답으로 따로 확인한다.

사용자가 새로고침 후 2.1.18로 바뀌었다고 알렸고, 앱 탭을 다시 불러온 뒤 실제 확장 응답에서도 **설치된 버전 2.1.18**을 확인했다. `outputs/step780-runtime-2.1.18-dom.txt`와 화면 캡처에 보관했다. 현재 Supplier Hub 탭의 유앤채 로그인·회사코드 A01526306도 읽기 확인했다. 사용자가 다른 업무 화면으로 이동해 있었으므로 그 화면에서 아무 조작도 하지 않았다.

후속 확장 배포에서도 개발 폴더와 실제 로드 폴더를 함께 확인한다. Chrome의 새로고침은 이미 로드한 폴더를 다시 읽으며 다운로드 ZIP의 변경분을 가져오지 않는다. 실제 로드 경로가 다르면 기존 폴더 전체 백업·권한 대조·파일 전체 동기화·해시 검증 후 실행 버전을 확인해야 한다.
