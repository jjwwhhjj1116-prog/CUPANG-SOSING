## 실제 공개 상품 확인

지정 상품 `813724060928`을 2026-10-05 14:45:57 KST에 현재 운영 수집 함수로
읽었다. 공개 PC·모바일·SKU·상세 응답은 HTTP 200이고 검증 결과는 옵션 6개,
이미지 19개, 속성 24개, 설명 텍스트 0자였다. 설명 텍스트가 없다는 결과를 상세
이미지가 없다는 뜻으로 해석하지 않는다.

`scripts/check-public-product.mjs --verify-images`로 같은 원문의 이미지 19개를
현재 운영 다운로드 함수에 전달했다. 최대 3개 동시 다운로드, 파일당 10MB 제한,
HTTPS Alibaba 이미지 주소·실제 파일 형식 검사를 적용했다. 전부 통과했고 총
2,600,378바이트 및 19개 헤더 치수를 확인했다. 바이트는 메모리에서만 처리했다.
진단 결과는 `outputs/step569-live1688-images.json`에 있으며 Git에 포함하지 않는다.

이 실행은 실제 1688 공개 응답/이미지 읽기 증거다. 운영 회원의 앱 등록, R2 저장,
AI 호출·번역·이미지 전체 디코딩 또는 Supplier Hub 접수 성공으로 확대하지 않는다.

## 변경한 작업 흐름

1. 기본 SEO·가격 모드는 Couplus 신규 초안 관찰을 유지한다. 원본은 자료함에
   보관하고 대표·추가·옵션 이미지를 임의로 선택하지 않는다. 상세 배너도 유지한다.
2. 명시적인 ‘SEO·가격 + 이미지 초안’ 선택은 저장 원본의 순서와 정확한 SKU/이미지
   번호를 사용해 대표·추가·상세·옵션 이미지 초안을 연결한다. 기존 파일을 재사용하며
   수동 선택·공란·배너·생성/번역 결과·제외 옵션은 보존한다. 이 추가 선택의 배치
   알고리즘이 Couplus와 동일하다고 주장하지 않는다. 이미지 완료 상태도 쓰지 않는다.
3. 새로 읽은 카테고리의 정확한 고시명 5개를 기존 6단계 입력과 연결했다. ‘제품 구성’,
   ‘색상’, ‘크기, 중량’, ‘상품별 세부 사양’, ‘KC 인증정보’이며, legalPage의 이름이
   일치하는 공통 고시 필드만 처리한다. 다른 속성·유사 이름은 추정하지 않는다.
   카테고리 ID/원본 필드 경로/기본값을 유지하고 수동 견적값과 명시 공란이 우선한다.
4. 7단계의 ‘저장한 견적 전송 준비’는 현재 상품과 선택한 양식을 전달한다. 최근
   200건 밖 보관함 상품도 검사 → 견적 수정 → 전송 준비 복귀가 가능하다. 기존
   목록의 체크 선택을 바꾸지 않는다. 미저장 입력·진행 중 저장은 화면 이동 전에
   보존한다. 첨부 검토·필수 동의·실제 전송은 기존 전송 화면의 명시 동작을 따른다.

  재시도·누락 파일 재개·응답 유실·수동 공란·동시 수정 시 원자적 중단을 검사한다.

  CSV/XLSX 출력 셀에 도달함을 검사했다. KC 공란 및 공통/옵션별 견적 공란도 검사한다.
  새 카테고리 모형은 실제 선글라스 판매 분류가 아니다.
- 실제 React 컴포넌트 조합으로 보관함 상품/정확한 양식/기존 목록 선택/숨겨진 단계의
