# Step643 — 모바일 수집 재사용과 대표·추가 이미지 편집

선택한 카테고리 → 1688 URL → 편집 가능한 1~7단계 초안 → 사용자의 검토·수정 → 명시적인 등록전송 흐름을 유지한다. 기존 상품·대기 초안·회사 설정·Couplus 작업 자료는 변경하지 않는다.

서버가 모바일 SKU와 상세 원문을 이미 수집했더라도 설명 텍스트가 비어 있으면 Chrome에서 같은 수집을 반복하던 경계를 수정했다. 검증된 원문 응답과 저장 시각 확인을 통과한 full/partial 모바일 수집을 재사용한다. JSON-LD·SKU-only 원문의 보완은 유지하고, 실제 누락된 설명·속성·상세사진 경고와 사용자가 요청하는 원문 보완 기능도 유지한다. provider 이름만으로 자료의 완성 상태나 견적서 접수 완료를 선언하지 않는다. 취소·재개·원문 변경·수동값과 공란·가격·번역 이력을 보호한다.

3단계 옵션 대표이미지와 4단계 옵션 추가이미지에 `편집하기`를 연결했다. 원본을 조회한 다음 문구·영역·브러시를 수동 편집하고 미리보기 후 명시적으로 적용한다. 대표이미지는 해당 옵션의 mainImage 0번 위치, 추가이미지는 사용자가 선택한 정확한 사진 위치를 갱신한다. 다른 옵션과 공통 이미지 원문은 유지한다. 대표이미지의 외부 이미지 작업 잠금과 해제 후 조회 재개, 오래된 콜백과 미저장·응답 미확인 입력 보존을 함께 반영했다.

같은 지정 Chrome에서 Couplus 작업상품 261013005001을 읽기 전용으로 열어 3·4단계와 대표사진 편집 화면을 확인했다. 대표 편집은 xiangji iframe의 텍스트·지우개·직사각형·브러시·잘라내기·다운로드·저장 도구를 사용한다. 이번 구현이 해당 외부 편집기의 잘라내기 등 모든 동작과 동일하다는 뜻은 아니다. 사진 편집·AI·업로드·저장·전송은 실행하지 않았고, 원래 옵션 목록으로 돌아가 기존 옵션·가격을 확인했다. DOM와 대표 편집 실제 스크린샷은 Git 제외 outputs/step643-couplus-*.txt/json/jpg에 보관했다. 추가 단계 캡처는 브라우저 제한 시간으로 성공하지 못했으므로 텍스트 대조 근거로만 기록한다.

카테고리 기본값은 기록된 공개 초기화 동작과 공식 69900 원본을 다시 대조했다. 이번 범위에서 확정할 수 있는 새로운 기본값 연결 결함은 발견하지 못했다. 기존 상품에 저장된 포장값·N/A·AI 입력을 초기 기본값으로 간주해 복사하지 않았다. 모델명 제안과 공식 Excel 항목 적용은 기존 명시적인 검토·저장 경로를 유지한다.

신규 모바일 수집 시험은 기록된 모바일·SKU·상세 응답을 합성 URL에 사용한다. 와이홉의 원본 6행 시험은 유앤채 기록 양식을 회사만 격리하여 재사용한 계약 검수다. 별도 와이홉 공식 양식 캡처나 새 실상품 수집으로 주장하지 않는다. 기존 JSON-LD 브라우저 시험의 읽기 횟수 4 기대값은 HEAD에서도 7로 재현됐으며, 초기 안정화 4회와 원문 보완 안정화 3회를 실제 계약에 맞게 보정했다. 정확한 보완 1회와 최초 상품 저장 전 순서·SKU·원가·MOQ·재고 보존도 함께 검사한다.

지정 Chrome의 격리된 로컬 UI에서 유앤채·와이홉 각각 대표이미지 0번과 추가이미지 1번 편집을 실행했다. 실제 React/API/SQLite를 사용하여 원본 조회 후 명시적인 적용 POST 1회로 선택 위치만 바뀌고, 화면 카드가 저장된 참조로 갱신되는 것을 확인했다. 네 사례 각 10개 검사 모두 통과했다. 원본 바이트·메타데이터·다른 옵션·가격·회사와 선택하지 않은 사진 순서를 유지했다. OCR·번역 모델·실제 Supplier Hub 호출은 없었다.
