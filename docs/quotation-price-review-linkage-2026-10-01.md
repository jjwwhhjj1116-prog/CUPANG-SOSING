# 2단계 가격 오류 표시와 7단계·견적서·전송 첨부 연결

## 재현과 수정

2단계 옵션별 가격 편집은 숫자의 형식·범위와 판매가/공급가 관계만 검사했다. 자동 계산 자체가 실패해 공란이 된 권장소비자가격은 선택 항목이어서, 7단계에는 남아 있는 계산 오류를 2단계에서는 표시하지 않았다. 다른 가격을 직접 입력한 후 이 권장가를 복원하면 오류 없는 공란처럼 취급하고 가격 저장을 허용했다. 최종 전송 검사는 기존에도 이 오류를 차단했지만 두 단계의 검토 결과가 달랐다.

실제 가격 resolver에서 범위 초과를 만들고 공급가·판매가에 검토한 공통값을 넣은 회귀 시험에서, 수정 전 2단계 화면에 `계산 가능한 가격 범위` 오류가 없다는 실패를 확인했다. 이는 격리된 계산 상태 시험이다. 운영 옵션/가격 저장 API가 이 범위 초과 입력을 받아들인다는 증거가 아니다.

가격 편집도 자동 셀의 `validationIssues`를 보존한다. 옵션 직접 수정, 공통 직접 수정, 자동값 복원의 우선순위에 맞춰 오류를 적용하고 오류가 있으면 가격 저장을 막는다. 메시지에는 SKU 옵션명과 가격 항목을 함께 표시한다. 직접 확인한 값과 의도적으로 비운 선택 권장가는 자동 계산 오류를 이어받지 않는다. 판매가/공급가 관계 오류는 현재 입력 두 값으로 다시 계산하므로, 이전 자동 셀의 관계 오류가 수정 후 계속 남지 않는다.

환율·마진·최소 마진·반올림·시장가격 배수의 계산식, 서버의 저장·최종 전송 검사, 카테고리 기본값은 변경하지 않았다.

## 통합 검증

추가 회귀 5개는 계산 오류/복원, 검토한 공통값/선택 공란, 현재 가격 관계와 두 회사의 통합 흐름을 검사한다. 편집·가격 관련 집중 검사 96건을 통과했다.

와이홉 `A01464742`, 유앤채 `A01526306` 각각에서 기록된 지정 URL 원문을 실제 앱 API·임시 SQLite·실제 React 가격 편집·견적서 생성·전송 준비 컴포넌트에 연결했다.

1. 카테고리 양식을 연결하고 1688 원문으로 6개 옵션 초안을 생성한다. 첫 SKU의 구성 수량을 2개입으로 변경하고 마지막 SKU를 견적에서 제외한다.
2. 7단계에서 공통 공급가/판매가/권장가를 5,000/9,000/12,000원으로 입력한다. 2단계의 실제 가격 편집에서 첫 SKU만 6,000/10,000/13,000원으로 저장한다. 한 번의 revision/fingerprint 검사 요청에 해당 SKU의 세 변경만 담긴다.
3. 7단계에서 두 번째 SKU의 판매가를 11,000원으로 수정하고 권장가는 명시적으로 비운다. 2단계에서 최신 상품 버전을 불러오면 이 값들이 보인다. 판매가 복원은 공통 9,000원을 사용하고, 비운 권장가는 그대로 유지한다.
4. 실제 상품 가격 API로 환율을 400원으로 변경한 뒤 공통 가격 수동값을 해제한다. 첫 SKU의 직접 가격과 두 번째 SKU의 명시적 권장가 공란은 유지되고, 나머지 가격은 각 SKU 원가·구성 수량·저장된 새 정책으로 계산된다. 별도로 입력한 SKU 모델·브랜드·고시 크기도 유지한다.
5. 이전 미리보기 지문을 사용한 파일 생성은 HTTP 409로 거절된다. URL 수집 재시도는 원문 재조회·AI 재실행 없이 수동값을 보존한다.
6. 새 미리보기 오류 0개, 견적 포함 5행을 확인한다. Excel 셀과 quotation-fields JSON의 최종 가격·공란·수량·SKU별 상품정보를 대조한다. 제외 SKU는 출력하지 않는다.
7. 실제 전송 준비 컴포넌트의 동의 선택 전에는 전송 버튼이 비활성이다. 명시적으로 첨부 준비·동의·전송한 요청을 로컬에서 포착하고 회사·카테고리·옵션 수 및 **최종 첨부 XLSX 바이트가 검사한 XLSX와 완전히 같은지** 확인한다. 실계정 Hub에는 쓰지 않으며 DB의 상태는 `미전송`이다.

인증·AI·이미지 바이트·원본 공식 Excel 대신의 합성 양식·최종 Hub 전송은 시험 자료다. `813724060928`은 선글라스이고 `80719`는 관찰한 폼의 시험 계약이지 이 상품의 판매 분류가 아니다. 공개 원가와 과거 Couplus 관찰 원가의 차이는 임의 할인율로 보정하지 않는다. 통합 시험 준비 중 콘텐츠/견적 저장 후의 최신 상품 버전을 사용하도록 보정했고 합성 바스켓의 재질 선택은 비웠다. 이 보정으로 운영 검증을 우회하지 않았다.

## 검증의 한계

전체 **1,514/1,514**, TypeScript, 운영 Cloudflare 빌드·산출물·diff 검사를 통과했다. 기본 변경 파일 lint는 기존 `react-hooks/set-state-in-effect` 오류 1개와 경고 3개를 반환했다. 변경 전 HEAD의 가격 편집 컴포넌트를 별도로 검사해 같은 effect 오류와 의존성 경고가 있음을 확인했다. 나머지 두 경고는 기존 시험 콜백의 미사용 매개변수다. 기본 lint 또는 전체 저장소 lint 통과로 보고하지 않는다. 이 수정은 해당 effect를 바꾸지 않았다.

초기 일반 빌드는 Windows 샌드박스의 esbuild 상위 경로 읽기 거부로 실패했다. 승인된 기존 프로젝트 운영 빌드를 권한 있는 실행으로 다시 수행해 통과했다. 자동 승인 검토의 거절이나 소스 누락을 확인한 것은 아니다.

운영 앱 `https://sourceflow.jjwwhhjj1116.workers.dev`에 버전 `be67a4f4-c681-4e81-afda-cfd635d7e11e`를 배포했다. 앱 새로고침으로 적용한다. 확장 0.2.29는 변경하지 않았으며 빌드에서 30개 파일/366,181바이트/SHA-256 `80a1d38d37bcd65b6b6d8e83e7c268d289b95320f00c91d0ae80147b21684444` 일치를 확인했다. DB·비밀 설정·공개 이미지 Worker·유료 자원 변경은 없다.

익명 운영 홈·확장 ZIP·원문 수집 API의 세 요청은 기존 Cloudflare Access 호스트로 HTTP 302를 반환했다. 로그인 보호 확인이며 인증한 화면·운영 다운로드 바이트·실계정 Hub 접수 시험은 아니다.

실제 지정 Chrome의 URL→1~7단계 작업, 전체 카테고리의 Couplus 기본값·공식 Excel 대조, 운영 이미지 번역·법적 서류 첨부, 두 회사의 최종 Supplier Hub 견적 접수·SKU 확인은 남아 있다. 이번 가격 연결 검사를 전체 시스템 완료로 보고하지 않는다.

기존 Chrome 바인딩의 탭 목록은 빈 목록이었다. Windows 창 목록에는 관련 작업으로 식별되지 않는 Chrome 창만 보여 입력하거나 내용을 읽지 않았다. 새 Chrome 창·프로필이나 로그인/승인을 요청하지 않았고 기존 Couplus 작업 상품을 조작하지 않았다. 이는 사이트 차단·로그아웃을 관찰했다는 뜻이 아니다.
