# Step609 — 견적 표시사항 PNG와 최종 저장값 일치

## 확인한 문제와 변경

견적서의 색상·재질 등 인쇄 항목을 수정해도 이미 생성한 견적 표시사항 PNG가 이전 값을 담은 채 최종 첨부에 남았다. 합성 상품의 색상을 녹색에서 파랑으로 수정한 경우, 기존 검토 오류는 0개였고 확장의 파일 준비도 통과했다. 운영 상품은 이 재현에 사용하지 않았다.

새 `quotation-label-png-v2` 생성 파일에는 서버가 다시 읽은 상품·옵션·실효 카테고리 프로필과 인쇄 계획의 SHA-256을 기록한다. 최종 견적의 인쇄 계획과 다르면 `GENERATED_QUOTATION_LABEL_STALE` 오류를 검토와 전송 패키지에 포함한다. 손상되거나 다른 상품·옵션에 속한 기록은 `GENERATED_QUOTATION_LABEL_UNCONFIRMED` 오류다. 가격 등 PNG에 인쇄하지 않은 값의 변경만으로는 오래된 라벨로 판정하지 않는다.

사용자가 새 PNG를 생성·연결하면 동일 상품·옵션·실효 프로필·카테고리에 속한다고 서버가 확인한 v2 참조만 교체한다. 수동 첨부, 원천을 확인할 수 없는 이전 버전, 다른 옵션의 참조는 유지한다. 이전 R2 파일과 상품 이미지 목록의 원본은 지우지 않는다. 파일명만 보고 생성 이미지라고 추정하지 않는다.

업로드와 참조 저장 사이에는 최신 견적을 다시 읽는다. 서버의 영속 업로드 확인, 제품 이미지 연결의 버전 검사, 견적 수정의 revision/fingerprint 검사, 전체 overrides 저장 응답 및 최종 GET 확인을 적용한다. 이미 연결한 경우에도 파일 확인 사이 원천이 달라지면 성공으로 보고하지 않는다. 응답 유실 뒤에는 확인된 저장본만 재사용한다.

이미지 번역 재시도에서 `translated: null`이 반환되면 같은 원문에 앞서 성공한 번역을 유지하고 실패 사유를 표시한다. 원문을 바꿨거나 수동으로 비운 문구에는 이전 번역을 복원하지 않는다.

## 검수 범위

- 쿠플러스 기존 상품을 읽기 전용으로 열어 5단계 상세이미지, 6단계 표시사항 결과, 7단계 견적 폼을 대조하고 화면을 보관했다. 저장·재작성·삭제·번역·전송은 실행하지 않았다.
- 두 승인 회사의 합성 상품으로 실제 앱 API, SQLite, PNG 렌더링, 파일 저장, 견적 Excel/ZIP 및 확장 `prepareAttachments` 경로를 검사한다. 운영 상품의 값이나 Hub 접수 상태를 변경하지 않는다.
- 서버 기록은 인쇄 계획과 저장 원천의 연결 증거다. 서버가 이미지의 글자를 OCR로 판독해 증명한 결과는 아니다.
- 이 단계는 기존 수동/이전 버전 파일을 자동 분류하거나 다시 쓰지 않는다. 사용자가 내용과 법정 표시 항목을 검토하는 기존 흐름을 유지한다.

최종 회귀 검사는 번역 82개, 라벨·원천 증거 111개, 견적·전송 준비 291개로 **484/484 통과**, 실패·취소·건너뛰기 0개다. TypeScript 오류 0개, ESLint 오류 0개(기존 경고 8개), 운영 빌드 검사를 통과했다. 17개 DB 마이그레이션과 확장 0.2.57/0.2.58 배포 파일의 해시는 이전과 동일하다.

## 남은 전체 작업 검증

이 변경만으로 전체 워크플로가 완료되었다고 판단하지 않는다. 모든 카테고리와 쿠플러스 기본값의 완전한 일치, 새 실제 1688 URL 수집부터 이미지 처리와 Supplier Hub 신규 접수 번호 확인까지의 전체 과정은 별도 실제 검증이 남아 있다.
