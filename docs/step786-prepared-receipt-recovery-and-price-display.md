# Step786 · 접수 조회 복구와 목록 가격 표시

## 수정

준비한 문서가 SUBMITTED 접수 기록을 가진 상태에서 결과 조회 응답을 받은 뒤, 현재 자료를 확인하는 후속 읽기가 일시 실패하면 `uncertain=true`가 된다. 이전 UI는 접수 기록이 있으면 복구 버튼을 숨기고, 불확실 상태에서는 조회 버튼도 숨겼다. 그 결과 기존 기록을 보존했지만 화면 안에서 재조회할 수 없었다.

이제 준비한 문서의 불확실 상태에서는 접수 기록이 있어도 **준비한 문서 단계 확인 · 읽기 전용**을 표시한다. 같은 요청번호·회사·상품·본문·문서·단계 검증을 계속 적용한다. 확인되지 않은 결과를 성공으로 바꾸거나 문서를 재생성·재전송하지 않는다. 일반 live-verified 플래그, 동의 확인, 변경 잠금은 유지한다.

다른 수정은 등록 목록의 상품명 아래에 표시되던 공급·판매 금액 요약 제거다. 해당 숫자는 원본 대표원가 기준이며 수정한 옵션별 견적 가격이 아니었다. 쿠플러스 방식의 요청된 목록 열은 그대로 두고, 정확한 옵션별 금액은 가격 설정에서 확인한다. 가격 계산·원가 보존·DB/API·저장 응답 검증·견적서 전송값은 변경하지 않았다.

## 검증

새 복구 회귀는 실제 전송 컴포넌트·클라이언트·pending/receipt 검증을 사용하고 React 일정·Chrome 메시지·로컬 API만 합성한다. 양사 SUBMITTED→조회 후 후속 읽기 실패→동일 UUID 읽기 복구→FINISHED 확인, 중복 클릭, busy, 잘못된 회사·요청·본문 ACK, 계정 변경, ABA와 늦은 응답을 확인했다. 처음 실행의 VM realm 배열 비교 실패와 수정한 최종 실행은 별도 로그로 보관했다. 실제 접수 검증은 아니다.

보드 회귀는 원본 대표 금액 5,120/8,530을 표시하지 않으며 상품명·옵션 수·가격설정 진입과 입력 객체를 보존하는지 확인한다.

최종 관련 5개 파일은 97/97 통과했다. 최초 관련 실행의 96/97은 이전 2.1.19 다운로드를 고정한 테스트 기대값 1건이었으며, 현재 manifest 버전과 실제 ZIP 존재를 확인하는 계약으로 바꾼 뒤 동일 검사 전부 통과했다. 타입·변경 파일 lint·운영 빌드도 통과했다. 별도로 확대한 native 통합 두 파일은 출력 없이 CPU를 사용해 중단했다. 원인은 미확정이며 이 두 파일을 성공·완료 수에 포함하지 않는다. 초기 격리 실행 문제라는 추정도 host에서 같은 현상이 나타나 철회했다.

새 localhost 합성 상품의 실제 Chrome UI에서 SEO 상품명·검색태그·한국어 옵션명을 함께 저장했고, 가격 정책과 옵션 원가도 저장했다. 20CNY·FX400·공급마진50%·쿠팡마진40%·10원 반올림·최소3,000원 ON의 첫 옵션은 11,000/18,330원으로 표시·저장됐다. 원가6.1인 두 번째 옵션은 5,440/9,070원이다. 대표 이미지 교체와 추가 이미지 순서 변경도 각각 견적 필드 PUT200으로 저장됐다. 보호 합성 상품은 그대로이며 실제 source/Hub/native 요청은 0회다.

5단계에서 합성 사진의 선택 제거를 누른 뒤 Chrome 기본 확인 창이 열렸다. 브라우저 도구의 getJsDialog·확인 버튼·탭 닫기가 모두 focus 명령에서 시간 초과돼, 사용자에게 로컬 확인 창의 OK 클릭을 비동기로 요청했다. 도구 한계를 앱의 저장 실패로 간주하지 않는다. 5~7단계의 이번 브라우저 검수는 미완료이며 앞서 1~4단계 저장 증거로 전체 7단계·실접수 완료를 주장하지 않는다. 임시 검수 탭은 handoff로 표시하고 합성 데이터 전용 localhost 서버를 유지했다.
