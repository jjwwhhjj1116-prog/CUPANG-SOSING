# 수집 원본 썸네일과 견적 이미지 선택 분리

## 변경 이유와 기준

첨부된 Couplus 화면에는 대표 이미지 작업이 대기인 상품도 상품 목록과 옵션 목록에 썸네일이 표시된다. `couplus-new-intake-observation-2026-09-27.md`의 신규 초안 관찰에서도 수집 원본은 존재하지만 견적서의 대표·추가 이미지 값은 비어 있다. YOOFAM PLUS는 원본 보관과 견적 이미지 선택을 분리한 후 이 목록 미리보기가 사라져, 수집 직후 상품을 구분하기 어려웠다.

이번 변경은 목록 미리보기다. Couplus를 새로 조작하거나 원본의 서버 구현을 확인한 결과는 아니다. 기존 작업 상품이나 실계정 Supplier Hub 견적서는 수정하지 않았다.

## 반영한 동작

- 상품 목록은 저장한 대표 이미지를 먼저 표시한다. 선택한 대표 이미지가 없으면 해당 상품의 정확한 수집 작업에 연결된 첫 원본 이미지를 표시한다. 계정 배너나 임의 업로드 파일을 첫 이미지라는 이유로 사용하지 않는다.
- 옵션 목록은 저장한 개별 이미지, 공통 대표 이미지 순서를 유지한다. 둘 다 선택하지 않았으면 원문 SKU의 `imageIndex`와 해당 수집 작업에서 저장한 파일을 연결해 보여준다. 옵션명 번역·수동 수정이나 행 순서를 이미지 매칭 근거로 쓰지 않는다. 원본 미리보기에는 대표 이미지 미설정 상태를 함께 표시한다.
- 대표·추가·상세·라벨 선택값, 옵션의 `imageKey`, 가격, 상태와 견적서 출력은 조회로 변경되지 않는다. 손상된 명시적 옵션 이미지 선택은 원본으로 가려서 정상 처리하지 않는다.
- 목록 응답의 `source_image_key`와 옵션 응답의 `sourceImageKeys`는 읽기 전용 미리보기다. 선택값이나 등록 완료의 근거로 사용하지 않는다. 미리보기 조회 실패 시에도 저장한 상품·옵션·가격·대표 이미지 조회는 계속 사용할 수 있다.
- 상품 목록은 80개씩 조회해 요청당 최대 81개 SQL 바인딩을 사용한다. 옵션 원본 조회는 최대 200개 반환을 허용하며, 상품·회사 소유자·수집 작업·원문 SKU·이미지 번호·파일 네임스페이스와 현재 이미지 목록을 확인한다. 같은 URL의 다른 수집 기록은 대체 자료로 사용하지 않는다.
- 옵션 화면은 상품 ID와 새로고침 차수에 맞는 조회 결과만 보여준다. 조회 중 이전 상품/차수의 옵션·가격·이미지가 남는 것을 방지하고, 비동기 응답에서만 상태를 갱신한다.

DB 마이그레이션이나 확장 변경은 없다. 확장 버전은 0.2.27을 유지한다.

## 검증 범위

기록된 지정 URL `813724060928`의 모바일 원문과 SKU 데이터를 실제 API·SQLite·React 화면 코드에 연결했다. 인증·AI·이미지 바이트는 fixture다. 6개 옵션의 원본 이미지 연결, 초기 견적 이미지 공란, 수동 대표 선택 후 우선 표시/견적 반영, 조회 전후 저장값 불변, 다른 소유자·수집 작업·SKU 변경·삭제된 이미지·손상된 JSON·조회 실패·165개 상품 배치를 검사했다. 상품 목록과 옵션 목록의 React HTML에 실제 API가 반환한 미리보기 이미지가 표시되는 것도 확인했다.

이 시험은 운영 Chrome에서 전체 UI를 육안 대조하거나 실계정 Supplier Hub에 등록한 시험이 아니다. 전체 카테고리의 Couplus 기본값/공식 양식 일치, 운영 AI·이미지 번역·공개 상세 HTML·법적 서류 첨부와 최종 접수 검증은 여전히 남아 있다.
