# 자동 가격 저장과 원래 문서 전체 대조

작업 개시의 가격 단계가 계산값 조회만 하고 검토 기록을 저장하지 않던 문제를 수정했다. 현재 회원 설정의 계산·옵션·견적을 두 번 대조한 뒤 기존 stage-two POST와 독립 GET 검증으로 저장한다. 수동 가격·수량·공란은 보존한다. 전송 전 사전검사 거절은 재시도할 수 있고, 실제 요청 뒤 응답이 불명확하면 원래 요청의 저장본만 조회한다. 포함하지 않은 중국어 옵션 때문에 SEO 완료가 대기로 남던 판단도 포함 옵션 기준으로 고쳤다.

격리 DB 검수에서 새 상품의 회원 설정(환율 320, 공급/쿠팡 마진 45/35, 최소 마진 4,500원, MSRP 1.6, 반올림 100원)에 따라 공급가 5,500원·판매가 8,500원·MSRP 13,600원이 저장되고 실제 목록의 가격 완료 근거로 연결됐다. 운영 기존 상품을 소급 수정하지 않았다.

## 원래 요청의 읽기 전용 대조

원래 상품 `e2f8037c-294e-45a8-b06d-58cc5909683c` / 등록번호 261024001001 / 요청 `f29491bd-1882-456a-8a63-eec8586db6c6` / 문서 2347603을 유지한다.

2.1.64 라이브 조회에서 certificate 첨부 1건, 파일명 계획 이미지 일치·S3 불일치, LABEL 원래 본문 참조 3건, certN- 연결 없음, 법적 본문 불일치를 확인했다. 이 진단은 이미지 바이트 전체와 본문 동등성 검사를 마친 결과가 아니므로 첨부 삭제·접수를 허용하지 않는다.

2.1.65는 별도 `auditUnexpectedLegal` 읽기 action을 추가한다. 원래 전체 packet과 phase-created 예약 탭만 사용하며 원문·회사·중복·전체 이미지 descriptor/바이트·본문·전체 법적 첨부·실제 스키마 인증행을 대조한다. 감사 전후 체크포인트를 비교하고, DOM 바인딩·체크포인트 저장·생성·파일/본문 재전송·삭제·동의·등록전송은 하지 않는다. 보고서는 해시·개수·제한된 항목/값 상태만 반환하고 `canResume:false`, `canDelete:false`를 유지한다. 정상 전송의 기존 비어 있지 않은 서류 목록 차단을 완화하지 않았다.

REA 공식 원문 확인은 `step877-native-single-file-cleanup-contract.md`, `step877-native-certificate-schema-coverage.md`에 기록했다. 실제 삭제 계약은 확인했으나 이번 구현에 삭제 action은 없다. 인증서 바이트 다운로드 경로도 임의로 만들지 않는다.
