# 상품고시·물류 기본설정과 초안 연결 — 547

## 확인 근거와 구현 범위

546에서 인증·쿠키 없는 공개 HTTPS GET으로 확보한 [AIRocketReg 청크](https://couplus.co.kr/js/chunk-e2dd462a.8dc4d2d7.js)의 `applyDefaultSettings` 및 기본 설정 객체를 다시 분석했다. SHA-256은 `38aee73a04100657ed8463a6156cc096ceaf68d4f3d671f34845a9cda515d587`이다. 분석 파일은 `outputs/step546-*`에 있으며 저장소에 포함하지 않는다. 공급자의 코드를 실행하거나 제품에 복사하지 않고 입력·출력 규칙을 독립 구현했다.

공개 코드에서 확인되는 규칙:

- 세탁방법과 취급시 주의사항이 모두 있으면 항목명을 붙이고 쉼표로 합친다. 한 값만 있으면 그 값을 사용하며 둘 다 없으면 기존 고시 초기값을 유지한다. 대상 법적 고시의 이름은 정확히 `세탁방법 및 취급시 주의사항`이다. 숨은 상품 속성 `세탁방법`이나 다른 주의사항 고시와 혼동하지 않는다.
- 제조년월 설정은 입력 문자열의 날짜를 사용하는 대신 켜짐 여부로 동작하며, 법적 고시 `출시년월` 또는 `제조년월`에 전월을 넣는다. 앱에서는 의도를 명확히 하는 `manufactureDatePreviousMonth` 불리언으로 저장한다.
- 유통기간과 취급주의 사유는 기본설정에서 물류 페이지로 전달한다. 공개 신규 설정의 유통기간은 0, 취급주의는 해당사항없음이다. 앱 신규 기본설정에도 반영한다.

카테고리별 비공개 `schemaString`, 전체 분류의 필수 여부·선택지, 공식 제출 양식을 이번에 새로 확보한 것은 아니다. 기록된 28개 양식의 상태를 전체 검증 완료로 바꾸지 않는다. 현재 기록에는 위 이름의 합산 세탁 고시가 없으므로, 세탁·취급 입력은 6단계 편집값/표시사항 문서까지 연결하고 정확한 이름의 법적 고시를 처리하는 연결 규칙을 준비했다. 다른 이름의 고시에 억지로 넣지 않는다. 출시년월 고시와 물류 입력은 기존 기록 양식 및 최종 견적 행에서 검사했다.

## 변경 동작

- 기본설정에 세탁방법·취급시 주의사항, 제조년월 전월 입력, 유통기간, 취급주의 사유 입력을 추가했다. 0일과 미입력을 구별하고 저장 API에서 형식·범위·선택값을 검증한다.
- 수집 요청에 저장한 설정을 상품에 연결한다. 상품을 만든 뒤 다른 기본설정을 저장해도 이 상품의 고시·물류값은 바뀌지 않는다. 새 항목이 없는 이전 수집 컨텍스트는 세탁 공란/전월 꺼짐/물류 미입력으로 해석하여 기존 상품에 신규 설정을 소급 적용하지 않는다. 기존 80719의 관찰된 초안 초기값은 유지한다.
- 세탁·취급 합산값은 6단계의 독립 편집 필드로 보관하며 표시사항 문서에도 반영한다. 6단계 입력과 7단계 직접 수정은 자동값보다 우선한다. 의도적으로 지운 값도 다시 채우지 않는다.
- 출시년월 고시가 기록된 카테고리는 상품추가 시점의 한국 날짜를 기준으로 전월을 초안에 저장한다. 조회/내보내기 시각을 사용하지 않는다. 직접 월 인덱스를 계산하여 31일에 `setMonth`를 호출할 때 발생하는 날짜 넘침을 피한다. 이는 공개 코드의 일자 넘침까지 복제한 것이 아니라 전월 입력 의도를 일관되게 구현한 것이다.
- 출시년월 고시가 없는 카테고리에는 해당 날짜를 추가하지 않는다. 실제 상품정보나 사용자가 수정한 날짜를 덮지 않는다. 생성값을 제조 사실 확인/증빙으로 취급하지 않는다.
- 유통기간과 취급주의는 최종 견적 행/숫자 출력까지 동일한 저장값을 사용한다. 포장 치수와 포장 무게는 상품별 실제 입력으로 남긴다.
