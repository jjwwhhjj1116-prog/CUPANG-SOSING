# Step743 — 완료 상품의 반려 오인과 상태 필터 수정

2026-10-19 KST. 기준 commit `73618194a4dae34f109042f65d18bde2a145e134`. 기존 작업 상품·입력 대기열·견적서·약관을 수정하거나 전송하지 않았다. 현재 Chrome4의 앱에서 읽기 전용으로 확인한 실행 확장은0.2.72다. Step742에서 요청한 업데이트를 중복 요청하지 않고 독립적으로 가능한 구현·검증을 계속했다.

## 재현한 결함

현재 QVT의 `statusFormatter`는 상태 라벨과 별도 **반려내역 버튼**을 같은 셀에 렌더한다. 기존 두 자체 reader는 셀 전체 innerText를 상태로 반환했다. 따라서 정상 완료 행이 `상품 검수 완료 반려내역`이 되어 완료 필터와 일치하지 않았다. 자체 app의 기존 rejection evidence가 `반려|거절|실패`를 검사하므로 이 행은 실제 반려로도 오인될 수 있었다.

현재 공개 QVT JS의 함수 범위·해시, filter enum 및 직접 자식 구조는 [독립 REA 감사](step743-qvt-status-audit.md)에 있다. vendor 함수를 실행하거나 새로운 원문·업무 API를 요청하지 않았다. `rejectRemark=DROP`의 미관측 번역 라벨이나 추가 회신 링크 구조까지 지원한다고 주장하지 않는다.

기준 commit에서 자체 reader를 그대로 불러 동일한 합성 셀에 실행해 raw 상태와 완료 필터 오류를 재현했다. 운영 파일을 교체하지 않았다. `outputs/step743-baseline-and-replay-proof.json`에 before/after를 남겼다.

## 수정 경계

두 serialized reader의 `reviewStatus`는 다음만 읽는다.

- 알려진3개 상태 라벨과 원문에 대응하는 class.
- root DIV·첫 라벨 DIV의 정확한 직접 자식 구조.
- 관측된 class를 가진 반려내역 BUTTON 한 개, 표시 여부와 전체 셀 문자 일치.
- 텍스트만 있는 표의 알려진3개 상태.

버튼이나 링크를 누르지 않는다. 알 수 없는 라벨·모순 class·추가 상태·회신 링크·중복/변조 버튼은 오류로 중단한다. 임의의 문자열에서 `반려`라는 글자를 지우지 않는다. 기존 저장 기록을 재작성하지 않았고 app의 실제 반려 판정 정규식도 완화하지 않았다. UUID·estimationId 구분, 페이지 순서·회사·검색조건·표 갱신 보호는 그대로 남는다.

새 시험13개는 두 회사의4가지 관측 상태와 선택 필터, 실제 자체 page aggregator·validator·receipt evidence·표시 요약 연결을 실행한다. 완료+반려내역은 `rejected:false`이고, 고유 SKU 증거가 있는 합성 결과는 `SKU ID 확인`으로 표시된다. 상품 검수 완료나 실제 신규 접수 성공으로 승격하지 않는다. 실제 반려 상태와 단계 본문의 반려 사유는 여전히 `rejected:true`·`상품 반려`다. 미지원/변조 DOM과 다른 필터도 거절한다.
