# Step975 — 저장된 견적서의 작성 완료 상태

COUPLUS 보관 코드의 `savePendingChanges`는 저장 당시 전체 옵션 양식을 검증하고 옵션별/global quotationStatus를 갱신한다. YOOFAM은 현재 수동 입력 저장과 목록의 견적서 단계 증거가 연결되지 않아, 정상 입력을 저장해도 견적서가 대기로 남는다. 기존 인수인계·단계 순서·원본 대표이미지 정책과 재전송 금지는 유지한다.

## 동작

- 실제 필드 PUT 저장이 성공한 뒤 현재 공식 양식을 다시 해석해 필수값·형식·가격·포장 등의 기존 검증 결과를 보관한다. 저장됐다는 사실이나 필드 수만으로 완료로 표시하지 않는다.
- 포함 옵션의 검사 결과가 모두 유효하면 상품의 견적서 작성 단계를 완료로 표시한다. 옵션 목록은 각 옵션의 결과를 표시한다. 제외된 옵션의 오류는 포함 옵션 완료를 막지 않는다. 공통 입력 행은 실제 옵션이 있으면 별도 판매 옵션으로 집계하지 않는다.
- 검토 문구와 출처를 그대로 유지한다. 작성 검사 완료는 전송 준비 또는 Hub 접수 완료가 아니다. `submissionReady`/`registered`는 false다.
- 검사 결과를 회원·회사, 상품 원본, 콘텐츠, 전체 옵션·포함 여부, 견적 수정본, 현재 설정, 정확한 카테고리·양식·수집 문맥, 상세 공개 버전에 묶는다. 어느 하나가 바뀌면 이전 완료를 사용하지 않는다.
- 검사 메타데이터는 기존 견적 JSON에 CAS로 보관한다. 견적 revision·상품 clock·입력값·옵션·이미지·실제 전송 본문은 이 메타데이터 보관 때문에 변경하지 않는다. 새 DB 테이블이나 마이그레이션은 만들지 않는다.
- 기존 저장본은 명시적인 ‘저장본 입력 검사’로 다시 확인할 수 있다. 이 요청은 입력 변경·내보내기·업로드·동의·Hub 전송을 실행하지 않는다. 응답 유실/원본 변경은 완료를 추측하지 않는다.
- 상품 목록은 이미 사용하는 소유자별 배치 조회에 필요한 설정·선택 양식 메타데이터를 함께 읽어 증거를 검증한다. 상품마다 전체 견적 API나 R2 파일을 다시 읽지 않는다.
- 원본 결합값에는 검사 결과의 옵션·포함 여부·오류 수·양식 상태·입력 fingerprint도 함께 포함한다. 저장된 오류 수만 바꿔 완료로 만드는 자료는 전체 GET과 배치 목록에서 모두 거절한다.
- 검사 메타데이터는 자동화 및 견적 내보내기 fingerprint의 입력에서 제외하고 saved-scopes 다운로드에도 섞지 않는다. 원문 견적 JSON은 기존 법적 자료 저장의 payload CAS를 위해 그대로 유지한다. 재검사는 검토한 native source identity·본문·이미지 계획을 바꾸지 않는다.

## 검증 경계

양사 합성 SQLite/API와 실제 React 입력기·상품/옵션 목록으로 저장→완료/미완료→재열기, 원본/설정/회사/양식 변경 무효화, 명시적인 재검사, CAS 경합·응답 유실을 검증한다. 기존 상품·완료 문서는 재전송하지 않는다. 실제 신규 상품의 최종 Hub 접수와 모든 COUPLUS 화면 상태의 동일성은 별도 미검증이다.

최종 영향 검사548개 중538개 통과,10개 실패는 수정 전 HEAD의 동일 세 파일에서 모두 재현했다. 이를 통과나 수정 완료로 집계하지 않는다. 새 UI7개에는 서버 저장 뒤 응답 유실·진행 중 unmount와 실패 입력 저장 보존이 포함된다. 실제 브라우저는 정상 저장,503 초안 보존,설정 변경 무효화,metadata-only 재검사,옵션1 완료/옵션2 대기,재열기를 확인했다. 실제 Hub 요청·확장 명령·이미지 객체 변경은0이다. 독립 리뷰의 결과 무결성 및 export/native fingerprint 두 결함은 RED→GREEN으로 수정했다.
