# 공식 미리보기의 저장 부작용과 후속 확인

## 발생한 동작

원래 886 상품 / Supplier Hub 문서 2347603 검수 중, agent가 공식 StartPage의 ‘미리보기’를 읽기 전용이라고 잘못 판단해 클릭했다. 클릭 전 해당 탭에는 원래 상품명, 카테고리 68183, 마지막 저장 2026.10.29 13:15가 표시되어 있었다. 버튼 클릭 후 공식 상품 미리보기가 열렸고 대표·추가·상세 이미지가 실제로 로드됐다.

이후 정확한 공식 출하 코드를 확인해, **기존 양수 docId에서는 미리보기 버튼도 `saveDraft()`를 호출한다**는 사실을 발견했다. 이는 사용자의 원래 문서 파일·본문 재전송 금지 조건과 충돌하는 시도다. 사용자에게 잘못 판단해 클릭했음을 즉시 알리고 사과했으며, 더 이상의 저장·제출·미리보기 조작은 중단했다. 되돌리기를 명목으로 본문을 다시 쓰지도 않았다.

## 확인된 계약

공식 원문 `outputs/step755-current-sr-main.js` SHA-256은 `6fc9c0fae51702e62e2d1376ac8854d0d97c0035b0bf96afeb42069c2a5abe11`이다. 아래 범위는 0부터 시작하는 반개방 UTF-16 offset이다.

- `Cd [2886828,2887365)`의 onClick은 `preventDefault`, `docId > -1 && saveDraft()`, modal 열기, telemetry 순서다. 저장 응답을 기다리지 않고 modal을 연다. 함수 raw UTF-8 SHA-256은 `6f4237150b1686fa5bae6df486c00a9659b015aade2dc17718138c5f7d5504d0`이다.
- 공통 footer `hb`는 3025769 위치에서 `Cd`를 렌더링하므로 이 동작은 StartPage에도 해당한다.
- `saveDraft [2868857,2870255)`는 양수 docId의 전체 현재 form을 `/draft/api/update`로 보낸다. 이 미리보기 경로에는 파일 업로드·삭제 대기열 `upAndDelFilesById` 호출은 없다.
- 저장 성공 handler는 서버 응답 전체로 현재 draft를 교체하고 form을 복원한다. footer는 그 `draft.modifiedAt`을 분 단위로 표시한다. 요청 전에 로컬 시간을 넣거나 server-now/getById를 부르는 handler가 아니다.

정적 코드로 저장 경로를 확인했지만, 이번 실제 HTTP 요청·응답 본문은 캡처되지 않았다. 따라서 어떤 필드가 실제로 변경됐는지는 아직 확정하지 못했다.

## 실제 화면 관측

- 공식 미리보기: 상품명 ‘유앤채 4D 날개형 스펀지 뒤꿈치 보호 패드’, 카테고리 68183, 판매가 6,220원, 권장소비자가 8,090원, 선택 옵션 베이지/해당사항없음/1쌍을 관찰했다. 표시된 이미지 10개는 naturalWidth/Height가 모두 양수였다. 이 수에는 장식 이미지도 포함되므로 ‘첨부 10개’로 해석하지 않는다.
- 화면 하단 표에는 인증/허가 해당사항없음, 제조국 중국, 제조자/수입자 문구 등이 표시됐다. 이것은 미리보기의 선택 옵션 표시이며 전체 문서/법적 첨부/바이트 대조 결과가 아니다.
- 이후 footer에는 2026.10.31 01:01이 표시됐다. 이 시각만으로 이번 저장 시도 결과를 판단하지 않았다.
- 소스에서 읽기 전용임을 확인한 **별도 빈 StartPage 탭의 ‘중간 저장 불러오기’ 목록 열기**만 수행해 서버 목록을 읽었다. 행의 불러오기/삭제/미리보기는 누르지 않았다.
- 동일 상품명·카테고리 행은 한 건이었고, 그 수정 시각은 **2026.10.31 03:24**였다. 이번 미리보기 클릭 시간대에 해당하므로 본문 재저장이 실행된 것으로 보인다고 사용자에게 알렸다. 다만 이 UI는 docId와 초/시간대를 표시하지 않으므로 원래 문서의 전체 본문과 원인·결과를 암호학적으로 확정한 증거로 취급하지 않는다.
- 목록 열기 `$4 [4150702,4153320)`는 modal 표시와 `getDrafts` GET만 수행한다. `getDrafts [2867890,2868034)`는 기존 GET `/draft/api/drafts`를 호출하고 목록만 갱신한다. header `[4159515,4160125)`에 폼 밖으로 배치된다. 목록 함수 SHA-256은 `86a8a08d958d34462018f9a8a5ebb98dd23a28b36f30cb445c160211e2ac841b`다.
- console 오류 metadata를 읽었으나 해당 저장의 성공·실패를 입증하는 항목은 없었다. 이를 성공이나 실패의 증거로 쓰지 않는다.

증빙은 `outputs/step881-official-preview.png`, `outputs/step881-official-preview-row-observation.json`에 보관했다. 첫 미리보기는 작은 영역 screenshot이 성공했지만, 별도 목록 탭 screenshot은 CDP timeout으로 실패했다. 네이티브 우회는 시도하지 않았다.

## 보존·중단·다음 작업

이번 턴은 새 문서 생성, 파일 업로드/삭제, 단계 검증, 약관 동의, 최종 제출을 실행하지 않았다. 하지만 미리보기의 **본문 저장 시도**가 있었으므로 ‘기존 Hub 본문을 건드리지 않았다’고 보고해서는 안 된다. 원래 DB 자료가 그대로라는 사실도 원격 Hub 본문 불변의 증거가 아니다.

현재 Chrome 실행 응답은 2.1.64이며 실제 설치 폴더는 이미 2.1.67이다. 사용자에게 이번 시도의 영향을 읽기 전용으로 대조하기 위해 기존 확장을 새로고침해 달라고 요청했다. 아직 답변은 없다. 2.1.67을 확인한 뒤 원래 요청 `f29491bd-1882-456a-8a63-eec8586db6c6` / 문서 2347603의 전체 audit를 실행해야 한다. 수정 범위가 확인되기 전에는 저장·복구·되돌리기 요청을 보내지 않는다.

**공식 Next/Submit뿐 아니라 ‘미리보기’도 재전송 금지 검수에서 누르지 않는다.** 현재 원래 탭 727940002는 이미 열린 미리보기 상태로 보존하고, 추가 읽기 목록 탭 legal881(727940052)을 handoff했다. 자동 접수/완료나 원래 본문 무변경을 주장하지 않는다.
