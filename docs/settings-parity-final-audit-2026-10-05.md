## 이미지 기본값 불일치 수정

설정을 한 번도 저장하지 않은 계정은 화면에서 새 기본값 `removeBackground:false`를 보지만 이미지 API는 레거시 `true`를 사용했다. 실제 API 회귀의 null/undefined 두 경우가 수정 전 실패했다.

이미지 조회·검토 요청은 설정 행이 없을 때 화면과 같은 새 기본값을 사용한다. 저장된 빈 객체 또는 부분 레거시 payload는 기존 누락 필드 규칙을 유지한다. 이미지 작업 생성·승인·실행 claim의 원자적 SQL 조건도 행 없음과 저장된 레거시 행을 구분한다. 검토 도중 최초 설정이 저장되면 실제 설정 지문이 같을 때만 진행한다. 다른 설정이면 provider 호출 전에 409로 거절한다. 이미 완료한 이미지·상품·수동 문구를 수정하지 않는다.

실제 API와 임시 SQLite로 미저장/레거시/명시적 false·true 경계, 검토·실행 중 최초 설정 저장을 검사했다. 별도 읽기 전용 검토에서는 두 회사×네 설정 형태의 실제 설정 API→수집 접수→임시 상품 변환→견적 필드 연결도 확인했다. 운영 데이터나 외부 AI 공급자를 호출한 검사는 아니다.
