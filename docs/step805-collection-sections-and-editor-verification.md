- 사용자 완료 문구는 수집기 2.1.24 / 서버 수집본 3 / 2026-10-23 11:40:19 KST / 제품속성 0 / 포장정보 0/3 / 상세이미지 0이었다. 현재 앱에서 실제 실행 2.1.24를 확인했으며, 활성 수집함에는 같은 상품 886034098637의 수집본 5(11:41:36)와 4(11:41:29)가 있었다. 두 수집본도 3옵션, 각 0.28위안이며 속성·포장·상세사진은 없었다. 수집본 3을 복원하거나 다른 수집본을 삭제하지 않았다.

- 새 상품 SEO는 자동 번역 결과가 적절하지 않아 수동으로 `유앤채 4D 날개형 스펀지 뒤꿈치 보호 패드`, 관련 태그, 베이지/핑크/블랙 옵션명을 저장했다. 계정 가격 정책으로 공급가 3,420원 / 판매가 6,220원이 세 옵션에 자동 적용된 것을 확인했다. 자동 SEO 품질 성공으로 세지 않는다.
- 대표이미지 편집의 일반 진입이 상세이미지를 고르는 오류와, 새 상품에 진입할 때 변경되지 않은 초안에도 상품 변경 경고가 뜨는 오류를 재현했다. 새 상품에서 원본 문구 읽기를 1회 실행했으나 OCR 품질이 낮아 번역·이미지 적용은 0회다. 임시 OCR 편집 초안만 지우고 원본 이미지는 보존했다. 상세사진 0장인 사실은 그대로 표시했다.
- 새 상품 표시사항을 내용량 1쌍 / 재질 스펀지 / 상품유형 신발 뒤꿈치 보호 패드로 검토해 공통 및 세 옵션에 저장했다. PNG 연결 과정에서 조회 응답이 HTML 503으로 실패했으며, 동일 저장 요청을 무작정 재전송하지 않고 읽기 복구를 한 번 시도했다. 운영 로그의 `GET /api/products/[product]/product-labels`에서 `exceededCpu`, status 503, CPU 11ms를 확인했다. 이 시점의 내용 저장과 PNG 연결 완료는 구분한다.
- Supplier Hub에서 로그인 회사 유앤채 / A01526306을 확인했다. 실제 신규 접수는 아직 0회다.

## 구현

- 2.1.25: 제품속성·포장정보의 알려진 중국어/한국어 탭을 고유 ID와 ARIA 연결로 실제 본문에 연결한다. 넓은 shop-page-layout을 가게 카드로 오인하지 않으며 다른 상품·추천·리뷰·탐색 영역의 행과 셀은 제외한다. 정상 preview 이름은 보존한다.
- 보관된 RS 확장 분석에서 확인한 별도 상세문서 조회를 사용자 수집 클릭 안에 연결했다. 현재 상품의 정적 구조화 원문에 직접 연결된 detailUrl만 허용하며, 기존 host 권한 안에서 한 번 조회한다. 자격정보 없이 리디렉션·크기·시간·MIME·원문/상품/탭 수명 검사를 적용한다. 실패하면 DOM 수집값만 보존하며 상세사진을 만들어내지 않는다. 실제 1688 또는 상세문서 조회는 도구로 실행하지 않았다.
- 편집 3/4/5단계의 일반 진입을 각각 대표/추가/상세 역할로 연결한다. 기존 개별 카드 진입과 수정 중인 초안의 충돌 방지는 유지한다.
- 견적서 상단에서 실제 필수 공란과 입력 오류를 긴 검토·참고 안내와 분리한다. 저장 검증·전송 가드와 기본값은 변경하지 않는다.
- 표시사항 조회는 인증·회사·카테고리·안정화 resolver의 같은 순서와 최종 source guard를 유지한 공유 읽기 함수를 사용한다. 내부 견적 응답의 JSON 직렬화/재파싱 1쌍만 제거했다. 합성 3옵션 fixture의 내부 JSON은 125,513바이트이며, 결과 view·DB와 SQL 38회·R2 조회 0회는 동일했다. 로컬 CPU 측정은 GC/Windows 계단 오차가 있어 운영 제한 해결 증거로 사용하지 않는다.

## 검사 및 배포 준비

- 수집기·역할 진입·견적 안내 관련 17개 고유 파일을 한 번에 실행해 328/328 통과했다. 라벨 공유 읽기·저장·PNG·견적 연결·ACK 복구 관련 6개 파일은 46/46 통과했다. 독립 검토에서 남은 P1/P2는 없었다. 각 집중 검사 숫자를 중복 합산하지 않는다.
- TypeScript, 변경 파일 ESLint, diff 공백 검사, 운영 빌드를 통과했다. 두 초기 통합 fixture 실패와 최종 수정 결과는 별도 보관했다.
- 2.1.25 ZIP은 95개 파일 / 1,203,542바이트 / SHA-256 `b7b19b7a76cbd97a5954b1bb15f313350fd5be205e431ee5db4d5502a757484a`이며 생성 수집기·ZIP 일치 검사를 통과했다.
- Chrome 실제 로드 폴더를 `outputs/step805-loaded-extension-backup`으로 먼저 백업하고 95개 파일을 복사한 뒤 전체 SHA를 대조했다. 권한·host 권한 변경과 파일 삭제는 0이다. 준비 버전 2.1.25와 실제 실행 관찰 2.1.24는 구분한다.
- Worker `721e7fe4-ad29-474a-8632-bd86aed2c517` 배포 후 현재 탭의 같은 `전체 옵션 저장 결과 확인·계속`을 한 번 실행했다. 공통 및 세 옵션에 같은 PNG 한 장의 저장·견적 연결 완료를 UI에서 확인했다. 실제 label GET과 quotation GET은 200이었다. 운영 CPU 수치는 로컬 벤치와 직접 비교하지 않으며 단순한 비용 감소율로 보고하지 않는다. 완료 증거는 `outputs/step805-label-recovered.png`와 AX 보관본이다.
- 저장 완료 후 앱을 새로고침해 새 화면에서 견적 첫 옵션을 열었다. 기존 85개 참고 안내와 별도로 실제 필수 공란 3개(이미지 ALT, 단품 포장 크기, 단품 포장 무게), 입력 오류 0개를 표시했다. 3옵션의 노출 색상이 모두 해당사항없음으로 남은 것도 확인해 별도 검토 대상으로 유지했다.
- 사용자 스크린샷에 명시된 10g과 상품 이미지 설명을 세 옵션에 저장했다. 저장 응답이 비JSON 503으로 실패했지만, `입력 버리고 저장본 불러오기` GET으로 두 값이 이미 저장됐음을 확인했다. 재PUT은 하지 않았다. 이 실제 ACK 불명확 사례를 재현하는 테스트와 함께 GET/PUT 비JSON 오류 안내만 보완했다. AI 도구에서 본 ‘입력 내용을 저장하고 최신 견적을…’ 문구는 형제 라벨 도구의 busy 안내이며 AI 사전 차단 증거가 아닌 것도 소스에서 확인했다. 기존 AI 작업 GET에는 저장된 결과가 없었고 추가 AI 처리 요청은 하지 않았다.
- 실제 화면에서 대표·추가·상세 일반 편집 진입이 각각 MAIN/ADDITIONAL/DETAIL로 열리고, 잘못된 상품 변경 경고가 없는 것을 확인했다. 원본 선택과 이미지 적용은 하지 않았다. 대표 진입 증거는 `outputs/step805-main-entry.png`다.
- 포장 크기 AI를 한 번 실행해 세 옵션 모두 200×300×100mm를 제안하는 것을 확인했다. 모델 입력에 근거 없는 1kg 및 200×300×100mm 문맥이 고정돼 있어 이를 제거하고, 현재 견적에서 검증된 10g을 수집값과 구분한 reviewed context로 전달하도록 수정했다. 고정 수치 예시도 제거했다. 수동 공란·오래된 수량·근거 없는 값 보호와 기존 fallback/저장/전송 가드는 유지한다.
- 최종 Worker `6349dbd3-afe2-4ce4-81ad-548cef15a3f4` 배포 후 같은 새 상품의 size-only 추정을 1회 더 실행했으나 세 옵션이 10×10×10mm로 제안돼 적용하지 않았다. 첫 고정값 입력 결함의 제거와 실제 추정 품질을 구분한다. 포장 크기 자동 품질 완료로 보고하지 않는다. 10g은 계속 보존됐다.
- 포장 관련 4개 파일 40/40, 견적 편집 최종 108/108(앞선 106개에 신규 2개 추가), 타입·린트·빌드·독립 검토를 통과했다. 고유 파일 기준 27개 / 최신 결과 416개이며 중복 집중 실행은 합산하지 않는다. 라벨 검증 요약은 원본 stdout이 아닌 완료된 도구 실행 요약임을 별도로 표시했다.
- 운영 로그에서 source-inbox, quotation-ai, native-assets에도 간헐적 `exceededCpu`가 발생했다. 일부 재조회는 200이므로 전부 고쳐졌다고 판단하지 않는다. 계정 구독 이름의 읽기 전용 API는 403으로 조회할 수 없어 요금제는 미확인이다. 요금제·CPU 한도·인증·권한은 변경하지 않았다. Cloudflare의 [실행 제한 설명](https://developers.cloudflare.com/workers/platform/limits/#cpu-time)은 일시적으로 한도를 넘는 실행이 허용되다가 반복하면 중단될 수 있다고 설명한다.
- 2.1.25 배포 및 실제 로드 폴더 동기화 후 사용자에게 확장 새로고침→상품 탭 F5→1회 수집만 요청했다. 새 실행과 원문 개수 결과는 아직 대기다. 실제 Hub 신규 접수는 계속 0회다.

## 제한 및 다음 확인

- 모형 검사는 실제 1688 DOM 호환성 증거가 아니다. 2.1.25 적용 뒤 새 수집본에서 제품속성, 옵션별 10g, 상세사진을 다시 확인해야 한다.
- 포장 크기를 공급자 실측인 것처럼 임의 입력하지 않았다. 원문과 사용자 스크린샷의 확인값, 자동 초안은 출처를 구분한다.
- 이전 브라우저의 1688 도구 거절을 다른 도구·CLI·서버로 우회하지 않았다. CLI 연결 범위나 권한도 확대하지 않았다.
- 일반 실제 전송 검증 gate를 통과시켰다고 보고하지 않는다. 이번 변경은 전체 Couplus UI 동등성·CLI 전체 복제·실제 Hub 접수 완료를 뜻하지 않는다.
