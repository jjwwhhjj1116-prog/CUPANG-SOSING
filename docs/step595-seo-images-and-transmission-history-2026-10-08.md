# 상품 편집과 전송 이력 연결 검수

카테고리·1688 수집 자료로 만든 초안을 사용자가 수정한 뒤, 최종 견적서가 그 수정값을 사용하도록 보완했다. 기존 쿠플러스와 Supplier Hub 작업 상품은 조회만 했다.

## 이번 변경

- SEO 무료 재번역은 현재 수집 자료의 제목·설명으로 별도 작업을 만든다. 옵션 번역 작업과 섞이지 않으며, 사용자가 선택해 적용한 필드만 바꾼다. 요청 응답이 유실되면 같은 작업을 조회하고 중복 실행하지 않는다.
- 3단계는 원본 옵션 사진과 구분해 최종 견적 대표이미지를 편집한다. 선택 SKU의 정규 필드와 실제 양식 필드를 한 번에 저장한다. 공란과 복원도 유지하며 원본 사진·가격·다른 SKU는 보존한다.
- 6단계에서 최종 견적의 표시사항 이미지 참조를 확인하고 제외할 수 있다. 제외는 파일 삭제가 아니다. 등록표의 표시사항 이미지 수도 최종 견적 참조를 사용한다.
- 같은 상품의 모든 전송 이력을 서버와 확장에서 확인한다. 초안을 수정해 식별값이 달라져도 이전 접수가 진행 중이면 새 업로드를 막는다. 확인할 수 없는 이력을 빈 이력으로 취급하지 않는다.
- 수정 전 접수 결과는 원래 회사·카테고리·파일·접수 식별값으로 조회하고 기록만 갱신한다. 현재 상품 초안과 이미지 파일은 바꾸지 않는다. 실제 발급된 견적·SKU 식별값은 보존하고, 발급 전 `-` 같은 표시값은 실제 SKU로 진행할 수 있다.
- 단일 접수 조회에서도 SQL 키와 payload 식별값의 일치를 확인한다. 불일치 자료로 다른 접수를 갱신할 수 없다.
- 확장 0.2.57은 전체 전송 이력과 과거 접수 조회 기능을 제공한다. 설치된 확장이 새 기능을 제공하는지 확인한 뒤 새 업로드를 허용한다.

## 실제 화면에서 확인한 범위

와이홉 쿠플러스 기본설정과 앱의 적용값에서 환율 350, 공급/쿠팡 마진율 50/40, 최소 공급 마진 3,000원, 박스 SKU 50, MSRP 1.3을 대조했다. 기존 장갑 상품의 SKU 팝업과 1–7단계 화면, 이미지 번역·표시사항·견적 양식을 읽었다. 기존 상품의 저장·삭제·AI 실행·전송은 하지 않았다. 화면 증거는 비공개 `outputs`에 보관한다.

2026-10-08에는 기존 와이홉 Chrome에서 Supplier Hub 회사명 와이홉, 회사코드 A01464742를 확인했다. 이 확인은 신규 견적 등록 성공을 의미하지 않는다.

## 검증과 남은 범위

무료 번역·응답 유실·선택 적용, 최종 이미지·표시사항·원본 파일 보존, 두 회사의 이력 격리·등록 결과 CAS·중복 업로드 방지, 공식 양식·카테고리·수집 통합 검사를 순차 실행했고 모두 통과했다. 범위가 일부 중복되는 6묶음의 검사 수는 각각 157, 36, 25, 114, 159, 50건이다. 타입 오류는 없고 린트는 오류 0, 기존 경고 9건이다. 배포 파일 검사 결과는 비공개 릴리스 기록에 남긴다.

모든 카테고리의 실제 양식 대조와 최종 Supplier Hub 등록 완료 증거는 아직 전체 확인되지 않았다. SKU별 4·5단계에서 최종 견적 이미지에 직접 번역을 적용하는 동작은 별도 보완 대상이다. 테스트에서 성공한 흐름을 실제 신규 접수 완료로 표시하지 않는다.
