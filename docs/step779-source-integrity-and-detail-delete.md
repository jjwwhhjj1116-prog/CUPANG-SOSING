# Step779 — 수집 원문의 전송 한도·옵션 사진 연결과 상세 삭제 확인

기존 업무 상품을 열어 수정하거나 검수 상품으로 재사용하지 않는다. RS 방식의 새 수집본이 앱 목록과 편집 초안으로 이어지는 경로에서 확인된 결함만 수정한다. 실제 1688 접근·Supplier Hub 접수와 합성 검수는 구분한다.

## 새 수집본의 완전성

이전 수집 검사는 JSON 문자열 길이를 사용했지만 서버는 UTF-8 바이트를 제한했다. 중국어 200개 옵션의 합성 원문은 201,226자 검사에 통과하고도 실제 수집함 API에서 540,260바이트 요청으로 413을 반환했다. 새 추출·보관·전달·검토 저장은 서버와 같은 524,288바이트 원문 한도를 사용한다. 중국어·이모지 경계를 포함해 정확한 한도는 허용하고 1바이트 초과는 저장 전에 알린다.

200장 제한에서 상세 사진을 먼저 채우면 이후 SKU 사진이 누락되는 문제도 확인했다. 제한을 넘는 새 추출은 일부 성공으로 반환하지 않는다. 관찰된 옵션 사진 URL이 이미지 목록에 없는 새 전달도 거절한다. 일반 13개 SKU와 제한 안의 이미지 연결은 유지한다.

기존 보관본의 디코딩·조회는 변경하지 않는다. 과거 누락 원문도 원본 바이트 그대로 조회할 수 있다. 다만 조회 시 계산하는 `옵션 이미지 원본 연결` 문제를 표시해 새 초안 작성 경로가 불완전한 원문을 준비 완료로 취급하지 않게 한다. 데이터 재작성·기존 상품 재수집은 하지 않는다.

## 상세 사진 삭제

보관한 Couplus 코드의 상세 이미지 삭제 버튼과 hover + Delete는 확인창을 경유한다. REA 근거는 `outputs/step779-rea-detail-audit.json`의 원본 SHA와 UTF-16 범위에 보관했다.

YOOFAM도 선택 옵션의 개별 상세 사진 삭제 버튼과 Delete 키가 같은 확인을 사용한다. 취소하면 순서·선택·HTML·미저장 입력·저장값을 바꾸지 않는다. 확인창이 열린 동안 옵션·단계·원본 버전이 바뀌거나 새 입력이 생겼으면 이전 삭제를 적용하지 않는다. 확인 후에는 기존의 명시적 저장을 사용한다.

현재 견적 이미지 입력에는 원본과 편집 결과의 신뢰할 수 있는 분류가 전달되지 않는다. 파일명으로 추정하지 않고 일반 문구 `이 이미지를 삭제하시겠습니까?`를 사용한다. Couplus의 원본 전용 문구까지 완전히 같다고 주장하지 않는다.

## 설치·운영 확인

같은 기존 Chrome에서 앱 로그인과 유앤채 회사코드 `A01526306`의 기본설정을 읽기 확인했다. 설정 저장과 업무 상품 행 열기는 하지 않았다. 이전 Cloudflare 앱 로그인 대기는 해소됐다.

실제 설치된 확장은 `2.1.4`였다. 이전 업데이트 안내는 이 버전을 최신 수정이 필요한 대상으로 표시하지 않았다. 앱은 실행 중인 버전을 그대로 표시하고 새 `2.1.18` 다운로드를 제공한다. 확장 관리 화면의 사용자 적용 요청은 별도로 전달했다. 패키지 생성만으로 설치 완료를 보고하지 않는다.

배포 뒤 같은 로그인 탭을 다시 열어 `설치된 버전 2.1.4`와 실제 `확장 2.1.18 다운로드` 링크가 함께 표시되는 것을 확인했다. `outputs/step779-ui/deployed-extension-update.png`와 `step779-deployed-update-dom.txt`에 보관했다. 상품 행과 설정값은 변경하지 않았다.

## 검증과 남은 범위

최종 검사 명단·개수·파일 해시·배포·푸시는 `outputs/step779-final-validation.json`에 기록한다. 로컬 API·SQLite·실제 컴포넌트의 검수는 합성 상품·사진·회원 연결을 사용하며 실접수 증거가 아니다.

실제 Chrome의 격리 상세 편집에서 두 장과 삭제 확인창을 관찰했다. 취소 처리 후 브라우저 도구가 해당 검수 탭의 초점 명령에서 지연돼 후속 화면 검수는 완료하지 못했다. 별도 로컬 서버 읽기에서는 저장값·보호 합성 상품·요청 수가 그대로였다. 이 읽기만으로 화면 취소 동작까지 성공했다고 간주하지 않는다. 취소·확인·화면 변경 보호는 별도의 컴포넌트 회귀 검사로 확인했다. 운영 앱 탭은 정상 접근됐으며 검수 서버는 정리했다.

이전 자동 승인 검토가 거절한 1688 경로는 재접근하거나 다른 도구로 우회하지 않았다. 실제 새 수집·모든 카테고리와 1~7 UI의 완전한 동등성·새 Hub 문서의 실제 업로드 및 약관 확인·최종 문서/QVT/SKU 접수는 여전히 실증 전이다. 일반 전송의 두 live gate는 false로 유지하며 합성 검사를 실제 접수 완료로 보고하지 않는다.
