## 원본 근거

## 구현

선택 옵션의 Stage3 업로드는 단일 파일을 즉시 업로드한 뒤 `image-upload-link`의 기존 source-sealed D1 transaction으로 이미지 보관함과 정확한 최종 mainImage/wire를 함께 저장한다. 다른 옵션·공통 이미지 역할·원본 옵션·내용은 보존한다. main의 null 공통 대상은 UI·basis·API에서 거절한다. 옵션을 선택하지 않은 공통 보관함 업로드는 기존 동작을 유지한다.

파일 응답이 불확실하면 자동 재업로드하지 않는다. 연결 ACK 유실은 GET으로 확인하며, 미연결이 확인된 파일만 같은 키로 명시 재연결한다. R2 파일 저장과 D1 연결 전체가 원자 작업이라는 주장은 하지 않는다. 실패한 파일은 보관한다.

후보 탭은 메인이 비어 있어도 메인으로 시작한다. 옵션 전환/왕복은 이전 방문의 탭 callback을 폐기하며 현재 최종 선택과 초안은 보존한다. 출처 분류를 확인하지 못할 때의 전체 저장 이미지 fallback은 유지한다.

Stage6는 항목명·한 줄 값·삭제를 기본으로 노출하고 이동/비우기/복원 도구를 접는다. 저장된 CR/LF는 textarea로 유지하며 편집 도중 마지막 줄바꿈을 지워도 갑자기 input으로 바뀌지 않는다. 명시적 여러 줄 전환과 필수 제품명 삭제 보호를 유지한다. 기존 정보 저장→PNG→견적 연결·실패 복구 계약은 변경하지 않는다.

브라우저 검수에서 접힌 이전 공통 표시사항 편집기의 자동 채움이 미저장 초안을 만들어 7단계 이동을 막는 문제를 발견했다. Dashboard에서는 `autoFillLabel=false`를 전달해 이 자동 채움만 중단한다. 기존 독립 편집기의 기본 동작, 명시적 채우기, 실제 사용자 초안 보호는 유지한다. 늦은 자동 응답도 활성화 epoch로 차단한다.
