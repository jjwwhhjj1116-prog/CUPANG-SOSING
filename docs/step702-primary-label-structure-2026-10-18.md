# Step702 — 6단계 제품 표시사항의 공통 항목 구조 편집

2026-10-18 KST. 기준 `f519254bf4cc9ae7545597840105c96413bcf7b6`. 쿠플러스의 표시사항 항목명 변경·추가·삭제·순서 저장을 주 제품 표시사항 편집기에 연결했다. 기존 작업 상품을 열거나 수정하지 않았다.

## 원본 대조와 구현 범위

보관 원본은 항목 배열의 순서대로 `{id,label,required}`를 상품 공통 `koreanLabelStructure`에 저장한다. 각 옵션에는 같은 ID에 대응하는 내용값·이미지·상태를 따로 저장한다. 필수 제품명은 삭제할 수 없고, 다른 항목은 삭제·추가·명칭 수정이 가능하다. 원본의 정확한 위치·SHA와 Evidence는 `docs/step702-image-label-parity-audit.md`에 기록했다. 새 vendor 실행·현재 서버 저장 관찰은 하지 않았다.

기존 YOOFAM의 주 `ProductLabelEditor`와 `productLabelPlan`은 9개 항목에 고정돼 있었다. 별도 접힌 이전 공통자료 편집기는 추가 항목·20개 필드 조판을 지원했으나 주 제품 라벨과는 다른 저장·생성 경로였다. 이 이전 자료를 자동 이관하거나 주 라벨을 덮어쓰지 않고, 주 라벨에 명시적으로 저장하는 공통 구조를 추가했다.

원본의 보관 PNG 렌더러는 변경한 항목명 대신 고정 이름표 또는 raw custom ID를 사용한다. 자체 라벨은 **저장한 항목명·순서와 실제 옵션값을 일치시켜 렌더링**한다. 구조 편집·저장·재진입은 원본 근거에 따른 것이며, 변경한 항목명의 PNG 반영은 이 불일치를 해소한 자체 재구성이다. 원본의 모든 픽셀과 동작이 같다고 주장하지 않는다.

## 저장·편집·PNG 연결

- 주 편집기에서 항목명 수정, 위·아래 이동, 비필수 항목 삭제, 새 항목 추가, 기본9개 구조 복원을 지원한다. 이름·순서·추가·삭제는 모든 옵션에 공통이며 내용값은 현재 공통 또는 선택 옵션에만 저장된다. 필수 제품명은 항상 남는다.
- 기존 `product_labels` JSON의 선택적 `structure`에 저장하므로 새 테이블·migration은 없다. 구조가 없는 기존 자료는 기본9개·기존 PNG plan을 유지한다. 1~39개 항목, 항목명80자, 기존 내용2,000자·전체 저장512KB 한도를 적용한다. 이 한도를 원본에서 관찰한 것처럼 표현하지 않는다.
- 삭제한 항목의 기존 공통·옵션 값은 보관한다. 같은 ID를 다시 활성화하면 값이 복원된다. 구조 복원은 이전 값을 지우는 전체 초기화가 아니다. 비활성 ID에 새로운 내용을 쓰는 요청, 임의 ID·필수 여부·중복 ID·빈 이름은 거절한다.
- 구조와 내용은 같은 revision·원문 fingerprint·계정·카테고리 검사 아래 저장한다. 값만 저장하는 기존 호출도 구조를 유지한다. 조회에서 보정하거나 기존 상품을 소급 갱신하지 않는다.
- 저장 전 구조·내용을 유지하고 PNG 생성을 막는다. 저장 응답 유실은 정확한 구조와 값이 저장됐는지 GET으로 확인한다. 다른 창의 구조 수정은 입력 유지 조회에서 충돌로 알리며, 명시적 입력 취소·최신 조회는 새 저장 구조를 받아들인다. 독립 검수에서 이 취소 조회가 막히는 경계를 발견해 수정했다.
- PNG plan·업로드 recipe·서버 증빙은 저장된 구조와 옵션 내용에 묶인다. 항목명·순서·삭제가 바뀌면 이전 PNG를 현재 라벨로 인정하지 않는다. 다시 생성·연결하면 같은 범위의 이전 참조만 교체하고 원본 파일을 보존한다. 긴 항목명은 별도 굵은 줄로 감싸고 내용은 아래에 배치한다. 기존 짧은9개 렌더 경로와 높이·10MB 제한은 유지한다.
