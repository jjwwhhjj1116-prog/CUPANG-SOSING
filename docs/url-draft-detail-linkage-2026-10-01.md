# URL 초안 설명과 카테고리를 1~7단계 견적서에 연결

새 URL 상품은 수집한 설명 또는 생성 후 저장한 SEO 설명이 있어도 5단계의 초기 빈 필드 때문에 7단계 상세 HTML이 공란이었다. 두 회사의 공개 SKU 수집 경로에서 수정 전 견적서 ZIP 검사가 실패해 이 누락을 확인했다.

## 설명 연동과 직접 수정 보존

새로 수집해 생성하는 상품에만 서버의 `detailDescriptionLinked` 값을 설정한다. 연결 중에는 5단계 설명, 7단계 HTML, 상세페이지 미리보기와 견적서 출력이 같은 저장 SEO 설명을 사용한다. 설명의 수집·생성·직접 수정 출처도 그대로 따른다. 상세 HTML에는 일반 텍스트를 이스케이프하고 줄바꿈을 반영한다.

5단계에서 설명을 저장하면 연결을 해제하고 그 설명을 직접 수정값으로 보관한다. 같은 설명을 확인해 저장하거나 빈 설명을 저장해도 해제된다. 이후 SEO 수정·생성이 직접 작성한 상세 설명이나 명시적 공란을 복원하지 않는다. 7단계에 별도로 저장한 수동 HTML은 기존 우선순위를 유지한다.

SEO 저장 응답이 돌아오면 편집 중인 상세 설명과 대체 텍스트를 각각 대조한다. 다른 단계의 미저장 입력은 유지하고 수정하지 않은 설명만 최신 연결값을 표시한다. 기존 상품에는 연결 값을 추가하거나 일괄 수정하지 않는다. 연결 값이 없는 기존 문서와 상세 필드가 없는 오래된 문서는 이전 동작을 유지한다. 클라이언트 편집 요청으로 연결 값을 주입할 수 없다.

## 상품 추가 시 선택한 카테고리

상품 편집 창은 상품 ID에 연결된 수집 기록만 읽어 최초 선택한 카테고리의 전체 경로와 코드를 표시한다. 다른 상품·다른 offer·잘못된 경로의 응답은 표시하지 않는다. 탭 전환에는 추가 조회가 없고 상품 변경·창 닫기 때 조회를 취소한다. 기존 상품에 수집 연결이 없으면 추정하지 않는다.

URL 재적용으로 저장 초안을 여는 검사도 프로필 ID·버전·코드뿐 아니라 전체 경로가 같아야 한다. 같은 URL이라는 이유로 다른 카테고리의 초안을 재사용하지 않는다. 견적서의 기존 회사 승인·프로필·카테고리·버전 대조를 유지한다.

## 원문에 없는 정보

`1688-public-sku-v1` 또는 `chrome-public-sku-v1`의 옵션 원문에는 상세 설명·상세 이미지·일반 속성이 없다. 이 사실을 상품 편집 단계와 최종 견적서 검토/ZIP에도 유지한다. 저장한 상세 설명이나 재질을 지우거나 견적서 셀에 원문 누락 안내를 넣지 않는다. 원문에 없는 정보를 자동 생성한 경우 실제 상품과 대조할 검토 항목으로 남긴다.

최종 검토에서 상세 설명·이미지는 5단계, 일반 속성은 6단계로 이동할 수 있다. 상품 원문 조회와 버튼은 읽기·단계 이동만 수행한다. 별도 수집·상품 수정·등록 전송을 시작하지 않는다. 동일한 검토 항목을 API, 패키지 JSON/CSV에 반영하며 등록 오류로 간주하지 않는다.

견적서 출력이 읽는 수집 원문도 해당 회원/상품에 연결된 정확한 job을 사용한다. 다른 상품번호의 원문이면 첨부 파일을 읽기 전에 409로 중단한다. 원문 종류가 같은 기존 전체 수집·수동 상품에는 빈 `sourceGaps` 필드를 추가하지 않는다.

## 검증 범위

- 신규 설명 초기 연결, SEO 수정, 5단계 같은 값·다른 값·공란 저장, 이후 SEO 변경, 동시 수정, 기존 문서 보존과 클라이언트 연결 주입 거절을 검사했다.
- 실제 React 편집 컴포넌트에서 SEO 저장 후 5단계 표시, 다른 단계의 미저장 설명, 직접 상세 저장 후 연결 해제와 공란 보존을 검사했다.
- 와이홉 `A01464742`·유앤채 `A01526306` 각각 PC 실패/지연/공개 SKU 원문 경로에서 URL 초안→수동 제목·설명·재질·옵션·금액 수정→5개 포함 옵션의 7단계 HTML/Excel/ZIP→로컬 전송 경계가 같은 값을 사용하는지 확인했다. 재적용에는 원문·AI·이미지 추가 요청이나 상품 중복이 없다.
- 카테고리 변경, 응답 지연/취소, 잘못된 상품 응답, 조회 재시도, 원문 누락 검토 항목의 복원·출력, 다른 상품 원문 거절을 검사했다.

인증·AI 응답·이미지 바이트·카테고리/Excel·최종 Chrome 전달은 시험 자료다. `80719`는 관찰한 바스켓 폼 계약 시험이며 해당 1688 선글라스의 실제 판매 카테고리가 아니다. 이 단계에 새 실상품 HTTP 조회, 운영 회원 상품 저장 또는 실제 Supplier Hub 쓰기는 없다. 실제 최종 접수 성공으로 해석하지 않는다.

## 적용

최종 검사·배포 결과는 `HANDOFF.md`의 541 항목에 기록한다. 앱 새로고침으로 적용되며 확장 0.2.32 원본/번들/ZIP은 변경 없이 검사 일치다. DB migration·비밀 설정·별도 이미지 Worker·유료 자원 변경은 없다.

모든 실제 카테고리의 Couplus 기본값·공식 양식 일치, 운영 이미지 번역/필수 서류 및 두 회사의 실제 Supplier Hub 최종 접수는 남아 있다. 기존 Chrome의 알려진 쿠플러스/Hub 탭 핸들이 있는지만 확인했고 다른 탭 목록 조회·새 Chrome/프로필 생성·기존 작업 상품 수정은 하지 않았다. 전체 완성률이나 완벽 복제 완료를 주장하지 않는다.
