# YOOFAM 스튜디오 운영관리

기준일: 2026-10-30 KST. 진입 경로는 `/operations`이며 기존 상품등록 스튜디오의 운영관리 메뉴로 연결된다. 상품소싱 5개, 판매관리 6개, 손익계산 4개, 물류 4개, 총 19개 메뉴를 제공한다.

현재 상태는 **운영 웹 배포 및 로그인 계정의 19개 메뉴·설정 화면 조회 검수 완료, 신규 연결 확장의 실제 외부 수집·승인 동작 미검증**이다. 아래의 ‘수집 지원’은 연결 프로그램의 구현 범위이며 실제 사이트에서 성공했다는 의미가 아니다. 기존 상품등록·견적서·라벨 기능은 기존 화면을 사용한다.

## 1. 공통 데이터와 업무 순서

```text
검색어·관측상품 → 수요/리뷰 검토 → 1688 공급후보·쿠팡 비교
                                      ↓ 검토 후 SKU 연결
기존 YOOFAM 상품관리 ── 동기화 ──→ 공통 SKU
                                      ├→ 구매주문 → 자체 창고 입고 기록
                                      ├→ 매입묶음·상품행·공통비 → 판매세트 원가
                                      │                           ↓
                                      │                  월별 재고수불부 → 매출원가
                                      ├→ 쿠팡 재고관측 + 쿠팡 입고/반출 → 판매 추정
                                      └→ 실제 매출원장 ─────────────────→ 손익 매출
광고 원시지표 + 캠페인·상품 연결 → 광고 성과·재고 기반 추정마진
경비 원장 → 분류·검토 → 확정 경비 ─────────────────────────→ 손익 비용
매출차감/환입 ────────────────────────────────────────────→ 손익 매출 조정
```

공통 SKU의 내부 ID를 매입·재고·판매·광고가 참조한다. 공급사 SKU ID, 바코드, 옵션ID, 기존 YOOFAM 상품 ID는 서로 다른 식별자이며 문자열로 보존한다. 외부 수집 결과는 명시된 식별자가 공통 SKU 하나에 유일하게 대응할 때 연결하고, 매칭 불가·충돌 행은 진단에 남긴다. 상품명 유사성으로 자동 합치지 않는다.

‘공통 SKU·데이터 연결’의 **상품관리 SKU 동기화**는 로그인 회원과 현재 회사에 속한 상품관리 원장을 서버에서 읽는다. 원래 상품등록 작업을 수정하거나, 회사가 없는 등록 초안을 임의의 회사에 배정하지 않는다. 소싱 후보의 **SKU로 연결**은 운영관리 SKU를 만들고 후보와 연결한다. 내부 SKU 생성은 쿠팡 제안 접수나 판매 승인과 별개다.

기본 사용 순서는 ① 회사·공통 SKU 확인, ② 소싱 근거 검토, ③ 기초재고와 매입 원가 입력, ④ 재고·입고 및 실제 매출 입력, ⑤ 광고·경비 검토, ⑥ 손익 원천 대조, ⑦ 월 마감이다. 재고 추정판매는 손익의 확정 매출로 자동 전기하지 않는다. 광고 성과의 광고비도 경비 확정을 대신하지 않는다.

## 2. 메뉴별 구현

원장 화면은 추가·편집·삭제, 입력 양식 CSV, Excel/CSV/표 가져오기, 열 연결과 미리보기, CSV 출력, 정렬·페이지 나누기를 공통으로 제공한다. 계산 결과 화면은 원천 원장을 수정하면 서버에서 다시 계산된다. 연도·월·검색과 개별 화면의 상품·캠페인·묶음 필터를 사용해 범위를 좁힐 수 있다.

## 3. 계산과 회계 기준

### 판매세트와 매입원가

- 판매가능수량 = 구매 개수 ÷ 판매 세트당 구성 개수다. 20개를 2개 세트로 판매하면 수불부 매입은 10세트다. 세트구성은 양수이며 소수 세트가 나오면 구성을 검토한다.
- 원화 구매액 = `(외화 개당단가 × 구매 개수 + 외화 구매대행비 + 외화 현지운송비) × 적용환율`을 원 단위로 반올림한다. 행 환율이 없으면 매입묶음 환율을 사용한다.
- 중국·국내 공통비는 원화 구매액 비율, 검사비는 검사 대상의 구매액 비율로 배분한다. 기타 공통비는 대상 지정이 있으면 해당 행, 없으면 전체 행에 배분한다. 잔여 1원을 조정해 배분 합계를 보존한다. 검사비가 있는데 대상이 없거나 배분 기준액이 없는 경우 미배분 진단을 확인한다.
- 총원가 ÷ 판매가능수량이 판매단위원가다. SKU의 초기 원가·후보 표시가격은 이 원가 계산의 대체값이 아니다.

### 월 가중평균과 매출원가

월 평균단가 = `(기초금액 + 당월 매입금액) ÷ (기초수량 + 당월 매입수량)`이다. 당월 출고금액은 출고수량×평균단가이며, 전량 출고일 때 기말금액은 0으로 맞춘다. 기말은 다음 월로 이월된다. 음수재고를 0으로 숨기지 않으므로 누락 매입·기초·출고 중복을 확인해야 한다.

일반·로켓·자회사 상품 출고는 재고에서 차감한다. 자회사 출고의 평균원가 몫은 손익 매출원가에서 제외하며 자회사 매출 공급가도 손익 매출에서 제외한다. 기타매출은 SKU 재고 출고와 원가를 생성하지 않는다.

### 매출·VAT·차감

- 로켓매출은 **개당 VAT 제외 공급단가 × 실제 수량**이다. 예정·취소 상태는 실제 매출과 출고원가에서 제외한다.
- 일반·자회사·기타의 판매금액은 **행 전체 VAT 포함 금액**이다. 공급가 = 행 금액÷1.1을 원 단위 반올림한 값, VAT = 행 금액−공급가다. 수량을 다시 곱하지 않는다. 현재 이 경로는 10% VAT 분리 기준이며 면세·혼합세율 원장의 자동 판정 기능은 없다.
- 매출차감은 귀속월의 VAT 제외 조정금액이다. 양수는 매출에서 빼고 음수는 환입한다.
- 광고 전환매출, 재고 기반 추정매출·마진, 키워드 추정 거래액은 실제 손익 매출에 자동 합산하지 않는다.

### 경비 확정과 손익

가져온 경비는 검토 대기가 기본이다. 분류가 없으면 확정할 수 없다. 공급가+세액과 합계를 대조하며, 선택 금액이 없으면 합계에서 공급가·세액을 분리한다. 일반 경비는 공급가, VAT 환급 미적용 경비는 합계를 비용으로 사용한다. 승인번호가 같은 동일 경비의 재가져오기는 이미 확정한 상태를 보존하며, 금액·거래처가 충돌하면 기존 행을 덮어쓰지 않는다. 승인번호 없는 유사 거래는 중복 의심 표시를 검토해야 한다.

손익 매출 = 로켓+일반+기타−매출차감, 매출총이익 = 손익 매출−수불부 매출원가, 영업이익 = 매출총이익−확정 판관비, 경상이익 = 영업이익+영업외수익−영업외비용, 순이익 = 경상이익−세금이다. 검토 대기·제외 경비는 반영하지 않는다.

### 관측 누락과 가격 이력

관측된 재고 0과 관측하지 못한 `null`을 구분한다. 판매 추정은 전일재고−당일재고+해당 SKU의 쿠팡 입고−반출이다. 두 날짜 중 하나라도 관측이 없으면 판매·추정마진은 미확인이다. 자체 창고의 구매입고는 쿠팡 재고 흐름에 합산하지 않는다. 수집일과 업무기준일은 각각 확인해야 하며 아침 관측을 전일 마감에 사용하는 경우 업무기준일을 명시한다.

공급가·판매가·초기 원가가 바뀌면 유효일을 가진 가격 이력을 보존해 일별 추정에 사용한다. 회계 매출원가는 매입·기초·실제 출고의 수불부 계산을 따른다. 초기 이력이 없던 과거 날짜까지 실제 단가를 관측한 것으로 주장하지 않는다.

### 월 마감

마감된 월의 매입·출고매출·경비·재고관측·기초재고 관련 변경/삭제와 다른 월로 이동하는 편집을 서버에서 제한한다. 여러 행 가져오기에 마감월 행이나 잘못된 참조가 있으면 명령 전체를 반영하지 않는다. 수정이 필요하면 명시적으로 월 마감을 취소하고 원천을 정정한 뒤 다시 대조·마감한다.

## 4. 수기·파일·표 가져오기

지원 형식은 `.xlsx`, CSV, TSV 및 머리글을 포함한 표 붙여넣기다. `.xls`는 Excel에서 `.xlsx` 또는 CSV로 변환해야 한다. XLSX는 첫 번째 시트를 읽고 앞부분의 머리글 후보를 선택하므로 상단 제목·여러 표가 섞인 문서는 가져오기 전에 확인한다. 여러 시트 통합과 Excel 수식 실행은 지원하지 않는다. CSV/텍스트는 UTF-8로 준비하는 것이 적합하다.

가져오기는 **읽기 → 원본 열 연결 → 필수값·SKU/캠페인/묶음 연결 → 앞 5행 미리보기 → 확인한 자료 반영** 순서다. 같은 원본 열을 여러 필드에 중복 연결할 수 없다. SKU가 미등록되었으면 공통 SKU를 먼저 준비한다. 숫자·날짜·세트·식별번호가 바르게 연결됐는지 확인하며, 0으로 시작하거나 긴 식별번호는 원본 Excel에서부터 텍스트로 보존한다. Excel이 이미 반올림한 번호는 가져오기에서 복구할 수 없다.

| 한도 | 현재 구현 |
| --- | --- |
| 파일 읽기 | 파일당 12MiB (`12 × 1024 × 1024` bytes, 화면 안내 12MB) |
| 한 번 가져오기/수집 반영 | 최대 5,000행 |
| 저장 문서 | 회원·회사별 전체 JSON UTF-8 최대 1,800,000 bytes, 요청 본문에도 크기 제한 적용 |
| 전체 원장 행 | 모든 종류 합계 최대 20,000행, 공통 SKU 최대 5,000개 |

D1의 단일 문자열·행 한도는 2,000,000 bytes이므로 현재 단일 문서 저장은 메타데이터 여유를 둔 1,800,000 UTF-8 bytes에서 먼저 제한한다([공식 D1 제한](https://developers.cloudflare.com/d1/platform/limits/)). 파일 크기가 작아도 누적 문서 한도나 요청 크기를 넘으면 반영할 수 없다. 한 번 반영 한도는 기간을 나누어 대응할 수 있지만, 회원·회사별 누적 문서 한도는 연도나 파일을 나누어도 바뀌지 않는다. 현재 저장 구조는 무제한 이력·자동 보관·대용량 데이터웨어하우스 기능을 제공하지 않는다. 키워드의 일시 보관 만료가 회계 원장의 용량 정리를 대신하지 않는다.

중복 처리는 원장별 외부 식별키에 따른다. 승인번호·외부 거래ID·발주/시각 등이 없는 모든 행을 자동 중복 제거하지 않는다. 같은 값을 반복 가져오기 전에 식별키와 미리보기를 확인한다. 표시 CSV는 분석·대조용이며 외부 세금계산서 발행이나 공식 신고 양식 생성이 아니다.

## 5. 연결 확장 설치와 실행 범위

운영관리 전용 확장은 기존 상품 수집·견적서 확장과 별도이다. 소스는 `extensions/operations-connector`, 배포용 파일은 `public/downloads/yoofam-operations-connector.zip`에 있다. 자세한 권한·프로토콜은 [확장 README](../extensions/operations-connector/README.md)를 따른다.

1. 운영관리의 **공통 SKU·데이터 연결 → 운영관리 연결 확장 다운로드**에서 ZIP을 받거나 로컬 ZIP을 준비해 압축을 푼다.
2. Chrome `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드**하여 `manifest.json`이 있는 폴더를 선택한다. 설치·기존 확장 교체를 앱이 자동 수행하지 않는다.
3. 같은 Chrome 창에서 필요한 쿠팡·WING·서플라이어허브·광고센터 탭을 열고 직접 로그인한다. 앱의 현재 회사와 외부 서비스의 회사가 같은지 확인한다.
4. YOOFAM `/operations`를 새로고침하고 **수집 연결 확인**으로 응답 버전과 연결 상태를 확인한다. 연결됨은 메시지 왕복 확인이며 실제 수집 성공 증거가 아니다.
5. 조회 조건을 정해 수집을 요청하고 수집 기록의 성공·일부 수집·실패·결과 확인 필요, 경고·미매칭 내역과 서버 반영 결과를 대조한다. 연결이 없거나 실패하면 파일·표·수기 입력을 사용한다.

현재 확장은 검색 상품·연관어·리뷰 표본·재고·입고·발주 SKU·광고지표·명세서 조회 인터페이스를 구현한다. 검색 결과의 렌더 구조와 로그인 상태에 영향을 받는다. 28일 수요 보강은 로그인 WING 자료와 유일한 상품 연결이 있을 때만 사용하며 지표의 집계범위는 미확정 참고값이다. 최대 페이지·행·응답크기·기간 제한이나 중간 실패는 일부 수집이 될 수 있다. 상품 제안 제출과 광고 예산 변경은 지원하지 않는다.

명세서 외부 승인은 한 번에 문자열 발주번호 1~10개를 대상으로 한다. 앱에서 선택한 뒤 확장이 서버 회사와 현재 RI 목록을 확인하고, **확장 전용 확인창**에 회사·발주·금액을 표시한다. 사용자가 확인란과 승인 버튼을 직접 조작해야 실행한다. 웹앱의 확인값이나 대기 작업 생성만으로 외부 승인되지 않는다. 승인 직전 회사·상태를 재검사하며 발주별 전송 체크포인트를 보존한다. 응답 불명·진행·성공 이력은 재실행을 막고 자동 재시도하지 않는다. 전송 후 창을 닫아도 이미 보낸 요청이 취소되는 것은 아니다. 불명 결과는 원본 상태를 재조회하여 확인한다.

**실제 로그인 계정에서 신규 연결 확장의 수집·승인 성공을 검증하지 않았다.** 로컬 합성 응답 검사와 설치 ZIP 생성 검사를 라이브 호환성으로 확대하지 않는다. 웹은 배포했고 첫 운영 조회에서 런타임의 `CREATE TABLE IF NOT EXISTS`가 실행됐다. 별도 마이그레이션 명령, 확장 설치, 실제 정산 승인은 실행하지 않았다. 운영 원장은 빈 상태로 조회했고, 표 가져오기는 열 연결·미리보기 후 취소해 검수용 자료를 서버에 저장하지 않았다.

## 6. 저장·회사 경계와 코드 위치
