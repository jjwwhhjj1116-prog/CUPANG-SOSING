# Step703 — 빈 표시사항 행의 출력과 전체 삭제

2026-10-18 KST. 기준 `17ec5d6654fd54cc2835aadec850d5612edc0e67`. 보관된 쿠플러스의 한글 표시사항 생성·전체 삭제 동작을 대조해 주 제품 라벨 경로에 반영했다. 기존 작업 상품·사용자 Chrome 탭·운영 DB에 접근하지 않았다.

## 원본 근거와 새 PNG

원본 클라이언트 renderer는 값이 truthy인 항목만 순서대로 출력한다. 문자열 입력에서 `''`는 생략하고 공백·탭·줄바꿈·문자열 `'0'`은 유지하며 trim하지 않는다. required는 삭제 보호에 쓰이고 값의 비공란 조건으로 검사하지 않는다. 정확한 slice·SHA·Evidence와 관측 한계는 `docs/step703-label-generation-parity-audit.md`에 있다. 원본 코드나 현재 서버를 실행해 검증했다고 표현하지 않는다.

새 `productLabelPlan()`은 저장 순서·항목명·현재 옵션값을 유지하면서 **값이 정확히 `''`인 행만** PNG plan에서 생략한다. 공백만 있는 값도 출력 행으로 남긴다. 편집기·DB·옵션별 공란을 지우거나 다른 값으로 채우지 않는다. 모든 값이 정확히 비어 있을 때의 PNG 생성 차단은 기존 보호 조건을 남긴 자체 선택이다. 원본의 빈 DOM 출력·500px 모양까지 복제한 것은 아니다. 기존 자체800px renderer·높이/파일 크기 제한은 유지한다.

## 이전 PNG의 좁은 호환

이전 v1 PNG는 빈 행의 항목명도 출력했다. 이 형식 변경만으로 기존 정상 라벨을 미확인으로 만들지 않도록, 서버가 기록한 PNG 증빙은 현재 생략형 plan SHA 또는 **현재 저장 구조·순서·항목명·값을 모두 반영한 이전 전체행 plan SHA**가 정확히 같을 때만 인정한다. 기존 소유자·상품·프로필·카테고리·증빙 형식 확인을 통과한 뒤 이 분기를 사용한다. 새 업로드·증빙 생성은 항상 생략형 plan을 사용한다. 임의 digest나 변경된 실제 출력값을 인정하는 예외가 아니며 파일·DB를 다시 쓰지 않는다.

빈 행의 이름·순서·삭제처럼 새 PNG에 출력되지 않는 변경은 새 생략형 plan과 업로드 ID를 바꾸지 않을 수 있다. 같은 변경도 이전 전체행 PNG에는 항목명으로 남아 있으므로 이전 plan SHA가 달라져 재생성이 필요하다. 실제 출력되는 내용·이름·순서 변경은 두 형식 모두 다시 대조한다. 신규 통합 검사는 과거 renderer 동작을 fixture 안에서만 복원해 서버 기록 PNG를 만든 뒤 현재 함수를 되돌려 호환성을 검사한다.

## 전체 삭제

주 표시사항 편집기에 `전체 삭제`를 추가했다. 현재 필수 제품명 항목의 이름을 유지하고 내용은 공란으로 만든 뒤, 비필수 항목을 현재 편집 배열에서 제거한다. 정보 저장하기 전까지 API 쓰기는 없다. 취소·최신 조회로 원래 저장 구조·내용을 불러올 수 있다. 저장 뒤에도 삭제한 항목의 공통·옵션 값은 보관되고 기본 구조 복원 시 다시 표시된다. 응답 유실은 정확한 공란과 구조의 GET 대조로 복구한다.

항목 구조는 상품 공통이고 비우는 내용은 현재 공통/선택 옵션 범위다. 원본은 저장한 같은 값을 모든 옵션에 복제하지만 자체는 다른 옵션의 직접 내용을 보존하는 기존 모델을 유지한다. 이를 전체 옵션까지 동일하게 비우는 동작이라고 표현하지 않는다. 카테고리 법적 고시·실제 상품명·가격·이미지 파일·다른 회원 자료는 변경하지 않는다. 처리 중 요청·이전 옵션의 callback·언마운트 후 동작은 새 편집을 바꾸지 못한다.
