# Step778 — 수집 보관본의 앱 복귀 전달과 SEO 원문 비교

기존 작업 상품을 새 검수 상품으로 재사용하지 않는다. 실제 외부 수집·접수와 로컬 격리 검수를 구분한다. 최종 소스 해시, 검사, 화면, 배포 및 커밋은 `outputs/step778-final-validation.json`에 기록한다.

## 수집한 자료를 목록까지 전달

1688 본문의 수집 버튼으로 담은 원문은 먼저 확장에 회원·회사·창·출처와 함께 보관된다. 서버의 정확한 저장 응답을 받아야 보관본을 지운다. 기존 앱은 마운트 때 한 번 재전달하고 이후 앱 복귀에서는 서버 목록만 조회해, 일시적인 전달 실패를 사용자가 별도로 복구해야 했다.

앱 복귀에서 이미 보관한 원문만 재전달한다. 새 상품 페이지를 읽거나 백그라운드 소싱을 시작하지 않는다. 요청 전후 현재 회원·회사·출처를 확인하고, 정확한 저장 결과를 받은 뒤 서버 목록을 다시 읽는다. 기존 작업 상품과 같은 URL인 원문은 기존 작업을 덮어쓰거나 자동으로 열지 않는다. 주기적인 목록 조회는 계속 읽기만 한다.

응답을 받지 못한 시도를 무기한 보유하면 확장이 나중에 정상화돼도 복귀 전달이 막힌다는 독립 검수 결과도 반영한다. 로컬 대기는 유한하게 유지하되 만료를 성공으로 표시하거나 타이머로 재전달하지 않는다. 다음 실제 앱 복귀에서 다시 확인한다. 확장에서는 현재 창·출처·회원·회사가 같은 진행 중 전달을 공유하며, 각 저장은 기존 원문 식별자·지문의 멱등 처리를 유지한다. 이전 계정의 응답은 현재 계정의 목록을 바꾸지 않는다.

## SEO의 원문과 번역 비교

보관한 Couplus SEO 화면의 옵션 캡션은 축별 원문과 저장 번역을 함께 보여준다. 예를 들어 `黑色 (검정) / 均码 (프리)` 아래에서 최종 옵션명은 따로 수정한다. 근거는 `outputs/step778-rea-seo-caption.json`의 원본 해시와 정확한 코드 범위에 있다.

YOOFAM의 참고 캡션은 같은 상품의 현재 수집 연결과 기존 완료 번역 이력에서만 읽는다. 정확한 옵션 식별자, 원래 옵션명, 번역 원문 인덱스, 현재 색상·사이즈 값과 번역 출처가 일치해야 한다. 수동값·공란·모호한 이력·연결 없는 과거 자료는 원문만 보여준다. 새 번역이나 옵션 저장은 실행하지 않는다. 표시용 메타데이터를 저장 요청에 포함할 수 없으며 기존 상품명·검색태그·옵션명 저장 검사는 유지한다.

## 검증의 한계

기존 Chrome의 Supplier Hub 탭에서 유앤채 로그인 표시를 읽기만 확인했다. 기존 상품 행을 열거나 수정하지 않았다. 운영 앱은 Cloudflare 인증 화면으로 이동했으며 인증 정책·비밀번호·기존 계정 권한을 바꾸지 않았다.

격리 검수의 상품·Chrome 연결·번역 증거는 합성이며 앱 컴포넌트, 수집 전달 코어, API와 SQLite를 실제 코드로 실행한다. 실제 1688 수집, 실제 Supplier Hub 신규 문서 업로드·약관 확인·접수 완료와 전체 카테고리·1~7단계의 완전한 동등성은 별도 실증이 필요하다. 이전 접근 거절 대상은 재접근하거나 우회하지 않는다.
