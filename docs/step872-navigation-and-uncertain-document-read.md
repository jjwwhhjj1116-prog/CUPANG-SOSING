# 접이식 운영 메뉴와 원래 문서 읽기 복구

운영관리 왼쪽 메뉴의 상품소싱·판매관리·손익계산·물류를 접기/펼치기 버튼으로 바꿨다. 한 그룹만 펼쳐지며 직접 들어간 화면의 그룹은 열린다. 접힌 항목은 키보드·접근성 탐색에서도 제외된다. 데이터 저장이나 수집을 메뉴 전환으로 실행하지 않는다.

실제 확장 2.1.61에서 원래 요청 `f29491bd-1882-456a-8a63-eec8586db6c6` / 문서 2347603의 checkpoint를 확인했다. 상태는 `update-requested`, 순번22, 검증0/4이며 웹 예약은 없었다. 이제 이 상태는 ‘파일·본문 저장 결과 미확정’으로 표시한다.

복구는 현재 전체 검토자료와 같은 checkpoint를 두 번 확인한 뒤 기존 native 읽기 경로만 사용한다. 정확한 원래 `:update` operation, 아직 제출하지 않은 초안, 빈 검증 단계 목록을 요구한다. 실제 원격 저장본과 본문이 일치하여 읽기 결과가 `updated`로 승격된 경우에만 원래 웹 예약을 복원한다. 생성 직후 상태나 불명확한 결과를 저장 완료로 바꾸지 않는다. 새 문서·파일 업로드·본문 재전송은 호출하지 않는다.

215개 관련 검사와 타입·lint·분리 빌드를 통과하고 Worker `8d09acae-c567-409a-8c44-98bc82242b65`에 배포했다. 이후 실제 읽기 복구와 접수 검수는 Cloudflare 인증 도메인 접근 거절로 진행하지 못했다. 로컬 checkpoint 읽기 성공은 실제 접수를 뜻하지 않는다.
