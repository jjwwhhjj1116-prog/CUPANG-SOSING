## 확인한 근거

2026-10-02에 쿠키·인증 없이 [쿠플러스 상품등록 공개 JavaScript](https://couplus.co.kr/js/chunk-e2dd462a.8dc4d2d7.js)를 HTTPS GET으로 다시 확인했다. 549198바이트, SHA-256 `38aee73a04100657ed8463a6156cc096ceaf68d4f3d671f34845a9cda515d587`이며 이전 [분석](couplus-schema-draft-defaults-2026-10-01.md)의 파일과 같다. 분석 원본은 Git에서 제외한 outputs에만 저장했다. 공개 코드를 실행하거나 본문을 제품 코드에 복사하지 않았다.

`extractAndApplySchema`와 `createFieldStructure`는 필수 페이지 → 필수 객체 → 필수 항목의 전체 경로를 따라 값을 초기화한다. 문자열 선택지는 해당사항없음을 우선하고, 없으면 첫 선택지를 사용한다. 선택지 없는 문자열은 공란, 숫자는 0, 정확한 boolean 타입은 false다. `fashionSeason`은 사계절을 사용한다. nullable boolean 등 나머지 구조는 null로 초기화한다. 우리 편집용 문자열 모델에서는 null을 공란으로 표현한다. JSON Schema의 `default` 주석을 이 초기화 대신 사용하지 않는다.

`initializeCoupangDoc`는 이후 imagePage의 msrpAgree 및 labelContactAgreed를 true로 설정하고 기본설정·기존 옵션 문서를 적용한다. 이번 구현에서는 실제 캡처 양식에 존재하는 두 직접 boolean 필드에만 해당 기본값을 연결한다. 같은 이름의 다른 구역 항목, 다른 동의 항목 또는 브라우저 체크박스를 일괄 선택하지 않는다. 실제 등록전송의 동의 절차는 기존 명시적 전송 흐름을 유지한다.

로그인한 쿠플러스의 GET_PRODUCT_INFO/createResult 응답이나 수집 서버 내부 구현을 이번 공개 파일 확인으로 검증한 것은 아니다. 기존 Chrome 창·계정·작업 중인 상품 및 Supplier Hub 견적서는 조회하거나 수정하지 않았다.

## 구현

- 회사·최종 분류코드·전체 경로를 확인해 새로 읽은 Hub 양식에 `draftInitialization: couplus-required-v1`을 저장한다. 해당 캡처에 위 스칼라 초기화 규칙을 적용한다. 카테고리코드나 선택지·필수 항목을 추측해서 만들지 않는다.
- 저장 당시 이 버전이 없던 기존 상품은 이전 캡처를 유지한다. 이후 카테고리 프로필을 갱신해도 기존 작업 상품의 양식·값·공란을 덮지 않는다. 기존 named-array의 비노출 null/그 밖의 해당사항없음 규칙은 유지한다.
- 원문에서 연결한 상품·옵션 정보, 브랜드/회사 등 기본설정, 실제 가격 계산 및 수동 공통/옵션 값이 초안 기본값보다 우선한다. 사용자가 직접 비운 항목도 공란으로 보존한다. 이번 변경은 기존 쿠플러스 가격·마진 계산식을 바꾸지 않는다.
- 0이 실제 최소값보다 작거나 사계절이 해당 양식 선택지에 없으면 검토 오류를 유지한다. 기본값 생성만으로 견적서를 제출 가능 상태로 만들지 않는다. enum/dropdown 모순, 잘못된 필수 목록·존재하지 않는 필수 항목, 지원하지 않는 루트 조건은 미확인 양식으로 남긴다.
