# Step 646 — 상품관리 계정별 허용스토어 설정

상품관리(신규)의 `허용스토어설정` 버튼과 조회·편집·저장 팝업을 연결했다. 유앤채와 와이홉의 로그인 회원·승인 회사별로 목록을 따로 저장한다.

## 대조한 쿠플러스 동작

`outputs/step630-couplus-management-public-methods.json`과 `step630-couplus-management-contracts.json`에서 허용 스토어 팝업, 네 줄 입력창, 현재 이름 배지, 저장·취소와 CSV 정규화를 확인했다. 쉼표로 나눈 뒤 앞뒤 공백과 빈 항목만 제거하며 이름의 순서·대소문자·중복을 유지한다. 원격 SKU 수집 옵션에 저장 목록을 전달하는 참조 동작도 확인했다. 스토어 저장만으로 기존 상품의 타사매칭 분류를 변경하지 않는다.

## 구현 범위

`managed_store_settings`에 회원 ID와 회사코드를 복합키로 사용한다. 기존 가격·기본설정의 전체 JSON을 덮어쓰지 않는 별도 테이블이다. `0019_managed_store_settings.sql`은 이 테이블만 추가한다. GET은 SELECT만 수행하고 테이블이 없으면 설정을 만들어내지 않고 503을 반환한다.

승인 회원과 원문 설정을 같은 DB 스냅샷에서 조회한다. 저장은 계정 문맥·검토한 버전·원문 해시·현재 승인 회사·저장 시각을 확인하는 단일 SQL로 수행한다. 다른 탭의 수정, 회사 변경, 승인 철회나 원문 변경이 있으면 이전 입력으로 덮어쓰지 않는다. 최대 100개 이름, 이름당 200자, 전체 32KB다. 배열의 이름 안에 쉼표를 넣어 재조회 시 다른 목록으로 나뉘는 요청은 거절한다.

아직 저장하지 않은 빈 목록과 명시적으로 저장한 빈 목록을 구분한다. 동일한 저장 목록은 버전과 저장 시각을 유지한다. 팝업은 저장 응답과 최신 GET이 일치한 뒤 닫는다. 응답 유실 시 입력을 보존하고 `저장 결과 확인`에서 GET으로 확인한다. 확인 과정은 PUT을 반복하지 않는다.

입력 변경·계정 변경·늦은 응답·오래된 버튼 콜백을 구분한다. 저장 중에는 파일 가져오기, 목록 조건 변경, 다운로드와 다른 매입·구매·바코드 팝업을 열 수 없다. 같은 렌더 사이에 매입정보와 허용스토어 버튼을 연속 누르는 경우도 한 창만 열린다.
