# Step729 — 기본 등록 전송을 전체 상품 문서에 연결

2026-10-19 KST. 기준 커밋은 `fd9c2e3b8c15beaefe18611a9b04fa19fa0020ac`다. 기존 운영 상품, 회원 기본설정, Couplus/Supplier Hub 작업 문서는 변경하지 않았다. 이번 범위는 상단 등록 전송과 7단계의 연결, 수집 당시 카테고리 보존, 이미 열린 상품 탭의 읽기 지연이다. 원문 수집 서비스나 실제 접수의 완성을 주장하지 않는다.

## 사용자 경로 수정

상단 등록 전송의 기본 화면이 포함 옵션 전체를 견적 문서 하나로 확인하는 경로를 사용한다. 7단계 편집 화면도 동일한 검토를 사용한다. 단일 옵션 선택기는 이 기본 경로에 표시하지 않는다. 기존 Excel 파일 방식은 별도 접기 메뉴를 사용자가 열 때만 파일 패키지를 조회한다. 전체 문서 조회 실패가 Excel 전송으로 자동 전환되지 않는다.

기본 진입기는 현재 회원·회사, 소유 상품, 저장한 견적 두 번, 소유 상품 재조회, 회원·회사 재조회를 순서대로 대조한다. 모든 요청은 GET이며 원문·AI·Hub 전송을 실행하지 않는다. 30초 지연, 취소, 다른 회사·상품·프로필, 옵션 및 저장 시점 변경은 명시적인 재조회로 정리한다. 늦은 응답은 이전 화면을 복원하지 못한다.

수집 시 캡처한 카테고리는 프로필 ID가 있더라도 queryless 상태를 유지한다. 사용자가 명시적으로 선택한 프로필만 쿼리에 전달한다. 이 차이가 편집기·전송 준비·전체 문서 확인 사이에서 사라지던 부분을 수정했다. 후보 이미지 패키지는 현재 회사와 정확한 nullable `requestedProfileId`를 다시 검사한다.

대시보드는 견적서 패널을 다른 단계에서도 숨긴 채 마운트한다. 새 `submissionActive` 전달로 7단계가 숨겨져 있을 때 전체 문서의 자동 조회를 막는다. 저장하지 않은 변경·로딩·충돌 중에도 조회와 전송 준비를 비활성화한다. 이미지 준비는 별도 명시 동작이며 자동 제출하지 않는다.

## 수집 순서와 원본 분석

같은 Chrome 창에 이미 열린 정확한 상품 탭에서 지원하는 완전한 상품정보가 읽히면 모바일 조회보다 먼저 사용한다. 안정 상태 확인은 최대 1초이며 프레임·소스·창·취소·로그인 변경을 계속 확인한다. 정보가 불완전하면 기존 모바일 경로를 사용한다. 새 데스크톱 hydration 형식을 추정하거나 부분 데이터를 완전한 상품으로 바꾸지 않는다. 관련 회귀검사는 실제 1688 접속 없이 합성 Chrome 경계에서 실행했다.

[REA 수집 계약 분석](step729-rea-acquisition-contract.md)은 기존 보관 증거와 CLI 1.3.37의 51개 JavaScript 원문을 사용한다. CLI는 서버 recipe 실행기이며, archive만으로 Couplus의 비공개 1688 상품 공급자를 복구했다는 근거가 없다. REA producer 재실행, vendor 코드 실행, 운영 상품 변경은 없었다.

회사 분리·카테고리 유지·저장값 일치·조회 취소·시간 초과·기본/별도 전송 경로를 실제 컴포넌트와 격리 SQLite/API로 검사했다. 고정된 소스의 전체 관련 검사는 `outputs/step729-related-final-proof.json`과 `-freeze.json`에 기록한다. TypeScript, lint, 메모리 DB 스키마 검사, 운영 빌드, 확장 ZIP 원문 일치도 별도로 확인한다.

같은 Chrome4에서 격리 합성 상품으로 실제 `SubmissionReviewPanel` 기본 화면을 열었다. 포함 2개/제외 1개, 옵션별 수정한 상품명·모델명·금액·수동 공란, 현재 회사, 전체 본문 및 문서 순서를 확인했다. Excel 메뉴는 접힌 상태였고 단일 옵션 선택기는 없었다. 브라우저 API는 GET만 허용했으며 로컬 미리보기 경계만 실제 dispatch에 연결했다. SQLite/R2 전후 해시는 같고 콘솔 오류·실제 확장 요청·실제 Hub 제출은 0이다.
