## 확인한 차이와 수정

보관된 쿠플러스 `applyBundleToOptions`는 기존 이름의 마지막 `(N개묶음)` 표시를 제거한다. 적용 수량이1이면 그 기본 이름을 사용하고,2 이상일 때만 새 묶음 표시를 붙인다. [REA 대조 문서](step696-option-bundle-parity-audit.md)에 원본 위치·SHA·Evidence와 수정 전 자체 재현을 기록했다. 원본 코드를 실행하거나 서버 저장을 관찰한 증거는 아니다.

자체 `previewOptionBulk`는1에도 `(1개묶음)`을 붙였다. 이 값이 저장 정규화와 견적 옵션명 구성까지 그대로 전달돼 `검정 (5개묶음)`을 단품으로 바꾸면 `검정 (1개묶음)`이 남았다.

같은 분기의 기본 이름을 분리하고 수량1에서는 묶음 표시를 추가하지 않게 했다.2 이상일 때의 기존 이름 교체와500자 제한은 유지한다. 끝에 있는 묶음 표시 하나만 처리하며, 이름 중간의 비슷한 문구를 지우지 않는다. 수동 공란·공백만 있는 번역명은 기존 보존 정책을 유지한다.

이 변경은 선택한 기존 UUID의 이름에만 적용된다. 구성 수량·기존 단품 가격 재계산, SKU·재고·옵션번호, 비선택/제외 옵션과 수동 견적 수정값을 새 규칙으로 바꾸지 않는다. 수량 변경 때 포장 측정값과 원래 측정 수량은 보존하고 확인을 해제하는 기존 동작도 유지한다. 기존 상품에 소급 적용하거나 자동 저장하지 않는다.
