# 견적 라벨 부분 실패·응답 유실 복구 (2026-10-01)

7단계의 일괄 옵션 라벨 생성이 일부 저장된 뒤 실패하면 서버에는 변경이 남아도 부모 편집기는 이전 revision/fingerprint를 유지했다. 다음 수동 수정은 409가 될 수 있었으며, 외부 견적 미리보기도 무효화되지 않았다. 저장 응답이 유실된 경우에는 클라이언트가 완료 건수를 추측할 수 없다.

실제 부모·자식 코드와 API로 수정 전 6개 회귀가 실패하는 것을 확인했다. 서버 저장 뒤 화면 revision `1 !== 2`, 실패 후 재조회 시도 없음이 재현됐다. 외부 미리보기 무효화 알림도 별도 회귀에서 `0 !== 1`로 실패했다.

## 변경

- 일괄 작업 실패는 오류를 부모에 전달하고 최신 견적을 GET으로 다시 읽는다. 조회가 끝날 때까지 작업 잠금을 유지하며, 실패만으로 추가 업로드·자동 재개·Hub 전송을 실행하지 않는다.
- 외부 견적 미리보기와 상품 자료의 기존 갱신 callback을 실패 시 호출한다. 잠재적인 부분 변경이 남은 이전 미리보기를 계속 보여주지 않는다. 성공 건수나 등록 완료를 알리는 것은 아니다.
- 실패 직후 자동 재조회가 성공하면 실제 revision/fingerprint·라벨 참조·상품 첨부를 편집기에 반영하고 원래 오류를 유지한다. 업로드 키는 기존 부모 ref에 남아 재마운트 후 같은 계획에서 재사용된다.
- 최신 저장본을 읽지 못하면 입력·저장·라벨 재실행을 잠그고 기존 '기본값 다시 반영'으로 조회를 재시도한다. 재조회 실패를 반복해도 원래 오류를 보존하며, 확인한 저장본을 읽어야 잠금을 푼다. 잠재적인 서버 변경을 추정해 적용하지 않는다.
- PNG 내용·상품·카테고리·포함 옵션이 달라지면 기존 캐시를 그대로 재사용하지 않는 기존 검사를 유지한다. 단일 미리보기 연결, 전체 페이지 재접속의 영구 재개, 파일 업로드 자체의 응답 유실로 키를 모르는 경우까지 해결한 것으로 해석하지 않는다.

## 검증

와이홉 A01464742와 유앤채 A01526306에 대해 다음 네 상황을 각각 검사했다.

1. 첫 라벨 저장 뒤 두 번째 PNG 생성 실패.
2. 첫 라벨의 견적 PUT은 저장되지만 응답이 유실됨.
3. 첫 PNG의 상품 이미지 POST는 저장되지만 응답이 유실됨. 라벨 참조 저장은 아직 남아 있음.
4. 첫 라벨 저장 뒤 생성 실패에 더해 최신 견적 GET이 두 번 실패함. 입력/재개 잠금, 원래 원인 유지, 수동 재조회 성공 후 해제를 확인함.

실제 `QuotationFieldsEditor`·`QuotationLabelPanel`, hook/effect 및 key 재마운트 모델, 실제 수집/콘텐츠/견적/업로드/상품 첨부/Excel/ZIP API와 임시 SQLite를 실행한다. 지정 상품 813724060928의 기록 원문에서 6옵션을 만들고 위 오류를 주입한 뒤, 첫 옵션 판매가 20,000원 수정 저장에 409가 없는지 확인한다.

재개 후 파일 업로드·상품 연결·라벨 저장은 각각 총 6회이며 완료된 PNG는 중복 생성하지 않는다. 두 번째 렌더 실패가 있는 시험은 실패한 호출 1회를 포함해 렌더 7회다. 기존 라벨을 보존하고 각 옵션에 고유 PNG 하나가 연결되며, 같은 완료 계획을 다시 실행해도 추가 업로드가 없다. URL 재시도에도 추가 원문/AI 요청이 없다. 최종 6행 Excel 라벨 파일명과 JSON 매핑, 검토 ZIP과 로컬 포착 전송 XLSX 및 7개 라벨 이미지 바이트, 회사·옵션 수가 일치한다. 잠금 유지와 패널 폐쇄 후 늦은 실패 무시도 검사한다.

80719는 관찰된 폼의 시험 계약이며 이 선글라스의 실제 판매 분류가 아니다. 인증/AI/PNG 조판/이미지 바이트/Excel 양식/Hub 최종 전달은 시험 자료다. 실계정에는 쓰지 않았고 시험 상품 상태는 미전송이다. 집중 검사 30/30 및 기존 견적 편집기 78/78을 통과했다. 초기 전체 검사의 편집기 6개 실패는 위치로 상태를 주입하는 기존 시험과 새 상태 선언 순서의 불일치였으며, 기존 상태 순서를 유지하여 수정했다. 새 패널 시험의 Error 객체도 VM과 공유하여 실제 원인 문자열을 검사한다.

현재 Chrome 연결의 탭은 빈 목록이고 Windows 창 목록에서도 지정된 우측 Couplus/Hub 창을 식별하지 못했다. 관련 없는 창의 내용은 읽거나 입력하지 않았다. 새 Chrome/프로필, 기존 Couplus 작업 상품, 추가 로그인/승인 요청은 없으며 사이트 차단/로그아웃으로 판단하지 않는다.

전체 실제 카테고리의 Couplus 기본값·공식 양식 대조, 지정 Chrome의 실제 URL→1~7단계 작업, 운영 이미지 번역·법적 서류 첨부 및 두 회사의 실제 최종 Supplier Hub 접수·SKU 확인은 미검증이다. 전체 완료율이나 완벽 구현 완료를 주장하지 않는다. `outputs/step529-*`는 로컬 검사 자료로 Git에서 제외한다.
