# Step 592 — 옵션 초안·물류 입력·전송 결과 복구

## 변경 결과

- 자동 번역 준비가 동일 계정·상품의 저장된 번역 이력을 전달합니다. 기존 v5 결과가 현재 원문을 그대로 복사했고 사용자가 수정하지 않았다는 증거가 있는 옵션만 v6 무료 번역 대상으로 복구합니다. 원문이 중국어라는 이유만으로 수동값·수동 공란·제외 옵션을 바꾸지 않습니다. 최신 20개 이력 밖의 canonical 수집 작업은 단일 조회로 보완합니다.
- 7단계에서 확인된 동일 g 단위 포장 무게를 직접 입력하거나 옵션에 복사하면 내부 입력과 공식 양식 입력을 같은 저장 요청에 담습니다. 대상 옵션의 기존 공식 양식 입력 때문에 출력 파일에 이전 무게가 남던 문제를 수정했습니다. 미리보기에도 두 변경을 표시하며, 옵션 제외·다른 항목·공통값은 적용 범위에 따라 유지합니다. 개별 수정 해제는 지정한 필드만 해제하고 기존 상충값은 명시적 입력 전까지 보존합니다.
- 서버에 파일 검증 중 기록이 보관된 뒤 원래 Supplier Hub 탭을 닫아도 결과를 조회할 수 있습니다. 정확한 회사·상품·카테고리·현재 견적 지문·옵션 수가 일치해야 같은 Chrome 창에 별도 읽기 전용 탭을 준비합니다. 파일 재첨부·검증 실행·등록 전송·기존 작업 탭 이동은 하지 않습니다. 접수 ID 확인 후 같은 연결로 SKU 상태 조회를 이어갑니다.
- 읽기 전용 조회 결과는 이전 기록과 일치할 때만 IndexedDB 트랜잭션으로 저장합니다. 동시 조회, 현재 회사 변경, 원본 변경, 다른 탭 연결, 최신 접수 결과와의 경합은 저장을 중단합니다. 확인된 접수 ID와 같은 ID의 SKU 관측은 후퇴시키지 않습니다.

## 회귀 검사 범위

- 유앤채 A01526306·와이홉 A01464742의 실제 앱 API와 임시 SQLite를 연결해 번역 준비·적용·수동값 보존·원본 버전 충돌을 검사합니다. 외부 Google 응답은 fixture입니다.
- 포장 무게 입력·공란·정확한 필드별 해제·선택 옵션·모든 포함 옵션·제외 옵션·이전 공통/옵션 충돌을 검사합니다. 보관한 69900 공식 XLSX 양식의 실제 6개 출력 행에서 같은 무게를 확인합니다. 테스트의 측정값을 운영 상품에 적용하지 않습니다.
- 실제 확장 worker/helper와 임시 IndexedDB 및 표시 DOM을 연결해 검증 중 → 원래 탭 닫힘 → 읽기 전용 조회 → 접수 ID → SKU 조회를 검사합니다. 운영 Supplier Hub에 견적서를 제출하는 검사가 아닙니다.
