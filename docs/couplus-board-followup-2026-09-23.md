# 바둑 견적 재대조와 출력 연결

2026-09-23, 로그인된 Chrome에서 쿠플러스 `/AIRocketReg`의 상품 옵션 → 견적서 완료 버튼으로 읽었다. 저장·AI 처리·초기화·등록 전송은 누르지 않았다.

## 확인

- 쿠플러스 상품번호 260923001001, 원본 URL https://detail.1688.com/offer/1078259572984.html, 상품명 `와이홉 휴대용 접이식 자석 오목 바둑판 세트`.
- 쿠플러스 목록에는 등록완료로 표시된다. 이는 Supplier Hub 접수 상태를 직접 확인한 것과 다르다.
- 견적 경로는 `완구/취미 > 보드게임 > 바둑/체스/윷놀이 > 바둑 > 바둑알+바둑판 (77442)`.
- 모델명은 상품명과 동일하다. 고시의 품명 및 모델명에는 해당 문자열이 한 번 나온다.
- 옵션은 `중형 자석 바둑판 13로 120알 (입문서 2권 포함)`, 공급가 5380, 판매가 8970, 권장소비자가격 11660. 노출 속성은 색상 `혼합색상`, 수량 `1세트`.
- 비노출 16개 항목과 선택지는 기존 `app/couplus-board-schema.ts` 관찰 항목과 일치한다. 저장값은 해당사항없음이다.
- 상품고시: 품명 및 모델명, 인증/허가 사항, 제조국(원산지), 제조자(수입자), 소비자상담 관련 전화번호. 인증/허가 사항의 저장값은 `해당 없음`이다.
- 대표·추가·라벨·상세 이미지에 실제 파일 주소가 표시된다. HTML 상세 내용은 비어 있다. 이미지 파일 내용까지 검사하지 않았다.
- 물류 저장값은 박스 내 SKU 50, 유통기간 0, 취급주의 해당사항없음, 포장무게 100, 포장사이즈 100*100*100이다. 이 값을 다른 상품의 기본값으로 사용하지 않는다.
- Supplier Hub `/qvt/registration` 로그인과 Excel/상품이미지/라벨/법적서류 업로드 UI를 재확인했다. `/sr/registration`에서 카테고리 검색 및 구조 선택을 시도했지만 이번 관찰에서는 바둑 분류 결과가 표시되지 않았다. 공식 77442 규격 확인으로 계산하지 않는다.

## 추정·미확인

저장된 견적만으로 각 값이 AI·사용자·자동 기본값 중 어디서 왔는지 판별할 수 없다. 특히 인증 여부, 포장 수치, `해당사항없음`을 공통 자동값으로 일반화하지 않는다. Couplus CLI 연결 표시는 보았으나 실제 수집/전송 실행 경로는 이번에 추적하지 않았다. 공식 Excel 바이너리·공식 바둑 필드 규격·최종 접수 결과는 미확인이다.

## 구현

기존 77442 견적 편집에는 16개 비노출 속성이 있었으나 Excel 연결 목록에는 없었다. 해당 필드와 인증/허가 사항을 연결 목록에 추가해 선택 카테고리 기준 머리글 자동 추천, 저장 검증, 견적 행 출력에 연결했다. 바둑 속성을 다른 카테고리에 연결하면 거절한다.

한글 표시사항에 저장한 인증·허가 사항을 고시로 연결한다. 직접 비운 값과 견적별 수동 수정의 우선순위를 보존한다. 품명과 모델명이 정확히 같을 때 고시에서 중복하지 않으며, 서로 다르면 둘 다 유지한다. 공식 양식이나 운영 접수 검증을 대신하는 변경은 아니다.
