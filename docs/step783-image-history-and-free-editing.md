# Step783 — AI 이력과 무료 이미지 편집 잠금 분리

이전 AI 작업이 `running`으로 남으면 공급자 미설정·현재 요청 없음에도 대표·추가·상세 이미지의 무료 번역과 직접 편집까지 계속 잠기는 결함을 수정했다. 과거 이력 상태는 그대로 보존하며, 현재 요청·미확정 견적 저장만 부모 편집을 잠근다. 이력이 미해결인 동안 새 AI 준비·승인·실행은 UI와 요청 직전 검사에서 계속 차단한다.

## 원본 대조와 변경 범위

- 보관 Couplus Stage5의 화면 동작은 `translateSingleImage` → 처리 결과 → 상세 HTML 생성 → 저장이다. 현재 YOOFAM의 선택 위치 고정·OCR·무료 번역·미리보기·해당 위치 적용과 대조했으며 이번 좁은 조사에서 새 누락은 확인하지 못했다. Stage4의 문구 제거 AI와 혼동해 상세 번역에 유료 cleanup 기능을 추가하지 않았다.
- 원본 route SHA-256 `5b92873c674c4b76c0e6ce4961caedbf8728ca86f6a15b6d9dc8cdfce80ad1d9`, UTF16 `[90603,90640)`, `[90811,90855)`, `[116160,117490)`, `[128446,129740)`, `[132036,137106)`. 기존 REA Evidence `ev_69740e390a2cc1e539a4a65a84e5c7065e2e6db9dcbc8a6311d0b4bfce5a3166`와 요약 `ev_26cdc76017d63fa2bb683d4165db034bae99266f6a3ad48bb3b45253f2ce9634`를 재사용했다. 새 producer·알려진 실패 lookup 반복·실사이트 실행 관측은 없었다.
- 생산 변경은 `image-generation-panel.tsx`의 이력/현재 요청 잠금 분리뿐이다. 서버·DB·공급자·원본 수집·카테고리·가격·전송 계약은 바꾸지 않았다. 실제 진행 요청과 응답이 불확실한 이미지 저장은 계속 잠긴다. 독립 검수에서 추가 확정 P1/P2는 없었다.
- 별도 소스 감사에서 Google 무료 텍스트 번역·OCR/Canvas 편집·초안 작성은 이미지 공급자와 분리돼 있음을 확인했다. 수집함의 수정 상품명은 불변 원문 대신 검토본에 저장되고 선택한 수집본의 정확한 버전으로 추천·초안에 연결된다. 해당 범위에 새 결함·생산 변경은 없으며 기존 검사를 재실행하거나 성과 건수에 추가하지 않았다.

## 검증

- 실제 Dashboard와 이미지 패널을 연결한 신규 5개 회귀가 세 이미지 단계의 무료 편집 진입, 오래된 유료 callback 차단, 실제 요청 중 잠금 유지를 검사한다.
- 최종 관련 5파일 **55/55 한 실행 통과**, 실패·취소·건너뜀 0. 최초 54/55의 유일 실패는 과거 running 이력만으로 종료도 막혀야 한다는 기존 기대값이었다. 이 기대를 바꾸고 실제 GET 중 종료 잠금·읽기 전용·쓰기 차단·수동 입력 보존은 유지했다. 초기 로그는 별도 보존했고 반복 검사를 합산하지 않았다.
- 타입·변경 파일 lint·운영 빌드·diff 검사 통과. 소스 SHA와 로그·배포·push는 `outputs/step783-final-validation.json` 참조.
- 같은 Chrome의 별도 localhost 새 합성 상품에서 실제 Dashboard/API/SQLite/R2 계약을 검수했다. 테스트 전용 running 이력을 만들고 공급자 설정을 제거했다. 외부 공급자 프로세스는 실행하지 않았다. 이 상태에서 선택 추가이미지 편집 → 직접 문구 `검수` 입력 → Canvas PNG 미리보기 → 검토 후 적용 POST 200 1회를 수행했다.
- 최종 조회에서 선택한 첫 추가이미지만 새 PNG로 교체됐고 다른 견적 필드·다른 옵션·원문·content·기존 파일·보호 합성 상품은 불변이었다. 이전 running 이력도 바이트 그대로 유지됐다. 이미지 목록은 PNG 한 장만 추가됐으며, 재편집용 `.edit.json`도 별도 보관됐다. 처음 검수 단언이 보조 문서를 제외한 1개 객체만 예상한 것은 실제 계약에 맞게 수정했으며 생산 코드는 바꾸지 않았다.
- 실제 미리보기 decode와 저장 이미지가 모두 32×32로 확인됐고 `outputs/step783-browser-free-edit.png`에 화면을 보관했다. 최종 단언은 `outputs/step783-browser-final-proof.json`에 있다. 외부 번역·AI 공급자·1688·Supplier Hub·native 요청은 0이다. 검수 탭과 서버는 정리했다.

## 남은 경계

기존 실제 업무 상품은 열거나 수정·삭제·전송하지 않았다. 이번 단계의 합성 이미지 편집 성공은 실제 1688 수집부터 Supplier Hub 접수까지의 성공이 아니다. 이전 브라우저 site-safety 거절 경로에 재접근하거나 간접 우회하지 않았다. 두 일반 live gate는 false를 유지한다. 실제 새 상품의 전체 과정·모든 카테고리/단계 UI 동등성·최종 docId/QVT/SKU 접수는 미검증이다. 운영 생성형 이미지 공급자 미설정도 그대로다. 확장 패키지·권한·호스트는 불변이며 새로고침을 요청하지 않았다. 기존 Worker만 갱신하고 새 리소스·마이그레이션·Access 정책 변경은 없다.
