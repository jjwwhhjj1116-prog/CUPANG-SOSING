# 다중 옵션 검증과 선택 상세이미지 자동 작업

## 수정한 워크프로세스

공식 SR의 단계 검증은 `data` 배열 전체에서 실패 결과를 집계한다. 기존 YOOFAM은 결과 한 행만 허용했고, 직렬화된 Hub 페이지는 첫 행의 성공 여부만 보고 상태를 정했다. 이제 1~200개의 모든 결과를 확인하고 뒤쪽 옵션의 실패도 전체 단계에 반영한다. 빈 응답·잘못된 행·성공과 오류의 동시 표시는 성공으로 처리하지 않는다. 불명확한 응답은 실제 관측값과 원래 요청 표식을 보존하며 자동 재전송하지 않는다.

공식 계약과 근거의 상세 기록은 `step878-native-step-validation-array-contract.md`에 있다. REA Evidence는 `ev_96936025b26ce0cebf6021c34efc5c48a480e8d631e4beb7e10dd47ad3fc596a`이며 공식 원문의 SHA-256은 `6fc9c0fae51702e62e2d1376ac8854d0d97c0035b0bf96afeb42069c2a5abe11`이다. 원래 문서 2347603의 실제 단계 검증 응답이 몇 행인지는 아직 관측하지 않았다. 이 코드 차이를 현재 라이브 복구 실패의 확정 원인으로 확대하지 않는다.

별도로, 상세이미지만 선택해도 플래너가 먼저 대표·추가·상세의 모든 연결을 검사해 관련 없는 대표이미지 오류 때문에 상세 작업을 시작하지 못했다. 플래너에 검증된 선택 단계 범위를 추가하고 선택 실행기는 해당 단계만 전달한다. 기본 전체 검토는 종전대로 세 단계를 모두 검사하고, 선택한 단계 안의 상품별 원자성·회원·회사·원본·저장 버전 검사는 유지한다.

## 통합 검증

- 이미지·자동 작업 4개 파일 171개 검사 통과. 실제 플래너·원본 검사·이미지 API·CAS 저장을 사용하는 격리 DB 회귀에서 잘못된 별도 대표이미지를 유지한 채 상세 원본 11장이 처리됐다. OCR·번역·렌더 제공자는 테스트 대역이다. 실제 AI 이미지 번역 품질이나 인페인팅 성공을 뜻하지 않는다.
- 단계 parser·직렬화 Hub adapter 2개 파일 63개 검사 통과. 전체 성공, 뒤쪽 실패, 총 오류 제한, 잘못된 응답 보관과 재전송 차단을 대조했다.
- 복구·접수 경로 15개 파일 201개 검사 통과. 실제 3개 옵션의 두 회사 흐름에서 원래 요청/문서의 읽기 복구→검증 2~5→명시적 단계 동의→접수 결과 확인을 검증했다. 세 번째 옵션 실패 시 전송 중지와 제출 응답 유실 후 동일 접수 조회를 포함한다. 외부 Chrome/Hub만 합성 환경이며 실제 접수 증거가 아니다.
- 위 그룹은 서로 다른 21개 파일, 435개 검사다. 넓은 helper 소비자 실행에서 기존 미갱신 preview-capability 기대 두 개가 실패했고, 해당 기대만 수정한 전체 파일 13개 검사를 다시 통과했다. 초기 실패 로그는 유지했다.
- TypeScript, 변경 소스 ESLint, diff 검사, 확장 생성물·ZIP 검사, 운영 빌드 통과. 코드 독립 검토에서 추가 결함은 발견하지 못했다.
