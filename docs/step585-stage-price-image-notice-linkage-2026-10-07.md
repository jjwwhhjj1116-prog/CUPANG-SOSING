# 단계별 가격·대표 이미지·표시사항 연결 — step585, 2026-10-07

이번 변경은 2단계에서 수정한 가격, 검토 후 적용한 번역 대표 이미지, 6단계 표시사항이 선택한 옵션과 Supplier Hub 견적서의 정확한 항목으로 이어지는 부분을 보완한다. 금액 계산식이나 전역 수동값 우선순위를 바꾸지 않았으며, 쿠플러스·Supplier Hub의 기존 작업 상품에는 저장·삭제·전송을 실행하지 않았다.

## 가격 수정과 카테고리 양식의 연결

Supplier Hub의 문자열 가격 항목은 `purchasePrice`, `coupangSalePrice`, `msrp`의 전체 경로와 별도 저장 ID를 유지한다. 이전 2단계 가격 입력은 공통 ID인 `supplyPrice`, `salePrice`, `msrp`만 수정했다. 이때 정확한 Hub 가격 항목과 Excel 열은 원래 자동 계산값을 유지할 수 있었고, 내보내기 검사가 두 값의 차이를 발견해 전송 준비를 막았다. 이는 소스 및 임시 저장소의 재현 사례이며, 운영 견적서에서 실제 오전송을 발견했다는 의미는 아니다.

`quotation-price-targets.ts`는 전체 경로·`hubInput`·숫자 입력 규칙으로 편집 대상을 확인한다. 화면에서는 실제 Hub 가격을 표시하고, 사용자가 직접 금액 또는 공란을 입력하면 공통 가격 ID와 해당 Hub 가격 ID를 한 요청으로 함께 수정한다. 복원은 해당 옵션의 두 수정값을 지우고 각 항목의 저장된 공통값 또는 자동 계산값으로 돌아간다. 조회만으로 기존 수정값을 복사하거나 삭제하지 않는다. 기존 공통값과 Hub 값이 서로 다르면 차이를 알리고, 다른 옵션·공통 수정값·별도 가격 값은 유지한다.

MSRP와 OSRP가 함께 있는 양식에서는 공식 판매처 가격인 OSRP를 독립적으로 보존한다. 실제 MSRP 경로가 없고, OSRP가 유일한 `msrp` 원천으로 정의된 양식에서만 OSRP를 연결한다. 잘못된 입력 규칙이나 중복 경로는 편집 대상으로 선택하지 않는다. `primaryNumericTextFields`의 Excel 연결도 이 좁은 OSRP 전용 조건을 반영하며, 포함된 모든 행의 최종 공통 가격과 연결 가격이 같은 경우에만 대응 관계를 인정한다. 서로 다른 기존 수동값을 자동으로 같게 만들지 않는다.

가격 정책 저장에는 즉시 동작하는 요청 잠금을 추가했다. 같은 제출 핸들러를 화면 갱신 전에 연속 실행하거나 첫 저장이 진행 중일 때 다시 호출해도 저장 요청은 한 번만 발생한다. 완료 후 새로 수정한 정책은 다시 저장할 수 있다. 계산식과 쿠플러스 관찰 범위는 [기본설정·가격 대조 기록](couplus-settings-pricing-parity-2026-10-06.md)을 따른다. 원본 내부의 최소 마진 분기나 미연결 통합통관 환율까지 완전히 같다고 확대하지 않는다.

## 번역 대표 이미지의 옵션 적용 범위

대표 이미지 번역 화면에 선택된 옵션 ID가 전달된다. 같은 원본을 개별 대표 이미지로 지정한 옵션만 함께 적용할 대상으로 선택할 수 있으며, 공통 대표 이미지를 사용하는 옵션은 갱신된 공통 이미지를 사용한다. 선택하지 않은 개별 대표 이미지와 견적서에서 직접 지정한 이미지 수정값은 보존한다. 적용 범위를 바꾸면 미리보기를 다시 작성하며, 편집한 문구·선택 영역·옵션 선택은 명시적으로 버리기 전까지 유지한다.

공통 대표 역할에 없는 개별 옵션 사진도 번역할 수 있다. 현재 그 사진을 사용하는 옵션이 정확히 연결돼 있어야 하고, 한 개 이상의 적용 옵션을 직접 선택해야 한다. 이 분기는 옵션 이미지와 상품 파일 목록만 저장하며 공통 이미지·표시사항·설명·콘텐츠 버전을 전혀 변경하지 않는다. 무선택·다른 원본의 옵션·삭제된 옵션을 적용 대상으로 받아들이지 않는다.

적용 요청은 원본 해시, 상품 버전, 내용 리비전, 옵션 리비전과 선택한 옵션 ID를 확인한다. 원본과 같은 PNG를 재확인할 때도 적용 범위를 결과의 고유성에 포함한다. 공통 역할도 바꾸는 경우에는 선택한 개별 옵션의 이미지 참조, 공통 이미지 역할, 상품 파일 목록을 같은 D1 배치에서 함께 저장한다. 개별 옵션 사진만 바꾸는 경우에는 콘텐츠 버전을 비교만 하고 옵션·상품만 함께 저장한다. 충돌하거나 저장 확인이 불완전하면 같은 결과의 저장 여부를 재확인하고, 다른 수정값을 덮어쓰지 않는다. R2에 저장됐으나 아직 연결되지 않은 결과 파일은 임의로 삭제하지 않는다.

옵션 범위·문구 수정은 미리보기를 즉시 무효화한다. 이전 적용 콜백은 현재 미리보기와 동일한 객체인지 확인하며, OCR 실패 후 남은 옵션 선택도 이전 재인식 콜백이 지우지 못한다. 명시적 초안 지우기 이후에만 다시 인식한다. 저장 상태 재확인에서 최신 옵션 후보가 바뀌어도 문구와 선택을 보존하고, 더 이상 연결되지 않은 선택은 사용자가 해제하도록 표시한다.

선택한 옵션 목록과 전체 원본 정보는 길어질 수 있어 R2 메타데이터에는 전체 JSON 대신 SHA-256을 보관한다. 원본·선택 범위·출력 PNG의 해시를 확인하고 필요한 버전은 DB와 요청에서 검증한다. 이전의 공통 이미지 전용 짧은 JSON 기록은 제한된 재시도 조건에서만 읽으며, 선택 옵션 정보가 없거나 해시 기록이 손상된 결과를 호환 기록으로 간주하지 않는다. Cloudflare의 객체 메타데이터 한도는 8,192바이트다. [Cloudflare R2 공식 한도](https://developers.cloudflare.com/r2/platform/limits/)에서 확인했으며, 최대 선택 범위의 저장 검사는 이 제약을 반영한다.

새 PNG에는 헤더로 검사한 픽셀 크기와 `dimensionValidation` 기록도 저장해 견적 화면이 검사 기록을 누락한 것으로 표시하지 않게 했다. 이 부분의 검증은 임시 DB·R2 객체 및 OCR/번역/캔버스 응답을 이용한 기능 검사다. 운영 브라우저에서 모든 상품 사진의 OCR 정확도나 번역 이미지 품질을 확인한 결과로 취급하지 않는다.

## 표시사항의 정확한 고시 항목

실제 수집한 상세 양식의 표시사항 원천 연결은 `legalPage.notices`의 정확한 이름과 이름/값 키를 확인한다. `legalPage`의 다른 위치에 같은 제목이 붙은 스칼라 제어 항목이나 배열을 표시사항으로 간주하지 않는다. 정적 참조 양식의 기존 고시 의미와 명시적인 수동값·공란은 유지한다.

자동 날짜·세탁 문구의 결과가 달라지는 좁은 범위에는 새 입력 지문을 반영한다. 이전 스포츠·바스켓 고시 원천 연결의 영향을 받을 수 있는 제한된 자동 항목에는 같은 값 또는 공란이어도 보수적으로 재검토 지문을 부여한다. 올바른 고시 항목, 관계없는 제어 항목, 저장된 견적서 수동값은 기존 지문 계약을 유지하며 과거 접수 기록을 다시 쓰지 않는다. 이 변경은 제어된 양식으로 재현한 잘못된 원천 연결을 차단하는 것이며, 운영 상품의 표시사항이 실제로 잘못 작성돼 있었다는 진단은 아니다.
