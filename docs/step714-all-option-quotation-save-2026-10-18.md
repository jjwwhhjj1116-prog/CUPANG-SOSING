## 변경 결과

7단계의 기본 스위치를 **모든 옵션에 적용**으로 맞췄다. 현재 상품의 실제 옵션은 견적 포함 여부와 관계없이 원본·대상이 될 수 있다. 저장 전 대상마다 변경 전/후 값을 보여주며, 제외 대상에는 ‘견적 제외’를 표시한다. 이 변경은 옵션의 포함 여부를 바꾸지 않는다. 공통 행은 이 복사의 원본이나 대상이 아니다.

현재 옵션에서 이번에 수정한 정확한 항목만 복사한다. 다른 옵션의 같은 항목에 입력한 값은 미리보기에 표시한 대로 바뀌지만, 수정하지 않은 자동값을 수동값으로 고정하지 않는다. 다른 항목의 대기 입력·공통값은 유지한다. 명시 공란 `''`은 공란을 저장하고 `null`은 각 대상의 해당 수동 입력만 해제해 원래 공통값/자동값으로 돌아간다. 가격 별칭과 포장 무게의 연결·가격 관계 검증·1,000개 변경 제한을 유지한다.

스위치 변경은 서버 요청을 하지 않는다. 명시적인 견적 입력 저장만 한 번의 기존 revision/fingerprint 검증 PUT을 수행한다. 스위치를 바꾸기 전에 캡처된 저장 callback은 이전 범위로 저장하지 못한다. 활성 저장·조회 중이거나 선택 옵션·저장 자료·현재 입력이 달라진 callback도 거절한다. 기존 실패 입력 보존, ACK 값 검증·필요 시 재조회, 요청 취소·중복 저장 방지는 유지한다. 별도의 ‘선택 항목 일괄 적용’에서 사용자가 지정하는 포함 옵션 범위는 바꾸지 않았다.

## 원본과 구분한 부분

원본은 모든 문서 경로의 pending을 순서대로 확장한다. 같은 항목을 여러 옵션에서 수정하면 열거 순서에 따라 값이 정해질 수 있다. 자체는 현재 선택 옵션의 대기 입력을 명시적인 원본으로 삼고 미리보기에서 확인하도록 유지했다. 원본의 blur 때 pending을 미리 확장하는 방식과 자체 저장 계획의 시점도 같다고 주장하지 않는다. 전체 옵션이라는 대상 범위를 맞춘 것이며, 모든 화면 전이가 완전히 동일하다는 증거는 아니다.

원본 ‘초기화’는 확인 후 initializeData만 호출하고 서버 저장·pending 삭제는 나타나지 않는다. 이를 저장된 견적 전체 삭제로 해석하지 않았다. 기존 미저장 입력 취소/저장본 다시 읽기를 유지했다.
