# Supplier Hub 전송 기록 복원 · 2026-09-30

앱의 견적서 검토 화면을 닫거나 새로고침하면 전송 시도 상태가 사라져 같은 파일의 전송 버튼이 다시 활성화되었다. 확장의 기존 영구 전송 claim은 재첨부를 막았지만 앱은 그 기록과 이미 확인한 견적서 ID/SKU를 불러오지 않았다. 수동 검증/상품별 조회는 자동 추적과 달리 현재 검토한 회사 및 옵션 수와 결과를 대조하지 않는 문제도 있었다.

## 변경

- 견적서 미리보기를 준비한 뒤 확장 `PING`의 `savedSubmission` 기능을 확인하고 `RESULT`로 해당 출처·상품·카테고리·저장 지문의 전송 시도 및 마지막 조회 결과를 읽는다. 복원 자체는 기존 확장 전용 IndexedDB의 읽기이며 Supplier Hub 탐색·파일 첨부·동의·검증 요청을 하지 않는다.
- 복원 전후 기존 로그인 상태의 읽기 전용 `quotation action:source` API로 최신 양식/상품/카테고리/저장 지문/파일명을 대조한다. 시도 기록의 정확한 회사코드/회사명과 포함 옵션 수도 현재 미리보기와 일치해야 한다. 회사는 `A01464742 · 와이홉`, `A01526306 · 유앤채`이다.
- 전송 시작·첨부됨·일부 전달·응답 불명·파일 검증 요청 및 저장된 검증 결과가 있으면 동일한 견적서의 재전송/첨부 준비를 차단한다. 저장된 결과에는 원래 확인 시각이 표시된다. 사용자는 파일을 다시 올리지 않고 `전송 결과 계속 확인` 또는 상품별 조회를 이어갈 수 있다.
- 확장 기록 읽기 실패/이전 확장에서는 미리보기와 다운로드를 유지하며 전송/준비만 차단한다. `전송 기록 다시 확인`은 기록을 다시 읽으며 새로운 ZIP이나 사용자 동의 선택을 만들지 않는다. `not-started`는 기존과 같이 claim이 없다는 증거가 있어야 사용자 재시도가 가능하다.
- 수동 결과 조회도 회사·파일명·포함 옵션 수·조회 행 한도를 대조하고, 상품별 조회는 기존에 확인한 견적서 ID를 유지해야 한다. 조회 중 이전 결과를 비워 다른 회사/견적서 결과가 이전 SKU 표와 함께 표시되지 않게 했다.
- 확장 `GET_RESULT` 발신자는 허용 출처의 최상위 앱 탭 및 유효한 탭/창 ID여야 한다. 기록의 원래 탭/창 ID는 값의 형식을 확인하며 복원 때 그 탭을 열거나 이동시키지 않는다. 실제 Hub 후속 조회는 기존 같은 창/회사 확인 경로를 사용한다.

## 검증 범위

- 실제 React 컴포넌트와 브리지/확장 worker 코드의 VM 검사: 두 회사의 재접속, 응답 유실, 부분 첨부, 파일 반려, 기록 읽기 실패 후 복구, 다른 회사/옵션 수/파일명/저장 지문/견적서 ID, 취소, 원본 변경 중 복구 및 수동 조회를 확인한다. worker 재생성 뒤 같은 기록을 읽는 fixture도 검사한다. 파일 바이트와 실제 업로드의 중복 claim은 기존 검사와 공유한다.
- 기록된 지정 1688 모바일 원문 `813724060928`으로 실제 API·SQLite·React·ZIP 판독·확장 소스 확인을 연결하는 두 회사 통합 검사에 재접속을 추가했다. SKU 6개·상품 이미지 3개·라벨 1개·저장 지문·회사·양식 및 필수 선택값을 대조한다. 전송 후 화면을 다시 구성하고 미리보기를 다시 준비해도 추가 ZIP 전송 없이 기록 확인을 이어간다.
- 인증·AI·이미지 바이트·양식·최종 전송/복원 기록은 fixture다. 80719는 선글라스 원문과 양식의 연결 시험용 합성 계약으로 실제 판매 분류가 아니다. 실제 Supplier Hub에 이 자료를 등록하지 않았다.
- TypeScript, 운영 빌드 및 Cloudflare 산출물 검사를 통과했다. 변경 코드 lint 오류는 없으며 intake-queue-panel.tsx의 기존 onBusy 의존성 경고 1개는 다운로드 링크 변경과 관계없는 기존 경고다. 최종 테스트 수와 배포 결과는 HANDOFF 517에 기록한다.
- 확장 0.2.28 ZIP의 27개 파일을 소스와 SHA-256으로 대조하고 운영 빌드의 ZIP도 대조했다. ZIP SHA-256: `BCE630ABF6CDB2623E3A3149CDD886949AB48C4F8D55A3DD8B82AF1C1CA75F0F`.

## 적용 및 남은 검증

기존 확장 폴더를 0.2.28로 갱신/새로고침한 뒤 앱 페이지를 새로고침해야 복원 기능이 적용된다. DB 마이그레이션과 Chrome 권한 추가는 없다. 기록은 해당 Chrome 프로필의 확장에 보관되며 다른 프로필/기기 또는 확장 제거 후에도 살아 있는 서버 전송 이력은 아니다.

복원한 파일 검증/SKU 발급은 검수 승인이나 최종 등록 완료가 아니다. 이번 수정은 앱의 중복 전송 표시와 결과 연결을 개선한 것이며, 전체 카테고리의 Couplus 기본값/공식 양식 일치 및 실계정 최종 등록, 운영 AI·이미지 번역·공개 상세 HTML·법적 서류 첨부 검증을 완료했다는 뜻이 아니다. 기존 Couplus 작업 상품·실계정 견적서·Chrome 프로필은 변경하지 않았다. 전체 완성률을 산출할 실검증 근거는 없다.
