# Step744 — 새 카테고리 폼 관측과 완료 검수 표시

기준 `4f9a6de1236818363842d285ee57925c411cbfe4`. 기존 작업 상품·견적서·전송 대기열·회원 기본설정은 수정하거나 재전송하지 않았다. 새로운 1688 원문이나 새로운 견적서 접수를 확인한 회차가 아니다.

## 실제 SR 화면

기존 Chrome4에서 별도로 연 빈 개별등록 화면 `/sr/registration/step/startPage`만 사용했다. 중간 저장·기존 등록 상품·등록 요청 상품은 불러오지 않았다. 회사 헤더는 유앤채다.

카테고리 구조에서 `스포츠/레져 → 헬스/요가 → 헬스기구/용품 → 헬스보호대`를 선택했다. 로딩 이후 실제 필드가 `스포츠/레져>헬스/요가>헬스기구/용품>헬스보호대 (81452)`로 표시됐다. 상품명은 빈 값이며 저장·미리보기·다음·전송은 누르지 않고 이 임시 탭을 닫았다. 따라서 서버 문서 생성·신청·약관 동의·신규 접수는 수행하지 않았다. 선택에 따른 Hub 최근 카테고리 갱신은 빈 폼의 정상 동작에 포함된다.

검색 상자는 값 설정 직후 이전 후보가 남거나 이전 키워드로 되돌아오는 동작이 있어 검색 결과만으로 leaf를 단정하지 않고 실제 구조 탐색을 사용했다. AX 근거는 로컬 `outputs/step744-hub-category-selected.ax.txt`다. 스크린샷 저장은 두 번 모두 CDP capture 시간 초과로 실패했으므로 이미지 근거로 집계하지 않는다.

이 화면 DOM에 표시된 `/sr/static/js/main.5239dce6.js`를 인증 정보 없이 공개 정적 파일로 읽었다. 4,346,727bytes, SHA-256 `6fc9c0fae51702e62e2d1376ac8854d0d97c0035b0bf96afeb42069c2a5abe11`로 기존 Step548와 동일하다. 이것은 현재 SR 코드가 같은 버전이라는 확인이며 실제 응답의 내부 Kan/고시/버전을 관측했다는 뜻은 아니다.

선택 카테고리·원문·새 초안·견적의 연결 감사는 [별도 보고서](step744-category-binding-audit.md)에 있다. 순수 assertion5그룹에서 공급자 category의 선택값 덮어쓰기, 새 초안 nested metadata 변경 수용, 표시 code와 내부 Kan ID 혼합에 대한 새 결함은 찾지 못했다.

## 확인된 표시 결함과 수정

기존 앱의 회사 단위 조회 화면에서 상태가 `상품 검수 완료`인37행 모두 `막힌 단계: 가격/정책`, 사유 `해당 검수가 완료되었습니다.`로 표시됐다. 이는 `registrationStageSummary`가 완료된 첫 단계 설명을 fallback으로 선택하고 표가 이를 '막힌 단계'라고 부른 결과다.

- 완료된 현재 검수 상태는 `검수 완료`, 요약 사유 `—`로 표시한다. 과거 단계 설명은 펼친 상세에 원문 그대로 남긴다.
- 진행 중인 단계와 실제 반려 단계가 함께 있을 때 반려·거절·실패 사유를 우선 표시한다.
- 열 이름은 모든 상태에 맞는 `진행 단계`로 바꾼다.
- 원격 상태·식별값·조회 응답이나 저장 이력은 수정하지 않는다. 회사 전체 조회로 새 YOOFAM 견적서 접수 이력을 만들지 않는다.

## 검사

관련4파일46/46검사가 통과했다. 회사 조회·원격 상태 파싱·두 회사의 원문 fixture부터 수동 수정/전송 packet까지 이어지는 격리 workflow·기존 receipt 조회를 포함한다. 새 완료/반려 요약 사례와 입력 불변도 확인했다. 이는 실제 새 상품 수집/접수 증명이 아니다.

타입 검사, 변경3파일 린트, Cloudflare 운영 빌드와 artifact 검사가 통과했다. 확장0.2.88의 모바일 모듈·ZIP도 기존 SHA `49ab5aad5a4507ea17bf2c3f811c7b1054c316bbab24695c6936679e8022c2fc`와 일치한다. 이번 수정에 확장 업데이트는 필요 없다.

## 남은 완료 조건

새 1688 URL의 실제 원문 수집, 해당 leaf의 실제 내부 양식 metadata 대응, 사람이 수정한 새 문서의 native 전송과 신규 발급 접수번호는 아직 확인하지 못했다. 이전에 도구가 거절한1688/Open1688 주소를 재시도하거나 다른 경로로 우회하지 않았다. 두 native live gate는 false를 유지한다. 이 회차 결과로 전체 동등 구현 또는 실제 접수를 완료했다고 보고할 수 없다.
