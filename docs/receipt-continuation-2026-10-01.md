# 접수 결과 복원과 견적서 ID를 유지하는 조회

작성일: 2026-10-01. 대상: YOOFAM PLUS 로켓배송 AI상품등록.

## 수정한 결함

견적서와 SKU 결과를 보관한 뒤 창을 다시 열면 상세 화면의 확인 문구는 현재 실행 중인 조회의 상태만 참고했다. 서버 또는 확장에 여섯 SKU가 보관되어 있어도 상품별 결과를 확인하지 못한 것처럼 표시했다. 또한 `전송 결과 계속 확인`은 이미 알고 있는 견적서 ID를 받지 않고 파일 검증부터 다시 시작했다. 기존 ID와 다른 검증 결과로 진행하거나 SKU 조회 전의 파일 결과로 기존 행을 지울 수 있었다.

네 회귀 검사를 수정 전에 실행해 네 건의 실패를 재현했다. 조회를 재개할 때 검토한 회사·파일명·옵션 수와 일치하는 기존 결과를 전달한다. 접수 ID가 있으면 그 ID를 기준으로 새 상품별 조회를 바로 시작한다. 기존 행을 새 조회의 증거로 승격하지 않으며, 응답을 받기 전 취소 또는 통신 실패가 나면 표시된 기존 결과를 유지한다. 최초 전송에는 기존 결과를 전달하지 않는다.

자동 조회도 파일명·회사·옵션 수·관찰 시각·상태·견적서 ID·상품별 조회 계약을 확인한다. 다른 ID, 다른 파일, 잘못된 회사 또는 옵션 수, 중복 SKU, 등록 완료를 임의로 주장한 응답은 표시하지 않는다. 수동 파일 검증 재조회도 이미 확인된 ID를 다른 ID로 바꾸지 못한다. 저장본 변경은 기존 source fingerprint 검사로 차단한다.

SKU 수와 중복·생략된 ID·반려·추가 페이지 여부에 대한 판정 함수를 상세 화면, 자동 조회, 서버 보관 요약에서 공유한다. 복원과 새 조회의 표시가 같아진다. SKU ID 확인은 관찰한 접수 결과이며 쿠팡의 최종 검수 승인으로 표시하지 않는다. 수동 수정값, 전송 동의, 견적서 내용과 첨부 파일은 이 변경으로 수정되지 않는다.
