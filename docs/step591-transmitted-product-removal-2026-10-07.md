# 쿠플러스와 동일한 전송 상품 삭제 보호

2026-10-07, Step590의 재수집·카테고리 연결 수정에 이어 적용했습니다.

## 확인한 원래 동작과 변경

로그인된 쿠플러스 AI상품등록 목록에서 이미 등록 전송된 상품의 삭제 아이콘은 비활성화되어 있으며, `쿠팡에 이미 전송된 상품이라 삭제할 수 없습니다` 안내가 나옵니다. 원래 상품은 읽기만 했으며 수정·삭제·재전송하지 않았습니다.

YOOFAM PLUS도 같은 휴지통 버튼과 안내를 사용합니다. 화면 상태 글자나 최신 반려 결과만으로 판단하지 않고, 소유자·상품의 저장된 Supplier Hub 전송 이력 전체를 확인합니다.

- 파일 검증 중, 견적서 접수, SKU 확인, 접수번호가 남은 상품 반려 기록은 삭제를 막습니다.
- 현재 초안의 회사·카테고리·버전이 변경되어도 과거 실제 전송은 보호됩니다. 새 지문의 반려 기록이 이전 접수를 지우지 않습니다.
- 접수번호·등록 근거가 없는, 완전히 검증된 파일 반려 기록만 있으면 삭제할 수 있습니다. 전송 기록이 없는 상품도 기존처럼 삭제·복원할 수 있습니다.
- 잘못된 지문·관찰시각·증거순서·불완전한 기록 또는 과도한 이력은 확인될 때까지 삭제를 막습니다.
- 삭제된 상품의 복원은 계속 허용합니다. 이미지·수정값·접수 자료는 그대로 보존합니다.

클라이언트는 삭제 직전에 최신 소유 상품과 서버 정책을 다시 조회합니다. 계정 전환·화면 종료 뒤에는 늦게 도착한 조회 결과로 DELETE를 보내지 않습니다.

서버는 검토한 반려 이력의 정확한 지문·원문·관찰시각·증거순서를 원자적 INSERT에 연결합니다. 조회 후 새 접수가 들어오거나 기존 기록이 바뀌면 상품 삭제 기록이 생성되지 않습니다. 정상 접수의 `registered:false` 값을 ‘미전송’으로 오인하지 않습니다.

- 회귀 111/111: 삭제/API/접수 이력/화면 72개, 정책 경합/재수집/스키마 39개
- 타입 검사 오류 0개, lint 오류 0개(기존 경고 9개), 빌드 통과
- Worker: `abc7eb2d-3bc5-4868-b976-539183d7e339`
- 배포 주소: https://sourceflow.jjwwhhjj1116.workers.dev/
- DB 추가 마이그레이션 없음(17개 유지), 확장 0.2.54 및 파일 해시 변경 없음

접수 이력·경합 검사는 실제 처리기와 SQLite fixture로 수행했습니다. 이를 실제 Supplier Hub 상품 전송 성공으로 계산하지 않습니다. 이번 배포에서도 기존 작업 상품을 삭제하거나 견적서를 전송하지 않았습니다.

실제 최종 접수번호 확인과 전체 카테고리의 운영 대조는 남아 있습니다. Chrome의 아직 서버에 관찰·저장되지 않은 전송 시도는 이 DB 이력 검사로 존재를 단정할 수 없습니다. 화면의 작업 중 잠금과 확장의 전송 복구 절차를 함께 유지합니다.
