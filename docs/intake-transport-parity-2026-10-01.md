# 1688 수집 출처별 이미지 저장 차이와 PC 이동 응답 처리

## 수정한 차이

기존 상품추가의 원본 이미지 묶음 저장은 `1688-public-mobile-v1` 서버 수집 결과에만 적용됐다. 확장 0.2.29의 `chrome-public-mobile-v1` 결과나 기존 Chrome JSON-LD/API 수집 결과는 같은 검증·원본 자료함을 사용하면서도 한 장씩 저장했다. 지정 상품의 19개 원본이 정상 처리될 때 Chrome 수집 이후 이미지 저장 API 호출이 19회였다.

서버가 검증해 저장한 수집 결과에서 `assignToStage:false`로 원본 자료함에 저장하면 출처 이름과 관계없이 기존 3장 묶음 경로를 사용하도록 수정했다. 같은 기록된 상품으로 19개 원본이 7개 요청에 저장되고 동시 CDN 다운로드는 최대 3개임을 확인했다. 다운로드만 병렬로 진행하고 DB 반영은 원문 번호 순서대로 진행한다. 대표·추가·상세 이미지와 옵션 대표는 자동 지정하지 않는다. 별도로 이미지 배치까지 반영하는 기존 요청은 순차 저장을 유지한다. 운영 실제 전송 시간의 3배 개선을 측정했다는 의미는 아니다.

## PC 페이지 이동 응답

공개 PC 페이지가 HTTP 301/302/303/307/308을 반환하면 기존 수집은 공식 모바일 원문을 시도하지 않고 끝났다. JSON-LD가 없는 HTTP 200에서만 모바일을 시도하던 차이를 수정했다. PC 응답 본문을 취소하고, 사용자 URL과 같은 상품번호의 고정 공식 모바일 주소를 조회한다. PC 응답의 Location이나 쿠키를 사용하지 않는다. 기존 30초 전체 제한·취소 신호, SKU 가격/MOQ/재고/이미지/상품번호 재검증을 유지한다. HTTP 401/403 인증 오류는 다른 원문 조회를 시작하지 않는다.

이 수정이 2026-09-30 진단 당시 초기 상품 데이터가 없었던 Cloudflare 모바일 응답을 데이터가 있는 응답으로 바꾸지는 않는다. 서버가 원문을 얻지 못하면 기존 Chrome 공개 수집 경로가 이어진다. 외부 서비스의 실제 응답 상태와 앱의 대체 경로 처리를 구분한다.

## 검증

- 원본 자료함 저장은 서버 모바일·Chrome 모바일·서버 JSON-LD·Chrome JSON-LD·API 출처에서 동일한 묶음 처리, 50개 용량/예약 공간, 제외한 원본 유지와 기존 파일 재사용을 검사했다. 배치에 이미지를 지정하는 요청은 순차 처리함을 별도로 확인했다.
- Chrome 공개 원문 → 실제 수집 API/임시 SQLite → 6옵션/19이미지/SEO 초안에서 7개 이미지 묶음 요청을 확인했다. 한 이미지 실패 후 재시도는 누락한 파일 하나만 다시 내려받았다. 원문 재수집·AI 재실행·중복 파일 생성 없이 직접 수정한 SEO명·상세 설명·옵션 판매가를 유지하고 Hub 상태는 미전송이었다.
- 두 회사 A01464742·와이홉과 A01526306·유앤채 각각에서 PC HTTP 200/302 → 기록된 모바일 원문 → 초안 → 수동 수정 → 견적 Excel/첨부 ZIP 연결을 검사했다. 80719는 관찰 폼의 합성 비교 계약이며 실제 선글라스 판매 분류가 아니다. 해당 시험은 실제 Supplier Hub에 제출하지 않는다.
- PC 이동 응답의 본문 정리·Location/응답 쿠키 비사용·취소 후 추가 요청 금지·401/403 종료를 검사했다. 관련 원문/초안/견적 회귀 검사 96개가 통과했다.

추가 회귀 7개 포함 전체 테스트 1,484/1,484, TypeScript와 변경 파일 lint(오류·경고 0)가 통과했다. 최초 새 회귀 실행의 두 실패는 두 개의 대표 이미지를 넣은 잘못된 fixture와 상품 공통행을 첫 옵션으로 검사한 예상값 오류였다. 원본 fixture를 단일 대표로 수정하고 저장 전후 실제 옵션 ID의 수정값을 대조한 뒤 관련·전체 검사를 통과했다. 기존 저장소 전체 lint 통과를 주장하지 않는다.

상품 데이터는 기록된 공개 원문이고 인증·AI·이미지 바이트·양식은 fixture다. 실제 Chrome의 네트워크 실행, 운영 AI/이미지 번역 품질 또는 실계정 Hub 등록 완료를 입증하지 않는다. 기존 Chrome 바인딩의 작업 탭 목록은 `[]`였으며 다른 창/프로필과 기존 Couplus 작업 상품을 조작하지 않았다. 전체 카테고리의 Couplus 기본값·공식 양식 대조와 최종 실계정 등록 검증은 남아 있다.
