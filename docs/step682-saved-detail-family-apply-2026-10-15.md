# Step682 — 저장한 통합 상세를 선택한 분할 상품에 적용

기준 커밋 `92324dfcc3e7892bffc5153f0d5a67468e0d5133`. Step681의 명시적 옵션 분할 가족 관계에 이어, 5단계에서 저장한 통합 상세 PNG를 선택한 같은 가족 상품의 견적서에 연결했다. 기존 운영 상품과 Couplus·Supplier Hub 탭은 수정하지 않았다.

## 비교 근거와 구현 범위

`docs/step680-split-audit.md`와 보관된 Couplus JS 조사를 재사용했다. 신규 사이트 접근·1688 재수집은 없다. 근거 파일은 `outputs/step652-current-couplus/chunk-27c89b44.6953b027.js`(SHA256 `ce8f14422c4e93a11592d886a369d633066a8a9f4cdba9f37dbb1276d798c6cc`) 및 `main.a20c7114.js`(SHA256 `29cfa2cf13011f62da4b99032fecbf7972d541f85cbfe622a5a906389ca7faad`)다.

Couplus의 일반 `saveDetailPage`와 별도 `applyDetailToSiblings`는 다른 동작이다. 후자는 원본을 저장한 뒤 공통 첫 견적서의 상세 이미지를 선택한 분할 상품의 공통·모든 옵션 첫 견적서에 연결하고 상세 HTML을 비운다. ALT·대표/추가 이미지·표시사항·가격은 바꾸지 않는다. 이 동작을 같은 URL의 모든 상품에 자동 전파하는 것으로 해석하지 않았다.

이번 구현은 이미 일반 상세 저장을 끝낸 **최종 통합 PNG의 견적서 연결**이다. 원본을 다시 저장하거나 원문 수집 자료를 덮어쓰지 않는다. Couplus가 함께 복사하는 루트 `detailHtml`·번역/처리 그룹·편집 상태 메타데이터의 완전 복제는 이번 범위에 포함하지 않았다. 자체 `ProductContent.detail.description`은 일반 텍스트이므로 루트 HTML과 같다고 취급하지 않는다. `originDetailImages`도 불변 수집 원문과 같은 의미가 아니다. 이 제한을 화면에 명시했다. 전송 이력이 있는 대상은 이번 초기 지원에서 제외한다.

## 화면과 저장

- 상세 단계의 `분할 상품에 상세 적용`에서 같은 회사·소유자·명시적 분할 가족의 대상만 표시한다. 같은 URL의 독립 초안은 대상이 아니다. 원본은 현재 카테고리의 일반 상세 저장 증거와 공통·모든 실제 옵션의 연결값이 일치해야 한다. 이후 다른 값만 수정한 원본에서도 해당 증거가 여전히 맞으면 쓸 수 있다.
- 최대 19개 대상을 선택해 미리보기와 적용 범위를 확인한 뒤 저장한다. 대상의 견적 제외 옵션도 실제 옵션이므로 빠뜨리지 않는다. 다른 카테고리의 수정값·수동 공란·ALT·가격·표시사항·대표/추가 이미지·원본 상세 편집 자료는 보존한다. 기존 이미지 풀은 순서를 유지하고 새 PNG가 없을 때만 추가한다.
- 대상 저장 전 상태와 후 상태·처리 결과를 불변 `detail_family_apply_operations`에 기록한다. 공통과 모든 옵션의 현재 카테고리 상세 이미지/HTML, 상품 이미지 풀·견적 대기 상태·저장시각만 갱신한다. 원본에는 쓰지 않는다. 일반 상세 저장 영수증을 대상에 새로 만들어 복제하지 않는다.
- 전체 회원/회사/원문/설정/카테고리/제품/옵션/견적/작업 상태의 원문을 비교한다. 조회 도중 같은 revision으로 내용이 바뀌는 문제를 막기 위해 stable view와 정확한 원문을 다시 짝지어 확인한다. 저장 직전 실제 소유 PNG의 바이트·SHA256·업로드 메타데이터·800px 규격을 재검증한다.
- 하나의 D1 batch에서 대상별 사전 조건과 저장 후 결과를 확인한다. 동반 INSERT/UPDATE가 무시돼도 일부만 남지 않고 모두 롤백한다. 최대 19개 대상의 실측은 **97 SQL 문 / 문당 최대 20 바인딩 / 최대 SQL 13,446바이트**다. 개별 견적 512KiB 및 전체 불변 기록 2MiB 제한을 초과하면 쓰기 전에 거절한다. 한도가 큰 실제 자료는 대상을 나눠 적용해야 한다.
- 응답이 불명확하면 POST를 반복하지 않는다. 검토 자료를 상품/프로필별 세션에 보관하고 새로고침 뒤 GET으로 확인한다. 과거 성공 이후 데이터나 PNG가 바뀌었거나 파일이 없어지면 영수증은 유지하되 `current:false`로 구분한다. 재조회 과정은 읽기만 수행한다.
- 미저장 입력·다른 이미지/가격 작업과 충돌하지 않도록 잠그며, 늦게 도착한 응답·탭/버전 변경·확인 체크의 재사용을 차단한다. 키보드 초점 순환과 복원, 진행 중 닫기 차단도 포함한다.

## 같은 Chrome의 실제 화면 검수

와이홉은 대상 2개 중 1개만 선택해 저장했다. 유앤채는 2개를 저장한 뒤 응답만 503으로 바꾸고 새로고침 후 GET만으로 성공을 확인했다. 회사별 42테이블 중 상품/견적을 제외한 40테이블 전체와 원본의 나머지 행도 정확히 유지했다. 와이홉 비대상은 불변이고, 선택한 총 3상품의 실제 6옵션(제외 3옵션 포함)의 상세 연결만 바뀌었다. ALT·모든 비상세 필드·수동 공란·다른 카테고리·원문·등록번호와 파일 바이트를 보존했다.
