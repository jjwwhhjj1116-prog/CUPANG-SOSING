# YOOFAM PLUS Chrome 상품 수집·Supplier Hub 첨부 연결 — 0.2.29

YOOFAM PLUS가 생성한 **견적서 + 첨부 ZIP**을 읽어 현재 Supplier Hub 대량 등록 탭의 Excel, 상품 이미지, 라벨 입력에 파일을 전달합니다. 공식 API 주소를 추측하거나 로그인 쿠키를 복사하지 않습니다.

## 현재 범위

- 앱의 원본 비압축 ZIP 형식, 파일 CRC, 견적서 SHA-256, 목록과 파일명 일치를 확인합니다.
- XLSX만 견적서로 전달하며 포함 옵션에 라벨이 빠져 있으면 중단합니다.
- 팝업 전달은 현재 활성 `https://supplier.coupang.com/qvt/registration` 탭에서 실행합니다. 앱 등록전송은 요청한 앱과 같은 Chrome 창의 회사코드가 일치하는 등록 탭에서 실행하며, 기존 첨부가 있으면 같은 창에 비활성 등록 탭을 준비합니다.
- 실제 화면에서 관찰한 구역 제목으로 입력을 찾습니다. 기존 첨부, 중복 구역, 비활성 입력이 있으면 변경 전에 중단합니다.
- 파일 선택의 `change` 이벤트를 전달합니다. 이는 Supplier Hub의 서버 업로드 성공을 의미하지 않습니다.
- 부분 실패 또는 결과 불명 시 재시도하지 않습니다. 입력이 변경되었을 수 있으므로 실제 첨부 목록을 먼저 확인해야 합니다.
- 파일 전달 후 같은 화면에서 필수 동의와 파일명 표시를 확인하고, 활성화된 파일 검증 버튼을 명시적으로 실행할 수 있습니다. 검증 요청은 검증 성공이나 등록 완료를 뜻하지 않습니다. 중복 검증 요청은 차단합니다.
- 팝업에서 직접 선택한 동의와 법적 서류 해당없음 선택을 전달합니다. 최종 등록 완료 확인은 **아직 구현하지 않았습니다**.
- 웹페이지에서 검토한 ZIP의 등록전송으로 파일 첨부·선택한 필수 동의·법적 서류 해당없음·파일 검증을 요청할 수 있습니다. 검증된 견적서 ID의 상품별 SKU/상태 조회도 앱에서 실행합니다. 기존 `/api/supplier-hub` POST는 이 확장 경로가 아니며, 전체 옵션의 최종 등록 완료 판정은 아직 미검증입니다.
- 앱의 지정된 운영 도메인과 localhost:3000/127.0.0.1:3000에서만 준비 메시지를 받습니다. Chrome 프로필 내 확장 전용 IndexedDB에 패키지 하나를 보관하고, 새 준비 시 교체합니다. 15분이 지나면 사용할 수 없으며 다음 확장 실행 시 삭제합니다. 전달 시도 전에 한 번만 소비하므로 종료·응답 유실 후 자동 재전송하지 않습니다.
- 사용자가 URL 수집을 시작하고 서버 공개 조회가 실패하면, 같은 앱 탭에 연결된 확장이 1688의 공개 모바일 상품·옵션·상세 원문을 먼저 조회합니다. 성공하면 상품 탭을 새로 만들지 않습니다. 공개 조회가 실패한 경우 기존 같은 창의 PC 페이지 JSON-LD 수집을 사용합니다. 앱 이동·주소 변경·취소 후에는 다른 탭을 열지 않습니다. 상품번호·SKU별 CNY 원가·최소 주문 수량은 서버에서 재검증하고, 사용자가 수정할 초안만 저장합니다.

### 0.2.29 공개 모바일 원문 수집

- Chrome 120 이상에서 동작합니다. 서버와 확장이 같은 HTML/JSON 원문 해석 코드를 사용합니다. 판매자 스크립트나 JSONP는 실행하지 않습니다. 잘못된 상품번호·누락 가격·접근 확인 요청은 초안으로 바꾸지 않습니다.
- 모바일 페이지·공개 SKU 서비스·해당 페이지가 지정한 상세 CDN에만 익명 GET을 보냅니다. 프로필 쿠키·로그인 토큰·비밀번호를 읽지 않습니다. 이번 익명 요청에 새로 발급된 mtop 전송값 두 개만 다음 정확한 SKU 요청에 잠시 사용하고 정리합니다. 기존 사용자 탭의 요청에는 적용하지 않습니다. 취소·오류·확장 재시작 시 정리하며 앱/DB/콘솔에 전송값을 보내지 않습니다.
- 앱은 원문을 다시 검증한 수집 기록으로 SEO·옵션·가격 초안을 만듭니다. 이 과정에서 Supplier Hub에 견적서를 전송하지 않습니다. 사용자가 1~7단계를 확인·수정한 후 별도로 등록전송합니다.
- 기존에 로드한 이 확장 폴더를 갱신한 후 Chrome 확장 관리 화면에서 해당 확장만 새로고침하고 앱 페이지를 새로고침하세요. 다른 Chrome 창이나 프로필을 만들 필요는 없습니다.
- 빌드: `npm run build:extension`, 원본·공유 파서·ZIP 일치 검사: `npm run check:extension`. 배포 빌드도 일치 검사를 실행합니다. `mobile-public.mjs`는 공유 소스에서 생성한 파일이며 직접 수정하지 않습니다. 포함 OSS의 라이선스는 `mobile-public.LICENSE.txt`에 있습니다.

### 0.2.28 앱 재접속 후 전송 기록 복원

- 앱에서 견적서를 준비하면 같은 Chrome 프로필의 확장에 저장한 이전 전송 시도와 조회 결과를 불러옵니다. 상품·카테고리·저장 지문·회사코드/회사명·옵션 수를 대조하며 복원 전후 최신 앱 저장본을 확인합니다. 복원은 확장 기록 조회이며 Hub 탭을 열거나 파일을 다시 첨부하지 않습니다.
- 응답 유실·부분 첨부·검증 대기·반려 기록도 같은 견적서의 재전송을 막습니다. 기록 읽기 실패 시 견적서 미리보기와 다운로드는 유지하며 기록 재확인 후 전송 여부를 결정합니다. 기록이 있는 견적서는 ‘전송 결과 계속 확인’으로 실제 Hub 상태를 다시 조회할 수 있습니다. 저장된 결과의 확인 시각을 표시하며 최종 등록 완료로 간주하지 않습니다.
- 기존 확장 폴더를 0.2.28로 갱신/새로고침하고 앱 페이지를 새로고침해야 적용됩니다. 이 기록은 해당 Chrome 프로필에 보관되므로 다른 프로필/기기나 확장 제거 후에도 복구되는 서버 이력은 아닙니다.

### 0.2.27 첨부 직전 최신 저장본 대조

- 앱 등록전송과 앱에서 준비한 파일의 팝업 전달은 원래 앱 탭을 같은 Chrome 창에 열어둔 상태에서 실행합니다. 해당 탭의 로그인 상태를 이용해 저장된 상품·카테고리·양식·회사정보와 준비한 파일을 다시 대조합니다. 계정 쿠키/토큰을 읽거나 Supplier Hub에 복사하지 않습니다.
- 준비 이후 수정한 견적서, 다른 창으로 이동/종료한 앱 탭, 회사정보 변경은 파일 첨부 전에 중단합니다. 앱 등록전송은 업로드 완료 후 파일 검증 요청 직전에도 저장본을 확인합니다. 이미 전달한 파일은 자동 재첨부하지 않습니다.
- 이전 버전에서 준비한 파일은 앱에서 다시 준비해야 합니다. 설치된 확장 폴더를 0.2.27로 갱신/새로고침하고 앱 페이지를 새로고침하면 적용됩니다. ZIP 직접 선택은 앱 상품과 연결되지 않는 기존 수동 경로이며 최신 저장본 대조 대상이 아닙니다.

### 0.2.26 견적서 결과의 여러 페이지 대조

- 앱이 만든 같은 Chrome 창의 조회 전용 탭에서, 검증 완료된 견적서 ID로 검색하고 화면에 표시된 페이지 번호와 다음 버튼을 따라 결과를 모읍니다. 매 페이지 전후 회사코드, 전송 기록과 검증 결과가 같은지 확인합니다. 다른 작업 탭의 검색·상품·첨부는 변경하지 않습니다.
- 페이지가 바뀌고 결과 표가 갱신된 뒤 읽습니다. SKU ID가 축약되어 있으면 해당 셀의 표시된 복사 버튼 값으로 전체 ID를 확인합니다. 클립보드는 읽지 않습니다. 옵션 수를 초과한 결과와 중복 SKU, 건너뛴 페이지, 검색 조건 변경을 거부합니다.
- 한 번에 최대 60초/200페이지를 읽고 실제 페이지 수·남은 페이지 여부를 반환합니다. 페이지 표시를 해석할 수 없으면 현재 페이지로 한정합니다. 남은 페이지가 있으면 전송 옵션 수와 같더라도 발급 확인을 끝내지 않습니다. SKU 발급은 검수 승인·최종 등록 완료와 구분합니다.
- 페이지 UI는 합성 DOM으로 검사했습니다. 현재 연결의 Chrome 탭에 실제 Hub가 표시되지 않아 실계정 페이지 이동·최종 접수는 아직 검증하지 않았습니다. 파일 검증·상품 결과 표의 기존 관찰 근거와 새 페이지 UI 시험을 구분합니다.
- 설치된 확장 폴더를 0.2.26으로 갱신/새로고침하고 앱 페이지를 새로고침해야 적용됩니다.

### 0.2.25 늦게 표시되는 원문과 수집 취소

- 페이지 로딩 이후에도 최대 10초 동안 상품 메타데이터를 다시 확인합니다. 서버와 같은 해석기로 실제 상품번호·SKU별 CNY 원가·최소 주문량을 읽고, 500ms 동안 동일한 원문이 관찰된 뒤 반환합니다. 가격 범위, 다른 상품, 없는 SKU를 임의로 채우지 않습니다.
- 같은 창의 중복 수집을 막고, 앱의 취소·시간 초과를 해당 요청에만 전달합니다. 앱이나 상품 탭이 다른 창·상품·로그인 화면으로 이동하면 수집을 중단합니다. 기존 탭과 사용자가 활성화한 탭은 닫지 않습니다.
- 공개 JSON-LD를 제공하지 않는 상품 페이지까지 지원한다는 의미는 아닙니다. 실제 지정 1688 상품에서 수집에 성공한 증거와 전체 Supplier Hub 등록 완료 검증은 아직 없습니다.
- 설치된 확장 폴더를 0.2.25로 갱신/새로고침하고 앱 페이지를 새로고침해야 적용됩니다.

## 개발 설치·확인

1. 사용자가 지정한 Chrome 프로필에서 `chrome://extensions`의 개발자 모드를 켜고 이 폴더를 압축해제된 확장으로 로드합니다.
2. Supplier Hub에서 **기존 작업 파일이 없는** 대량 상품 등록 화면을 엽니다.
3. 설치 후 앱 페이지를 새로고침하고, 견적서를 검사한 다음 `Supplier Hub 확장으로 파일 준비`를 누릅니다. 같은 Chrome의 Supplier Hub 탭에서 확장을 열면 파일이 자동으로 준비됩니다. ZIP 직접 선택도 가능합니다.
4. 현재 회사 계정과 파일 목록을 확인한 후 `현재 탭에 파일 전달`을 누릅니다.
5. Supplier Hub의 실제 업로드 결과와 필수 동의 내용을 확인합니다. 동의 항목을 직접 체크하고 확장의 `첨부한 파일 검증 요청`을 실행합니다. 최종 등록은 별도입니다.

관찰한 DOM 구조를 재현한 테스트와, 동일한 Chrome의 전용 localhost 테스트 페이지에서 실제 IndexedDB 저장·교체·동시 소비 7개 검사를 통과했습니다. 확장 자체의 실계정 파일 업로드·검증·등록 시험은 수행하지 않았고, 사용자가 0.2.1 설치 완료를 알려주었습니다. 0.2.5 변경분은 확장 새로고침 후 적용됩니다. 작업 중인 기존 상품을 시험에 사용하지 않습니다.

## 근거와 테스트

- 2026-09-27 기존 로그인 Chrome의 Supplier Hub 대량 상품 등록 화면에서 제목을 가진 각 구역에 `input[type=file]` 하나씩 있는 구조를 확인했습니다.
- [Chrome scripting 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/scripting), [activeTab 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab).
- `node --test tests/supplier-hub-extension.test.mjs tests/supplier-hub-handoff.test.mjs`
- 테스트 XLSX 바이트는 체크섬 전달을 위한 합성 자료이며 공식 양식 검증의 근거가 아닙니다.
- 저장소 실제 브라우저 검사: `node scripts/test-handoff-store-browser.mjs` 실행 후 기존 Chrome에서 `http://127.0.0.1:4243/` 열기. 이 전용 origin의 시험 데이터만 사용합니다.

### 0.2.5 검증 결과 확인
- `검증 결과 확인`은 이 화면에서 검증을 요청한 YOOFAM 견적서 파일명과 정확히 일치하는 결과만 표시합니다. 실제 관찰한 검증 진행상태 표의 5개 열을 사용합니다.
- 견적서 ID와 원문 검증 상태를 표시하며, 검증 완료를 상품 등록 완료로 바꾸지 않습니다. 결과가 없거나 같은 이름의 행이 여러 개인 경우 성공으로 처리하지 않습니다.
- 현재 화면에 열린 결과를 읽습니다. 갱신하려면 Supplier Hub 결과 창의 새로고침을 사용합니다. 페이지를 새로고침하면 전달 시도 연결 정보가 사라지므로 자동으로 다른 견적서를 추정하지 않습니다.
- 실제 계정의 결과 목록은 비어 있었습니다. 실제 업로드·검증 결과 수신은 아직 검증하지 않았고, 테스트는 관찰한 표 구조를 재현한 자료입니다.

### 0.2.5 상품 화면으로 결과 전달
앱에서 준비한 견적서는 전송 시 앱 출처·상품·카테고리·검토 식별값을 별도로 보관합니다. 확장의 검증 결과 확인 후 일치하는 파일 결과만 저장하고, 앱의 `Supplier Hub 검증 결과 불러오기`로 상태·견적서 ID·확인 시각을 표시합니다. ZIP 수동 선택은 앱 상품과 연결되지 않으므로 결과를 앱에 연결하지 않습니다. 상품 등록 상태를 완료로 변경하거나 서버 접수 기록을 생성하는 기능은 아닙니다. 실제 계정의 업로드와 최종 등록은 여전히 미검증입니다.

### 0.2.5 새로고침 후 결과 복구
앱에서 준비해 전달을 완료한 견적서는 같은 Supplier Hub 탭을 새로고침해도 저장된 정확한 파일명으로 결과를 다시 조회합니다. 새 파일 전달이 거절되거나 일부만 전달된 경우 이전 상품의 연결 정보를 덮어쓰지 않습니다. 조회는 읽기 전용이며 파일 재첨부·검증 재요청을 자동 실행하지 않습니다. 새 탭 또는 브라우저 재시작에 따른 탭 ID 변경은 아직 복구하지 않습니다. ZIP 직접 선택은 기존 페이지 연결 정보가 유지될 때만 조회 가능합니다.

### 0.2.6 상품별 등록 상태
파일 검증 완료와 견적서 ID를 먼저 확인한 뒤, 같은 Supplier Hub 탭에서 상품 등록 상태 확인 화면을 열고 견적서 ID로 검색합니다. 확장의 상품별 등록 상태 확인 버튼은 현재 보이는 표에서 해당 ID의 행만 읽습니다. 상품을 수정하거나 검색조건을 바꾸지 않습니다. 앱에서 결과를 불러오면 SKU·검수 상태·등록 진행 단계를 표시합니다. 페이지 전체 옵션 수는 검증하지 않으므로 최종 등록 완료로 표시하지 않습니다. 0.2.6 적용에는 확장 새로고침이 필요합니다.

### 0.2.7 검사 결과 확인 후 첨부
앱에서 준비하거나 직접 선택한 ZIP 모두 submission-review.json을 요구합니다. 상품·카테고리·지문·파일명과 검사 항목 수가 일치하고 오류가 0개일 때만 첨부를 준비합니다. Excel 열 미연결 등 오류가 남은 ZIP은 앱에서 수정 후 다시 준비해야 합니다. 증빙 검토 알림은 오류와 구분합니다. 이 검사는 패키지 내부 일관성 검사이며 서명 검증이나 Supplier Hub 공식 접수 성공 증명이 아닙니다. 새 버전은 확장 새로고침 후 적용됩니다.

### 0.2.8 전체 견적서 ID로 결과 대조
Supplier Hub 상품 등록 상태 표는 견적서 ID를 앞 8자리와 ...으로 표시합니다. 해당 셀의 표시된 복사 버튼에 있는 전체 ID로 정확하게 대조하도록 수정했습니다. 앞자리가 같은 다른 견적서는 연결하지 않으며, 복사 버튼이 여러 개이거나 표시와 값이 다르면 제외합니다. 클립보드를 읽거나 상품을 수정하지 않습니다. 적용에는 확장 새로고침이 필요합니다.

### 0.2.9 검증 결과 재조회 시 상품별 상태 보존
같은 상품·카테고리·견적서 ID의 완료 결과를 다시 조회하면 기존 상품별 등록 상태와 해당 상태의 확인 시각을 보존합니다. 다른 견적서 ID 또는 반려·진행중·조회되지 않는 결과에는 이전 상품별 상태를 연결하지 않습니다. 파일 검증을 다시 확인한 시각을 상품별 상태의 새 확인 시각으로 표시하지 않습니다. 확장 새로고침 후 적용됩니다.

### 0.2.10 앱 견적서 전달을 백그라운드에서 처리
앱에서 준비한 견적서는 확장 팝업에서 전달을 누르면 백그라운드가 저장된 파일을 다시 검사하고 한 번만 전달합니다. 확인된 전달 결과의 상품 연결정보도 백그라운드에서 저장하므로 팝업 응답 처리에 의존하지 않습니다. 부분 전달·실패는 이전 연결을 덮어쓰지 않습니다. 브라우저 종료나 백그라운드 자체 중단까지 복구하는 기능은 아니며, 확인되지 않은 전달을 자동 재시도하지 않습니다. 수동 ZIP 첨부는 기존 방식입니다. 적용에는 확장 새로고침이 필요합니다.

### 0.2.11 결과 조회의 백그라운드 저장
- 검증 결과와 상품별 등록 상태의 조회·저장을 서비스 워커로 이동했습니다. 팝업이 닫혀도 이미 요청한 조회의 저장을 처리합니다.
- 같은 탭의 동시 조회는 거절하며, 해당 탭·파일명·견적서 ID에 연결된 결과만 저장합니다.
- 파일 검증 완료와 전체 상품 등록 완료를 구분합니다. 브라우저 종료나 서비스 워커 강제 종료의 복구를 보장하지 않습니다.

### 0.2.12 검증 요청의 백그라운드 실행
- 팝업의 파일 검증 요청을 서비스 워커로 이동했습니다. 팝업 응답 수신과 독립적으로 실행하며 같은 탭의 동시 요청을 차단합니다.
- 현재 활성 Supplier Hub 등록 탭, 전달된 파일 목록, 필수 동의 및 활성 검증 버튼을 확인하는 기존 검사를 유지합니다. 화면의 요청 표시로 중복 클릭을 막습니다.
- 약관 자동 동의나 등록 완료 판정은 추가하지 않았습니다. 브라우저/워커 종료 후 요청 복구를 보장하지 않으며, 응답 불명 시 실제 검증 상태를 확인해야 합니다.
- 적용에는 설치된 확장 새로고침이 필요합니다. 이 버전의 실제 업로드·검증 요청은 실행하지 않았습니다.


### 0.2.13 검증된 견적서 ID로 결과 검색
- 같은 Supplier Hub 탭의 상품 등록 상태 확인 화면에서 `검증한 견적서 ID로 검색`을 누르면, 저장된 파일 검증 완료 결과의 전체 ID를 검색란에 입력하고 검색합니다. 기존의 다른 ID는 덮어쓰지 않습니다.
- 날짜·상태 등 다른 검색조건은 유지됩니다. 화면 로딩 후 `상품별 등록 상태 확인`으로 결과를 읽으세요. 검색 요청 자체는 등록 완료 증거로 저장하지 않습니다.
- 실제 로그인 화면에서 입력 ID·레이블·검색 버튼 구조를 확인했고 재현 테스트를 통과했습니다. 실계정 패키지의 업로드부터 등록 완료까지는 미검증입니다. 새 코드 적용에는 설치된 확장 새로고침이 필요합니다.

### 0.2.14 직접 확인한 동의 전달
- 확장 팝업에서 선택한 가격 정보·라벨 연락처 동의만 현재 등록 화면에 전달합니다. 실제 관찰한 ID와 전체 문구가 일치해야 하며, 선택되지 않은 항목은 체크하지 않습니다. 파일 검증 요청이며 최종 등록은 아닙니다. 법적 서류 해당없음은 자동 선택하지 않습니다.

### 0.2.15 확인한 법적 서류 해당없음 전달
- 사용자가 팝업에서 서류가 필요 없음을 직접 확인한 경우에만 관찰된 법적 서류 구역의 해당없음에 반영합니다. 기본값은 미선택이며 기존 법적 첨부가 있거나 구역이 달라지면 변경하지 않습니다. 미선택이면 해당 구역에 손대지 않습니다.

### 0.2.16 열린 검증 결과 새로고침
- 이미 열린 검증 결과 표는 관찰한 새로고침 버튼으로 갱신한 뒤 화면의 정확한 파일명 행을 읽습니다. 표 변경이 잠잠해질 때까지 기다리며 최대 대기는 6초입니다. 서버의 검증 완료나 상품 등록 완료를 보장하지 않습니다.

### 0.2.17 검증 완료 후 같은 탭에서 상태 검색
- 검증한 견적서 ID로 검색을 누르면 같은 업로드 탭에서 상품 등록 상태 화면으로 이동합니다. 화면 준비를 최대 5초 기다린 후 저장된 검증 완료 ID만 검색합니다. 이미 상태 화면이면 이동하지 않습니다.
- 검증 완료 기록이 없으면 이동하지 않으며 다른 탭으로 변경되거나 로그인 화면으로 이동하면 중단합니다. 검색·화면 이동은 등록 완료로 기록하지 않습니다. 설치된 확장을 새로고침해야 새 코드가 적용됩니다.

### 0.2.18 회원 회사코드 연결
- 승인된 회원의 회사명·코드가 서버에서 견적서 ZIP과 검토 지문에 포함됩니다. 유앤채 A01526306, 와이홉 A01464742의 정확한 쌍만 허용합니다. 회사정보 변경 후에는 견적서를 다시 검토해야 합니다.
- 파일 전달 전에 현재 Hub 회사 메뉴를 열어 표시된 Company Code와 대조합니다. 파일 전달 직전과 검증 요청 직전에 다시 확인합니다. 불일치하거나 확인할 수 없으면 파일 전달/검증을 실행하지 않습니다.
- 회사정보가 없는 이전 ZIP은 새로 준비해야 합니다. 앱은 회사 확인 기능이 없는 이전 확장으로 새 파일을 준비하지 않습니다. 확장 0.2.18 업데이트 및 앱 새로고침이 필요합니다.
- 회원 회사정보는 계정 관리 화면에서 지정합니다. 현재 Chrome 로그인 회사로 회원 소속을 임의 변경하지 않습니다. 패키지는 서명된 서버 권한 증명은 아니며, 실계정 첨부·등록 완료까지 검증한 것은 아닙니다.

### 0.2.19 결과 조회 회사 확인
- 전송 당시 회사정보를 보존하고 검증 결과 조회 및 상품별 결과 조회 전후에 현재 회사코드를 확인합니다. 회사가 바뀌면 결과를 저장하지 않습니다.
- 회사정보가 없는 이전 전송 기록은 현재 로그인 회사로 추정하지 않습니다. 기존 견적서는 Supplier Hub에서 직접 확인하세요.

### 0.2.20 견적서 ID 조회 전 검색 조건 초기화
- Hub의 재설정 버튼으로 이전 상품명·상태·단계 등의 검색 조건을 초기화한 뒤 검증된 견적서 ID를 입력합니다. 초기화되지 않은 입력이나 교체된 양식은 검색하지 않습니다.
- 다른 견적서 ID가 이미 입력된 경우에는 기존 검색을 지우지 않습니다. 검색 결과는 등록 완료로 간주하지 않습니다.

### 0.2.21 초안 옵션 수와 조회 행 수 대조
- 검토한 ZIP의 포함 옵션 수를 상품·카테고리·회사·견적서 지문과 함께 전달·보존합니다. 결과 조회에는 현재 페이지에서 실제 확인한 행 수와 원래 초안 옵션 수를 나란히 표시합니다.
- 이전 기록과 옵션 수가 다르면 조회 행을 재사용하지 않습니다. 페이지 밖 행과 최종 등록 완료는 이 비교만으로 판단하지 않습니다. 설치된 확장 새로고침이 필요합니다.
