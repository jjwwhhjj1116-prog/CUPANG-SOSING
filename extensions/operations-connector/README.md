# YOOFAM 운영 데이터 연결 1.0.0

기존 YOOFAM 상품 수집·견적서 확장과 별개인 운영관리용 MV3 확장이다. 설치를 자동 실행하지 않는다. 개발자 모드로 이 폴더를 로드하거나 배포 ZIP을 풀어 사용한다. 권한을 확인한 뒤 사용자가 직접 설치한다.

열린 같은 Chrome 창의 쿠팡 소비자/윙/서플라이어허브/광고센터 탭에서 자료를 읽는다. 기존 탭을 이동하지 않으며 외부 승인 시에만 확장 소유 확인 창을 연다. 로그인·보안 확인은 사용자가 직접 처리한다. 인증값이나 원본 HTML을 웹앱으로 전달하지 않는다.

- 지원: 검색 상품·첫 화면 순위, 연관검색어, 리뷰 표본, 광고센터 상품재고, 서플라이어 입고표·발주 SKU·RI 명세서 조회, 일별 캠페인 지표.
- 28일 수요는 로그인된 WING 탭이 있고 상품/옵션이 유일하게 연결될 때만 보강한다. 원천 지표의 집계 범위는 미확정 참고값이다.
- 검색·가격은 렌더 구조에 의존하므로 검증 전 관찰값이다. 검색 없음과 구조 해석 실패를 구별한다.
- 금융 자료는 `/vendor/` 또는 광고센터 `/marketing/cmg-api/advertiser`가 반환한 실제 회사코드를 수집 전후 확인한다. 앱이 보낸 회사코드만으로 확인을 대신하지 않는다.
- 기본 페이지 한도 40, 단일 요청 행 한도 5,000, 응답 크기 약 2.2MB. 상한·중간실패는 부분 수집으로 반환한다. 발주 SKU·광고 조회는 최대31일을 사용한다.
- 거래명세서 승인(`statementConfirm:true`)은 정확한 문자열 발주번호 1~10개를 지정한다. 서버 회사코드와 현재 RI 목록을 읽은 뒤 **확장 전용 확인 창**에 회사·발주번호·금액을 표시한다. 사용자가 확인란을 체크하고 직접 승인 버튼을 눌러야만 알려진 `confirmInvoice` POST를 건별 순차 실행한다. 웹앱의 `explicitConfirmation` 값으로는 실행되지 않는다.
- 승인 창의 송신 확장/탭/최상위 프레임·일회 nonce·5분 TTL·요청ID/회사/발주목록 해시를 검사한다. 매 발주 전 회사와 RI 상태를 다시 조회하며, POST 전 체크포인트를 기록한다. 성공·진행·불명 이력은 재실행을 차단한다. 불명 응답은 자동 재시도하지 않는다. 승인 전 창 닫기·취소·만료는 외부 작업을 실행하지 않는다. 전송 후 창을 닫아도 이미 전송된 작업은 취소되지 않는다.
- **미지원:** 상품 제안 제출, 광고 예산 변경. 승인 또는 수집의 실제 계정 동작은 실행 검증하지 않았다.
- 이 구현은 기존 분석에서 관찰된 인터페이스 계약에 맞춘 독립 구현이다. 라이브 계정에 실제 수집을 실행해 성공을 검증하지 않았으므로, 사이트 변경·로그인·상품목록 채널 차이로 제한될 수 있다. 실패 시 원본 Excel/CSV 가져오기를 사용한다.

웹 메시지: `YOOFAM_OPS_PAGE` → `YOOFAM_OPS_EXTENSION`, requestId·kind·companyCode·values. 승인 조건은 `values.purchaseOrderSeqs:string[]`, `startDate/endDate`다. 승인은 5분 확인 대기를 포함하므로 웹앱 응답 타임아웃을 445초 이상으로 둔다. 요청은 허용 앱의 최상위 프레임에 한정한다. 작업은 직렬로 실행되며 requestId 재전달을 거부한다. 저장 이력에는 종류·회사·상태와 발주별 승인 체크포인트만 보존한다.

개발 검증: `node --test tests/operations-connector.test.mjs`. 패키지 생성: `node scripts/package-operations-connector.mjs`; 동일성 검사: 같은 명령에 `--check`.
